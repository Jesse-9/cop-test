# 03 · 关键文件逐文件导读

> 目标：106 个源文件，哪个值得读、哪个查一下就行、哪个别碰。按"层"分组，每组先给结论，再逐个说。
>
> 记号：**★ 必读**（理解主线绕不开）· **◆ 核心**（改功能会动到）· **○ 查阅**（用到再看）· **· 可跳过**（兼容层/样板）
> 体量列用 KB（1 KB ≈ 20～25 行），方便判断"这篇要花多久"。

## 0. 如果你只有两小时

按这个顺序读 7 个文件 + 2 个测试，就能掌握 80%：

```text
1. domain/default_process.py        (18 KB)  工艺全貌，业务即代码
2. domain/rules.py                  (7 KB)   所有冻结常量
3. application/run.py               (19 KB)  一次运行的骨架
4. application/coordinator.py       (123 KB) 只读 docstring + step() + _dispatch_ready()
5. simulation/execution/base.py     (5 KB)   执行契约（很短但很关键）
6. artifacts/store.py               (36 KB)  manifest 结构
7. cli.py                           (29 KB)  命令 → 函数的映射

测试：
   tests/test_v1_process_model.py          目录校验规则
   tests/test_v1_coordinator_scheduler.py  调度行为
```

## N. 命名约定（读懂后缀就不迷路）

项目保留了迁移期的**分层后缀**，它们表达的是"从哪一层继承/派生"，不是模块序号：

| 文件族 | 语义 |
|---|---|
| `*_base`（`config_base` `layout_base` `scene_base` `unit_controller_base`） | 基础层：A/B 单站闭环 |
| `*_motion` / `motion/*`（`config_motion` `unit_controller_motion`） | 运动层：碰撞、规划、轨迹、安全、吸附 |
| `*_dual`（`config_dual` `layout_dual` `scene_dual`） | 双站层：`L2_MIRROR` 双工位 |
| 无后缀（`config` `layout` `scene` `unit_controller` `runtime` `coordinator`） | UFLOW 层：五岛 `L5_UFLOW` |

`runtime_common.py` 是"双站层与 UFLOW 层共用的单臂会话"，不属于任何单层。

**类名里的 `Stage3*` / `Stage4*` 是契约 ID 的一部分**（`spec.CONTROLLER_ID`、工件 `source_phase=stage4`），不能随便改名——改名需要新契约版本 + 新工件。日常讨论请说"基础层/运动层/双站层/UFLOW 层"，不要说"stage3 代码"。
