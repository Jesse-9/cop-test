## 3. 怎么用

在项目根目录、CoppeliaSim 已启动之后：

```powershell
# ① 离线看停放点：不需要 CoppeliaSim
.\.venv\Scripts\python.exe tools\cart.py spot

# ② 加载当前工件（v004 已不含手推车；本工具只用于临时摆放）
.\.venv\Scripts\flexible-factory.exe load

# ③ 查看小车
.\.venv\Scripts\python.exe tools\cart.py status

# ④ 独立演示：沿 +X 前进 0.7 m 再退回原位
.\.venv\Scripts\python.exe tools\cart.py drive --distance 0.7 --speed 0.12

# ⑤ 临时移除（只影响本次会话，不改工件）
.\.venv\Scripts\python.exe tools\cart.py remove
```

> 注意第 ⑤ 条：`remove` 只从**当前内存场景**删对象。重新 `load` 后小车会回来，因为它在工件里。

自定义位置（仅在想要新位置时用，会影响下次 save）：

```powershell
.\.venv\Scripts\python.exe tools\cart.py add --x 3.40 --y 2.40 --yaw 1.57 --replace
```

`spot` 的输出是一份可核对的几何报告：

## 4. 小车长什么样

8 个对象，全部 `static=1` + `respondable=1`，挂在根 dummy `WorkshopCart` 下：

| 别名 | 类型 | 说明 |
|---|---|---|
| `WorkshopCart` | dummy | 根节点，承载位姿 `(3.50, 2.30, 0)`，`yaw=0` |
| `WorkshopCart_Deck` | cuboid | 台面 0.42 × 0.30 × 0.04，中心高 0.135 |
| `WorkshopCart_Wheel_FL/FR/RL/RR` | cylinder | 4 个轮子，半径 0.055、厚 0.026，绕 X 转 90° |
| `WorkshopCart_Rail_L/R` | cuboid | 两侧矮护栏 0.42 × 0.018 × 0.05 |

占地（含轮子外凸）0.42 × 0.356，`footprint` = `[3.29, 2.122, 3.71, 2.478]`。

## 5. 为什么放在 (3.50, 2.30)

这是全车间的一个空角落：

- AGV 东直道在 `x=2.90`，小车在其**东侧**；
- 成品输出台在 `(3.50, 1.35)`，只到 `y≈1.45`，小车在其**北侧**；
- C→E 线与 E 岛碰撞包络在 `y ≤ 1.65`，够不到；
- 完全在地面 `x∈[-4,4], y∈[-3,3]` 以内。

`spot` 算出的最近障碍是 `dock:E`，间隙 **0.5125 m**，远大于要求的 0.08 m。

## 6. 为什么它不会影响 `full_flow`

1. **static**：不受重力、不会被 AGV 顶走，物理上不参与动力学；
2. **不在路径上**：离最近障碍 0.51 m；
3. **不占资源**：`ResourceTable` 只认 `rules.RESOURCE_ORDER` 里的 21 个资源；
4. **不建任务**：协调器只按工艺目录里的 `OperationTemplate` 建实例；
5. **manifest 容得下**：`validate_scene_against_manifest()` 把小车记进 `extra_aliases`，`ok` 只看 `missing`/`mismatch`（`artifacts/store.py:588-613`）。

## 7. 永久化是怎么做的（可复现）

没有手写 manifest，而是复用项目自带的生命周期，保证"原子写 + 保存后重载校验 + 只读保护"：

```text
① load  v1/L5_UFLOW/v001_20261103_004317      重新加载基线（清掉内存里的小车）
② cart.build_cart(sim)                        按固定几何放 8 个 static 对象
③ manager.validate()                          454 项通过（小车计入 extra_aliases）
④ manager.save(note=..., provenance=...)      → v002_20261116_225544
    ├─ sim.saveScene(scene.partial.ttt)
    ├─ 写 manifest（schema 2.0 / config.digest 不变 / 记录 provenance）
    ├─ 立即 loadScene(partial) 重载并做 455 项校验
    ├─ 通过后 os.replace 成 scene.ttt
    ├─ 原子更新 v1/current.json
    └─ 四个文件设为只读（protected: true）
```

结果：

| 项 | 值 |
|---|---|
| 新工件 | `v1/L5_UFLOW/v002_20261116_225544` |
| scene SHA-256 | `e8e468715d84a58635879e22a4efad46b9d411b9a9d44e1091bbd6009eb497af` |
| 保存后校验 | **455 项通过**，`extra_aliases` 59 个（含 `WorkshopCart*` 8 个） |
| 文件属性 | 4 个文件都 `只读` |
| 重新 `load` 验证 | `present=true`，`objects=8`，`static=1`，位姿 `(3.5, 2.3, 0)` |

v001 没有被删除也没有被修改（仍是只读基线），只是 `current.json` 不再指向它。

## 8. 两个必须知道的后果

**① 以后从 stage3 重新 `build` 不会带小车。**
`build_stage4_scene()` 不认识 `WorkshopCart`；`build --save` 生成的新工件里没有它。想让"重建也带小车"，得在构建器里加一段（属于改原有代码），或者重建后手动 `add` 再 `save` 一次。

**② 想回退到 v001。**
把 `v1/current.json` 指回 v001 即可（四个字段：`artifact_id` / `path` / `manifest_digest` / `scene_sha256`，可从 v001 的 manifest 取）。这属于改指针，需要我或你手工确认；v002 目录留着不影响。

## 10. 排错

| 现象 | 原因 / 处理 |
|---|---|
| `[ERROR] CART_STATE: 必须在仿真停止状态增删物体` | 场景在跑。先 `flexible-factory stop` |
| `[ERROR] CART_PLACEMENT: 场景里已存在小车` | 当前工件已自带小车，直接 `status` / `drive` 即可；要重摆用 `--replace` |
| `[ERROR] CART_PLACEMENT: 停放点与既有几何冲突` | 换位置 `--x/--y`，或 `spot` 看空位 |
| `validate` 里看到 `WorkshopCart*` 在 `extra_aliases` | 正常，不影响 `ok` |
| `load` 报 `InvalidTransitionError ... getSimulationState()=17` | 仿真器在运行（可能有人点了 Play）。先停：`flexible-factory stop`，再 `load` |
| `PermissionError: session.json.tmp` | 只有在**被沙箱限制的环境**里跑才会出现（例如自动化工具）；你自己的终端不会有 |
