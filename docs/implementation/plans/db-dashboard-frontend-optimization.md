# 本地数据库仪表盘前端优化方案

## 目标与边界

把 `tools/db_dashboard_template.html` 从一张按区块纵向铺开的只读报告，整理为更适合反复检查本地 SQLite 快照的工作台：用户能快速辨认数据库/迁移版本和数据新鲜度，筛选知识图谱节点，检查单次生产运行和工序 DAG，并在目录/来源信息间导航。

交付保持 `tools/db_dashboard.py` 生成、双击可打开、无外部运行时依赖、数据库只读和数据嵌入 HTML 的模式。此页面不是阶段 5 的实时订单 UI，不启动仿真、不发送写请求、不增加数据库查询/迁移责任。由于文件离线打开，页面内“刷新”只能说明需重新生成快照，不尝试 fetch API/SQLite。

交互组织参考 [Grafana dashboard 文档](https://grafana.com/docs/grafana/latest/dashboards/) 的面板分组与上下文筛选思路；本页只有本地静态 payload，因此把 Grafana 的动态变量收敛为本地筛选 state，不引入数据源插件、查询编辑器或实时刷新能力。

## 现状与主要问题

- 单 HTML、CSS 和原生 JS 自包含，Python payload 构造与脚本转义已有边界，适合继续沿用。
- 页面顺序是知识图谱、实体/关系计数、运行、目录、发布记录和来源；缺少页内导航和活跃数据域切换，长快照需要大量滚动。
- 顶部 `hero-row`/KPI 占据首屏，但统计卡片层级与“检查某次运行/工序”的任务关联弱；页面使用多重圆角卡片和固定 1440px 约束，信息密度偏低。
- 图谱 Canvas 有完整表格替代，但筛选只控制实体类型/搜索，运行筛选单独工作；节点数/边数较大时画布完整绘制和标签交互的性能需要验证。
- 目录包含 DAG SVG、工序详情、路线、依赖、设备、资源、区域、物料、入口、场景绑定等长内容，缺少按使用任务组织的导航和一致的搜索入口。
- 现有响应式规则对大区块有折叠，但移动端表格、详情 KV、节点图和长 ID 的优先级仍需明确；Canvas 的键盘操作有限，图表替代表格易发现性可加强。
- 空库、部分 schema、查询异常可正常生成部分数据，但 UI 需更清楚地区分“无数据”“schema 不存在”和“此区块读取失败”。

## 设计方向

面向维护 SQLite、知识抽取和仿真运行记录的工程人员。采用浅色为默认的检查台式视觉：暖白底 `#f7f8f6`、白面板 `#ffffff`、深墨 `#202624`、灰绿辅助 `#60706a`、青绿交互 `#087e78`、琥珀警示 `#b86b14`、红色失败 `#b53d3d`；深色模式沿用 token 映射，状态色需满足文字/背景对比。正文用系统 sans，ID/版本/计数用等宽数字；组件边角不超过 8px，控制面板以分隔线和网格为主，不叠卡片。

页面的单一签名是“可检查的快照”：固定头部在显眼处标识数据库路径、revision、生成时间及快照属性；下方以任务导航切换“总览 / 知识图谱 / 生产运行 / 工艺目录 / 来源”。区块内保留原始表格作为准确值与无障碍访问的首要替代，而 Canvas/SVG 只承担关系概览和关联选择。

## 信息架构与关键交互

### 固定快照头部

- 展示页面名、缩短显示但可复制的 DB 路径、schema revision、生成时间和总览数据量。
- 提供主题切换、复制 DB 路径、打印/保存提示；“重新生成”如暂不接 Python 进程，只显示清楚的生成命令提示，不制作无效刷新按钮。
- 带“离线只读快照”状态文字，避免用户把静态文件误认成实时数据。

### 任务导航和总览

- 主导航用锚点/原生按钮切换区块，保留 URL hash，使返回/分享定位有效；窄屏改成可滚动 tabs 或 select，不能挤压头部。
- 总览只放数据健康和入口：DB revision、实体/关系、已发布目录、运行数、最新运行终态，以及“缺少表/空数据”的直接说明。
- 移除当前 hero 单一巨大数字作为主视觉，统计值用对齐的紧凑指标行，并让各指标可跳转对应区块。

### 知识图谱

- 统一类型、状态、文本搜索过滤，并显示可清除的筛选条件和匹配数量；原始统计图表与筛选结果口径清晰分开。
- 选择节点后联动高亮相邻关系、节点表行和关系表；提供清空选择、缩放重置和“查看表格”命令。
- 继续用安全的 DOM `textContent` 输出数据库内容，避免拼接 HTML。Canvas 增加 DPR/resize 处理和绘制节流；若节点/边超过经样例验证的阈值，关闭力导向动画或显示静态抽样/仅表格模式，不增加重型图谱依赖。
- 节点、边和状态表格有 caption、scope、可见焦点、复制长 ID；不把颜色作为唯一分类编码。

### 生产运行

- 默认选择最近一次运行，同时允许选择其他快照内 run；显示 run ID、scenario、状态、开始/结束时间、整体结果和计数。
- 同页按 tabs/次级导航组织“摘要、工序时间线、资源等待、物料谱系、故障”；避免目前一次渲染所有详情导致的长滚动。
- 运行 DAG 与工序行联动；失败、阻断、等待、成功分别有文字状态和可访问标记。UID、失败原因、设备和时间可复制/可检索。
- 对 payload 中每个 run 的局部 `error` 显示区块级错误说明，不把空数组误呈现为“无故障/无等待”。

### 工艺目录、发布和来源

- 目录内使用二级导航分组：配方/路线、工序与依赖、设备能力、资源/区域/物料、订单入口/场景绑定；默认聚焦摘要和工序图。
- 增加目录内搜索，并提供 CSV 不在本期；表格使用 sticky header、窄屏水平滚动和 ID 复制，列排序仅在确有检查需求时实现。
- 发布历史与知识来源/抽取分别作为独立区块；摘要显示当前发布版本和来源抽取状态，完整行详情按需展开。
- 未发布、无目录表、无知识表等状态解释其含义，并提供下一步检查提示，而非共享一条泛化空态。

## 实施步骤与顺序

1. **冻结现有行为基线**：从 `db_dashboard.py`、template 和 `tests/test_v1_db_dashboard.py` 列出 payload 字段、区块 ID、筛选行为和安全输出保证。先保留 payload shape、CLI 和离线运行方式。
2. **重排结构与视觉 token**：改造 template 的 header/navigation/overview/section 框架和 CSS token，确保旧 renderer 的 DOM 接口要么保留、要么同步更新。先实现锚点导航和窄屏布局，再拆运行/目录子导航。
3. **总览与空态**：用既有 payload 增加数据健康摘要和导航计数；为知识不可用、目录不可用、无运行和局部 query error 分别呈现状态。
4. **图谱交互**：统一过滤、选中联动表格、canvas resize/DPR 和超大图降级策略。只有观察到真实 payload 性能不足时才启用阈值降级；不添加 worker/布局算法重写。
5. **运行和目录分组**：实现区块内 tabs/锚点，保持函数只读并按需渲染非首屏细节；验证 run 切换不会丢失全局搜索/主题设置。
6. **可访问性与移动端**：键盘导航、焦点样式、表格语义、状态文本、reduced motion、320px 窄屏和 200% 缩放检查；对缩窄时不可读的表格允许横向滚动。
7. **生成器集成和交付**：确认 `render_html()` 的 `</script>` 转义、模板占位符和直接打开路径保持有效；更新数据库查看指南中的页面结构/使用说明。

每步结束可独立查看生成 HTML；旧快照需要重生成才能反映改动。不能将临时 generated HTML 作为唯一被跟踪的源文件，源头始终是模板和 Python generator。

## 代码落点

- `tools/db_dashboard_template.html`：页面结构、设计 token、导航、过滤和视图状态。
- `tools/db_dashboard.py`：仅当 UI 需要现有 payload 中确实缺失的摘要/错误元数据时补字段；保持数据库只读，避免为视觉调整扩大 SQL 查询。
- `tests/test_v1_db_dashboard.py`：验证模板 payload 安全嵌入、必要区块标识和页面状态渲染；继续使用现有数据库构建测试，不复制每个区块的数据字段断言。
- `docs/implementation/reference/database-inspection-guide.md`：更新离线快照入口、导航和生成/刷新步骤。

## 精简验证方案

- 保留并运行现有 dashboard tests：只读 payload 构建、release/run 数据读取及 `</script>` 转义。
- 增加一条生成 HTML smoke test，检查必须区块/导航锚点存在，且 payload 内用户数据仍通过文本节点安全呈现。
- 浏览器手工检查两种主题和桌面/窄屏各一个视口，覆盖空库、含 run/目录/图谱的数据样例；不为每个颜色 token、表格列或空状态建立快照矩阵。
- 若采用 Playwright，最多做一条主流程 E2E：过滤知识节点、选择 run、导航到工艺目录；无需为只读区块逐项重复端到端操作。

## 不在本期范围

- 在线数据库查询、轮询、编辑、触发仿真或启动订单。
- 前端框架迁移、CDN/外部图表库、图数据库服务、写入 SQL 或新增 API。
- 为未知数据规模预先实现虚拟列表、Web Worker、复杂关系布局和缓存层。
- 复制阶段 5 订单 DAG 编辑器的服务端 API 或运行状态模型。

## 验收与回退

- 从数据库生成的单 HTML 可离线打开；页面明确显示快照来源/时间；交互不修改数据库。
- 桌面与窄屏都能定位五类数据任务，过滤状态和空/异常状态可解释；表格仍提供图形信息的可访问等价内容。
- 原有 CLI 参数、JSON payload 语义、HTML 注入防护与数据库只读性保持通过测试。
- 若图谱交互改动影响大图性能，退回简化为静态图概览加可筛选表格；不影响其他分区发布。
