# 自建订单 DAG 阶段 5：UI 设计规格

本文定义阶段 5 的页面骨架、关键交互和状态呈现，作为实现前的低保真设计模板。它不规定最终像素尺寸或视觉稿，也不扩展服务端 API。所有业务结论来自订单服务；浏览器只维护编辑草稿与临时视图状态。

## 设计原则

- 用户控制的是订单、工序模板、端口连接和运行请求；界面避免暴露 executor 内部对象或仿真 handle。
- 主编辑区始终能看出当前订单、未保存状态和服务端校验结论。
- 节点状态同时用文字和视觉标记表达；失败范围、阻断原因和仍继续的分支不可只靠颜色区分。
- DAG 画布有键盘等价操作：节点列表、属性表单、连接选择器和诊断列表均可不用拖拽完成。
- 错误显示原因、对象位置和可行的下一步；不将不可执行的操作静默禁用。

## 导航与页面路由

| 路由建议 | 页面目的 | 进入所需数据 |
|---|---|---|
| `/orders` | 浏览订单与最近运行 | `GET /api/orders` |
| `/orders/new` | 建立空白订单 | `GET /api/templates` |
| `/orders/:orderId` | 查看订单及不可变版本 | `GET /api/orders/{id}`、versions |
| `/orders/:orderId/edit` | 编辑当前草稿或以旧版本为基底创建新版本 | 订单版本、templates |
| `/planner` | 输入目标并请求候选 DAG | templates/health、planner API |
| `/runs/:runId` | 只读观察固定运行快照 | run、nodes、events |

具体 pathname 可按 router 选择调整，但 `runId` 必须可直接打开并恢复视图；编辑器 URL 不能代表仿真运行状态。

## 全局框架

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 工厂订单   订单列表  新建订单  自主规划               API · 已连接/离线 │
├────────────────────────────────────────────────────────────────────────┤
│ 面包屑 / 页面标题                                  帮助 · 用户偏好      │
│ 页面主体                                                                 │
└────────────────────────────────────────────────────────────────────────┘
```

API 状态用可见文字呈现；断连时保留已有只读信息，禁用需要写入的动作并提供重试。全局框架不显示仿真实时控制按钮，停止命令只出现在明确的运行详情页。

## 页面模板

### 订单列表 `/orders`

```text
订单                                      [新建订单] [自主规划]
搜索订单…       状态 ▾       来源 ▾
订单名       目标/数量      来源     版本     最近运行/状态     操作
Housing A    FINAL × 1      手工     v3       run-… PARTIAL…    打开
Kit B        FINAL × 2      planner  v1       无运行             打开
```

| 元素 | 规则 |
|---|---|
| 搜索/筛选 | 只过滤已加载订单；显示结果数和清除筛选动作 |
| 订单行 | 显示订单 ID/名称、目标摘要、来源、当前版本、最近运行状态 |
| 新建订单 | 打开 `/orders/new`，不预置隐式工序 |
| 打开 | 查看版本和历史运行；编辑必须显式创建新版本 |
| 空态 | 无订单时给出“创建空白订单”和“自主规划”入口 |
| 加载/错误 | 首屏 skeleton；服务不可用时显示重试和本地 API 状态，不显示成空列表 |

窄屏以订单摘要行替代表格列，操作置于行尾菜单；状态和目标不可折叠隐藏。

### 订单编辑器 `/orders/new` 或 `/orders/:id/edit`

```text
订单名 · 草稿 / 未保存                         [预览] [保存版本] [更多]
目标: FINAL × 1     投料: RAW_A × 1, RAW_D × 1     场景: L5_UFLOW
┌─────────────────┬──────────────────────────────┬──────────────────────┐
│ 工序模板         │ DAG 画布                     │ 选择器 / 检查器      │
│ 搜索模板…        │  [原料A] ─→ [加工A] ─┐       │ 选中: 加工A          │
│ 装配 / 搬运 / 加工│                  [合流] → [FINAL]│ 模板 / 端口 / 资源   │
│ 模板行含输入输出 │  [原料D] ─→ [加工D] ─┘       │ 前置 / 后继          │
└─────────────────┴──────────────────────────────┴──────────────────────┘
校验摘要: 未校验 / 通过 digest… / 3 个问题 [定位第一个]
节点列表 | 连线列表
```

| 区域 | 交互和显示要求 |
|---|---|
| 顶栏 | 订单名可编辑；明确 `草稿/未保存/已保存版本`；保存、预览和运行入口动作命名不混用 |
| 模板 palette | 搜索/分类；模板显示语义、输入输出类型、能力和资源摘要；拖入与点击“添加”均可 |
| DAG 画布 | 自定义节点显示语义名、模板短 ID、端口、诊断/选择标记；边有方向和端口标签；提供缩放、适配、撤销/重做、自动布局 |
| 检查器 | 未选择时显示订单目标/投料；选择节点时显示可编辑字段及只读模板约束；选择边时显示端口映射和删除操作 |
| 诊断摘要 | 调用服务端 preview 后出现；错误/警告按 code 分组；点击一项聚焦节点/边/端口并滚动到详情 |
| 节点/边列表 | 与画布双向选择；支持键盘操作和搜索；移动设备默认使用此视图 |

连线创建流程：选中输出端口并选择合法输入端口，或用连线选择器指定起点/端点；浏览器可即时提示端口方向、重复边和自环，但最终校验依赖服务端 preview。连接过程提供取消和当前起点反馈。

删除节点时提示会同时删除的连接边数；确认后把变更作为一次撤销操作。节点复制生成新的 `node_id`，复制的边不自动创建。自动布局只改画布位置，不改变 `OrderSpec` 节点/边语义。

### 自动规划 `/planner`

```text
自主规划订单
目标物料 [FINAL ▾] 数量 [1]    场景 [L5_UFLOW ▾]
可用投料 [添加物料/数量]       模板/设备范围 [默认允许集合]
路线偏好 [无偏好 ▾]                                      [生成候选]
结果: 找到 1 个候选 / 无解及约束原因
选择解释 | 候选 DAG | 投料消耗 | join 绑定 | 排除的候选
[载入订单草稿] [取消]
```

成功结果先作为 planner preview 展示；“载入订单草稿”才进入可编辑状态，保存后仍遵守不可变版本语义。无解时保留用户输入并展示服务端 diagnostics，不能显示空白成功画布。调用接口按同步响应处理；除非服务端增加异步 job 契约，不展示虚构进度百分比。

### 运行详情 `/runs/:runId`

```text
运行 run-123 · PARTIAL_FAILED    订单 order-7 v3 · digest …
场景工件 …   开始时间 …   [请求停止]
┌─────────────────────────────────────┬──────────────────────────────┐
│ 节点状态图 / 节点表                 │ 选中节点详情                 │
│ RAW_A → CUT_A FAILED → JOIN BLOCKED │ failure code / 安全状态      │
│ RAW_D → CUT_D DONE → JOIN BLOCKED   │ 物料 UID / 设备 / 时间       │
│ 独立分支仍运行                      │ 失败原因链                   │
├─────────────────────────────────────┴──────────────────────────────┤
│ 事件时间线 · 最新事件 · 刷新状态                                   │
└───────────────────────────────────────────────────────────────────┘
```

顶部固定显示运行 ID、绑定订单版本/digest、场景工件、订单终态和停止请求状态。节点状态图与节点表/事件时间线联动；节点详情展示当前 API 可提供的 `state/phase/device/wait reason/material UID/failure` 字段。字段缺失显示“未记录”，不得推导成功或安全。

| 运行状态 | 画布呈现 | 页面级信息 |
|---|---|---|
| `PENDING/READY` | 待执行/可派工 | 等待前置或资源原因（若事件提供） |
| `RUNNING` | 正在执行 | 当前阶段和设备；不以动画代替状态文字 |
| `DONE` | 已完成 | 输出 UID/提交时间（若可用） |
| `FAILED` | 失败并高亮原因 | failure code、诊断、局部/全局 scope |
| `BLOCKED` | 依赖失败导致阻断 | 显示导致阻断的上游失败节点 |
| `CANCELLED` | 已取消 | 展示取消来源/原因 |
| 订单 `PARTIAL_FAILED` | 保留完成与继续执行分支 | 显示目标是否已达成及失败影响范围，按服务端字段呈现 |
| 订单 `ABORTED` | 全图停止态 | 显示全局故障及最后已知节点状态 |

stop 点击后先显示“停止请求已提交/处理中”，最终状态以服务端查询为准。网络中断时提示状态可能过期，不自动重试 POST stop；状态/events 查询可由用户重试或按既有 API 轮询。

## 交互状态与反馈模板

| 场景 | 用户看到 | 可用动作 |
|---|---|---|
| 首次加载 | 页面骨架和区域标题 | 无重复提交 |
| 空模板目录 | 目录未发布/无模板的明确解释 | 重试目录读取；不允许空白模板伪装为有效工序 |
| 编辑未保存 | 顶栏 `未保存`，离开页面确认 | 保存、放弃、留在页面 |
| preview 通过 | 通过状态、digest、诊断数 | 保存版本、继续编辑 |
| preview 失败 | 错误数、诊断列表和画布定位 | 跳转问题、修改后重新预览 |
| 保存冲突 `409` | 版本/订单状态冲突说明 | 重新加载；将本地内容另存新订单（若支持创建） |
| planner 无解 `422` | 保留输入和结构化原因 | 调整目标/约束后重试 |
| 启动冲突 `409` | 该仿真实例已有活动运行 | 打开当前运行；不自动重复启动 |
| API 离线/超时 | 明确最后更新时间和离线状态 | 重试查询；写请求仅在用户再次确认后提交 |

Toast 只用于短暂成功/复制反馈；会影响订单正确性的错误留在页面内，不用自动消失 toast 承载。

## 窄屏与键盘行为

- 桌面编辑器采用三栏；视口不足时 palette/检查器折叠为有标签的抽屉，画布拥有主要空间。
- 手机编辑器用“模板 / 画布 / 详情”分段切换；详情页含 accessible 节点列表与端口连接表单，不要求横向拖拽连线。
- 所有图标按钮有可访问名称和 tooltip；焦点移动、选中和错误状态有明显非颜色标志；Escape 关闭抽屉/弹窗并返回触发控件。
- 尊重 `prefers-reduced-motion`；缩放不让节点文字、按钮和状态标志重叠。

## 视觉 token 草案

| Token | 初始值 | 用途 |
|---|---|---|
| `canvas` | `#f5f7f5` | 主画布底色 |
| `surface` | `#ffffff` | 导航、检查器和表格底色 |
| `ink` | `#202624` | 主文字与节点标题 |
| `muted` | `#61706b` | 辅助说明、次要字段 |
| `accent` | `#087e78` | 选中、焦点和主要动作 |
| `success` | `#18794e` | 完成 |
| `warning` | `#9a5b05` | 等待/风险 |
| `failure` | `#b53d3d` | 失败/全局停止 |
| `blocked` | `#7354a3` | 被依赖阻断，配文字标记 |

状态色要通过对比检查并有文字/图标冗余编码。ID、digest、UID 使用等宽字和复制按钮；业务文案使用中文，代码态值保留原始大写枚举并提供可读标签。

## 设计交付与实施门槛

实现开始前至少完成：本规格线框复核；选定 React Flow 版本/许可证与组件方案；检查现有 API 字段能否支撑运行页各栏；确认开发 API 地址。若运行事件没有 failure scope、reason chain 或端口 path，设计显示缺失状态并将 API 扩展作为单独 contract 变更评估，不在前端猜测。

最终实现验收沿用 [阶段 5 前端方案](v1-order-dag-phase-05-frontend.md) 中三条 E2E 用户旅程。无需对本规格中的每个视觉 token 编写快照测试。
