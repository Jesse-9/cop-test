本方案只保留运动规划效率主题的**未实施或未完成**项。P0 计时字段、P1 固定路径
回放、五臂 `PLACING` 扩展和订单运行路径复用接入已实施；已有证据见
[P0/P1 报告](../../reports/simulation/v1-motion-planning-performance.md)、

[订单运行路径复用报告](../../reports/order-orchestration/v1-order-run-path-reuse.md)。

## 1. 全阶段路径缓存扩展（部分已具备，待扩展）

**现状：**路径复用目前只接入 `PLACING`。机械臂其余最终执行阶段仍直接调用
在线规划器；`CACHE_THEN_PLAN` 未命中时也不会自动写回。CLI、订单运行和 API
默认关闭路径复用。缓存库已采用按场景组织的 JSON 路径记录，默认根目录为
`docs/path_library/`；`PLACING` 的规划墙钟在命中时下降，但 full_flow 总墙钟
未下降。

### 现状核对（2026-11-26）

本节的扩展步骤不是全部从零开始。以下已有实现只作为基础，不重复列为剩余工作：

| 扩展项 | 已有实现 | 仍缺 |
|---|---|---|
| 路径记录与精确键 | `PathKey` 已含 scene/phase/unit/robot/tool/payload/start_digest/targets_digest/motion_version；`PathRecord` 已存 waypoints/segments/start_q/end_q/format_version，按场景目录 + 原子替换写入 | 路径变体身份、完整目标序列、多目标/多段记录 |
| 缓存核心边界 | `PathReusePolicy` 已包装 planner，`PathLibrary` 只保存可序列化路径；回放仍进入原执行器检查 | 扩展到其他阶段；命中后的阶段复核测试 |
| 统计 | 已有 lookup/replay/fallback/planner_calls/export_saved、按臂统计和 `last_miss_reason` | miss 自动写回计数、阶段/变体/记录 ID 日志、文档 |
| 默认值 | 前端启动对话框已默认 `CACHE_THEN_PLAN` | CLI、订单运行、API 服务默认仍为 `off` |
| 回放安全 | 回放路径仍交给原 `JointStreamExecutor`，执行期联锁未取消 | 保持现状并在扩展阶段补对照测试 |

因此下列步骤中，1/5/7/8 是**部分已有、只需扩展**；2/3/4/6 才是主要未实施工作。

### 目标与行为

让所有**最终执行**的机械臂运动阶段共用路径缓存策略：动作首次出现时精确查找；
未命中则使用现有规划器在线规划，现有阶段复核成功后把结果写入路径库；之后
同一缓存键再次出现时回放已保存路径，并继续执行现有的阶段复核与执行期检查。
覆盖阶段为 `APPROACHING`、`LIFTING`、`TRANSFERRING`、`PLACING`、
`RETREATING`，包括订单中的每个实际执行动作。影子规划、下游 lookahead 和仅用于
候选评估但未被最终执行的路径不写入缓存。

继续支持显式 `off`、`PLAN_ONLY`、`CACHE_ONLY`、`CACHE_THEN_PLAN`。其中：

- `off` 完全绕过路径库。
- `PLAN_ONLY` 在线规划并导出成功路径，供预热或离线采集使用。
- `CACHE_ONLY` 只尝试回放，未命中时按现有语义失败，不在线规划。
- `CACHE_THEN_PLAN` 先查缓存，未命中时在线规划；规划与阶段复核成功后自动写回。

CLI、订单运行以及 API/前端未显式指定模式时默认采用 `CACHE_THEN_PLAN`；调用方
仍可显式选择其他模式，尤其可用 `off` 关闭缓存。显式配置的优先级高于默认值。

### 组件边界与场景扩展

路径缓存应作为相对独立的运动基础设施，供工艺流程调用，而不是把工艺状态机、
工位拓扑或某个场景的动作顺序写进缓存实现。当前 `PathReusePolicy` 已在规划调用
外层包装 planner，`PathLibrary` 也只保存可序列化路径数据；后续扩展应保持这个
方向，并进一步把“业务阶段到运动请求”的适配留在流程/控制器侧。

边界按以下职责划分：

- **缓存核心**负责规范化请求键、精确查询、路径记录的序列化/存储、命中或未命中
  结果、规划回退和基础统计；不导入订单、工艺路线、工位流程或 CoppeliaSim 运行时
  对象。
- **流程/设备适配层**把一次具体运动转换为缓存请求，提供运动阶段/变体、机器人、
  工具、载荷、起点、目标和运动配置身份，并决定阶段复核与执行时机。业务流程可以
  定义如 `APPROACHING`、`TRANSFERRING` 等语义阶段，但这些标识通过请求传入，不能
  让缓存核心依赖某个固定阶段枚举或工厂订单模型。
- **执行与安全检查**继续由当前运行时的规划器、碰撞/运动约束复核和执行器负责。
  缓存只提供候选关节路径，不缓存设备句柄、旧运行时对象或安全检查结论；场景或
  设备适配器在回放后仍按当前运行状态复核路径。

因此，“解耦”不等于不同设备和场景共享同一条路径。设备型号、工具/载荷、起始
构型、目标、场景工件和运动配置等影响路径有效性的身份信息必须进入缓存键；不同
条件自然形成不同记录。后续场景若只更换工艺流程，可复用缓存核心并新增流程适配；
若增加新的机器人或执行后端，则实现该设备到通用运动请求/路径格式的适配。跨场景
迁移、几何变换或近似匹配不属于本方案。

### 实施步骤

1. **（部分已具备）扩展路径记录与精确键。** 现有记录已保存阶段、规划起点、
   关节 waypoint、分段边界和记录版本；仍缺路径变体身份、完整目标序列和多
   目标/多段记录。路径键继续纳入场景工件、阶段、工位、机器人、工具、载荷、
   起始关节摘要、目标摘要和运动配置版本；键字段
   发生语义变化时提升记录/键版本，避免旧记录被误用。路径 ID 由规范化路径键
   摘要生成，只做精确匹配，不以最近邻或相似目标代替命中。
2. **统一接入并保持组件边界。** 将 `PathReusePolicy` 接入控制器各实际执行阶段的
   规划入口；由控制器/流程适配层构造通用运动请求，缓存核心只接收规范化阶段、
   设备身份、起点、目标、运动配置和 planner 回调，不读取订单对象或场景状态机。
   保持现有 planner 调用和阶段级复核作为未命中后的路径。接入时区分实际执行规划
   与影子 lookahead：只有会交给机械臂执行的成功结果可写库。避免只在 `PLACING`
   保留专用接入逻辑而遗漏其他控制器分支。
3. **逐阶段定义稳定标识。** 为 `APPROACHING`、`LIFTING`、`PLACING`、
   `RETREATING` 使用稳定阶段标识；为 `TRANSFERRING` 的直线、绕行等规划候选增加
   稳定的路径变体标识，使不同策略不会共用同一记录。阶段和变体进入键及摘要，
   同一动作在同一规划条件下才会命中。
4. **支持多目标与多段回放。** 扩展目前要求单目标的回放就绪条件，使接近和转运等
   由多个目标/段构成的计划能按原分段顺序保存与恢复。回放时验证记录目标序列与
   当前请求一致，并保持 waypoint 与段边界的对应关系；不可完整表示或不匹配时按
   所选模式处理未命中，不拼接近似路径。
5. **（已有保障，补对照）缓存命中后的阶段复核。** 回放路径仍进入原有的阶段
   约束检查。转运候选命中后继续复核水平高度、姿态和碰撞；抬升、放置和撤退沿用各自已有的终点、
   关节/碰撞及执行检查。只有被当前阶段接受的在线规划结果才写入；复核失败的
   候选不落库，也不改变现有 fallback 的选择顺序。
6. **实现未命中自动写回。** `CACHE_THEN_PLAN` 在线规划成功并通过阶段复核后，
   将最终选中的执行路径交给 `PathLibrary.put()`；保留现有临时文件加原子替换的
   写入方式。回放命中不重复生成记录。`PLAN_ONLY` 继续执行规划并写入，
   `CACHE_ONLY` 不触发 planner 或写入。
7. **（前端已默认，打通 CLI/订单/API）默认启用并贯通配置。** 将 CLI 单次
   运行、CLI 订单运行、订单应用服务、API 服务和前端初始选项的默认值统一为
   `CACHE_THEN_PLAN`。更新参数帮助、请求默认值
   和运行配置摘要，保留显式 `off` 和其他模式的覆盖能力。确认同一默认策略实际
   传递至每个订单动作，而不是只设置在 CLI 参数层。
8. **（部分已有，补写回/阶段/文档）补齐可观测性与使用说明。** 运行摘要按
   阶段报告 lookup、hit/replay、miss、online planner、写入及复核失败计数，并显示缓存根目录和当前模式；日志可以定位
   命中的阶段/变体与记录 ID。更新项目使用指南，说明默认目录、JSON 记录组织方式、
   首次运行生成缓存、后续运行回放，以及如何用 `--path-reuse off` 禁用。

### 存储约定

默认缓存根目录为 `docs/path_library/`，允许通过现有路径库目录配置覆盖。按场景、
阶段和路径 ID 组织 JSON 文件，例如：

```text
docs/path_library/
  <scene-artifact-slug>/
    <phase-slug>/
      <path-id>.json
```

每条 JSON 记录保存规范化键、阶段/变体、目标与分段信息、关节 waypoint、状态和
记录版本等可序列化数据；不保存 CoppeliaSim 句柄、运行时 context 或会话对象。
写入继续采用临时文件和原子替换。该目录独立于 `.ttt` 场景工件及其 manifest。

### 聚焦验证与验收

验证围绕主流程，复用现有路径库和规划策略测试，不扩展成覆盖任意损坏输入、所有
字段组合或极端状态的防御性测试集。新增/调整以下少量检查：

1. 代表性的执行阶段在 `CACHE_THEN_PLAN` 首次遇到键时调用 planner，并将通过阶段
   复核的结果写入；第二次相同键命中回放且不再调用 planner。
2. 多目标/多段路径可保存并按原边界回放；转运候选必须通过现有最终复核后才写入。
3. CLI/订单/API 的未指定默认模式为 `CACHE_THEN_PLAN`，显式 `off` 仍可关闭。

完成后跑相关离线测试，再用同一固定场景和动作做一次 focused 仿真验收：首次运行
观察在线规划与写入，第二次运行观察缓存命中与回放；比较目标容差、现有安全复核、
命令数和执行步数。报告缓存命中与规划耗时结果，不将单段命中外推为 full_flow
总耗时必然下降。

## 2. 未覆盖运动段计时基线

缓存扩展实施前后，使用同一固定场景和动作采集抓取、抬升、转运段的
`search_wall_s`、`verify_wall_s`、IK、命令数和执行步数。现有 `PLACING` 规划墙钟
命中结果只作为该段证据，不推断其他阶段的命中率或 full_flow 总墙钟收益。

## 3. P2：按计时证据选择热点

**现状：**未开始；现有证据不足以证明全流程规划是主要瓶颈。

只有 P0/P1 数据显示在线规划仍是主要耗时时，才选择一个具体热点：

1. `search_wall_s` 占主导：检查固定动作失败前尝试了哪些策略，再评估
   优先尝试已知成功策略；不删掉失败兜底。
2. `verify_wall_s` 占主导：先确认是否对同一路径重复执行了多次最终复核；
   不通过减小碰撞采样密度解决。
3. IK 占主导：只针对固定目标测量候选 seed 是否反复求出相同解，再评估
   有限范围的 IK 结果缓存；动态目标不共用缓存。
4. 执行步数或仿真等待占主导：评估控制周期和测试等待，不用贝塞尔曲线
   掩盖问题。

每轮只改一个因素，用相同场景、起点、目标、故障设置重复对照，报告规划
成功率、路径终点误差、最小净距、规划墙钟、命令数和仿真执行时间。收益
不稳定或安全/终点指标退化时不合入。

## 4. P3：贝塞尔后处理（可选，未触发）

仅在 P0 显示需要改善自由空间轨迹平滑度时，针对一个静态、无接触、无载荷
的自由空间运动段做独立实验：

1. 从已通过在线规划的固定段导出 waypoint，保留段首、段尾和所有语义
   边界；不跨 `pick`/`lift`/`transfer`/`place`/`retreat` 拟合曲线。
2. 用三次贝塞尔拟合关节 waypoint 的中间形状，首版不自动调控制点、不加
   多阶配置。
3. 按不大于现有关节采样间隔取样，逐段交给
   `ConfigurationChecker.check_segment()`；检查机械臂、载荷/吸盘、腕部
   分支和净空，不只检查端点。
4. 检查 TCP 偏差、终点精度、关节限位、速度/加速度/jerk；任何失败放弃
   曲线，使用原始路径。
5. 只比较同一基准路径的原始/贝塞尔版本：路径长度/关节总变差、最大
   速度/加速度/jerk、执行时间、命令数和最小净距。
6. 一个离线单元测试覆盖端点保持和碰撞拒绝，再用一个固定场景实机动作
   确认；仅视觉更圆滑但指标无改善时不启用默认开关。

**结论门槛：**贝塞尔是可选后处理，不是“更快规划”的承诺；第一版保持
`TRAJECTORY_SMOOTHING_ENABLED=False`，只有单段实验全部通过后才讨论配置化。

## 5. 边界

- 不通过放宽安全容差、碰撞采样或执行联锁换命中率/速度。
- 不做跨工件路径迁移、托盘相对变换、路径平移或局部修复；这些需要单独的
  验证方案。
- 不把 `PLACING` 的 focused 结果、mock 前端请求或编译器测试写成物理
  可行性结论。
- 每轮独立提交、独立报告；没有计时证据时不调整采样/缓存/时间预算。
