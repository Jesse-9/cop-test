## 1. 结论摘要

1. **选定布局 `L1_S1`**：UR5 基座 `(-0.20, 0.55, 0.30) m`，置物台
   `(-0.20, 1.20) m`，AGV dock `(0.40, 0.75) m`。机械臂从传送带 **+Y 侧方**
   接近取料点，不再位于传送带末端延长线上。31 个离散 TCP 目标全部通过
   pose 约束 IK 与关节限位检查；选定后 15 个关键目标实际运动验证全部到位，
   最大 TCP 位置误差 `0.00581 m`、姿态误差 `0.00935 rad`。
2. **无挡板主动停带**：B 组（移除 `Conveyor_In_PickupStopper`，sensor 命中后
   立即零速，等待 pad 与物料稳定后按实测位姿抓取）在 `0.20 m/s` 名义速度、
   3 个初始位置、每组 10 次重复下 **30/30** 通过冻结门槛；每个位置另做
   1 次完整吸附/抬升/放置/释放，**3/3** 成功。结果见 §5.3 与 §6。
3. **阶段一当前流程不能覆盖全部初始位置**：A 组完整流程实测 sensor 首次
   命中后 **0.30 s** 才发零速（当前流程按行程进度 1.0 停带，不是 sensor
   命中即停）。停带矩阵中 front 的最终 X 为 `-0.1751…-0.1727 m`、middle
   为 `-0.1813…-0.1801 m`，均越过允许区下游边界 `-0.19 m`；rear 为
   `-0.195 m`，通过。即当前流程 **20/30** 通过冻结允许区，前/中位置不满足。
   这是“保留现状即可”的反例，也说明 B 组的主动停带是必要的。
4. **物理输送诊断（C 组）推翻了旧结论**：关闭 `HYBRID_DYNAMIC` 位置补偿后，
   入口物料 10/10 仍前进 `0.8298 m` 到达检测区（约 `0.20 m/s`）。当前
   `stage1` 场景中 pad→物料存在真实物理输送，不再支持“4.10 pad 不传递
   切向速度”的旧结论。A 组从入口到 sensor 的平均速度约 `0.38 m/s`，接近
   “带速 `0.20` + 补偿步率 `0.20`”，说明当前补偿叠加在物理输送之上，
   是 A 组越程的直接原因。阶段二必须改为“仅在物料落后时补偿”并重测。
5. **`-Y` 侧候选被生产 pose-IK 契约拒绝**：`L2_S1/L2_S2` 的 20 个取料 pose
   目标失败，但同点的 position-only IK 全部成功（线误差 ≤ `0.010 m`）。
   这是当前 seed/姿态约束下的局部求解问题，不是几何不可达；若后续需要
   `-Y` 侧布局，应在阶段二评估基座偏航/多 seed。`L1_S2` 仅
   `station_approach` 失败（position-only 成功），同样记录为失败候选。

## 2. 范围与方法

- 只验证：UR5 侧置布局与置物台位置、离散 TCP 可达性、无挡板停带/实测位姿
  抓取、挡板保留/移除决策。
- 不验证：路径碰撞、TCP 外表面接触、运行期急停、停止失败处理、AGV 路径
  跟踪、多工位队列；这些属于阶段二/三。
- “sensor 检测”与“仿真器 ground-truth 位姿”分开记录：`Sensor_PickStation`
  只报告命中对象；抓取 TCP 由命中对象句柄的 `sim.getObjectPose` 生成。
  这证明仿真状态读取链路，不代表现实设备已具备视觉/三维定位能力。
- 允许抓取区域在试验前冻结：X `[-0.40, -0.19] m`、Y `[-0.04, 0.04] m`、
  物料中心 Z `0.50 ± 0.02 m`。推导见 [06-07 §5.1](../wiki/06-工业案例/06-07-柔性工业车间步骤1.1-布局与无挡板取料验证.md)
  与 `src/stage1_1/config.py`。
- 速度：只测阶段一已验证的名义速度 `0.20 m/s`；最低/最高速度尚无冻结值，
  在证据中记录为 `speeds_pending = ["min", "max"]`，未自行扩大。

运行与复算命令（完整/分阶段/冒烟/复用布局证据/分析脚本）见
[06-07 §4.5](../wiki/06-工业案例/06-07-柔性工业车间步骤1.1-布局与无挡板取料验证.md)。

基座与岛体中心一致，以及取料/工位/AGV 三个目标的粗可达距离 ≤ `0.80 m`。
所有候选的静态几何均通过；失败来自 simIK，而不是平面布局压占。

### 4.2 目标集合

每个候选 31 个 TCP 目标：

- 取料允许区 9 点（中心 + 4 角 + 4 边中点）× 抓取 / 垂直接近（+0.15 m）/
  抬升（+0.15 m）= 27；
- 工位放置点 + 接近点 = 2；
- AGV 放置点 + 接近点 = 2。

取料抓取点由物料顶面中心生成：TCP = 物料中心 + `(0,0,0.05) m`，姿态
`[0,0,0,1]`。工位/AGV 目标由候选布局派生。

### 4.3 simIK 结果

- **L1_S1**：31 个 pose 目标全部成功，关节全部在限位内；position-only
  诊断同样全部成功。边界余量（允许区边界到最近不可达点）：
  `+X 0.50 m`、`-X 0.40 m`（扫描上限 0.60 m 内未失败）、`+Y 0.33 m`、
  `-Y 0.23 m`；最小边界余量 **0.23 m**。粗可达余量：
  取料 `0.05966 m`、工位 `0.10358 m`、AGV `0.13452 m`。
- **L1_S2**：仅 `station_approach` 失败（pose 线误差 `0.19758 m`、角误差
  `0.14493 rad`；同点 position-only 线误差 `0.00943 m`）。工位放置点本身
  成功，但生产控制要求先到接近点，因此该候选不通过。
- **L2_S1 / L2_S2**：20 个取料 pose 失败，线误差 `0.021–0.142 m`、角误差
  `0.012–0.084 rad`；**同点 position-only 全部成功**（线误差
  `0.0002–0.010 m`）。边界扫描在 0.01 m 处即失败，余量为负。该失败集中在
  取料点姿态约束/局部 seed，而不是位置不可达；按生产契约仍判为不可用。
- 未使用 `simIK.syncToSim` 直接写场景关节；失败目标不写伪造角度。

### 4.4 选定布局与实际运动验证

选择规则在扫描前固定：静态通过、全部 pose 目标成功且关节限位通过；
取 `min(边界余量)` 最大者，并列时比较 `min(粗可达余量)`，再按名称。
唯一合格候选为 **L1_S1**。

选定后实际驱动关节验证 15 个关键目标（5 个取料点的接近+抓取、中心抬升、
工位接近+放置、AGV 接近+放置）：**15/15 成功**。TCP 位置误差
`0.00096–0.00581 m`，姿态误差 `0.00009–0.00935 rad`；最长单段运动为
`station_approach` 的 `5.1 s`（`ARM_MOVE_TIMEOUT=8 s` 内）。

> 离散 IK/运动验证不检查 waypoint 之间的路径碰撞；选定布局仍需阶段二
> 的碰撞集合与避障验收。

### 5.3 B 组：无挡板主动停带

证据：[step1_1_trials_B_20261020_104655.jsonl](evidence/step1_1_trials_B_20261020_104655.jsonl)。

每个“初始位置 × 10 次”的流程严格为：

```
sensor 命中 → 校验目标 UID → 发零速 → 等 pad 速度/位姿确认停止
→ 等物料连续多步速度/位移稳定 → 读取 ground-truth 位姿
→ 生成 TCP → simIK → TCP 到位 → 吸附前置检查
```

停带/稳定等待期间没有机械臂抓取运动；整个目标固定同一 UID。pad 停止优先
使用 `__state__.vel`，同时用连续步 pad 位移确认；速度回读与位姿不一致时
记录为 `position_fallback`。物料稳定要求连续 5 步速度 ≤ `0.05 m/s` 且
单步位移 ≤ `0.005 m`。

结果（全量 30 次 + 3 次完整取放）：

| 初始位置 | 触发 X (m) | 最终 X 范围 (m) | 零速延迟 (s) | pad 停车 (s) | 停后残余位移 (m) | 稳定等待 (s) | gate |
|---|---|---|---|---|---|---|---|
| front | `-0.3207 … -0.3089` | `-0.3157 … -0.3039` | `0.00` | `0.15` | `0.005` | `0.25` | **10/10** |
| middle | `-0.2550` | `-0.2507 … -0.2500` | `0.00` | `0.15` | `0.005` | `0.25` | **10/10** |
| rear | `-0.2100` | `-0.2050` | `0.00` | `0.15` | `0.005` | `0.25` | **10/10** |

- 30/30 的 IK pose 求解、TCP 到位和吸附前置检查均通过；pad 停止判据全部为
  `velocity+position`，无 `position_fallback`。
- 完整取放：front/middle/rear 各 1 次，均完成吸附、抬升、转运、工位放置、
  释放和属性恢复（`static=0, respondable=1, mass=0.1, friction=0.6,
  mask=65535`）；放置误差 **0.0000 m**，吸附接触间隙
  `0.0005–0.0007 m`，工具倾角 `0.00056–0.00070 rad`，运动段 TCP 最大
  位置误差 `0.00487 m`；吸附/释放均 `stable=True, penetration=False`。
- 选定布局的 **AGV 装卸点**由 31 目标 IK 和 §4.4 的实际运动验证覆盖
  （AGV 放置目标 + 接近目标），本步骤不重复执行完整 AGV 运输任务；
  AGV 路径/载荷运输属于阶段一/阶段三。
- **方法说明**：B 矩阵按 06-07 §4.4 从传感器检测区内出发，`compensation_count=0`，
  因此它验证的是“检测到目标后停带/稳定/按实测位姿抓取”，不是入口输送。
  入口输运与补偿叠加由 A 组完整流程和 C 组入口诊断覆盖。

### 5.4 C 组：物理输送诊断

证据：[step1_1_trials_C_20261020_104655.jsonl](evidence/step1_1_trials_C_20261020_104655.jsonl)。

- 入口生成 10 次：物料在**关闭位置补偿**的情况下仍从入口前进
  `0.8297–0.8300 m`（10/10，均值 `0.8298 m`）到达检测区，运动阶段约
  `0.20 m/s`，与带速一致；含 0.5 s 落稳等待的全程平均约 `0.177 m/s`
  （分析脚本的保守口径）。为避免越出带尾，到达允许区下游边界 `-0.19 m`
  即停带；停带后物料仍有约 `0.005 m` 残余运动，最终 X 约 `-0.184 m`。
  C 组是物理诊断，不参与 §5.3 的允许区 gate。
- 从检测区内 3 个初始位置出发：物料同样沿带前进到下游边界
  （front `0.1199–0.1300 m`、middle `0.0697–0.0700 m`、
  rear `0.0198–0.0201 m`）。rear 的位移集中在 `0.02 m` 阈值两侧，
  10 次中 3 次略高于阈值、7 次略低于阈值；这是短距离/初始偏航造成的
  阈值边界效应，不代表物料没有随带运动（10/10 都到达检测区）。
- **结论**：当前场景的 pad→物料物理输送成立；旧结论“4.10 pad 不传递切向
  速度”不适用于当前配置。A 组从入口到 sensor 的平均速度为
  `0.376–0.380 m/s`，接近带速 `0.20` 加补偿步率 `0.20`，说明当前
  `HYBRID_DYNAMIC` 每步固定 `0.01 m` 补偿与物理输送叠加。阶段二必须改为
  按“物料进度落后量”补偿，而不是无条件每步推进。

> C 组是诊断，不是生产方案；它不建议关闭补偿后直接投产。物理输送的
> 摩擦/接触机制、带速/载荷依赖和停止可靠性仍需阶段二专门标定。

## 6. 挡板移除决策

### 6.1 冻结门槛

B 组每个计划测试条件必须同时满足：

1. 物料 UID 正确绑定（sensor 命中对象 == 当前任务 UID）；
2. pad 停止后物料稳定，未滚落/越界；
3. 最终位姿落入冻结允许区（X/Y/Z、倾角）；
4. 该位姿生成的 TCP 目标通过 pose-IK、关节限位和 TCP 到位判据；
5. 吸附前置检查通过（suction sensor 命中同一 UID、TCP 接触间隙、
   工具倾角、物料/TCP 速度）；
6. 无未解释失败或数据缺失。

### 6.2 决策

**B 组门槛通过**：30/30 筛选试验 `gate_ok=True`，3/3 完整取放成功，
无未解释失败或数据缺失。因此在本仿真配置和已测 `0.20 m/s` 范围内，
**无挡板主动停带方案可行**。

但生产默认切换前仍建议**保留 `Conveyor_In_PickupStopper` 作为失效保护**：

1. 本步骤只验证了名义速度；最低/最高速度、不同载荷/摩擦尚未冻结和测试；
2. 停带可靠性、停止失败处理、通信中断和运行期急停属于阶段二 §3.9–§3.10；
3. A 组证明阶段一当前“按行程进度停带”会在 front/middle 越出允许区，
   不能把旧判据直接搬到无挡板生产；
4. 物理挡板不能取代主动停带和安全策略。阶段二完成停止延迟/最大越程/
   停止失败验收后，再决定是否物理移除挡板。

> 该决策只表示“在本仿真配置和已测范围内可行”，不表示真实设备已经满足
> 安全认证或量产可靠性。

   与物料之间的穿模/碰撞未检查。

   生产建议。
8. **“sensor 检测”与“ground-truth 位姿”**：本步骤的 TCP 来自仿真器读取，
   不代表现实视觉/定位能力。
9. **生产控制器的布局参数化尚未贯通**：本次只把 `stage1.scene.build_scene`
   参数化为 `LayoutSpec`；`stage1.unit_controller` / `stage1.run` 仍读取
