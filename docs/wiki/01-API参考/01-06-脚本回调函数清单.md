# 脚本回调函数清单

> 回调函数（callback functions）是由特定事件触发的脚本函数，**是进入脚本代码的唯一入口**。它们分为用户回调（user callbacks）与系统回调（system callbacks）两类。本文以官方手册 `callbackFunctions.htm` 为准，列出全部系统回调函数及各专用回调的触发时机。

## 分类

### 用户回调（user callbacks）

由用户代码或插件直接触发，可在任意类型脚本中运行。典型场景：

- 通过 `sim.callScriptFunction` 调用另一脚本中的函数；
- 点击自定义 UI 按钮触发自定义事件。

### 系统回调（system callbacks）

由 CoppeliaSim 在特定事件发生时触发，函数名固定（如 `sysCall_init`、`sysCall_beforeInstanceSwitch`）。并非所有系统回调都能在所有脚本类型中运行，例如 `sysCall_addOnScriptSuspend` 仅适用于 add-on。

多数系统回调支持返回 `{cmd='cleanup'}` 或 `{cmd='restart'}` 以结束或重启脚本，详见各回调代码注释。

## 全部系统回调函数清单

下表以 `callbackFunctions.htm` 实际给出的清单为准（Python 版本示例为准，Lua 同名函数行为一致）：

### 生命周期与仿真循环

| 回调函数 | 触发时机 | 适用范围 |
|----------|----------|----------|
| `sysCall_init()` | 脚本初始化时 | 通用 |
| `sysCall_thread()` | 线程脚本的入口点 | 线程脚本 |
| `sysCall_cleanup()` | 脚本清理时 | 通用 |
| `sysCall_nonSimulation()` | 仿真未运行时执行 | 非仿真脚本、非 main 脚本 |
| `sysCall_beforeSimulation()` | 仿真即将开始 | 非仿真脚本、非 main 脚本 |
| `sysCall_afterSimulation()` | 仿真刚结束 | 非仿真脚本、非 main 脚本 |
| `sysCall_actuation()` | 执行驱动代码 | 仿真步进 |
| `sysCall_sensing()` | 执行传感代码 | 仿真步进 |
| `sysCall_suspend()` | 仿真即将挂起 | 通用 |
| `sysCall_suspended()` | 仿真已挂起 | 通用 |
| `sysCall_resume()` | 仿真即将恢复 | 通用 |
| `sysCall_realTimeIdle()` | 实时模式下空闲时 | 通用 |
| `sysCall_beforeInstanceSwitch()` | 即将切换到另一场景 | 非仿真脚本、非 main 脚本 |
| `sysCall_afterInstanceSwitch()` | 已切换到另一场景 | 非仿真脚本、非 main 脚本 |

### 保存/加载与编辑事件

| 回调函数 | 触发时机 | 参数 |
|----------|----------|------|
| `sysCall_beforeSave(inData)` | 即将保存场景或设置 undo/redo 点 | `inData['regularSave']`、`inData['file']` |
| `sysCall_afterSave(inData)` | 场景已保存或 undo/redo 点已设置 | `inData['regularSave']`、`inData['file']` |
| `sysCall_afterLoad()` | 场景已加载 | — |
| `sysCall_selChange(inData)` | 选择集改变后 | `inData['sel']`：选中对象句柄列表 |
| `sysCall_beforeCopy(inData)` | 即将复制对象（可重入） | `inData['objects']` |
| `sysCall_afterCopy(inData)` | 已复制对象（可重入） | `inData['objects']` |
| `sysCall_afterCreate(inData)` | 已创建对象（可重入） | `inData['objects']` |
| `sysCall_beforeDelete(inData)` | 即将删除对象（可重入） | `inData['objects']`、`inData['allObjects']` |
| `sysCall_afterDelete(inData)` | 已删除对象（可重入） | `inData['objects']`、`inData['allObjects']` |

### 主脚本与 add-on 专用

| 回调函数 | 触发时机 | 说明 |
|----------|----------|------|
| `sysCall_beforeMainScript()` | 用于自定义方式推进仿真 | 返回 `{doNotRunMainScript=True}` 可阻止主脚本执行 |
| `sysCall_addOnScriptSuspend()` | add-on 执行即将挂起 | 仅 add-on |
| `sysCall_addOnScriptResume()` | add-on 执行即将恢复 | 仅 add-on |
| `sysCall_info()` | 指定初始配置（仅 Lua） | 返回 `{autoStart=false, menu='...', menuEnabled=true}` |

### 消息与数据

| 回调函数 | 触发时机 | 说明 |
|----------|----------|------|
| `sysCall_msg(msg, origin)` | `sim.broadcastMsg` 调用时同步触发；`sysCall_init`/`sysCall_cleanup`/`sysCall_addOnScriptSuspend`/`sysCall_addOnScriptResume`/`sysCall_userConfig` 被调用时也会触发（可重入） | — |
| `sysCall_data(inData)` | 脚本或其父对象上的自定义数据属性被修改时异步触发 | 仅仿真脚本与 customization 脚本 |
| `sysCall_event(cborBuffer)` | 内部变量或状态改变时异步触发（可重入） | 主要用于外部 GUI/查看器/渲染器与 CoppeliaSim 同步；参见 `sim.getGenesisEvents`、`sim.setEventFilters` |
| `sysCall_ext(funcName, inData)` | 当该函数存在时，所有对脚本函数的外部调用（即用户回调）都会被拦截（原函数被遮蔽） | 若仅做监控，应使用 `sim.registerScriptFuncHook` |
| `sysCall_moduleEntry(inData)` | 用户模块菜单项被选中时 | 参见 `sim.moduleEntry`；`inData['handle']` |

## 专用回调函数

以下系统回调因与物理引擎或特定传感器深度耦合，单独成节。多数支持返回 `{cmd='cleanup'}` 或 `{cmd='restart'}`。

### 动力学回调（sysCall_dyn）

来源：`dynCallbackFunctions.htm`。

物理引擎在**每个动力学仿真步之前与之后**调用 `sysCall_dyn(inData)`。默认每个常规仿真步触发 10×2 次（约 20 倍于普通仿真脚本频率），因此应保持逻辑轻量，避免拖慢仿真。

`inData` 字段：

- `passCnt`：当前动力学计算 pass（默认 1–10）。
- `totalPasses`：每个常规仿真步的动力学 pass 数（默认 10，即 10×5ms=50ms 的默认仿真时间步）。
- `dt`：动力学计算步长（默认 5ms）。
- `afterStep`：`False` 表示在步前调用，`True` 表示在步后调用。

### 接触回调（sysCall_contact）

来源：`contactCallbackFunction.htm`。

当物理引擎检测到两个可响应形状之间的碰撞时调用 `sysCall_contact(inData)`，可能非常频繁——有时每仿真步数百次，应保持轻量。返回 `retData` 可定制接触处理：

- `ignoreContact`：是否忽略该接触。
- `collisionResponse`：形状是否产生碰撞响应。
- `bullet`/`ode`/`mujoco`/`vortex`/`newton`：按 `inData['engine']` 分支，填写各引擎特有参数（摩擦、恢复、接触模式等）。

`inData` 字段：`engine`、`handle1`、`handle2`。

### 关节回调（sysCall_joint）

来源：`jointCallbackFunctions.htm`。

当脚本对象的父对象是关节（或关节的后代）且满足以下条件时，CoppeliaSim 触发 `sysCall_joint(inData)`：

- **运动学模式关节**：调用 `sim.setJointTargetPosition` 或 `sim.setJointTargetVelocity` 会触发；主脚本含默认关节回调，提供默认运动 profile。
- **动力学模式、动态启用、设为 custom control 的关节**：物理引擎每个动力学步触发，通常每仿真步每关节 10 次。

关节回调沿关节向上层脚本传播，**一旦某脚本返回数据则中断**（即向上最近的脚本胜出）。

`inData` 主要字段：`mode`、`handle`、`revolute`、`cyclic`、`lowLimit`、`highLimit`、`dt`、`pos`、`vel`（仅 Mujoco）、`accel`（仅 Mujoco）、`targetPos`、`targetVel`、`initVel`、`error`（`targetPos - pos`，循环关节取最短循环距离）、`maxVel`、`maxAccel`、`maxJerk`、`first`、`passCnt`、`rk4pass`、`totalPasses`、`effort`、`force`。

返回值：

- 运动学关节：`outData = {'pos': pos, 'vel': vel, 'immobile': False}`。
- 动力学关节：`outData = {'force': f, 'vel': vel}`。

### 视觉回调（sysCall_vision）

来源：`visionCallbackFunctions.htm`。

当脚本对象的父对象是视觉传感器时，系统在**每次获取或应用新图像**时调用 `sysCall_vision(inData)`，允许用户进行图像处理。触发该回调的 API：`sim.handleVisionSensor`、`sim.checkVisionSensor`、`sim.checkVisionSensorEx`、`sim.setVisionSensorImg`。仅适用于 customization 脚本与仿真脚本。

`inData` 字段：`handle`、`resolution`、`clippingPlanes`、`viewAngle`（透视模式）、`orthoSize`（正交模式）、`perspectiveOperation`。

返回 `outData`：`trigger`（是否触发传感器）、`packedPackets`（打包数据包列表，可经 `sim.readVisionSensor` 读取）。

### 触发回调（sysCall_trigger）

来源：`triggerCallbackFunctions.htm`。

当脚本对象的父对象是视觉传感器或接近传感器时，可包含 `sysCall_trigger(inData)`：

- **视觉传感器**：可在视觉回调内生成触发信号；`inData` 含 `handle`、`packedPackets`（第一包含 15 个辅助值：强度/红/绿/蓝/深度的最小、最大、平均值）。
- **接近传感器**：检测到对象时生成触发信号；`inData` 含 `handle`、`detectedObjectHandle`、`detectedPoint`（相对传感器系）、`normalVector`（相对传感器系）。

返回 `outData = {'trigger': True/False}`。仅 customization 脚本与仿真脚本。

### 用户配置回调（sysCall_userConfig）

来源：`userConfigCallbackFunctions.htm`。

含 `sysCall_userConfig` 的 customization 脚本会在场景层级显示配置对话框图标（父对象上也为方便显示），双击触发该回调。常用于为模型显示自定义配置 UI，用户数据通过自定义数据属性（custom data properties）读写，例如：

```python
sim.setBufferProperty(self.modelHandle, 'customData.RobotParams', sim.packTable(data))
data = sim.unpackTable(sim.getBufferProperty(self.modelHandle, 'customData.RobotParams'))
```

也可使用 `configUI` 模块快速搭建配置对话框并自动写入自定义数据。仅 customization 脚本。

## 通用回调脚本（已弃用）

来源：`generalCallbackScript.htm`。

**general callback script 已弃用**，应改用 customization 脚本。旧脚本仍可运行但编辑被禁用；如需临时启用编辑，在 `system/usrset.txt` 中将 `enableOldGeneralCallbackScriptEdition` 设为 `true`。

## 完整脚本骨架示例（Python）

以下为一个含 `sysCall_init`/`sysCall_actuation`/`sysCall_sensing`/`sysCall_cleanup` 的最小仿真脚本骨架（CoppeliaSim 4.10，Python 脚本对象内）：

```python
#python
def sysCall_init():
    # 仿真开始时执行一次性初始化
    sim = require('sim')
    self.handle = sim.getObject('..')  # 脚本父对象
    self.targetPos = 0.5
    print('sysCall_init: initialized for', self.handle)

def sysCall_actuation():
    # 每个仿真步执行驱动代码（如设关节目标位置）
    sim = require('sim')
    joint = sim.getObject('./joint', {'proxy': self.handle})
    sim.setJointTargetPosition(joint, self.targetPos, {'proxy': self.handle})

def sysCall_sensing():
    # 每个仿真步执行传感代码（如读位置）
    sim = require('sim')
    joint = sim.getObject('./joint', {'proxy': self.handle})
    pos = sim.getJointPosition(joint)
    # 达到目标后切换方向，演示简单状态机
    if abs(pos - self.targetPos) < 0.01:
        self.targetPos = 0.0 if self.targetPos > 0.25 else 0.5

def sysCall_cleanup():
    # 仿真结束清理
    print('sysCall_cleanup: done')

def sysCall_beforeSimulation():
    # 仿真即将开始（非仿真脚本/非 main 脚本可用）
    pass

def sysCall_afterSimulation():
    # 仿真刚结束（非仿真脚本/非 main 脚本可用）
    pass
```

> 说明：上述骨架遵循官方手册给出的 Python 回调签名；`sim.getObject` 路径查询用斜杠前缀（`./` 相对父对象），别名设置时别名本身不含斜杠。参见 [[wiki/02-仿真建模/02-01-分层命名场景构建]]。
