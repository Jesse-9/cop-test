# 机械臂与传送带代码审查及修复计划

> [!info] 当前状态
> 本文记录 `src/` 下机械臂和传送带相关代码的审查结果、机械臂实际运行重构方案、验证计划及当前进度。当前状态为 **refactor-in-progress**；单元测试已通过，§9.9 **阶段一（单关节）已于 2026-10-09 在 CoppeliaSim 4.10 上实测通过**（见 §6），阶段二至五与 60 秒全流程仿真仍未完成验收。

## 1. 范围与术语

本轮审查覆盖：

- `src/factory_robot.py`：UR5 关节采集、关键帧动画和动作触发。
- `src/factory_physics.py`：物料与传送带 pad 的物理属性。
- `src/factory_controller.py`：物料生成、传送带推进、工位出料和机械臂触发。
- `src/build_scene.py`：UR5、夹爪、传送带和 AGV 场景构建。
- `src/factory_config.py`：机械臂关键帧、传送带速度和物理参数。
- `src/factory_types.py`：物料的传送带、冻结和物理状态。

本文中的“履带”指 CoppeliaSim 内置 `generic conveyor (belt).ttm` 的闭环 pad 传送带。当前 AGV 使用 Pioneer P3DX 轮式模型，不是履带式移动底盘。

## 2. 审查基线

- CoppeliaSim 场景中存在 6 台 UR5，每台本体有 6 个关节。
- UR5 本体关节实际为 `jointmode_dynamic=5`。
- UR5 动态控制模式实际为 `jointdynctrl_position=8`。
- 每条内置传送带包含约 50 个名为 `pad` 的 shape。
- pad 沿上表面、右端滚轮、底部、左端滚轮构成闭环。
- Python 仿真步长与 CoppeliaSim 步长均为 `0.05 s`。
- 工作区在审查开始前已有未提交修改，后续必须保留并与之兼容。

## 3. 已确认问题

| 严重度 | 问题 | 影响 | 状态 |
|---|---|---|---|
| P1 | 动态 UR5 使用 `setJointPosition` | 写入会被下一次物理解算覆盖，关节接近零位，动画不可用 | 已形成候选修复 |
| P1 | pad 仅增加局部 X 并按带长回卷 | 滚轮和底部 pad 被破坏，无法保持闭环履带形状 | 已形成候选修复 |
| P1 | 物理模式物料生成在仓库中心而非传送带入口 | 物料可能落到带外或地板，无法依靠摩擦输送 | 已形成候选修复 |
| P2 | C 岛出料后只设置 `on_conveyor` | 物理模式跳过 Python 位姿同步，物料不会自动移动到 C→E 入口 | 已形成候选修复 |
| P2 | 非循环动画结束前先清除 `anim` | 动作最后一帧没有被精确写入，可能停在接近 HOME 的姿态 | 已形成候选修复 |
| P2 | UR5 关节顺序依赖对象树返回顺序 | 模型或版本变化时关键帧可能映射到错误关节 | 已形成候选修复 |
| P2 | `factory_physics`、`factory_scene` 未列入打包模块 | 开发目录可运行，安装后的 CLI 可能导入失败 | 已形成候选修复 |
| P3 | `factory_robot.update()` 文档与实际触发逻辑不一致 | 文档声称 COMPLETE 自动触发，实际由控制器事件更可靠 | 已同步文档 (factory_robot.update() 注释已更新) |

### 全流程

- 仿真时间持续推进，不停在启动后的少数帧。

## 9. 机械臂实际运行重构方案

### 9.1 重构目标

当前 `RobotArmAnimator` 仍是视觉动画器：它按照关键帧写关节目标，但没有完整的设备初始化、运动反馈、动作完成条件和夹爪控制。因此“调用过 API”不等于“机械臂实际完成动作”。重构目标是建立以下闭环：

```text
工位事件
  ↓
RobotArmCoordinator
  ↓
ArmTrajectoryExecutor
  ↓
RobotArmDevice
  ↓
setJointTargetPosition
  ↓
sim.step()
  ↓
读取实际关节位置 / TCP 位姿
  ↓
动作完成或失败
  ↓
更新物料和工位状态
```

第一阶段优先保证单台 UR5 稳定运动；第二阶段再增加真实夹爪和动态物理抓取。

### 9.2 推荐控制模式

推荐机械臂本体使用 `kinematic` 模式，配合 `setJointTargetPosition`：

```python
sim.setJointMode(joint_handle, sim.jointmode_kinematic)
sim.setJointTargetPosition(joint_handle, target_angle)
```

选择理由：

- 本项目机械臂主要承担产线演示和动作可视化，不是动力学研究对象。
- 当前 UR5 模型虽然显示为 dynamic + position control，但模型脚本已被剥离，动态配置和力矩是否完整需要逐台验证。
- 运动学模式不依赖 link 的动态启用、关节力矩和物理引擎差异，更适合先打通控制闭环。
- 传送带物料仍可以单独保留 dynamic/respondable，实现“运动学机械臂 + 动态物料”的混合仿真。

动态模式不删除，作为第二阶段方案。恢复 dynamic 前必须确认 link 动态配置、目标力矩、碰撞体、位置控制器和物理引擎均有效。

### 9.3 `RobotArmDevice`：单臂设备层

重构 `src/factory_robot.py`，将单台机械臂设备能力独立出来：

- 查找机械臂根对象。
- 沿父子链收集并排序六个 UR5 本体关节。
- 排除 `Gripper` 子树及夹爪关节。
- 查找 `tip`、`connection`、`flange` 或 `tcp` 作为 TCP。
- 初始化并记录关节模式、动态控制模式和关节区间。
- 提供当前关节位置、目标位置、最大误差和 TCP 位姿读取接口。
- 提供单关节目标和整组关节目标接口。
- 设备不可用时设置 `enabled=False`，不阻塞工厂控制器。

建议数据结构：

```text
RobotArmDevice
├── island_key
├── root_handle
├── joint_handles[6]
├── tcp_handle
├── gripper_handle
├── control_mode
├── current_positions
├── target_positions
└── enabled
```

句柄定位优先使用配置中的显式路径；路径失效时才使用根对象子树回退。最终必须校验恰好得到六个本体关节，并输出每个关节的别名、父对象和模式。

### 9.4 `ArmTrajectoryExecutor`：轨迹执行层

轨迹执行器不直接处理工厂业务，只负责动作：

```text
HOME
APPROACH
PICK
LIFT
PLACE
RELEASE
RETURN_HOME
```

动作状态从简单的 `anim is None` 改为：

```text
IDLE
MOVING
WAITING_SETTLE
COMPLETED
FAILED
```

每个动作必须具备：

- 关键帧列表。
- 当前帧和帧内时间。
- 当前目标关节角。
- 关节最大误差。
- 稳定等待时间。
- 超时限制。
- 完成和失败原因。

动作完成不能只依据 Python 关键帧播放完毕，而要满足：

```text
max(abs(current_joint - target_joint)) < position_tolerance
持续 settle_time 秒
```

超过 `action_timeout` 则进入 `FAILED` 并记录错误，不得阻塞主循环。

### 9.5 `GripperAdapter`：夹爪控制层

当前夹爪脚本会被剥离，不能假定夹爪会自动开合。增加两种明确模式：

- `visual_only`：只加载和挂载夹爪模型。
- `joint_control`：查找夹爪主动关节，用目标位置控制开合。

接口建议为：

```text
open()
close()
is_open()
is_closed()
attach_material()
detach_material()
```

第一阶段先实现运动学夹爪和物料绑定，验证动作流程；第二阶段再改为动态接触抓取。真实抓取至少需要检查 TCP 与物料距离、夹爪关闭状态、物料绑定状态和释放后的位姿。

### 9.6 `RobotArmCoordinator`：业务协调层

`FactoryController` 不再直接依赖关键帧动画细节，也不直接调用多个 `trigger()`。由协调器接收业务事件并提交动作任务：

```text
WAREHOUSE_MATERIAL_ARRIVED
ISLAND_PROCESSING_STARTED
ISLAND_PROCESSING_COMPLETED
MATERIAL_PICKUP_REQUIRED
MATERIAL_PLACE_REQUIRED
ASSEMBLY_REQUIRED
```

接口建议为：

```python
robot_coordinator.submit(
    arm="A",
    task="pick_and_place",
    material_uid=uid,
)
```

协调器负责防止同一机械臂动作被覆盖，并把动作结果反馈给物料和工位状态机。

### 9.7 场景构建策略

修改 `src/build_scene.py`：

1. 增加配置项：

   ```python
   ARM_CONTROL_MODE = "kinematic"
   ARM_USE_BUILTIN_SCRIPT = False
   GRIPPER_USE_BUILTIN_SCRIPT = False
   AGV_USE_BUILTIN_SCRIPT = False
   ```

2. 外部 Python 控制时剥离模型脚本；使用 CoppeliaSim 原生 IK 或夹爪脚本时保留脚本。
3. 同一关节不能同时由 Python 和模型脚本控制。
4. 机械臂加载后立即完成六轴查找、模式配置、速度参数配置和 HOME 初始化。
5. 首次验收只启用 A 岛机械臂，确认后再逐台启用 B、C、D、E_C、E_D。

### 9.8 主循环顺序

`FactoryController` 每个仿真步采用以下顺序：

1. 读取当前仿真时间和机械臂反馈。
2. 更新工厂状态机。
3. 将工位完成、取料、放料和装配转换为机械臂业务事件。
4. 协调器接收并排队动作。
5. 推进机械臂轨迹和夹爪状态。
6. 将动作反馈写回物料状态。
7. 写入诊断日志。
8. 调用 `sim.step()`。

每台机械臂至少记录：

```text
arm=A
state=MOVING
joint1_current=...
joint1_target=...
max_joint_error=...
tcp_position=...
gripper_state=...
```

控制命令必须在 `sim.step()` 前下发，下一步读取实际位置验证响应。

### 9.10 动态模式第二阶段验收

恢复 dynamic 模式前检查：

- 所有 link 是否动态启用。
- 关节是否为 dynamic + position control。
- 目标力矩是否足够。
- 机械臂连接结构是否有效。
- 夹爪和物料是否有真实 respondable 碰撞体。
- 是否存在残留脚本重复控制。

建议验收指标：

```text
目标位置误差 < 0.05 rad
1 秒内关节实际位置变化 > 0.1 rad
TCP 位移 > 0.05 m
连续运行 60 秒不冻结
```

如果动态模式达不到指标，继续采用运动学机械臂本体和动态物料的混合方案。
