# 数字孪生概述与实现架构

> 本条目为**概念性条目**，并非对应官方手册中某一单一页面，而是综合 external front-end、external controller tutorial、ZeroMQ remote API、ROS 2 interface 等多篇手册内容，提炼 CoppeliaSim 作为数字孪生底座的架构与协同模式。技术细节以手册原文为准。

## 数字孪生的概念

**数字孪生（Digital Twin）** 指物理设备与其虚拟模型之间的实时双向映射：物理世界的传感器数据持续同步到仿真模型，仿真侧的规划与决策又可回控物理执行器。按同步方向与自动化程度，通常分为三级：

- **数字模型（Digital Model）**：离线、单向、手工同步，无实时性要求。
- **数字影子（Digital Shadow）**：自动、单向（物理 → 虚拟），物理状态实时反映到仿真。
- **数字孪生（Digital Twin）**：自动、双向（物理 ←→ 虚拟），控制指令可回写下发。

CoppeliaSim 适合承担 L1/L2 级孪生的虚拟侧底座，核心原因在于它同时提供物理仿真引擎与多种外部通信接口，既能复现物理行为，又能与真实控制器/SCADA/ERP 对接。

## CoppeliaSim 作为孪生底座的优势

依据官方手册，CoppeliaSim 提供了以下支撑数字孪生的能力：

1. **物理仿真 + 精确时序**：内置物理引擎可复现碰撞、关节、运动学；`sim.setStepping(True)` 后由外部客户端逐帧 `sim.step()` 推进，使仿真时间与外部逻辑严格同步（见 `zmqRemoteApiOverview.htm`）。
2. **多语言多接口接入**：ZeroMQ Remote API 支持 Python、C++、Java、Matlab/Octave、Lua、Rust 等客户端（见 `zmqRemoteApiOverview.htm`），可复用"控制真实机器人的同一套代码"控制虚拟模型（见 `externalControllerTutorial.htm`）。
3. **ROS/ROS2 节点能力**：CoppeliaSim 可作为 ROS2 节点，通过 topic/service/action 与分布式系统互联（见 `ros2Interface.htm`）。
4. **可移植与可嵌入**：仿真场景与模型可随 CoppeliaSim 实例部署到工控机或边缘设备，与真实产线同机运行。
5. **事件追踪与外部前端**：`sysCall_event` + `sim.setEventFilters` + `sim.getGenesisEvents` 可追踪场景内大多数变化并发布，据此可实现 Web 端可视化前端（如 Three.js front-end，见 `externalFrontEnd.htm`）。

## 典型协同架构

数字孪生系统的外部协同通常采用以下分层：

```
┌──────────────────────────────────────────────────────────┐
│  企业层：ERP / MES / SCADA                                │
│      ↓ 订单 / 工艺参数 / 节拍指令                          │
├──────────────────────────────────────────────────────────┤
│  控制层：PLC / 真实机器人控制器 / 上位机                   │
│      ↕ 传感器编码器数据      ↕ 控制指令                     │
├──────────────────────────────────────────────────────────┤
│  孪生层：外部控制器（Python/C++）+ CoppeliaSim 虚拟模型     │
│   ┌────────────────────┐    ┌──────────────────────┐     │
│   │ 外部控制器 (ZMQ/ROS2)│←→│ CoppeliaSim 仿真场景  │     │
│   │ - 状态同步          │    │ - 物理引擎            │     │
│   │ - 路径/IK 规划      │    │ - 机械臂/AGV/传送带   │     │
│   │ - 决策与回控        │    │ - 碰撞检测            │     │
│   └────────────────────┘    └──────────────────────┘     │
└──────────────────────────────────────────────────────────┘
```

CoppeliaSim 与外部世界对接的主要通路（按手册列举的控制方式，见 `externalControllerTutorial.htm`）：

| 通路 | 机制 | 特点 |
|------|------|------|
| ZeroMQ Remote API | ZMQ + CBOR，`sim.*` 全量函数 | 轻量、快、易用，本仓库 cop-test 即采用 |
| ROS / ROS2 接口 | `simROS2.*` 插件，节点间 topic/service | 分布式生态，跨进程跨机 |
| 仿真脚本 + 自定义通道 | 脚本内用 pipe/socket/串口与外部应用通信 | 语言灵活，但需自行处理协议 |
| 插件（C++） | 回调 + 自定义脚本函数注册 | 无通信延迟，主线程同步，但需编译 |
| Web 前端（事件流） | visualization stream + Three.js | 远程监控/可视化，非控制主回路 |

## 数据流：传感器 → 仿真 → 决策 → 回控

一个完整的孪生回路在每个同步周期内完成以下四步：

1. **采集**：从物理设备读取传感器/编码器/状态量。
2. **注入**：通过 `sim.setJointPosition`、`sim.setFloatSignal` 等把物理状态写入虚拟模型。
3. **推演/决策**：在仿真中运行 IK、OMPL 规划或业务逻辑，必要时推进一帧物理引擎。
4. **回控**：把仿真侧计算出的目标关节/速度/指令下发回 PLC 或机器人控制器。

### ZMQ 同步循环示例（stepping 模式）

手册给出的标准 stepping 模式（`zmqRemoteApiOverview.htm`）是孪生时序一致性的基础：外部客户端是 clock master，每次 `sim.step()` 推进一个固定步长，控制逻辑与物理引擎严格同步。下面给出一个最简孪生数据流示例（Python 客户端，4.10）：

```python
from coppeliasim_zmqremoteapi_client import RemoteAPIClient

client = RemoteAPIClient()
sim = client.require('sim')

sim.setStepping(True)          # 外部客户端成为时钟主导者
sim.startSimulation()

joint = sim.getObject('/robot/joint')
dt = 0.05                      # 单步 50ms，与真实产线节拍对齐

while sim.getSimulationState() != sim.simulation_stopped:
    # 1. 采集物理设备状态（示例：从 PLC/串口读取）
    physical_pos = read_from_plc()

    # 2. 注入虚拟模型
    sim.setJointPosition(joint, physical_pos)

    # 3. 推演/决策（可在仿真中运行 IK/规划，读取碰撞结果等）
    sim.step()                 # 推进一帧物理引擎

    # 4. 回控（把仿真侧决策下发到物理执行器）
    cmd = compute_command()
    send_to_plc(cmd)

sim.stopSimulation()
```

> 要点：`setStepping(True)` + `sim.step()` 保证每个控制周期与一帧物理仿真一一对应，避免仿真时间漂移；这正是工业孪生精确节拍时序的前提。本仓库 cop-test 的 `FactoryController` 即采用此模式驱动岛式车间仿真（见 [[wiki/06-工业案例/06-02-岛式车间柔性生产案例]]）。

## 与 external front-end / controller tutorial 的关系

- **external controller tutorial**（`externalControllerTutorial.htm`）列举了控制 CoppeliaSim 中机器人/仿真的六种方式（仿真脚本、插件、自定义客户端应用、Remote API、ROS 节点、自定义通道），并提供了 7 个 `controlTypeExamples` 场景。孪生系统的"控制层"即从中选择一种与外部控制器对接，其中 ZeroMQ Remote API 是最便捷、最常用的选择。
- **external front-end**（`externalFrontEnd.htm`）面向监控/可视化场景：通过事件流把场景变化发布到 Web 端，适合作为孪生系统的"看板"，但不参与控制主回路。
- **ROS2 interface**（`ros2Interface.htm`）使 CoppeliaSim 成为 ROS2 节点，适合需要与多台分布式设备/中间件互联的孪生场景，详见 [[wiki/05-数字孪生与协同仿真/05-01-ROS2集成]]。

## 本仓库的孪生雏形

本仓库 cop-test 是一个岛式车间柔性生产仿真的数字孪生雏形：Python 控制层通过 ZMQ Remote API 以 stepping 模式驱动 CoppeliaSim 中的仓库、传送带、工作岛、AGV 与机械臂，按固定单步循环推进仿真，构成"外部控制器 + 虚拟工厂"的孪生架构。详见 [[wiki/06-工业案例/06-02-岛式车间柔性生产案例]]。
