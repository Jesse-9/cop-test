# ROS1 集成（simROS）

> CoppeliaSim 的 ROS1 Interface 插件（`libsimROS.*`），通过 `simROS.*` 命名空间在仿真脚本中发布/订阅话题、调用/提供服务、广播 TF 变换，使 CoppeliaSim 作为 ROS1 节点参与分布式通信。

官方手册 `rosInterfaces.htm` 同时提供 ROS1 与 ROS2 两套接口；本条目对应 ROS1（`simROS`），ROS2 详见 [[wiki/05-数字孪生与协同仿真/05-06-simROS2接口]]。注意：`rosInterfaceApi.htm` 仅是重定向到 `simROS.htm` 的跳转页，实际 API 内容以 `simROS.htm` 为准。

## 概述

ROS Interface 属于 CoppeliaSim API 框架，以较高保真度复刻 C++ ROS1 API，是进行灵活 ROS 通信的理想选择。CoppeliaSim 可作为 ROS 节点，通过 **话题（topic）发布/订阅**、**服务（service）服务端/客户端** 与其他节点交互。

插件以共享库形式提供（Linux 为 `libsimROS.so`），在脚本中通过 `require` 加载：

```python
simROS = require('simROS')
```

```lua
simROS = require('simROS')
```

加载仅在 `roscore` 已启动时才会成功，加载前需 source ROS 环境；请留意 CoppeliaSim 终端/控制台窗口中的插件加载日志。

## 插件加载与编译

Linux 发行版通常在 `CoppeliaSim/compiledROSPlugins` 下附带预编译插件，需复制到 `CoppeliaSim/` 根目录才会被加载。若预编译插件因系统差异无法加载，可自行编译：

```bash
# 1. 将 simROS、ros_bubble_rob 两个包复制到 catkin_ws/src
# 2. 设置 CoppeliaSim 根目录并编译
export COPPELIASIM_ROOT_DIR=~/path/to/coppeliaSim
catkin build --cmake-args -DCMAKE_BUILD_TYPE=Release
# Ubuntu 20.04 因 python-catkin-tools bug 需改用 catkin_make

# 3. 复制产物
cp devel/lib/libsimROS.so ~/path/to/coppeliaSim/

# 4. 启动 ROS master
roscore
```

需要自定义消息/服务时，编辑 `simROS/meta/` 下的文件再重新编译。插件加载成功后 `rosnode list` 可看到 `/sim_ros_interface` 节点。

## simROS 命名空间 API 清单

`simROS` 命名空间共 33 个函数，按用途分组如下（函数名以 `docs/raw/manual/en/simROS.htm` 字母序索引为准，与 `docs/raw/manual/index/simROS.json` 一致）：

| 分组 | 函数 |
|------|------|
| **话题（发布/订阅）** | `advertise`、`subscribe`、`publish`、`shutdownPublisher`、`shutdownSubscriber`、`publisherTreatUInt8ArrayAsString`、`subscriberTreatUInt8ArrayAsString` |
| **服务** | `advertiseService`、`serviceClient`、`call`、`shutdownServiceServer`、`shutdownServiceClient`、`serviceServerTreatUInt8ArrayAsString`、`serviceClientTreatUInt8ArrayAsString` |
| **TF 变换** | `sendTransform`、`sendTransforms` |
| **图像传输（image_transport）** | `imageTransportAdvertise`、`imageTransportSubscribe`、`imageTransportPublish`、`imageTransportShutdownPublisher`、`imageTransportShutdownSubscriber` |
| **参数服务器** | `getParamBool`、`getParamInt`、`getParamDouble`、`getParamString`、`setParamBool`、`setParamInt`、`setParamDouble`、`setParamString`、`hasParam`、`searchParam`、`deleteParam` |
| **时间** | `getTime` |

关键签名（Python 与 Lua 一致，仅返回容器类型不同——Python `list`/Lua `table`）：

```python
# 创建发布者/订阅者
string publisherHandle = simROS.advertise(string topicName, string topicType,
                                         int queueSize=1, bool latch=false)
string subscriberHandle = simROS.subscribe(string topicName, string topicType,
                                           func topicCallback, int queueSize=1)
# 发布消息（message 为 dict，键对应 ROS 消息字段）
simROS.publish(string publisherHandle, list message)

# 服务端/客户端
string serviceServerHandle = simROS.advertiseService(string serviceName, string serviceType,
                                                     func serviceCallback)
string serviceClientHandle = simROS.serviceClient(string serviceName, string serviceType)
list result = simROS.call(string serviceClientHandle, list request)

# TF 变换
simROS.sendTransform(list transform)   # 单个 geometry_msgs/TransformStamped
simROS.sendTransforms(list transforms) # 多个

# ROS 时间（秒）
float time = simROS.getTime(int flag=0)
```

## 消息类型支持

话题/服务类型以字符串指定。官方手册中存在两种写法：

- `simROS.htm` API 参考用双冒号 `::`，如 `'geometry_msgs::Twist'`、`'std_msgs::Float32'`
- `ros1Tutorial.htm` 教程示例用单斜杠 `/`，如 `'std_msgs/Float32'`

两者在实践中均可被插件接受（ROS1 历史上 `::` 与 `/` 并存）。新代码建议统一用单斜杠 `/`，与 ROS2 的 `package/msg/Type` 命名更接近，便于将来迁移。

回调函数收到的是 dict/table，键名与 ROS 消息字段一致。`uint8[]` 字段默认按整数数组处理，调用 `publisherTreatUInt8ArrayAsString` / `subscriberTreatUInt8ArrayAsString` 可改按字符串处理，在 Lua 中通常更快。

## 简明示例：发布仿真时间 + 订阅回环

以下脚本附加到某对象上，发布 `/simulationTime`（`std_msgs/Float32`）并订阅自身发布的话题，同时广播该对象的 TF 变换（改编自官方 `ros1Tutorial.htm`）：

```python
#python (simulation script, 适用 CoppeliaSim 4.10)
def subscriber_callback(msg):
    sim.addLog(sim.verbosity_scriptinfos,
               f'subscriber received Float32: {msg["data"]}')

def get_transform_stamped(obj_handle, name, rel_to, rel_to_name):
    t = sim.getSystemTime()
    p = sim.getObjectPosition(obj_handle, rel_to)
    o = sim.getObjectQuaternion(obj_handle, rel_to)
    return {
        'header': {'stamp': t, 'frame_id': rel_to_name},
        'child_frame_id': name,
        'transform': {
            'translation': {'x': p[0], 'y': p[1], 'z': p[2]},
            'rotation':    {'x': o[0], 'y': o[1], 'z': o[2], 'w': o[3]},
        },
    }

def sysCall_init():
    global sim, simROS
    sim = require('sim')
    simROS = require('simROS')
    self.object_handle = sim.getObject('..')
    self.object_alias = sim.getObjectAlias(self.object_handle, 3)
    # 发布者与订阅者订阅同一话题，形成回环
    self.publisher = simROS.advertise('/simulationTime', 'std_msgs/Float32')
    self.subscriber = simROS.subscribe('/simulationTime', 'std_msgs/Float32',
                                       subscriber_callback)

def sysCall_actuation():
    simROS.publish(self.publisher, {'data': sim.getSimulationTime()})
    simROS.sendTransform(
        get_transform_stamped(self.object_handle, self.object_alias,
                              -1, 'world'))

def sysCall_cleanup():
    simROS.shutdownPublisher(self.publisher)
    simROS.shutdownSubscriber(self.subscriber)
```

```lua
--lua (simulation script, 适用 CoppeliaSim 4.10)
function subscriber_callback(msg)
    sim.addLog(sim.verbosity_scriptinfos,
               'subscriber received Float32: '..msg.data)
end

function getTransformStamped(objHandle, name, relTo, relToName)
    local t = sim.getSystemTime()
    local p = sim.getObjectPosition(objHandle, relTo)
    local o = sim.getObjectQuaternion(objHandle, relTo)
    return {
        header = {stamp = t, frame_id = relToName},
        child_frame_id = name,
        transform = {
            translation = {x = p[1], y = p[2], z = p[3]},
            rotation    = {x = o[1], y = o[2], z = o[3], w = o[4]},
        },
    }
end

function sysCall_init()
    sim = require('sim')
    simROS = require('simROS')
    object_handle = sim.getObject('..')
    object_alias = sim.getObjectAlias(object_handle, 3)
    publisher  = simROS.advertise('/simulationTime', 'std_msgs/Float32')
    subscriber = simROS.subscribe('/simulationTime', 'std_msgs/Float32',
                                  subscriber_callback)
end

function sysCall_actuation()
    simROS.publish(publisher, {data = sim.getSimulationTime()})
    simROS.sendTransform(
        getTransformStamped(object_handle, object_alias, -1, 'world'))
end

function sysCall_cleanup()
    simROS.shutdownPublisher(publisher)
    simROS.shutdownSubscriber(subscriber)
end
```

## 与 ROS2 Interface 的对应关系

CoppeliaSim 同时提供 ROS1（`simROS`）与 ROS2（`simROS2`）两套接口，二者在功能上高度对应，但命名与能力有差异：

| 能力 | ROS1（`simROS`） | ROS2（`simROS2`） |
|------|------------------|-------------------|
| 创建发布者 | `advertise` | `createPublisher` |
| 创建订阅者 | `subscribe` | `createSubscription` |
| 发布/订阅关闭 | `shutdownPublisher`/`shutdownSubscriber` | `shutdownPublisher`/`shutdownSubscription` |
| 服务端 | `advertiseService` | `createService` |
| 服务客户端 | `serviceClient` | `createClient` |
| 服务调用 | `call` | `call` |
| 服务等待 | — | `waitForService` |
| Action | **不支持** | `createActionServer`/`createActionClient` 及一整套 goal 状态机 |
| QoS | `queueSize`/`latch` 参数 | 显式 `simros2_qos` 结构体 |
| 消息构造 | 手工 dict | `createInterface`/`importInterface`/`getInterfaceConstants` |
| 时间 | `getTime`（float 秒） | `getTime`（`simros2_time` 结构体）、`getSimulationTime`、`getSystemTime`、`timeToFloat`/`timeFromFloat` |
| 参数服务器 | 4 类型 get/set + `searchParam` | 4 类型 get/set（无 `searchParam`） |
| 类型字符串 | `package/MsgType`（单斜杠） | `package/msg/MsgType`（双斜杠，ROS2 命名规范） |

ROS1 接口的 `advertise`/`subscribe` 在 ROS2 中被拆分为 `create*` + `shutdown*` 的更显式生命周期管理；ROS2 还新增了 Action 完整支持和 QoS 策略。详见 [[wiki/05-数字孪生与协同仿真/05-06-simROS2接口]]。

## 为何新项目选 ROS2

新项目建议优先采用 ROS2 Interface（`simROS2`），原因如下：

1. **ROS1 已停止主线维护**：Open Robotics 已将开发重心转向 ROS2，ROS1 仅维护 LTS。CoppeliaSim 官方在 `rosInterfaces.htm` 中并列推荐两套接口，但 ROS2 是面向未来的方向。
2. **Action 原生支持**：`simROS2` 提供完整的 action server/client 与 goal 状态机（`actionServerActionExecute`/`Succeed`/`Abort`/`Canceled` 等），ROS1 接口无此能力，长时序任务需自行用话题模拟。
3. **QoS 策略**：ROS2 的 DDS 中间件支持可靠/尽力、持久/易失等 QoS，`simros2_qos` 结构体可精细配置；ROS1 仅 `queueSize`/`latch` 两个参数。
4. **消息接口工具**：`createInterface` 按类型生成默认值消息、`getInterfaceConstants` 取常量、`supportedInterfaces` 列出已编译支持的类型，比 ROS1 手工拼 dict 更安全。
5. **无 master 依赖**：ROS2 去中心化，无需先启动 `roscore`，插件加载更稳健，更契合数字孪生的多机部署场景（见 [[wiki/05-数字孪生与协同仿真/05-02-数字孪生概述]]）。
6. **与 Python 控制层契合**：本仓库主推 Python + ZeroMQ Remote API 编排仿真（见 [[wiki/01-API参考/01-02-Remote-API-ZMQ]]），ROS2 的 `rclpy` 与 ZMQ 客户端可同进程共存，而 ROS1 的 `rospy` 与某些事件循环场景兼容性更弱。

仅在必须对接既有 ROS1 生态（旧节点、旧 bag 数据、已部署机器人）时才选用 `simROS`。
