# 分层命名场景构建实战

> **当前工程约束**：斜杠路径只用于说明层级概念，实际 alias 必须直接使用
> 扁平下划线形式。当前柔性车间生产构建强制使用内置
> `generic conveyor (belt).ttm`、`UR5.ttm`、`suction pad.ttm` 和
> `pioneer p3dx.ttm`；模型缺失时生产构建必须报错，几何体回退只允许诊断测试。

> 取自真实项目 `cop-test`（岛式车间柔性生产仿真）的
> [scene.py](../../../src/flexible_factory/simulation/scene.py) 实践。

## 为什么用分层命名

CoppeliaSim 默认给每个对象一个扁平别名（如 `Cuboid#0`）。当场景中有几十个传送带、工作岛、AGV、机械臂时，扁平命名会让"按别名定位对象"变成猜谜。分层命名用斜杠路径表达归属：

```
/Warehouse/S1_Main             — 主原料库
/Conveyor/S1_to_A              — S1→A 传送带
/Island/A_Assembly/Robot_A     — A 岛上的机械臂
/Mobile/AGV_Shared             — 共享 AGV
```

## 标准做法

### 1. 建立层级根节点

先创建一组不可见的"文件夹" dummy 作为分层根，再把设备 `setObjectParent` 到对应根下：

```python
def create_hierarchy_roots(sim) -> dict[str, int]:
    roots = {}
    for name in ("/Warehouse", "/Island", "/Conveyor", "/Mobile"):
        h = sim.createDummy(0.01)
        sim.setObjectAlias(h, name[1:])   # 去掉前导斜杠
        sim.setObjectInt32Param(h, sim.objintparam_visibility, 0)
        roots[name] = h
    return roots
```

### 2. 子对象挂载 + 命名

```python
belt = sim.loadModel(os.path.join(cfg.MODEL_BASE, "conveyor.ttm"))
sim.setObjectParent(belt, roots["/Conveyor"], True)   # inPlace=True 保留世界坐标
sim.setObjectAlias(belt, "Conveyor_S1_to_A")          # 实际 alias：扁平下划线
```

## ⚠ 4.10 别名路径陷阱（重要）

`sim.setObjectAlias(handle, "Conveyor/S1_to_A")` 会把含 `/` 的路径**转成下划线别名** `_Conveyor_S1_to_A` 存储。后果：

```python
sim.getObject("Conveyor/S1_to_A")   # ❌ 查询失败
sim.getObject("/Conveyor/S1_to_A")  # ❌ 同样失败
```

**正确做法**：定位时枚举对象按**别名叶名匹配**，而非按斜杠路径查询：

```python
def find_by_leaf(sim, leaf: str, obj_type):
    i = 0
    while True:
        try:
            h = sim.getObjects(i, obj_type)
            if h is None or h < 0:
                break
            alias = sim.getObjectAlias(h)
            # 取最后一段叶名，兼容斜杠与下划线两种形态
            norm = alias.rsplit("/", 1)[-1].rsplit("_", 1)[-1]
            if alias == leaf or norm == leaf:
                return h
            i += 1
        except Exception:
            break
    return None
```

> 本项目把这段匹配逻辑分散在 `build_scene.clear_scene`、
> `factory_controller._setup_agv_visual`、`factory_robot._collect_arm_joints` 三处，
> 属于已知重复，理想做法是抽成单一 helper。

## 内置模型与生产失败策略

CoppeliaSim 自带 UR5、generic conveyor、suction pad 和 pioneer p3dx 等模型。
生产场景必须通过 `sim.loadModel` 加载指定模型；找不到时应明确失败并指出模型路径。
`sim.createPureShape` 仅可用于不宣称生产能力的诊断场景，不能静默替换物理模型：

```python
def _resolve_model_path(key: str) -> str | None:
    p = os.path.join(cfg.MODEL_BASE, cfg.MODELS[key])
    return p if os.path.isfile(p) else None
```

## 幂等清场

重复构建会导致别名冲突（同叶名多个对象）。`build_scene` 前必须 `clear_scene`：枚举所有主类型对象、`removeObjects` 批量删除。

> 注意：`clear_scene` 若把 `object_camera_type`/`object_light_type` 一并删除，
> 会清掉默认视口相机和灯光。如需保留，从类型清单中移除这两项。

## 小结

| 原则 | 做法 |
|------|------|
| 分层表达归属 | 文档可用 `/Group/Item`，实际 alias 使用 `Group_Item` |
| 根节点 | 不可见 dummy 作为文件夹 |
| 定位 | 枚举 + 叶名匹配，**不要**按斜杠路径 getObject |
| 模型 | 生产必须使用指定内置模型；primitive 仅诊断回退 |
| 幂等 | 构建前清场 |
