# 轨迹与路径规划模块

> CoppeliaSim 中"路径规划"与"轨迹生成"两条互补的运动功能链路总览：OMPL 负责全局避障的几何路径，Ruckig/Reflexxes 与 TOPPRA 负责沿路径或关节空间的时间最优、加加速度受限轨迹执行。

## 路径规划 vs 轨迹生成

两者解决的是运动问题的不同阶段，常被混称但职责分明：

| 维度 | 路径规划（Path Planning） | 轨迹生成（Trajectory Generation） |
|------|---------------------------|-------------------------------------|
| 产出 | 几何路径（一串位姿/构型，无时间标度） | 带时间律的轨迹（每个点有时刻、速度、加速度） |
| 关注点 | 避障、可达性、构型空间采样 | 时间最优、速度/加速度/加加速度上限、平滑性 |
| 典型实现 | **simOMPL** 插件（OMPL 库，采样式随机规划） | **Ruckig** OTG、**Reflexxes** RML Type II、**TOPPRA** |
| 计算时机 | 离线/一次性规划，可多次重用（PRM 路图） | 在线、每控制周期步进一次 |
| 输入 | 起点、目标状态/位姿、碰撞对、状态空间 | 当前 pos/vel/accel、目标 pos/vel、运动学约束 |

**协作工作流**（手册推荐流程）：

1. `simOMPL` 规划出一条构型空间路径（离散关节构型序列）；
2. 用 `sim.getPathLengths` 计算路径弧长，`sim.generateTimeOptimalTrajectory`（TOPPRA）将其时间参数化为时间最优轨迹；
3. 执行阶段用 `sim.moveToConfig`（内部 Ruckig）按约束平滑跟踪，或直接沿路径对象用 `sim.getPathInterpolatedConfig` 逐帧插值。

对于抓取放置等末段需直线逼近的任务，手册建议把 `simOMPL` 的全局规划与 `simIK.generatePath` 生成的直线 IK 路径拼接使用。

## pathsAndTrajectories 概念

手册（`pathsAndTrajectories.htm`）明确：一条**路径或轨迹本质上就是一组数据**，可以是 1D/2D/3D 位置，也可以是姿态、机器人构型/状态。具体数据结构由用户代码决定，CoppeliaSim 只提供辅助 API 来创建、解释、操纵这些基础数据。

其中一种常用特例是**位姿路径**（位置 + 方向），CoppeliaSim 为此提供**路径对象（Path object）**，可在 3D 场景中可视化：路径由**控制点**支撑一条曲线，控制点可平移、复制/粘贴、删除。路径对象本质是伪对象——由若干 Dummy 加一个定制脚本（customization script）描述其行为构成。路径数据以 custom data 形式存储：

```python
# 控制点（每个 x,y,z,qx,qy,qz,qw）
ctrlPts = sim.unpackDoubleTable(sim.getBufferProperty(pathHandle, 'customData.PATHCTRLPTS'))
# 路径数据（每个 x,y,z,qx,qy,qz,qw）
pathData = sim.unpackDoubleTable(sim.getBufferProperty(pathHandle, 'customData.PATH'))
```

详见 [[wiki/02-仿真建模/02-05-路径-Path]]。

## path position 计算方法：线性 vs 弧长

`sim.getPathLengths(path, dof, distCallback)` 返回每个路径点距起点的累计长度与总长度。手册明确：即便路径点维度高于 3（如 7 维位姿），也**只在 1/2/3D 笛卡尔空间计算长度**——位置部分算欧氏距离累加，方向部分不参与长度。

这是"沿路径运动"的基础：拿到 `pathLengths` 后，给定一个距离 `t`，用 `sim.getPathInterpolatedConfig` 取出该距离处的插值构型。

`sim.getPathInterpolatedConfig` 的 `method` 字段决定插值方式：

- `linear`（默认）：线性插值，速度不连续（折角处）。
- `quadraticBezier`：二次贝塞尔，`strength` 0.05–1.0 控制平滑度，路径更平滑。
- `forceOpen`：即便首末点重合也视作开放路径，不环形闭合。

`types` 数组按维度标注值类型，决定插值语义：

| types 值 | 含义 | 典型用途 |
|----------|------|----------|
| 0 | 笛卡尔值 | 位置 x/y/z |
| 1 | 2π 周期值 | 旋转关节（取最短角差方向） |
| 2 | 四元数值 | qx/qy/qz/qw（球面插值） |

例：3D 位姿路径用 `types=[0,0,0,2,2,2,2]`；全旋转关节构型用 `types=[1,1,1,...]`。

## 轨迹生成：Ruckig / Reflexxes / TOPPRA

### Ruckig（在线轨迹生成 OTG，推荐）

CoppeliaSim 4.10 集成 **Ruckig Online Trajectory Generator**（Lars Berscheid 贡献，LGPL），提供**即时（instantaneous）**轨迹生成：给定当前 pos/vel/accel 与目标 pos/vel，以及最大速度/加速度/**加加速度（jerk）**上限，每个周期输出一段满足约束的时间最优运动。这是手册 `Motion functionality` 分类的核心 API。

底层四函数：

- `sim.ruckigPos(dofs, baseCycleTime, flags, currentPosVelAccel, maxVelAccelJerk, selection, targetPosVel)` → 创建位置型 OTG 对象，返回 handle。
- `sim.ruckigVel(...)` → 创建速度型 OTG 对象。
- `sim.ruckigStep(handle, cycleTime)` → 步进一次，返回 `result`、`newPosVelAccel`、`synchronizationTime`。`result`：`1`=到达目标，`0`=仍在运动，负值=错误。
- `sim.ruckigRemove(handle)` → 释放对象。

`flags` 的同步模式常量（`apiConstants.htm`）：

- `sim.ruckig_phasesync`（默认）：相位同步，各 DoF 同时到达。
- `sim.ruckig_timesync`：时间同步。
- `sim.ruckig_nosync`：不强制同步。

`baseCycleTime` 建议取 `0.0001`（0.1ms），`cycleTime` 应是其整数倍。

### Reflexxes Motion Library（RML，旧版）

**Reflexxes Type II**（Torsten Kroener / Reflexxes GmbH，LGPL V3.0）是早期的在线轨迹库。手册明确：`sim.rmlMoveToJointPositions` 与 `sim.rmlMoveToPosition` **已废弃**，改用 `sim.moveToConfig` / `sim.moveToPose`，后者通过回调机制提供更大灵活性。RML Type IV 已不再分发，Type II 不支持加加速度限制。

### TOPPRA（时间最优路径参数化）

`sim.generateTimeOptimalTrajectory(path, pathLengths, minMaxVel, minMaxAccel, ...)` 基于 **TOPPRA 库**，将一条已有的几何路径（构型序列 + 弧长）参数化为时间最优轨迹，返回带时间戳的路径点 `outP` 与对应 `times`。与 Ruckig 的区别：TOPPRA 处理的是**离线给定整条路径**的时间最优化；Ruckig 是**在线逐步生成**、可即时响应目标变更。

## 执行：sim.moveToConfig / sim.moveToPose

`sim.moveToConfig` 是手册推荐的高层运动函数，内部封装 Ruckig，执行 n-DoF 构型空间的平滑运动。**只能在 thread 脚本中调用**（阻塞式）。`sim.moveToPose` 与之类似，面向位姿。

关键参数（`sim.moveToConfig`）：

- `pos` 或 `joints`：当前构型，或关节句柄向量（直接读关节）。
- `targetPos`：目标构型。
- `maxVel` / `maxAccel` / `maxJerk`：每 DoF 的运动学上限（三者至少给一组）。
- `targetVel`：目标速度，默认全零（到位即停）。
- `callback`：每步回调，参数为当前运动状态，可在此做碰撞检查或记录。
- `cyclicJoints`：标记哪些关节走最短角差方向。
- `timeStep`：步长，0 表示用当前仿真步长。

对应的 `_init` / `_step` / `_cleanup` 三段式版本可在非 thread 脚本中手动驱动状态机。

## 典型工作流与代码

### 工作流 A：OMPL 规划 → Ruckig 平滑执行

```python
from coppeliasim_zmqremoteapi_client import RemoteAPIClient
client = RemoteAPIClient()
sim = client.require('sim')
simOMPL = client.require('simOMPL')
simIK = client.require('simIK')

# 1. OMPL 全局规划（详见 03-02 条目）
task = simOMPL.createTask('arm')
simOMPL.setAlgorithm(task, simOMPL.Algorithm.RRTstar)
# ... 设置 state space / collision pairs / start & goal ...
simOMPL.setup(task)
path, _ = simOMPL.compute(task, 0.2, 0.0)   # 离散构型序列
simOMPL.destroyTask(task)

# 2. Ruckig 逐步执行（在 thread 中用 moveToConfig 更简洁）
joints = [sim.getObject(f'/robot/joint{i}') for i in range(6)]
current = [sim.getJointPosition(j) for j in joints]
for cfg in path:
    sim.moveToConfig(joints=joints, targetPos=cfg,
                     maxVel=[0.5]*6, maxAccel=[0.5]*6, maxJerk=[5]*6,
                     targetVel=[0]*6, timeStep=0)
```

### 工作流 B：沿路径对象按弧长跟随（手册原例改写）

```python
import numpy as np

sim.setStepping(True)
path_handle = sim.getObject('/Path')
pathData = sim.unpackDoubleTable(sim.getBufferProperty(path_handle, 'customData.PATH'))

m = np.array(pathData).reshape(len(pathData) // 7, 7)
pathPositions = m[:, :3].flatten().tolist()
pathQuaternions = m[:, 3:].flatten().tolist()

# 关键：用弧长（非线性索引）定位
pathLengths, totalLength = sim.getPathLengths(pathPositions, 3)

velocity = 0.04  # m/s
posAlongPath = 0.0
prev_t = 0.0
obj = sim.getObject('..')

while sim.getSimulationState() != sim.simulation_stopped:
    t = sim.getSimulationTime()
    posAlongPath = (posAlongPath + velocity * (t - prev_t)) % totalLength
    # types=[2,2,2,2] 使四元数走球面插值
    pos = sim.getPathInterpolatedConfig(pathPositions, pathLengths, posAlongPath)
    quat = sim.getPathInterpolatedConfig(pathQuaternions, pathLengths,
                                         posAlongPath, None, [2, 2, 2, 2])
    sim.setObjectPosition(obj, pos, path_handle)
    sim.setObjectQuaternion(obj, quat, path_handle)
    prev_t = t
    sim.step()
```

### 工作流 C：TOPPRA 时间最优 + 关节执行

```python
pathLengths, total = sim.getPathLengths(path, 6)   # 6-DoF 构型路径
outP, times, _ = sim.generateTimeOptimalTrajectory(
    path, pathLengths,
    minMaxVel=[-0.5, 0.5] * 6,
    minMaxAccel=[-0.5, 0.5] * 6,
    trajPtSamples=1000)

# 按 times 逐点驱动关节（或交给 moveToConfig 跟踪）
```

## 要点速记

- **路径对象**存储在 `customData.PATH` / `customData.PATHCTRLPTS`，7 维位姿序列，行优先。
- **路径长度只看笛卡尔前 3 维**，与方向无关；用弧长定位比线性索引更贴合真实运动。
- **Ruckig 是 4.10 在线轨迹生成首选**；Reflexxes（RML）的 `rml*` 函数已废弃，改用 `moveToConfig`/`moveToPose`。
- **moveToConfig 阻塞式**，必须在 thread 脚本调用；非 thread 用 `_init/_step/_cleanup` 三段式。
- **TOPPRA（generateTimeOptimalTrajectory）离线参数化整条路径**，与 Ruckig 在线即时生成互补。
- `sim.getConfigDistance` 配合自定义 metric 和 types 数组，可定义构型空间距离——OMPL 与路径函数共用此语义。
