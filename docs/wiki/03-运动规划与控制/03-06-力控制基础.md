# 力控制基础

> CoppeliaSim 中力/力矩控制的核心思路：force sensor 读力、关节 force 控制模式施加力、阻抗控制用虚拟弹簧阻尼柔顺接触、力位混合在约束方向分工、接触回调逐碰撞定制响应。

## 适用场景

- **装配接触**：轴孔配合、对接、插装——末端在受限方向上推入，需根据反力调整位移，避免硬挤。
- **柔顺操作**：打磨、去毛刺、擦拭——工具需以恒定法向力贴合曲面，位置由几何给定、力由控制修正。
- **人机协作**：机械臂被推时顺应退让，靠阻抗/导纳控制实现安全交互。
- **抓取力限**：夹爪以目标力闭合，避免捏碎脆性工件。

核心区别：纯位置控制在有模型误差或刚性环境时会产生极大接触力；力控制引入力反馈，使末端在接触方向"软"下来。

## force sensor 读力

force sensor 是两个 shape 之间的刚性链接，能测量所传递的力与扭矩。仿真期间需动态启用（dynamically enabled）才有读数。`sim.readForceSensor` 返回过滤后的 3 元素力向量与 3 元素扭矩向量。

```python
from coppeliasim_zmqremoteapi_client import RemoteAPIClient

client = RemoteAPIClient()
sim = client.require('sim')

fs = sim.getObject('/robot/attachmentForceSensor')
result, force, torque = sim.readForceSensor(fs)
# result bit 0 = 1 表示数据可用
# force = [fx, fy, fz]（沿传感器 x/y/z 轴，单位 N）
# torque = [tx, ty, tz]（绕传感器 x/y/z 轴，单位 N·m）
if result & 1:
    fz = force[2]  # 法向接触力
    print(f'法向力 fz = {fz:.2f} N')
```

**原始值（raw value）**：默认每个仿真步内部有 10 个动力学子步，`sim.readForceSensor` 默认返回滤波后的值。若要读取每个动力学子步的原始值，把 `sim.handleflag_rawvalue` 加到句柄上传入；但原始值只能在物理引擎触发的回调函数内访问。普通控制循环里用过滤值即可。

关节也能测力，但仅沿其 z 轴：`sim.getJointForce(jointHandle)` 返回该关节沿/绕 z 轴的力或扭矩，且仅当关节为 prismatic/revolute 且动态启用时才有意义。

## 关节力控制

关节动力学对话框提供多种控制模式，其中：

| 模式 | 含义 | 调制 API |
|------|------|-----------|
| Free | 不电机化，自由运动 | — |
| **Force/torque control** | 施加恒定力/扭矩，可调制 | `sim.setJointTargetForce` |
| Velocity control | 以指定力推到目标速度 | `setJointTargetVelocity` + `setJointTargetForce` |
| Position control | 力调制下趋近目标位置 | `setJointTargetPosition` + `setJointTargetForce` |
| **Spring-damper control** | 用 KC 控制器趋近零位移位置 | `setJointTargetPosition` + 关节属性 |
| Custom control | 调用 joint callback function 自定义力与目标速度 | 用户回调 |

Force/torque 模式下，`sim.setJointTargetForce(handle, forceOrTorque, signedValue=True)` 设定关节可施加的最大力/扭矩；`signedValue` 为 True 时，符号表示期望运动方向。这是力控制装配的基础：直接给关节一个推力，让末端在受限方向上"柔性"挤入，由 force sensor 反馈决定何时减小或反向。

```python
# 关节 force 控制示例：给 prismatic 关节恒定推力
j = sim.getObject('/robot/pushJoint')
sim.setJointTargetForce(j, 5.0, True)  # 5 N，正方向推
```

## 阻抗控制概念

阻抗控制让末端表现为一个"虚拟弹簧-阻尼"系统，对外力产生柔顺响应：

$$
M \ddot{x} + B \dot{x} + K (x - x_0) = F_{\text{ext}}
$$

- $K$：虚拟刚度（弹簧），决定位置偏离时产生的回复力大小；
- $B$：虚拟阻尼，抑制振荡；
- $M$：虚拟惯性；
- $x_0$：期望位置轨迹。

环境接触力 $F_{\text{ext}}$ 由 force sensor 测得。接触时，末端实际位置 $x$ 与期望 $x_0$ 的偏差通过 $K$、$B$ 生成期望输出力，再由关节 force 模式施加。调节 $K$ 越小越"软"，越大越接近位置控制；$B$ 过小会振，过大会黏滞。

CoppeliaSim 没有内置"阻抗控制"模块，但提供了拼装它的所有元件：force sensor 读 $F_{\text{ext}}$、关节 force/torque 模式施力、自定义回调里写控制律。下例演示一个单步阻抗控制循环。

## 力位混合控制

力位混合（hybrid force/position control）将任务空间按约束方向分解：

- **力控方向**（法向，如沿曲面法线）：用力环控制——force sensor 反馈使法向力跟踪期望值；
- **位置方向**（切向，如沿曲面滑动）：用位置环控制——IK 或位置模式跟踪轨迹。

用选择矩阵 $S$ 标记哪些自由度走力控、哪些走位置控。装配轴孔时，轴向用力控推入、径向用位置控对中，正是力位混合的典型应用。

## 接触回调获取接触信息

当物理引擎检测到两个 respondable shape 之间的碰撞时，会调用脚本中的 `sysCall_contact` 回调，传入碰撞双方句柄、引擎、接触点等，允许逐接触定制摩擦/恢复/忽略等行为。该回调可能在一个仿真步内被调用上百次，必须保持轻量。

```python
# Python 脚本对象内
def sysCall_contact(inData):
    # inData["handle1"], inData["handle2"] 为碰撞双方
    # inData["engine"] = sim.physics_bullet / _ode / _mujoco / _vortex / _newton
    retData = {}
    retData["ignoreContact"] = False        # 设 True 则引擎忽略此接触
    retData["collisionResponse"] = True     # 设 False 则双方不弹开（穿过）
    if inData["engine"] == sim.physics_newton:
        retData["newton"] = {}
        retData["newton"]["staticFriction"] = 0.5
        retData["newton"]["kineticFriction"] = 0.3
        retData["newton"]["restitution"] = 0.0  # 无反弹，装配接触常用
    return retData
```

接触回调虽非直接的"力控"，但通过调整摩擦与碰撞响应，可稳定接触力（避免弹跳、减小粘滑），是力控装配场景的常用辅助。

## 阻抗控制单步示例

下面是一个在 stepping 模式下、每个动力学步推进一次的阻抗控制循环（ZMQ Remote API 视角，契合本仓库用法）。

```python
from coppeliasim_zmqremoteapi_client import RemoteAPIClient

client = RemoteAPIClient()
sim = client.require('sim')

# 句柄
fs = sim.getObject('/robot/wristForceSensor')   # 末端力传感器
joint = sim.getObject('/robot/pushJoint')      # prismatic/revolute 关节，force 模式

# 阻抗参数（SI 单位）
K = 200.0   # 虚拟刚度 N/m
B = 20.0    # 虚拟阻尼 N·s/m
M = 1.0     # 虚拟惯性 kg
x0 = 0.0    # 期望位置（0 = 当前）
x_prev = 0.0
v_prev = 0.0

# 启用 stepping：Python 为时钟主导者
sim.setStepping(True)
sim.startSimulation()

dt = sim.getSimulationTimeStep()  # 仿真步长（秒），默认 0.05
for _ in range(200):
    result, force, _ = sim.readForceSensor(fs)
    if not (result & 1):
        sim.step()
        continue

    # 读取当前关节位置与速度
    x = sim.getJointPosition(joint)
    v = sim.getObjectVelocity(joint)[0]  # 沿关节轴速度

    # 阻抗控制律：M*x_dd + B*x_d + K*(x - x0) = F_ext
    # 解出期望加速度，再积分得期望速度，转为推力（简化版：直接用力反馈）
    f_ext = force[2]  # 法向接触力（按传感器朝向调整符号）

    # 期望力 = -K*(x - x0) - B*v + f_ext  （环境力作为前馈）
    f_desired = -K * (x - x0) - B * v + f_ext
    # 限幅保护
    f_desired = max(-50.0, min(50.0, f_desired))

    sim.setJointTargetForce(joint, f_desired, True)
    sim.step()  # 推进一个仿真步（内部含若干动力学子步）

sim.stopSimulation()
```

> 注：上例为概念演示。实际阻抗控制需考虑传感器坐标系到关节坐标系的映射、重力补偿、低通滤波力信号（避免噪声微分放大）。$K$、$B$ 需按具体质量与刚度整定。

## 为何力控制须 stepping 且 dt = 动力学步长

力控制本质上是闭环控制：每一步根据当前力/位置误差计算下一步施力。CoppeliaSim 有两层时间：

- **仿真步（simulation step）**：默认 0.05 s，由 `sim.setStepping(True)` + `sim.step()` 手动推进，Python 端为时钟主导者；
- **动力学子步（dynamic sub-step）**：每个仿真步内部默认分 10 个动力学子步，物理引擎在每个子步积分接触/约束力。

力控制循环必须锁在仿真步级别（stepping 模式），原因有三：

1. **同步性**：`sim.readForceSensor` 的过滤值在每个仿真步末刷新，`sim.setJointTargetForce` 在下一仿真步生效；非 stepping 时仿真自走，控制律与物理步不同步，力环会漂移或发散。
2. **确定性**：stepping 下每个 `sim.step()` 推进固定 `dt`，控制律的 $K$、$B$、$dt$ 三者构成可分析的离散系统；自走模式下帧率波动，整定参数无意义。
3. **原始值定位**：若需读取每个动力学子步的原始力（`sim.handleflag_rawvalue`），只能在物理引擎触发的回调内访问——这进一步要求仿真以 stepping 方式受控运行，便于在回调中插入高带宽力处理。

简言之：**stepping 让力控环的 $dt$ 与物理引擎的动力学步长一致，控制律才能稳定整定**。这也是本仓库 v1 运行器以 `sim.setStepping(True)` + 每 `SIM_STEP` 固定节拍驱动全部控制逻辑的设计依据（详见 [[wiki/00-基础知识/00-01-CoppeliaSim-overview]]）。

## 设计注意事项（来自官方动力学设计指南）

- **质量相近**：用动态启用关节或 force sensor 连接两 shape 时，质量比应满足 $m_1 < 10 m_2$ 且 $m_2 < 10 m_1$，否则连接会过软、抖动；极轻 shape 即使大力电机也发不出大力。
- **避免静态 shape 夹在动态链中间**：会切断动态链逻辑行为，力控连接失效。
- **力控末端用 primitive shape**：非原始 shape（三角网格）在接触时计算慢且不稳，力信号会抖。
- **force sensor 阈值**：力/扭矩超阈值时 force sensor 会"断裂"，力控装配时要确保阈值高于正常工作力上限。
