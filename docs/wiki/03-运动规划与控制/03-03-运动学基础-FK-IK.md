# 运动学基础 — FK 与 IK

> CoppeliaSim 的运动学功能由 **Coppelia Kinematics Routines**（一组 C++ 函数，经 kinematics 插件暴露）提供，支持 IK 与 FK 两类问题，并在独立的 IK 环境中求解，与动力学等其他仿真层面分离。本文以官方手册 kinematics.htm / solvingIkAndFk.htm 为准，梳理 FK/IK 问题定义、IK group/element 结构、约束、求解方法与求解顺序依赖。

## 一、FK vs IK：问题定义

| | 正运动学 Forward Kinematics (FK) | 逆运动学 Inverse Kinematics (IK) |
|---|---|---|
| 输入 | 关节值（线/角位置） | 末端位姿（位置/姿态） |
| 输出 | 末端位姿 | 关节值 |
| 方向 | 关节空间 → 任务空间 | 任务空间 → 关节空间 |
| 难度 | 通常较易（多为矩阵链相乘） | 通常较难，可能多解/无解/奇异 |
| 典型用途 | 已知指令角推末端位置 | 让末端跟随目标位姿反算关节角 |

⚠ 注意：FK 并非总比 IK 简单。手册给出反例——某些闭链/并联机构中，给定关节值求末端位姿反而是非平凡问题。因此不要把"FK 一定简单"当作公理。

- **IK 问题**：给定某末端构件（end effector）期望的位置/姿态，求满足条件的各关节值。对串联机械臂即"已知末端位姿，求各关节角"。
- **FK 问题**：上述问题的逆——给定关节值，求末端位姿。

## 二、IK group 与 IK element

CoppeliaSim 用两层结构描述一个 IK 任务：

```
IK group  ── 含 1 个或多个 IK element
             │
             └── IK element = base + links + joints + tip + target
                              （一条简单运动链）
```

### IK element（简单运动链）

一个 IK element 表示**一条至少含一个关节的简单运动链**，由下列部件组成：

| 部件 | 说明 |
|------|------|
| **base** | 运动链起点（参考系）。位置约束默认相对 base 参考系。 |
| **links** | 任意非关节对象（包括被当作刚性关节的 passive joint，即线/角位置固定的关节）。 |
| **joints** | 至少一个关节。 |
| **tip** | 链末端对象，通常即 end effector。**必须**链接到一个 target。 |
| **target** | tip 要跟随的目标对象，表示期望的 tip 位置/姿态。**必须**链接到 tip。 |

IK element 描述的是一个"裸雅可比"（naked Jacobian）：**行 = 约束数，列 = 自由度**。

### IK group（求解单元）

- 一个 IK group 含一个或多个 IK element。
- IK group 设置**整体求解属性**：求解方法、迭代次数等。
- IK group 的雅可比 = 将其各 IK element 的雅可比**水平拼接**（horizontal stacking）得到。
- 即便最简单的单链 IK 任务，也是通过求解其所在的 IK group 完成的。

### 约束（tip-target 之间的跟随方式）

求解 IK element 的目标：在给定约束与容差下，让 tip 与 target 重叠。约束类型：

**位置约束**（默认相对 base 参考系，也可选任意参考系）：
- **X 位置约束**：tip 仅沿 X 轴跟随 target。示例 2D 链因此有 3 个自由度，对该任务呈冗余。
- **X/Y 位置约束**：tip 仅跟随 target 位置（不跟姿态）。链仍冗余。
- **X/Y 位置 + 姿态约束**：tip 同时跟位置和姿态，链不再冗余。

**姿态约束**（自由度从 3 到 0）：
| 类型 | 约束 | 自由度 |
|------|------|--------|
| 全姿态 (full) | alpha-beta-gamma | 3 |
| 部分 3D | alpha-beta（仅 tip 与 target 的 z 轴重合） | 2 |
| 部分 2D | gamma | 1 |
| 关闭 | 无姿态约束 | 0 |

## 三、冗余性与过约束

- **冗余（redundant）**：当运动链自由度多于约束数，链对当前任务呈冗余，存在零空间（null-space），可用零空间投影实现次级目标（如避障、避奇异）。
- **过约束（overconstrained）**：约束数多于自由度时，元素过约束。**必须**检查各 IK element 是否过约束，否则会出现异常行为。
- **奇异性（singularity）**：接近奇异位形或过约束无法避免时，**阻尼最小二乘法**可稳定求解，代价是收敛变慢、计算变慢。

## 四、求解方法

IK group 的求解方法（`simIK.setGroupCalculation`）：

| 方法 | 特点 |
|------|------|
| **雅可比伪逆** (pseudo_inverse, undamped) | 无阻尼，收敛快但对奇异/不可达敏感，失败时返回非 success。手册示例中先用它求解。 |
| **阻尼最小二乘** (damped_least_squares) | 加阻尼项，奇异/不可达时更稳定，但收敛变慢、阻尼越大越慢。手册示例在无阻尼失败后回退到此法。 |
| **零空间投影** (null-space projection) | 求解多个 IK element 同时满足优先级层次（prioritization hierarchy），或通过 dependency constraint 联动多个关节实现复杂行为。 |

典型策略（手册教程）：**先试无阻尼伪逆，失败再回退阻尼最小二乘**，以保证鲁棒性。

## 五、求解顺序依赖

多个 IK group / element 的求解顺序并非总无关：

### 1. 两条独立链
两链互不依赖时，两个 IK group 的求解顺序**无关**。

### 2. 依赖链（target 附着在另一链的运动件上）
若链 2 的 target 附着在链 1 的可动部分上，则链 1 求解会移动链 2 的 target，**求解顺序相关**——必须**先解 IK group 1，再解 IK group 2**。

### 3. 共享 link 但不共享 joint
一个 IK element 建在另一个之上且不共享关节时，求解顺序也相关：**先解 element 1**（会移动公共对象），再解 element 2（不会反向移动公共对象）。对应必须**先 IK group 1 后 IK group 2**。

### 4. 共享 joint —— 需同组同时求解
两条或多条链**共享关节**时，顺序求解通常失败，必须用**同时求解**：把这些 IK element 放进**同一个 IK group**，IK group 会将它们的雅可比水平拼接后联立求解。

## 六、Debug overlay

调试 IK 时，可开启表示 IK world 内容的 debug overlay：

- **[Tools > Visualize IK world]**：显示 IK 环境中的 base / tip / target / 约束等，便于核对链结构与约束是否正确。

## 七、代码示例：用 simIK 从场景对象构建 IK 链

以下为手册教程（inverseKinematicsTutorial.htm）给出的 Python 脚本，适用于 4.10，挂在机械臂基座对象的 simulation script 上。它演示"简单方式"——用 `simIK.addElementFromScene` 直接从场景对象构建 IK element，并建两个 IK group（无阻尼 + 阻尼）做回退求解。

```python
#python
def sysCall_init():
    sim = require('sim')
    simIK = require('simIK')
    simBase = sim.getObject('..')
    simTip = sim.getObject('../redundantRob_tip')
    simTarget = sim.getObject('../redundantRob_target')

    # 创建 IK 环境
    self.ikEnv = simIK.createEnvironment()

    # 无阻尼 IK group
    self.ikGroup_undamped = simIK.createGroup(self.ikEnv)
    simIK.setGroupCalculation(self.ikEnv, self.ikGroup_undamped,
                              simIK.method_pseudo_inverse, 0, 6)
    # 基于场景内容直接添加 IK element，约束为 pose（位置+全姿态）
    simIK.addElementFromScene(self.ikEnv, self.ikGroup_undamped,
                             simBase, simTip, simTarget, simIK.constraint_pose)

    # 阻尼 IK group（回退用）
    self.ikGroup_damped = simIK.createGroup(self.ikEnv)
    simIK.setGroupCalculation(self.ikEnv, self.ikGroup_damped,
                              simIK.method_damped_least_squares, 1, 99)
    simIK.addElementFromScene(self.ikEnv, self.ikGroup_damped,
                             simBase, simTip, simTarget, simIK.constraint_pose)

def sysCall_actuation():
    # 先试无阻尼；失败则回退阻尼
    res, *_ = simIK.handleGroup(self.ikEnv, self.ikGroup_undamped, {'syncWorlds': True})
    if res != simIK.result_success:
        simIK.handleGroup(self.ikEnv, self.ikGroup_damped, {'syncWorlds': True})
        sim.addLog(sim.verbosity_scriptwarnings, "IK solver failed.")

def sysCall_cleanup():
    simIK.eraseEnvironment(self.ikEnv)
```

对应 Lua 版（核心一致，仅语法差异）：

```lua
--lua
function sysCall_init()
    sim = require('sim')
    simIK = require('simIK')
    local simBase = sim.getObject('..')
    local simTip = sim.getObject('../redundantRob_tip')
    local simTarget = sim.getObject('../redundantRob_target')

    ikEnv = simIK.createEnvironment()
    ikGroup_undamped = simIK.createGroup(ikEnv)
    simIK.setGroupCalculation(ikEnv, ikGroup_undamped, simIK.method_pseudo_inverse, 0, 6)
    simIK.addElementFromScene(ikEnv, ikGroup_undamped, simBase, simTip, simTarget, simIK.constraint_pose)

    ikGroup_damped = simIK.createGroup(ikEnv)
    simIK.setGroupCalculation(ikEnv, ikGroup_damped, simIK.method_damped_least_squares, 1, 99)
    simIK.addElementFromScene(ikEnv, ikGroup_damped, simBase, simTip, simTarget, simIK.constraint_pose)
end

function sysCall_actuation()
    if simIK.handleGroup(ikEnv, ikGroup_undamped, {syncWorlds = true}) ~= simIK.result_success then
        simIK.handleGroup(ikEnv, ikGroup_damped, {syncWorlds = true})
        sim.addLog(sim.verbosity_scriptwarnings, "IK solver failed.")
    end
end

function sysCall_cleanup()
    simIK.eraseEnvironment(ikEnv)
end
```

### "精细方式"要点

手册同时给出精细方式（手动在 IK 环境中逐个创建 dummy/joint、设矩阵、设父子、设 target-tip 链接、`addElement`+`setElementBase`+`setElementConstraints`），关键 API：

- `simIK.createEnvironment()` — 建独立 IK 环境。
- `simIK.createDummy(ikEnv)` / `simIK.createJoint(ikEnv, simIK.jointtype_revolute)` — 在 IK 环境中创建对象。
- `simIK.setObjectMatrix(ikEnv, ikObj, -1, sim.getObjectMatrix(simObj))` — 把场景对象的位姿同步到 IK 环境的对应对象。
- `simIK.setObjectParent(ikEnv, ikChild, ikParent, true)` — 在 IK 环境中搭运动链父子关系。
- `simIK.setTargetDummy(ikEnv, ikTip, ikTarget)` — 链接 tip 与 target。
- `simIK.addElement(ikEnv, ikGroup, ikTip)` → 返回 element handle → `simIK.setElementBase(...)` / `simIK.setElementConstraints(...)`。
- 求解循环：`simIK.setObjectMatrix(ikEnv, ikTarget, ikBase, sim.getObjectMatrix(simTarget, simBase))` 同步 target → `simIK.handleGroup` → `sim.setJointPosition(simJoint, simIK.getJointPosition(ikEnv, ikJoint))` 把算得的关节角回写到场景关节。

### 与本仓库的关系

本仓库（cop-test）的机械臂动画由 Python 端关键帧插值驱动（见 v1 `simulation/unit_controller`），**不依赖** IK 求解或模型自带脚本；CoppeliaSim 的 IK 功能主要用于需要末端跟随目标位姿的场景。若需在仿真中实时求 IK，可参照上方脚本在 simulation script 中调用 simIK，或通过 ZMQ Remote API 触发 `sim.checkIkGroup` / `sim.getConfigForTipPose`（对应待建 API 条目 [[wiki/01-API参考/api/api-simCheckIkGroup]]、[[wiki/01-API参考/api/api-simGetConfigForTipPose]]）。
