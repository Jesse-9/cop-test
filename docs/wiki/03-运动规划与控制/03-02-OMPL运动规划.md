# OMPL 运动规划 (simOMPL)

## 定位

**simOMPL** 是 CoppeliaSim 内置的运动规划插件，封装了开源的 [OMPL 库](http://ompl.kavrakilab.org/)（Open Motion Planning Library），在场景中为机器人提供**基于采样的全局避障路径规划**。插件由 Federico Ferri 贡献，源码托管于 [CoppeliaRobotics/simOMPL](https://github.com/CoppeliaRobotics/simOMPL)。

其核心职责是：给定机器人的**状态空间**、**起止状态**与**碰撞约束**，调用 OMPL 的随机化规划算法搜索一条从起点到目标的**无碰撞状态路径**（一组离散状态序列）。手册原文将 `simOMPL.compute` 等价于 `solve → simplifyPath → interpolatePath → getPath` 四步的组合。

## 核心概念

### Task（任务对象）
任务对象是 simOMPL 的顶层容器，由 `simOMPL.createTask(name)` 创建，返回字符串句柄。一个任务承载一次规划问题的全部信息：
- 状态空间（state spaces）的组合
- 碰撞对（collision pairs），供默认状态合法性检查使用
- 起始状态与目标（目标状态 / Dummy 对 / 回调）
- 各类回调（投影、状态校验、目标判定、有效状态采样）
- 选定的规划算法

仿真期间创建的任务与状态空间在仿真结束时自动销毁；也可手动 `destroyTask` / `destroyStateSpace`。

### State Space（状态空间）
状态空间描述机器人配置的维度与边界，由若干**分量**组合而成。`simOMPL.createStateSpace` 创建单个分量，`simOMPL.setStateSpace` 将多个分量挂到任务上。手册定义的状态空间类型（`simOMPL.StateSpaceType`）：

| 类型 | 说明 | objectHandle 要求 |
|------|------|------|
| `joint_position` | 关节位置（最常用，非循环关节） | 关节对象 |
| `cyclic_joint_position` | 循环关节位置（如无限旋转关节） | 关节对象 |
| `position2d` / `position3d` | 2D / 3D 位置空间 | 形状对象 |
| `pose2d` / `pose3d` | 2D / 3D 位姿空间（位置+朝向） | 形状对象 |
| `dubins` | Dubins 曲线空间（车辆式运动），需配合 `setDubinsParams` 设转弯半径与对称性 | 形状对象 |

便捷函数 `createStateSpaceForJoint` 与 `setStateSpaceForJoints` 封装了关节空间的创建，避免手动逐个构造。`createStateSpace` 的 `boundsLow`/`boundsHigh` 设定各维边界（pose 类型只指定位置 3 分量），`useForProjection` 标记该分量是否参与默认投影（用于 OMPL 内部可视化与某些算法），`weight` 影响状态间距离计算，`refObjectHandle` 指定位置/朝向的参考系（默认绝对系）。

### State Validation（状态合法性）
默认情况下，simOMPL 通过 `setCollisionPairs` 设置的碰撞对进行碰撞检测来判定状态是否合法。也可用 `setStateValidationCallback` 注入自定义校验逻辑（任意约束，不限于碰撞）。`setStateValidityCheckingResolution` 设定状态校验分辨率（默认 0.01，即状态空间范围的 1%）。

`setCollisionPairs` 接受一个句柄列表，每两个元素构成一对（collider, collidee）。collidee 可为 `sim.handle_all`，表示 collider 与场景中所有可碰撞对象检测。碰撞检测的底层机制见 [[wiki/02-仿真建模/02-12-碰撞检测与距离计算]]。

### Algorithm（规划算法）
`setAlgorithm` 选定搜索算法，**默认为 KPIECE1**。手册列出的全部算法（`simOMPL.Algorithm`）：

- **RRT 族**：`RRT`、`RRTConnect`（双向，通用首选）、`RRTstar`（渐近最优）、`LazyRRT`、`TRRT`、`BiTRRT`、`LBTRRT`
- **PRM 族**（多查询）：`PRM`、`PRMstar`、`LazyPRM`、`LazyPRMstar`
- **其他**：`KPIECE1`（默认）、`BKPIECE1`、`LBKPIECE1`、`EST`、`FMT`、`BITstar`、`CForest`、`PDST`、`SBL`、`SPARS`、`SPARStwo`、`STRIDE`

> 大部分算法是随机的，不保证最短路径；`RRTstar`/`PRMstar` 等为**优化型规划器**，会在剩余时间内持续改进首条解，提供渐近最优性。多查询规划器（PRM 族）在多次 `compute` 间复用已建路标图。

## 典型 API 速查

| 函数 | 作用 |
|------|------|
| `createTask(name)` / `destroyTask` | 创建 / 销毁任务 |
| `createStateSpace` / `setStateSpace` | 创建状态空间分量 / 挂载到任务 |
| `createStateSpaceForJoint` / `setStateSpaceForJoints` | 关节空间便捷封装 |
| `setCollisionPairs` | 设置碰撞对（默认状态校验） |
| `setStateValidationCallback` | 自定义状态合法性回调 |
| `setStateValidityCheckingResolution` | 状态校验分辨率（默认 0.01） |
| `setAlgorithm` | 选定算法（默认 KPIECE1） |
| `setStartState` / `setGoalState` / `addGoalState` / `setGoalStates` | 设起始 / 目标状态 |
| `setGoal` | 以 Dummy 对指定目标位姿（含容差与度量） |
| `setGoalCallback` / `setProjectionEvaluationCallback` / `setValidStateSamplerCallback` | 各类回调 |
| `setup` | 初始化 OMPL 内部数据结构（compute 前调用） |
| `solve(task, maxTime)` | 单步搜索，返回是否找到解 |
| `simplifyPath` / `interpolatePath` | 路径简化 / 插值到指定状态数 |
| `compute(task, maxTime, maxSimplificationTime, stateCnt)` | 一站式：solve + simplify + interpolate + getPath |
| `getPath` / `getPathState` / `getPathStateCount` / `getReversedPath` | 取路径 / 取第 i 个状态 / 状态数 / 反转路径 |
| `hasSolution` / `hasExactSolution` / `hasApproximateSolution` / `getGoalDistance` | 解判定与距离查询 |
| `readState` / `writeState` / `isStateValid` / `isStateWithinBounds` / `enforceBounds` | 状态读写与边界操作 |
| `drawPath` / `drawPlannerData` / `removeDrawingObjects` | 路径与规划图可视化 |
| `getPlannerData` | 取规划器内部搜索图（顶点+边） |

## 规划流程

手册 `pathAndMotionPlanningModules.htm` 给出的标准步骤：

1. **确定起止状态**。串联机械臂常给末端位姿而非关节状态，先用 `simIK.findConfigs` 求满足目标位姿的关节配置作为目标状态。
2. `createTask` 建任务。
3. `setAlgorithm` 选算法。
4. `createStateSpace` + `setStateSpace` 构造状态空间（可复合）。
5. `setCollisionPairs` 声明禁止碰撞的对象对。
6. `setStartState` / `setGoalState`（或 `setGoal` 用 Dummy 对）。
7. `setup` 一次性初始化 OMPL 数据结构。
8. `compute` 求解（可多次调用，多查询规划器复用已有数据）。
9. `getPath` 取路径；`drawPath` 可视化。
10. `destroyTask` 销毁。

进阶：若默认流程不够灵活，可注入 `setStateValidationCallback`（自定义合法性）、`setProjectionEvaluationCallback`（自定义投影，配合 `projectionSize`）、`setGoalCallback`（自定义目标判定，返回是否满足与到目标距离）、`setValidStateSamplerCallback`（自定义有效状态采样，含 near 变体）。

## Python ZMQ 示例：UR5 避障路径规划骨架

```python
# 适用 CoppeliaSim 4.10 + ZMQ Remote API
from coppeliasim_zmqremoteapi_client import RemoteAPIClient

client = RemoteAPIClient()
sim = client.require('sim')
simOMPL = client.require('simOMPL')

# 1. 采集 UR5 六个关节
joints = [sim.getObject(f'/UR5/joint{i}') for i in range(1, 7)]

# 2. 建任务并选算法
task = simOMPL.createTask('ur5_plan')
simOMPL.setAlgorithm(task, simOMPL.Algorithm.RRTConnect)

# 3. 关节状态空间（便捷封装，自动建 6 个 joint_position 分量）
simOMPL.setStateSpaceForJoints(task, joints)

# 4. 碰撞对：机器人本体各形状可简化为一个 collection，
#    与场景中所有可碰撞对象检测。此处用 handle_all 示意。
robot_collection = sim.createCollection(0)  # 实际使用时用 sim.addToCollection 填充
simOMPL.setCollisionPairs(task, [robot_collection, sim.handle_all])

# 5. 起止状态（6 维，单位 rad）
start = [sim.getJointPosition(j) for j in joints]
goal  = [0.5, -0.8, 1.2, 0.0, 0.5, 0.0]
simOMPL.setStartState(task, start)
simOMPL.setGoalState(task, goal)

# 6. 初始化并求解
simOMPL.setup(task)
solved, path = simOMPL.compute(task, maxTime=5.0, maxSimplificationTime=-1.0, stateCnt=0)

if solved:
    n = simOMPL.getPathStateCount(task, path)
    print(f'规划成功，{n} 个路径点')
    # 逐状态执行（实际应配合轨迹时间参数化，见 03-05）
    for i in range(n):
        state = simOMPL.getPathState(task, path, i)
        for j, joint in enumerate(joints):
            sim.setJointTargetPosition(joint, state[j])
        # 简单步进；生产环境改为插值 + 速度限制
        sim.step()
else:
    approx = simOMPL.hasApproximateSolution(task)
    print(f'未找到精确解，近似解={approx}')

simOMPL.destroyTask(task)
```

> 注：`compute` 的 `maxSimplificationTime=-1` 走默认简化流程；`stateCnt=0` 走默认插值行为。若需更细粒度，可拆成 `solve → simplifyPath → interpolatePath(stateCnt) → getPath`。

## 与其他路径方法的区别

- **vs `simIK.generatePath`**：`simIK.generatePath` 生成的是 IK 层面的直线段路径（适合末端接近段的直线进给）；simOMPL 做的是关节空间的全局随机化避障规划。手册建议两者配合：OMPL 规划长距离避障段，`simIK.generatePath` 生成末端最终直线接近段。
- **vs `sim.moveToConfig` / `sim.moveToPose`**：MoveTo 系列是局部平滑插值（样条/抛物线混合），不感知障碍；OMPL 是全局规划，显式避开碰撞对。典型工业流程是 OMPL 出离散路径 → 插值平滑 → MoveTo/轨迹跟踪执行。
- **vs 路径对象（Path object）**：路径对象是 3D 位姿数据点序列的可视化容器（见 [[wiki/02-仿真建模/02-05-路径-Path]] 与 [[wiki/03-运动规划与控制/03-05-轨迹与路径规划模块]]），可存储 OMPL 输出但本身不做规划。

## 性能与调试建议

- 简化碰撞几何：用基本体代替网格，降低单次状态校验成本。
- 默认校验分辨率 0.01 偏保守，窄通道场景可适当调高以加速，但可能漏检。
- 规划失败时用 `printTaskInfo` 打印任务摘要排查；`hasApproximateSolution` / `getGoalDistance` 判断是否近似解与接近度。
- `drawPlannerData` 可绘制规划器内部搜索图（顶点+边），辅助调参。
- 多查询场景（同环境多次规划）优先 PRM 族，复用路标图。
