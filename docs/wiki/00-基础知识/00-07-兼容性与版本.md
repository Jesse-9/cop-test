# 兼容性与版本

> CoppeliaSim 采用敏捷开发，版本更新频繁。本条目以官方手册为准，梳理版本号规则、主要版本的向后/向前兼容性要点、legacy 项的废弃轨迹，以及 legacy remote API 的废弃定位。

## 版本号规则

版本号格式为 `Version X.Y.Z (rev. W)`（依 `versionInfo.htm`）：

- **X**：特别发布（约每两年一次）
- **Y.Z**：常规发布
- **W**：修订号（主要用于 bug 修复）

## 兼容性要点（依 `compatibility.htm`）

CoppeliaSim 由小团队以敏捷方式开发，更新频繁、修复快速，偶尔可能引入问题。用户反馈（论坛 bug 报告）是识别与解决问题的重要途径。以下为几项关键兼容性话题。

### V4.7 引入 script objects

- **向前兼容**：旧的 associated scripts 仍可运行，但建议转为 script objects；自动转换不完美，可能需手动调整
- **向后兼容**：含 script objects 的场景/模型可转回只含 associated scripts 的形式——设置用户设置参数 `scriptConversion = -1`；但相关脚本代码不被此转换触碰，需手动调整。若 script objects 出现严重问题，可设 `useSceneObjectScripts = false` 回退到旧 associated scripts

### V4.7 引入 buffers

为区分二进制数据引入 buffer 类型，潜在破坏现有代码：

- 依赖 `type()` 判断字符串的代码会失效（buffer 不等于 string）
- 明确返回二进制的 API（如 `sim.getVisionSensorImg`）现在返回 buffer，与字符串比较恒为 false
- `sim.packTable` 返回的 buffer 长度与旧版不同（text/string 与 buffer 被区分，反映在 packed 数据中）

**变通方法**：

- 用 `tostring` 把 buffer 转字符串后再传给不识别 buffer 的代码库
- buffer 与 string 比较时，先用 `tostring` 或 `tobuffer` 转换其一，否则恒为 false
- 在用户设置中用 `useBuffers` 变量可禁用 buffer

**向后兼容**：旧版不识别 `isbuffer`/`tobuffer`。变通：在 `lua/base.lua`（或 `lua/sim.lua`，或特定脚本）加：

```lua
function tobuffer(a)
    return a
end
function isbuffer(a)
    return false
end
```

### 其他常见弃用（跨版本汇总）

- V4.2：Lua 5.1 → 5.3，旧 Lua 模块需更新
- V4.2：静态 IK groups / collision objects / distance objects / graph streams & curves（GUI 创建）弃用，改为 API 动态创建
- V4.6：`sim.setThreadAutomaticSwitch` → `sim.setStepping`；`sim.switchThread` → `sim.step`；新插件架构（需显式 `require`）
- V4.7：deprecated 函数被调用时会输出一次简短告警；告警冗长度可由用户设置 `notifyDeprecated`（0=无/1=简单默认/2=详尽）控制
- V4.4：legacy remote API 弃用，改用 ZeroMQ remote API

## Legacy Remote API 的定位

Legacy remote API 自 **V4.4 起弃用**，改用 ZeroMQ remote API（依 `legacyRemoteApiOverview.htm`）。

Legacy remote API 允许从外部应用或远程硬件（真实机器人、远程计算机等）控制仿真或仿真器本身。它由约 100 个专用函数加 1 个通用函数组成，可从 C/C++、Python、Java、Matlab/Octave 调用，经 socket 通信（或可选共享内存）与 CoppeliaSim 交互，对用户透明。支持 stepping（与每个仿真步同步）或 non-stepping（常规模式）方式，甚至支持远程控制仿真器（远程加载场景、启停仿真等）。

Legacy remote API 由两个经 socket 交互的实体组成：

- **客户端（你的应用）**：支持 C/C++、Python、Java、Matlab、Octave
- **服务端（CoppeliaSim）**：经插件实现，CoppeliaSim 默认加载 `simExtRemoteApi.dll`/`libsimExtRemoteApi.dylib`/`libsimExtRemoteApi.so`

新项目应使用 ZeroMQ remote API（见 [[wiki/01-API参考/01-02-Remote-API-ZMQ]]），它轻量、易用，且支持与脚本完全相同的 API 函数（含所有 `sim.*` 常规 API 及各插件 API 如 `simOMPL.*`/`simIK.*`/`simUI.*`）。legacy 与 ZMQ 远程 API 对比详见 [[wiki/05-数字孪生与协同仿真/05-05-B0与Legacy远程API]]。

## 迁移建议

- 新代码一律用 ZMQ remote API + script objects + buffers，不引入 legacy remote API 与 associated scripts
- 旧脚本迁移到 V4.10 时，优先把 associated scripts 转为 script objects，并检查 buffer 相关比较
- 用 `notifyDeprecated=2` 临时打开详尽弃用告警，定位所有 deprecated 调用，逐项替换
- 单位与 API 行为以 [[wiki/01-API参考/01-03-常量与参数ID]] 与手册函数页为准
