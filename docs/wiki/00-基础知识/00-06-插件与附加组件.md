# 插件与附加组件

> CoppeliaSim 的功能可经插件（plugin，按需加载的共享库）与附加组件（add-on，随程序启动自动加载的后台脚本）扩展。两者常与脚本配合使用：插件提供需要高速计算或硬件接口的定制脚本命令，add-on 提供跨场景的常驻功能。本条目以官方手册为准，梳理两者机制、入口点、与脚本的关系，以及插件开发流程。

## 功能总览

CoppeliaSim 的主要功能经插件、add-on、Python 包或 Lua 模块启用（依 `functionality.htm`），包括：几何/网格、运动学、动力学、数据可视化/输出、数据操作/变换、消息/接口/连通性、路径/轨迹、路径规划、合成视觉、自定义用户界面、导入/导出、命令/设置、杂项。其中许多能力（如 OMPL 路径规划、IK、Eigen 线性代数、MuJoCo 动力学、Vision、ROS/ROS2 接口）都以插件形式提供，通过 `require` 加载。

## 插件（Plugins）

插件是可通过 `loadPlugin` API 函数按需加载的共享库（依 `plugins.htm`）。允许用任何能生成共享库并能调用导出 C 函数的语言编写。插件常用于：

- 为仿真提供定制脚本命令（常与脚本配合）
- 提供需要高速计算（编译语言比脚本快）或硬件设备接口（如真实机器人）的特殊功能

### 入口点

每个插件至少需有 `simInit` 入口点，其余可选：

```c
#include <simLib/simExp.h>
#include <simLib/simTypes.h>

SIM_DLLEXPORT int simInit(SSimInit* info);
SIM_DLLEXPORT void simMsg(SSimMsg* info);
SIM_DLLEXPORT void simCleanup();

SIM_DLLEXPORT void simInit_ui();    // 紧随 simInit 之后调用
SIM_DLLEXPORT void simMsg_ui(SSimMsg_ui* info);
SIM_DLLEXPORT void simCleanup_ui(); // 紧随 simCleanup 之前调用
```

`*_ui` 入口点仅由 UI 线程调用，其余入口点由仿真线程调用。

### 命名与加载

插件应命名为 `sim<name>-<version>`（version 可选），如 `simIK-2-1`，文件名 Linux 下为 `libsimIK-2-1.so`。插件文件放在 `<coppeliaSim 可执行文件目录>`，可用 Lua 直接加载：

```lua
simIK = loadPlugin('simIK-2-1')
```

更好的做法是把加载过程封装进同名 Lua 模块（如 `simIK-2-1.lua`，放在 `<可执行文件目录>/lua`），再从脚本用 `require` 加载：

```python
# Python 脚本
def sysCall_init():
    simIK = require('simIK-2-1')
```

```lua
-- Lua 脚本
function sysCall_init()
    simIK = require('simIK-2-1')
end
```

封装模块可额外提供纯 Lua 函数，与插件命名空间混合。V4.6 起切换到新插件架构，支持 API 版本控制；新插件需显式 `require` 或 `loadPlugin` 加载，可经 `unloadPlugin` 卸载；旧脚本经隐式 require 机制支持。

### 参考插件仓库

- **simSkeleton**：易于理解的插件模板，适合小项目
- **simSkel**：类似 simSkeleton，但自动生成大量冗余代码，适合大项目
- **simVision**：处理视觉任务（如 LIDAR 仿真、全向相机）
- **simBubble**：演示如何添加定制脚本函数并处理多个特定模型，见插件教程
- **simROS** / **simROS2**：构建 ROS / ROS2 Interface 的包
- **simMTB**：集成机器人语言解释器（或其他仿真器）的 Qt 插件

CoppeliaSim 插件可采用任何许可证发布。

## 附加组件（Add-ons）

Add-on 是在 CoppeliaSim 中运行的脚本，行为类似插件（依 `addOns.htm`）：随程序启动自动加载、跨所有打开的场景常驻、在后台持续运行。可线程化或非线程化，应分割为若干系统回调函数，并遵循与其他脚本类型相关的精确执行顺序。Add-on 与 sandbox 共享许多属性，可通过 `Menu bar > Modules` 访问。

### 位置与启动

Add-on 文件放在 `<CoppeliaSim folder>/addOns/` 目录，扩展名标识语言（`<name>.py` 或 `<name>.lua`）。也可经命令行选项加载其他 add-on。

默认随 CoppeliaSim 启动而自动启动：

```python
def sysCall_init():
    print("Executing the initialization section. Starting together with CoppeliaSim")

def sysCall_addOnScriptSuspend():
    print("Ending... (triggered by the user)")
    return {'cmd': 'cleanup'}  # 结束此 add-on，将调用 cleanup

def sysCall_cleanup():
    print("Executing the clean-up section")
```

### 手动启动/停止

通过 `sysCall_info` 返回 `{autoStart = false}` 禁用自动启动，改为用户从 add-on 菜单手动启动/停止：

```lua
function sysCall_info()
    return {autoStart = false}
end
```

也可在 `sysCall_addOnScriptSuspend` / `sysCall_addOnScriptResume` 中响应挂起/恢复；或让 add-on 作为用户触发的简单一次性函数（在 `sysCall_init` 执行完返回 `{'cmd': 'cleanup'}`）。`sysCall_info` 还可返回 `{menu = 'Exporters\nMy exporter'}` 在 Modules 菜单中显示自定义名称。

## 插件开发教程要点

以 BubbleRob 插件为例（依 `pluginTutorial.htm`），插件加载后通常封装进一个同名 Lua 模块，该模块额外可提供纯 Lua 函数。BubbleRob 插件注册了 4 个定制脚本函数：

- `simBubble.create(motorJointHandles, sensorHandle, backRelativeVelocities)` — 在插件中创建一个 BubbleRob 控制器实例，返回句柄
- `simBubble.destroy(bubbleRobHandle)` — 销毁实例
- `simBubble.start(bubbleRobHandle)` — 进入自动运动模式
- `simBubble.stop(bubbleRobHandle)` — 停止自动运动

脚本侧调用示例（Python）：

```python
def sysCall_thread():
    sim = require('sim')
    simBubble = require('simBubble')
    jointHandles = [sim.getObject('../leftMotor'), sim.getObject('../rightMotor')]
    sensorHandle = sim.getObject('../sensingNose')
    robHandle = simBubble.create(jointHandles, sensorHandle, [0.5, 0.25])
    if robHandle >= 0:
        simBubble.start(robHandle)
        sim.wait(20)  # 运行 20 秒
        simBubble.stop(robHandle)
        simBubble.destroy(robHandle)
```

### 注册与回调机制

插件在 `simInit` 中加载 CoppeliaSim 库以访问全部 API，然后注册定制脚本函数：指定函数名（不带前缀/命名空间）与回调地址。脚本调用该函数名时，CoppeliaSim 调用回调地址。回调内最困难的是正确读入参、写出返回值，通过栈完成，有两种方式：

- **辅助类**：`CScriptFunctionData` 与 `CScriptFunctionDataItem`（位于 `programming/include/simLib`），仅支持简单数据类型（布尔、整数、浮点、字符串及其数组）
- **栈函数**（位于 `programming/include/simStack`）：可交换任意类型数据，simSkeleton 插件有演示

回调应尽快执行并把控制权交还 CoppeliaSim，否则整个仿真器会停顿。

## 与脚本的关系

- **插件** 提供底层能力（编译速度、硬件接口、定制脚本命令），通过 `require`/`loadPlugin` 加载，与脚本协同：脚本调用插件注册的函数
- **add-on** 本身就是脚本，常驻后台、跨场景，常用于封装一组模块功能（如 `Modules` 菜单中的几何工具、导入导出器、属性查看器等）
- **script objects**（simulation script / customization script）是场景内的脚本对象，生命周期绑定场景；add-on 与之共享系统回调机制但跨场景常驻。脚本体系详见 [[wiki/07-API脚本示例/07-01-Lua基本脚本模式]]
