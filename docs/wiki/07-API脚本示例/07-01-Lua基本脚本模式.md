# 脚本系统总论与 Lua/Python 脚本模板

> CoppeliaSim 的几乎每一步仿真行为都可由用户脚本定义。脚本通过**回调函数（callback functions）**被调用，遵循固定的执行顺序，可选择线程化（threaded）或非线程化（non-threaded）运行。4.10 起统一采用 **script objects** 体系，不再使用旧版 child script / main script 二分法。

## 一、脚本类型体系（4.10）

CoppeliaSim 支持两大类脚本：**嵌入式脚本（embedded scripts）** 与 **非嵌入式脚本（sandbox / add-ons）**。

### 1. 嵌入式脚本

嵌入场景（或模型）内部，随场景一起保存/加载。分为三类：

| 类型 | 英文名 | 运行时机 | 数量 | 典型用途 |
|------|--------|----------|------|----------|
| 主脚本 | main script | 仿真运行时 | 场景唯一 | 仿真循环骨架，调度其他脚本 |
| 仿真脚本 | simulation script | 仅仿真运行时 | 任意 | 模型/设备的行为逻辑 |
| 定制化脚本 | customization script | 仿真内外都运行 | 任意 | 场景/模型自适应用户交互 |

> 注：自 V4.7 起，仿真脚本与定制化脚本统称为 **script objects**（旧称 associated scripts），是封装了脚本的**独立场景对象**，不再是挂在某个对象上的附属子脚本。Script objects 本身没有 3D 角色，多数时候在层级中隐藏。

### 2. 非嵌入式脚本

不绑定具体场景，跨所有场景运行：

| 类型 | 英文名 | 加载位置 | 运行方式 |
|------|--------|----------|----------|
| 沙盒 | sandbox | `python/sandboxScript.py` 或 `lua/sandboxscript.lua` | 程序启动时自动加载，常驻后台，被 commander 插件用作 REPL |
| 附加组件 | add-on | `<CoppeliaSim>/addOns/<name>.py` 或 `.lua` | 启动时自动加载（或手动从 Modules 菜单启动），常驻后台，可像插件一样扩展功能 |

### 3. 术语纠正（相对旧条目）

- **不再使用** "主脚本 / 子脚本 / 定制化脚本 / 联合仿真" 四分法。
- 旧版 "子脚本（child script）" 在 4.10 中已被 **simulation script**（封装为 script object）取代。
- 4.10 的正确层次：**embedded scripts** = main script + script objects（simulation / customization 两类）。
- 不存在旧条目所述的 "非线程子脚本 / 线程子脚本" 两种脚本类型；threaded 与 non-threaded 是**执行模式**，任何脚本都可选其一。

## 二、Script Objects

Script object 是封装脚本的场景对象（scene object），有两种形态：

- **simulation script**：只在仿真运行时执行，负责仿真时刻的行为。从 main script 的 `sim.handleSimulationScripts` 调用，每个仿真步至少调用两次（actuation 与 sensing 阶段）。
- **customization script**：仿真运行与不运行时都执行，用于场景/模型自适应、UI 交互、参数调整等。拥有专属回调如 `sysCall_nonSimulation`、`sysCall_beforeSimulation`、`sysCall_afterSimulation`。

添加方式：菜单 `Add > Script`，或 API `sim.createScript`。双击层级中的脚本对象图标可打开脚本编辑器。

## 三、执行模型

### 1. 执行优先级（precedence）

脚本回调的调用顺序由两级决定：

1. **位置**：script object 的调用优先于其祖先（父、祖父等）；同级按层级中出现的顺序，除非 priority flag 不同。
2. **类型**：从先到后依次为 — simulation script → customization script → add-on → sandbox。

> 口诀：越重要、越持久的脚本，越晚被调用（contact/dynamics 回调等有例外，反向执行）。

### 2. 线程化 vs 非线程化

任何脚本类型都可运行 threaded 和/或 non-threaded 代码。

**非线程化（non-threaded）**：
- 入口始终是回调函数，**不得阻塞**——每次被调用后必须返回控制权，否则整个 CoppeliaSim 卡死。
- 与仿真循环天然同步。

**线程化（threaded）**：
- 入口为 `sysCall_thread`，允许阻塞代码。
- 默认采用**抢占式**中断/恢复（CoppeliaSim 定期中断并在下个仿真步恢复）。
- 可用 `sim.setStepping(true)` 切到**步进模式**，此时需显式调用 `sim.step()` 让出并在下一仿真步恢复，保证每个仿真步只执行一次循环体。

## 四、主脚本（main script）

每个场景默认有唯一主脚本，包含仿真循环骨架。默认主脚本分四个核心回调：

- `sysCall_init`：仿真开始时调用一次。
- `sysCall_actuation`：每仿真步调用，执行 actuation。关键命令 `sim.handleSimulationScripts(sim.syscb_actuation)` 驱动所有 simulation script 的 actuation 回调。
- `sysCall_sensing`：每仿真步调用，执行 sensing。`sim.handleSimulationScripts(sim.syscb_sensing)` 驱动 simulation script 的 sensing 回调。
- `sysCall_cleanup`：仿真结束前调用一次。

默认主脚本还调用 `sim.handleAddOnScripts`、`sim.handleSandboxScript`、`sim.handleDynamics`、`sim.handleProximitySensor`、`sim.handleVisionSensor` 等。

> **不要随意修改主脚本**。一旦缺少 `sim.handleSimulationScripts`，场景中所有模型都将失效。主脚本图标位于层级顶部 world 图标旁（浅红色）。

### 默认主脚本（Python / Lua 双版）

```python
# python
def sysCall_init():
    sim = require('sim')
    # Initialization part

def sysCall_actuation():
    sim.handleEmbeddedScripts(sim.syscb_actuation)
    sim.handleAddOnScripts(sim.syscb_actuation)
    sim.handleSandboxScript(sim.syscb_actuation)
    sim.handleDynamics(sim.getSimulationTimeStep())

def sysCall_sensing():
    sim.handleProximitySensor(sim.handle_all_except_explicit)
    sim.handleVisionSensor(sim.handle_all_except_explicit)
    sim.handleEmbeddedScripts(sim.syscb_sensing)
    sim.handleAddOnScripts(sim.syscb_sensing)
    sim.handleSandboxScript(sim.syscb_sensing)

def sysCall_cleanup():
    sim.handleSimulationScripts(sim.syscb_cleanup)
    sim.resetProximitySensor(sim.handle_all_except_explicit)
    sim.resetVisionSensor(sim.handle_all_except_explicit)

def sysCall_suspend():
    sim.handleEmbeddedScripts(sim.syscb_suspend)
    sim.handleAddOnScripts(sim.syscb_suspend)
    sim.handleSandboxScript(sim.syscb_suspend)

def sysCall_suspended():
    sim.handleEmbeddedScripts(sim.syscb_suspended)
    sim.handleAddOnScripts(sim.syscb_suspended)
    sim.handleSandboxScript(sim.syscb_suspended)

def sysCall_resume():
    sim.handleEmbeddedScripts(sim.syscb_resume)
    sim.handleAddOnScripts(sim.syscb_resume)
    sim.handleSandboxScript(sim.syscb_resume)
```

```lua
--lua
function sysCall_init()
    sim = require('sim')
    -- Initialization part
end

function sysCall_actuation()
    sim.handleEmbeddedScripts(sim.syscb_actuation)
    sim.handleAddOnScripts(sim.syscb_actuation)
    sim.handleSandboxScript(sim.syscb_actuation)
    sim.handleDynamics(sim.getSimulationTimeStep())
end

function sysCall_sensing()

    sim.handleVisionSensor(sim.handle_all_except_explicit)
    sim.handleEmbeddedScripts(sim.syscb_sensing)
    sim.handleAddOnScripts(sim.syscb_sensing)
    sim.handleSandboxScript(sim.syscb_sensing)
end

function sysCall_cleanup()
    sim.handleSimulationScripts(sim.syscb_cleanup)
    sim.resetProximitySensor(sim.handle_all_except_explicit)
    sim.resetVisionSensor(sim.handle_all_except_explicit)
end
```

## 五、回调骨架（sysCall 全集）

所有脚本入口均为回调函数。系统回调（system callbacks）由 CoppeliaSim 在特定事件触发，函数名固定（`sysCall_*`）。完整清单见 [[wiki/01-API参考/01-06-脚本回调函数清单]]，以下列出最常用的：

| 回调 | 触发时机 | 适用脚本 |
|------|----------|----------|
| `sysCall_init` | 脚本首次调用，一次 | 全部 |
| `sysCall_thread` | 线程化入口 | 全部（threaded 模式） |
| `sysCall_actuation` | 每仿真步 actuation 阶段 | simulation / main |
| `sysCall_sensing` | 每仿真步 sensing 阶段 | simulation / main |
| `sysCall_cleanup` | 脚本状态销毁前 | 全部 |
| `sysCall_nonSimulation` | 仿真未运行时定期 | customization / add-on / sandbox |
| `sysCall_beforeSimulation` | 仿真即将开始 | customization / add-on / sandbox |
| `sysCall_afterSimulation` | 仿真刚结束 | customization / add-on / sandbox |
| `sysCall_suspend` / `sysCall_suspended` / `sysCall_resume` | 仿真暂停/挂起/恢复 | 全部 |
| `sysCall_beforeInstanceSwitch` / `sysCall_afterInstanceSwitch` | 场景切换前后 | customization / add-on / sandbox |
| `sysCall_beforeSave` / `sysCall_afterSave` / `sysCall_afterLoad` | 场景保存/加载 | 全部 |
| `sysCall_msg(msg, origin)` | `sim.broadcastMsg` 或特定回调同步触发 | 全部 |
| `sysCall_addOnScriptSuspend` / `sysCall_addOnScriptResume` | 附加组件挂起/恢复 | 仅 add-on |

## 六、Lua/Python 脚本模板

### 1. 非线程化仿真脚本（最常用）

每个仿真步被 actuation 与 sensing 各调用一次，必须立即返回。

```lua
--lua
function sysCall_init()
    sim = require('sim')
    motor = sim.getObject('/joint_motor')
    sensor = sim.getObject('/proximity_sensor')
    targetPos = 0.0
end

function sysCall_actuation()
    local detected, dist, point = sim.readProximitySensor(sensor)
    if detected > 0 then
        targetPos = math.pi
    else
        targetPos = 0.0
    end
    sim.setJointTargetPosition(motor, targetPos)
end

function sysCall_sensing()
    sim.setFloatSignal('current_time', sim.getSimulationTime())
end

function sysCall_cleanup()
    print('cleanup done')
end
```

```python
# python
def sysCall_init():
    sim = require('sim')
    self.motor = sim.getObject('/joint_motor')
    self.sensor = sim.getObject('/proximity_sensor')
    self.target_pos = 0.0

def sysCall_actuation():
    detected, dist, point = sim.readProximitySensor(self.sensor)
    if detected > 0:
        self.target_pos = math.pi
    else:
        self.target_pos = 0.0
    sim.setJointTargetPosition(self.motor, self.target_pos)

def sysCall_sensing():
    sim.setFloatSignal('current_time', sim.getSimulationTime())

def sysCall_cleanup():
    print('cleanup done')
```

### 2. 线程化仿真脚本（默认抢占式）

```lua
--lua
function sysCall_init()
    sim = require('sim')
    motor = sim.getObject('/joint_motor')
end

function sysCall_thread()
    while not sim.getSimulationStopping() do
        sim.setJointTargetPosition(motor, math.pi)
        -- 默认每步抢占式让出，无需手动 yield
    end
end
```

```python
# python
def sysCall_init():
    sim = require('sim')
    self.motor = sim.getObject('/joint_motor')

def sysCall_thread():
    while not sim.getSimulationStopping():
        sim.setJointTargetPosition(self.motor, math.pi)
```

### 3. 线程化脚本（步进模式，每步精确一次）

```lua
--lua
function sysCall_init()
    sim = require('sim')
    sim.setStepping(true)  -- 关闭抢占式让出，改为显式 step
end

function sysCall_thread()
    while not sim.getSimulationStopping() do
        print('simulation time: ', sim.getSimulationTime())
        sim.step()  -- 让出，下一仿真步恢复
    end
end
```

```python
# python
def sysCall_init():
    sim = require('sim')
    sim.setStepping(True)

def sysCall_thread():
    while not sim.getSimulationStopping():
        print('simulation time:', sim.getSimulationTime())
        sim.step()
```

### 4. 定制化脚本

仿真不运行时也执行，适合 UI、参数调整、模型自适应。

```lua
--lua
function sysCall_init()
    params = { speed = 1.0, amplitude = 0.5 }
end

function sysCall_nonSimulation()
    -- 仿真未运行时定期执行
end

function sysCall_beforeSimulation()
    -- 仿真即将开始
end

function sysCall_afterSimulation()
    -- 仿真刚结束
end

function sysCall_msg(msg)
    -- 处理 sim.broadcastMsg 广播
end

function sysCall_cleanup()
end
```

### 5. 附加组件（add-on）

位于 `<CoppeliaSim>/addOns/myAddOn.lua`，启动时自动加载。

```lua
--lua
function sysCall_init()
    print('add-on started with CoppeliaSim')
end

function sysCall_addOnScriptSuspend()
    print('suspending add-on')
    return {cmd = 'cleanup'}  -- 结束此 add-on
end

function sysCall_cleanup()
    print('add-on cleanup')
end
```

非自动启动的 add-on（需手动从 Modules 菜单启动）：

```lua
--lua
function sysCall_info()
    return {autoStart = false, menu = 'Exporters\nMy exporter'}
end

function sysCall_init()
    print('started by user')
    return {cmd = 'cleanup'}  -- 执行完即结束
end
```

## 七、Lua vs Python 差异

- **执行方式**：Lua 始终与 CoppeliaSim 同线程运行，速度快；Python 在独立进程中启动，经 socket 与 CoppeliaSim 通信，启动/运行较慢；但 Python 非 stepping 模式且不访问 API 时真正与 CoppeliaSim 并行。
- **全局变量**：Python 中不推荐用 `global`，改用 `self`（如 `self.motor = ...`）；Lua 用全局变量（`motor = ...`）。
- **索引基**：Python list 从 0 开始；Lua array-like table 从 1 开始。
- **语言标记**：V4.7 起不再需要 `#python` 头部；语言在脚本创建时指定或从文件扩展名推断。
- **包含外部文件**：Python 用 `include myExternalFile`（不带引号与 `.py`）；Lua 用 `require('myExternalFile')`。
- **Python 解释器**：默认取系统 Python，可在 `usrset.txt` 中改 `defaultPython` 项；也可用 `#luaExec pythonExecutable = 'c:/python38/python.exe'` 指定。
- **luaExec 指令**：Python 脚本顶部注释区可用 `#luaExec` 传递 wrapper、附加路径、启用 contact/dyn/event 等回调。
- **消息泵**：Python threaded 脚本若需服务用户回调（如 UI 按钮），须在循环中调 `sim.handleExtCalls()`。
- **独占区段**：Python 中需保证不被中断的区段用 `sim.acquireLock()` / `sim.releaseLock()` 包裹。
- **部分回调需显式启用**：`#luaExec contactCallback = true` / `dynCallback = true` / `eventCallback = true`。
- **文档中的 "table"**：Lua 中指数组/映射 table；Python 中指 `list` 或 `dict`。

## 八、Lua 速查

- 8 种基本类型：`nil`、`bool`、`number`、`string`、`function`、`userdata`、`thread`、`table`。
- 变量默认全局，`local` 声明局部变量。
- 注释：`-- 单行`。
- 字符串连接：`a .. b`。
- 长度运算符：`#table`。
- 多重赋值：`x, y, z = 1, 2, 3`。
- 表（array）首元素下标为 1。
- 协程（coroutine）：

```lua
corout = coroutine.create(coroutineMain)
if coroutine.status(corout) ~= 'dead' then
    coroutine.resume(corout)
end

function coroutineMain()
    while not sim.getSimulationStopping() do
        -- some code
    end
end
```

## 十、脚本间通信

```lua
-- 信号通信
sim.setFloatSignal('joint_target', 1.57)
local val = sim.getFloatSignal('joint_target')

-- 调用另一脚本的函数
```
