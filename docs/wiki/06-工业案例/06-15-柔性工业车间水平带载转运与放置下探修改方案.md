# 柔性工业车间水平带载转运与放置下探修改方案

> 本文是阶段二/三控制器的待实施方案，不描述当前代码行为。当前状态与路径基线见
> [机械臂运动阶段说明](06-14-柔性工业车间机械臂运动阶段说明.md)。

## 1. 目标状态与几何约束

拟将带载路径拆分为三个可独立观察的运动状态：

| 状态 | 运动目标 | 路径约束 | 完成后去向 |
|---|---|---|---|
| `LIFTING` | `pick` → `lift` | 吸附后沿法向抬升，终点到达选定的安全转运高度 | `TRANSFERRING` |
| `TRANSFERRING` | `lift` → `pre_place` | TCP 固定 Z、保持工具姿态，沿水平路径带载移动 | `PLACING` |
| `PLACING` | `pre_place` → `place` | 沿放置面的法向下探；AGV 目标须先确认到站、停稳且水平 | `RELEASING` |
| `RELEASING` → `SETTLING` | 无机械臂运动 | 释放载荷并确认载荷稳定 | `RETREATING` |

该拆分保留 `LIFTING` 与 `TRANSFERRING` 的状态边界，并让 `PLACING` 明确表示下探运动。
`RELEASING`、`SETTLING` 仍各自保留，便于区分下探失败、释放失败和载荷不稳定。

水平约束要求 `lift.z == pre_place.z`（在 TCP 位置容差内），且两点工具四元数一致。
因此 `pre_place` 定义为放置点正上方的共享绝对高度 `H_transfer`，不再无条件沿用
`place.z + PRE_APPROACH_CLEARANCE`。`LIFTING` 的终点也必须到达该高度。`H_transfer` 必须
由场景测量/既有验证确定，并通过带载全程净空检查；不能仅因端点同高就推断路径净空成立。
若既有预接近高度不足以达到已验证高度，应将 `pre_place` 抬高到 `H_transfer`，相应增加
`PLACING` 法向下探距离。

基线路径点 `rise`、`transit` 及其偏移/变体从目标序列移除。水平路径先采用一段固定高度的
XY 直线；`pre_place → place` 保持现有法向笛卡尔下探约束，不改变释放和稳定判据。

## 2. 水平路径求解方式比较与选型

| 方法                               | 如何表达路径                                       | 优点                                       | 对本项目的适配与限制                                                                                                          |
| -------------------------------- | -------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 关节空间端点插值                         | 求 `pre_place` 的 IK，再在关节空间插值到目标构型             | 实现简单、关节目标直接                              | 不约束 TCP 高度或水平轨迹；TCP 可能弧形升降并扫过设备，不满足本次工艺约束，不作为转运主方法                                                                  |
| 固定高度笛卡尔采样 + 连续 IK                | 在 XY 平面生成 TCP 采样位姿，逐点用前一 IK 解作 seed，连接成连续关节链 | 直接表达固定 Z/工具姿态；可复用现有碰撞、载荷、腕部分支与路径复核       | **推荐首选**。项目的 `cartesian_poses` 和 `LocalPlanner._cartesian_chain` 已支持直线位姿采样、连续 IK 与路径检查；应以统一的笛卡尔段接口接入 `TRANSFERRING` |
| CoppeliaSim `simIK.generatePath` | CoppeliaSim 沿 TCP 笛卡尔直线生成关节配置序列，可传入配置有效性回调   | 与 UR5 的末端直线运动直接匹配；官方将其列为抓放最终接近等路径的用途     | 可作为官方 API 参考或独立对照探针。但项目已有自己的 simIK 环境封装和 `ConfigurationChecker`；直接替换可能绕过载荷变换、项目碰撞集合、腕部分支及统一报告契约，因此首版不另接一条执行链        |
| 笛卡尔曲线采样 + 连续 IK                  | 在固定 Z 平面定义圆弧/样条等曲线，采样位姿后逐点求 IK               | 能绕过直线路径碰撞，也可控制转向连续性                      | 只有直线被具体障碍阻挡或有实测运动质量问题时才启用；曲线采样点仍须经过同一 IK 连续性与整段碰撞复核。CoppeliaSim `sim.createPath` 可由控制点生成路径，但路径对象本身不等于机械臂 IK/碰撞验证    |
| OMPL 关节空间采样规划                    | 在 UR5 关节状态空间搜索无碰路径，配置碰撞对/状态有效性回调             | 适合局部规划找不到避障路时搜索绕行；CoppeliaSim 提供 OMPL 插件 | 自由的关节空间搜索不保证 TCP 全程固定高度、姿态不变；加入硬约束需要自定义状态约束/投影与验证，增加实现面。首版不引入；仅当固定高度笛卡尔候选失败且确有避障需求时再单独评估约束路径搜索                      |

选型结论：采用项目现有局部规划器的**固定高度笛卡尔路径采样 + 连续 IK 链搜索**，不另建
OMPL 执行链。当前 `cartesian_poses` 对单个目标段做 XYZ 线性插值、姿态四元数球面插值；
当起止姿态相同且 z 相同时，TCP 位置轨迹就是固定高度 XY 直线。该语义与水平转运直接一致。
项目对笛卡尔段逐采样求 IK，并做 FK 偏差、关节路径碰撞筛查；计划还会做完整离散路径复核。
候选链搜索配置可沿用现有实现，不为本次状态调整新造求解器。

水平运动不要求直线。曲线可由多段笛卡尔线段或采样后的样条路径表达，但应作为直线路径失败
后的受控扩展，而非首版默认：在安全转运高度上，若平面直线可达且通过净空，曲线没有已证明的
额外收益。

## 3. 规划与执行流程

1. **冻结几何定义**：确定 `H_transfer`、目标放置姿态和放置面法向。设置 `lift` 为 `pick` 沿取料法向到 `H_transfer` 的位姿；设置 `pre_place` 为 `place` 沿放置法向到同一 `H_transfer` 的位姿。确认整段载荷扫掠包络的净空要求来自既有实测/场景验证。
2. **先规划抬升**：`LIFTING` 仍独立规划 `pick → lift` 法向段。规划成功并完成运动后再进入转运，保留原有阶段检查和报告。
3. **规划水平转运**：`TRANSFERRING` 目标只含 `pre_place`。从真实/已验证计划起点 TCP 到 `pre_place` 按固定 Z、固定姿态采样；逐点连续求 IK，维持当前腕部分支及关节限位策略，并对机器人、吸附载荷和工作单元执行现有碰撞/净空检查。
4. **检查目标设备后下探**：转运到 `pre_place` 后进入 `PLACING`。对 `target=agv`，先检查 dock 传感器、AGV 停稳及水平；未满足时按现有超时规则等待/失败，不生成下探命令。满足后规划 `pre_place → place` 法向笛卡尔段，并沿用最终载荷接触许可。
5. **释放和收尾**：`PLACING` 到位后进入现有 `RELEASING → SETTLING → RETREATING` 流程；保留释放、载荷稳定、滑移检查及撤离行为。
6. **失败可定位**：运动报告分别记录 `LIFTING`、`TRANSFERRING`、`PLACING`。转运规划失败不自动改走未验证的关节路径；未知碰撞/姿态查询仍按现有安全锁存契约处理。

## 4. 代码与测试修改边界

- `src/stage2/unit_controller.py`：将转运目标收束至 `pre_place`；为 `PLACING` 增加独立下探计划；更新运动状态完成转换及带载上下文；把 AGV dock/停稳/水平校验移到下探之前。
- `src/stage1/unit_controller.py`：仅修改共享状态机确有必要的部分，确保 `PLACING` 可被阶段二/三作为运动状态调度，同时阶段一原有关键帧路径和语义不被意外改变。阶段一是否采用新几何路径不在本方案范围。
- `src/stage3/coordinator.py` 与运行期故障注入：检查其对 `TRANSFERRING`/`PLACING` 的阶段判断与事件时序；只改为维持新状态语义和既有联锁行为所必需的条件。
- `src/stage2/config.py` / `scene_contract.py`：移除不再使用的 rise/transit 路径选项或更新其契约摘要；`H_transfer` 的配置名与工件 digest 影响按现有配置契约处理，不保留会产生歧义的旧路径开关。
- `tests/`：覆盖水平目标固定 Z/姿态、lift 与 pre-place 同高、三段状态顺序、PLACING 下探失败归因、AGV 未停稳时不开始下探，以及最终接触许可只作用于 place 终点。保留并更新已有 transfer 路径生成测试。
- 原阶段说明 §2–§6 应在代码落地并验证后再同步更新；实施前由本文表达目标方案，避免把提案误写成当前行为。

## 5. 验收条件

- 规划与执行记录显示 `lift.z`、`pre_place.z` 差值不超过现有 TCP 位置容差，且水平段采样 TCP 的 z 漂移不超过同一容差；工具姿态偏差满足现有角度容差。
- 三个运动状态按 `LIFTING → TRANSFERRING → PLACING` 完成；每个状态的计划目标、失败原因和执行指标可分别读取。
- 全路径通过当前关节限位、腕部分支、带载碰撞/净空及最终计划复核；运行期逐步复核、安全锁存和未知读数拒绝语义不回退。
- AGV 未到站、未停稳或不水平时不会执行 `pre_place → place`，并保留原有超时失败行为。
- 回归阶段二/三的 AGV、station、both 和运行期障碍用例；不要求无关的阶段一运动规划变化。

## 6. CoppeliaSim 参考资料

- [CoppeliaSim：Path/motion planning modules](https://manual.coppeliarobotics.com/en/pathAndMotionPlanningModules.htm)：说明 simIK 与 simOMPL 的组合方式，并举例末端直线路径可用 `simIK.generatePath` 生成。
- [CoppeliaSim：simIK API](https://manual.coppeliarobotics.com/en/simIK.htm)：`simIK.generatePath` 沿末端笛卡尔直线生成关节配置序列，支持对候选配置调用验证回调；不可达或无效中间构型会导致失败。
- [CoppeliaSim：simOMPL API](https://manual.coppeliarobotics.com/en/omplApi.htm)：提供关节状态空间规划、碰撞对和自定义状态有效性回调；随机规划器的路径最优性与采样/算法选择相关。
- [CoppeliaSim：sim.createPath](https://manual.coppeliarobotics.com/en/sim/simCreatePath.htm)：支持由控制点创建插值/Bezier 路径，可用于曲线路径采样的候选来源；仍需项目 IK 与碰撞检查。
- [CoppeliaSim：sim.generateTimeOptimalTrajectory](https://manual.coppeliarobotics.com/en/sim/simGenerateTimeOptimalTrajectory.htm)：轨迹时间参数化能力；不负责替代本方案的 TCP 几何路径、IK 连续性或碰撞规划。
