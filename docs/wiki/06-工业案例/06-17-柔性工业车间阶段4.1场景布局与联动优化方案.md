# 柔性工业车间阶段 4.1：场景布局与设备联动优化方案

> 本文审查阶段四当前实现，并规划一次有边界的布局与联动优化。阶段 4.1 目标是让设备布局、物流方向和机械臂工作区彼此协调，并让多岛流程有可观察的交错运行；不以增加验收数量或引入真实物理装配作为目标。

## 1. 审查结论

阶段四的业务链已连通，场景几何却仍沿用方便调试的列式基线。当前实现可以说明控制器和物料状态机已跨岛交接，但还不能说明平面布局已围绕全车间物流优化，也不能说明多岛会自然并行。

| 用户问题 | 审查结论 |
|---|---|
| 为什么机械臂平台高度不同？ | 这是阶段四迭代中为解决局部碰撞、可达性和传送带高度关系采用的补偿：A/B/E 沿用阶段三 `0.30 m`；C 抬至 `0.45 m` 以让 UR5 连杆越过 A 交接台；D 抬至 `0.45 m` 以匹配输送面并满足当前 `H_transfer=0.80 m` 的可达性。它不是统一 datum 下的高度设计。|
| 当前流程如何联动？ | S1→A→C→E 和 S1→B→AGV→A→C→E 两条输入链，另有 S2→D→AGV→E；E 按 `SEMI_CE + PART_DE` 生成 `FINAL`。阶段四已有任务/UID/资源/传感器联动，不是孤立工位。|
| 布局是否过于横平竖直？ | 是。五个基座均在 `x=-0.20`，AGV dock 均在 `x=0.40`，AGV 走单段直线；4 条输送带只沿 X/Y 轴。报告已明确 `L4_COLUMN` 不满足 06-16 所建议的外围路线与物流优先布局方向。|
| 是否未参考 06-15？ | 06-15 不是工厂平面布局方案，而是机械臂单次转运路径方案。阶段四采用了其 `LIFTING → TRANSFERRING → PLACING` 与 `H_transfer` 约束；它没有规定岛、传送带、仓库和 AGV 的 XY 排布。阶段 4.1 应把 06-15 当作每个工作单元的运动接口约束，不把 Bezier 当作重排场景的前置条件。|
| 岛间是否缺少联动、仿真是否单调？ | 代码链路已联动，但运行主要是互斥资源控制下的串行任务，AGV 每次走直线，E 只做逻辑配对。`full_flow` 只用 RAW_A/B/D 各 1 件，且目前不是几何装配。因此从生产节拍和空间运动观感上仍显简单。|

## 2. 当前业务流程与设备联动

```text
S1 ─┬─ Conveyor_S1_to_A → A 取料/加工 → SEMI_AC
    │                                  ↓ Sensor_Handoff_AC
    │                              A→C 固定交接
    │                                  ↓
    │                       C 取料/加工 → SEMI_CE
    │                                  ↓ Conveyor_C_to_E
    │                         E 的 C 线输入缓冲 ─┐
    │                                           ├─ 配对 → FINAL
    └─ Conveyor_S1_to_B → B 加工 → SEMI_AB      │
                                ↓ AGV B→A       │
                              A 再加工 → SEMI_AC ┘

S2 → Conveyor_S2_to_D → D 加工 → PART_DE → AGV D→E → E 的 D 线输入缓冲 ─┘
```

设备协作由 stage4 coordinator、每岛 `Stage4UnitController`、共享 `MaterialRegistry`、`TaskQueue`、资源表、AGV 路线控制器和同一 stepping 循环完成。物料只有在 UID、类型、区域/传感器证据匹配后才完成转移；AGV 是 pioneer 轮速控制。E 岛的 `FINAL` 目前为逻辑生成，不涉及真实拼装轨迹。

仍显得单调的原因主要有三项：

- 生产拓扑的空间投影退化成一列工位和一条 AGV 直线，工位间路线缺少分支、汇合和绕行。
- 资源策略为了安全默认串行化相邻工作区；现有优先级场景证明了派车选择，不代表多个物料正在不同支路并行流动。
- 一件式批次和逻辑配对减少了缓存填充、任务交错和成品离开 E 岛的可视过程。

因此 4.1 的重点应是让“物流图、设备位置、运动包络”一致，并用一个小型交错批次展示已有联动；不应把串行任务误判为缺少软件连接，也不应为视觉效果放开未经验证的并发。

## 3. 高度差原因与处理原则

当前高度来自 `src/stage4/config.py` 的明确局部设置：A/B 沿用阶段三基座和岛面 `0.30 m`；C 的岛面/基座设为 `0.45 m`，报告称是为了让 link3 越过 A 交接台 `0.30 m` 台面；D 的岛面/基座也为 `0.45 m`，用于对齐传送带承载面并让取料及 `H_transfer=0.80 m` 的路径可达；E 沿用 `0.30 m`。报告中的 v003→v004、后续 B/D 调整记录与当前坐标相符。

这解释了“为什么”，但不证明该高度差是最终正确的设备设计。现有做法是在固定 XY 拓扑和特定交接点下，通过垫高平台处理 link 碰撞或 IK 失败；代价是岛面、机械臂基座 datum 和工作高度不统一，也让场景看起来像逐点补丁。

阶段 4.1 采用以下处理原则：

1. 先把三个高度区分开：机械臂安装基准 `Z_base`、工作台/岛面 `Z_work`、传送带承载面及转运平面 `H_transfer`。它们不必数值相同，但必须在配置和布局图中显式表达，不能隐含为 `island_top_z`。
2. 以阶段三已验证的 `Z_base=0.30 m` 作为统一安装高度的首选候选，重排 C/D/E 的 XY、交接台和 conveyor 后复测。该值是候选 datum，不是强制结论。
3. 若某工位在统一安装基准下确实无法同时满足碰撞、关键 TCP 可达和 06-15 水平转运条件，可保留局部高度例外，但需记录具体冲突、测量值和可达性余量；不要仅为了让一个目标 IK 成功就垫高整岛。
4. 如果保留高低平台，使用明确的支座/安装板并按真实模型外包络参与碰撞和工作区检查；视觉上标识设备台面与基座，不把支撑几何误读为不同工艺基准。

## 4. 阶段 4.1 推荐布局方向

建议从当前列式 `L4_COLUMN` 迁移为**紧凑 U 形固定物流 + 外围 AGV 回路**的候选布局。核心不是追求斜线或曲线，而是减少 AGV 与固定物流/机械臂工作区的重叠，并让两类物料在 E 处有清楚、分离的到达方向。

```text
                         +X 固定物流主方向 →
            A ──短交接──► C ──Conveyor_C_to_E──► E[C入口]
           /                                        │
S1 ──分流─<                                          ├─配对/输出
           \                                        │
            B                         D ◄─Conveyor── S2
            │                         │             E[D入口]
            └──── AGV B→A ────────────┴── AGV D→E ───┘
               外围分段路段、停靠支线与等待区（概念示意）
```

设备布置要求：

- A/B 先保留阶段三“UR5 从 conveyor 侧方接近”的实测关系作为布局锚点；如因路网需要移动，明确对 stage3 坐标的差异并复测受影响路径。
- A→C 固定交接保持短并靠近两岛相邻边界；A/C 两台 UR5 的取放方向错开，交接台独立于 AGV dock，A 完成交接后按现有 park 动作退出共享区。
- C→E 带沿工艺流向进入 E 的一侧。D→E AGV 从另一侧靠 dock 到站；E 的两个缓冲继续按物料类型固定分区，成品输出朝向出口，不占用 AGV 停靠线。
- S1→A/B 用两条短支路或明确的分流点，不在两条线端头与机器人之间形成横穿动线。S2→D 独立供料，D 的工作区靠近自己的 conveyor 和 AGV dock。
- AGV 不再要求四个 dock 全部共线。首选外围单向 U/环状分段路线，dock 使用短支线接入；若当前 pioneer 控制器不适合转弯，则先做两段直线加一个明确转向/等待节点，保留已验证的差速轮速控制，不用车体瞬移。
- 机械臂与 AGV 路线交叉处只保留必要的 dock 交接，并用现有资源锁串行化；几何碰撞和净空仍由阶段二路径/碰撞检查证明，资源锁不能代替几何验证。

不在计划文档中预填新的精确坐标。先用轻量草图讨论相对位置，确定方向后将坐标写入候选布局配置；最终俯视预览从该配置生成，避免手工图与代码坐标分叉。图只用于检查空间关系，不替代 IK、碰撞和实际路线验证。

## 5. 实施步骤

按“确认基线 → 确定一份布局配置 → 分段实现和验证 → 运行交错批次”的顺序执行。`L4_COLUMN/v008` 始终作为未重排基线；候选布局使用独立名称和派生工件。布局图是配置的自动生成预览，不单独维护多版手工图。每次只保留一个当前候选，只有布局输入变化或出现失败证据时才重新执行受影响的检查，不为每个小步骤另造工件版本。

### 4.1-1：冻结基线与测量输入

1. 以 `PHASE4_REPORT.md` 中的父工件 ID、`L4_COLUMN/v008`、layout/config digest 和已通过场景作为基线；这些现有证据足够时直接引用，不另复制一套基线报告或测量 JSON。
2. 只有在当前工件、代码配置与报告不一致，或现有记录缺少本次要移动对象的尺寸/位置时，才执行只读校验或 `probe_stage4_layout.py` 补测。探针的 `--sim --ik` 会恢复 IK target；沿用该行为并确认仿真仍处于原状态。补测结果留在标准 probe 输出中，由阶段报告引用。
3. 按需读取布局修改会影响的对象：相关岛/平台、UR5 base/TCP、conveyor 有效承载区、A→C 交接、E 缓冲、AGV 车体/载荷 footprint 与 dock。沿用现有对象别名、物料边和工件契约，不另建一份完整对象清单。

产物：无新增基线文件；阶段报告引用既有工件和验收证据。若发现不一致，先查明工件漂移、报告过期或配置偏差，并只记录会影响本次布局选择的结论；未解释的差异不带入候选布局。

### 4.1-2：确定并检查候选布局

1. 先用简单俯视草图表达固定物流和 AGV 运输边，明确 A→C 固定交接、C→E 输送带、B→A 与 D→E AGV 运输，以及 E 的两个入口和输出。草图可用文本或在代码布局配置前的临时示意，不作为交付文件。
2. 根据草图选定一个 U 形固定物流与外围 AGV 分段通路候选：尽量保留 A/B 阶段三锚点；C 靠近 A→C 交接下游，E 位于 C→E 末端并为 D→E 留独立 dock 侧，D/S2 不横穿 C→E；S1→A/B 优先使用两条独立短支路。
3. 按真实设备 footprint、UR5 代表性工作区和 AGV 带载 footprint 检查 A park 与 C 取放、dock 与输送线/台面、E 两入口与输出、AGV 路线与机械臂工作区之间的冲突。先调整 dock、station、短 conveyor 或入口缓冲，只有这些局部调整不能解决时才移动整岛。
4. 将确定的候选坐标写入一份 `Stage4Layout` 配置，并从这份配置生成俯视预览。预览至少能区分固定输送/交接、AGV 路线、设备占地与 dock；不另制作基线图、差异图或路线图。布局未通过代码中的静态筛选或后续路径检查时，回到配置调整，不维护多份候选图片。

产物：候选 `Stage4Layout` 配置及其自动生成的单张俯视预览。阶段三锚点变更和主要布局取舍简要写入阶段报告；坐标和设备关系以配置为准。

### 4.1-3：冻结高度 datum 和候选坐标

1. 先分开定义 `Z_base`（UR5 安装基面）、`Z_work`（工位/台面/岛面）、`Z_belt`（带面）与 `H_transfer`（带载水平段 TCP 高度）；同时标注物料中心高度和吸盘接触面偏移。各高度允许不同，但每个目标位的计算必须引用正确 datum。
2. 从已验证的阶段三坐标开始尝试统一 `Z_base=0.30 m`。先调整 C/D/E 的 XY、dock、交接台位置和 conveyor 支路，再判断 C/D 的高台是否仍有必要；不要先把所有平台强行改成等高。
3. 对每个 island/工作台，按“机械臂基座安装面 → 台面/传感器/物料接触面”的尺寸关系计算支撑高度。确认 UR5 模型 base 所在面，避免把 base 世界 Z、platform 顶面 Z 和 island 厚度混作同一个数值。
4. 对每条输送线按有效 pad 高度复核入口、停止区、物料中心和 UR5 TCP 接触目标。旋转 conveyor 后重新计算局部轴到世界坐标的转换，不能只交换 X/Y 坐标而漏掉方向和传感器朝向。
5. 对 E 岛单独标注两输入 buffer 的台面高度/物料中心高度/AGV tray 高度/输出高度。若共用同一岛面，说明差异由物料或载台几何造成；若确需台阶，明确隔板/支撑几何及各输入实际接触面。
6. 将布局写为独立 `Stage4Layout` 候选数据：每个 unit 的 base、island、工作面、station/dock；每条 conveyor 的 center/yaw/entry/stop；AGV dock、route waypoint 和方向；E buffers/output；高度 datum。不要在 controller 中散落候选坐标。候选数据继续使用 `layout_from_dict` / `validate_layout` 所代表的数据契约；新增或调整测量入口时，让 `probe_stage4_layout.py` 能显式读取候选布局文件。当前探针默认调用 `default_layout()`，不能把它对 `L4_COLUMN` 的通过结果当作新候选的测量结果。
7. 先运行静态 footprint/边界/粗可达校验。静态校验通过后，再对每个岛最少必要的业务目标做 simIK 和关节限位检查；每臂只测其对应工序目标，不做全空间扫描。报告记录候选文件摘要、布局名和 probe 输出路径，确保静态结果与仿真结果来自同一个候选版本。
8. 对当前 `H_transfer`，分别检查 `pick→lift`、固定高度 `lift→pre_place`、`pre_place→place`。`lift.z` 与 `pre_place.z` 需符合 06-15 现有容差，带载水平段须经过现有离散碰撞/净空检查。遇到 C 交接冲突，先调整 A/C 接近方向或交接台偏置，再评估高台例外。
9. 若局部平台高度仍需保留，新增高度例外记录：涉及岛、基面和台面数值、具体碰撞/可达问题、尝试过的平面调整、支持结论的 simIK/路径证据。仅记录这个例外，不要求编写通用自动高度优化器。

验证记录：标准 probe/仿真结果引用同一候选配置。高度 datum 和必要例外写入布局配置或随工件保存的简短说明，不另建 datum 表。通过此步后不再边跑任务边改坐标；坐标变化应更新 layout/config digest 并重新派生工件。局部目标 IK 成功只是可达性证据，不替代对应带载路径碰撞检查。

### 4.1-4：按设备/动线逐段重建并检查

1. 从受保护的阶段三工件派生新的 stage4 工件；保留 `L4_COLUMN/v008`。将新布局命名为新 ID（例如 `L5_UFLOW`），同步更新 layout/config digest 和 stage4 manifest。复用报告中的 lifecycle 顺序：加载指定 stage3 parent、`build --phase stage4 --parent <parent>`、保存为新 stage4 工件；保存前核对 parent ID 和候选布局名，禁止把实验布局写回已保护的 v008。
2. 先只更新静态工位、台面、仓库和 conveyor 摆放，不启动生产任务。检查必需 alias、句柄、五台 UR5 六轴、每臂独立 IK 上下文、传感器和四条带的停止初始化行为。
3. 逐条确认固定物料路线：S1→A、S1→B、A→C 交接、C→E、S2→D。每条只运行一个指定 UID，观察它在传感器触发、停止、抓取、放置和缓冲确认后的状态变化；不要并行打开所有供料线排查。
4. A→C 专项先跑 A 放置到交接台、A 执行 park、C 接近并取走三段；核对传感器只把物料交接一次，两个机械臂不会同时进入共享交接区域。若接触/碰撞失败，调整相对位置或 park 方向后仅重跑该链。
5. C→E 专项确认 C 放到 belt entry 时 conveyor 未误启动，只有 E/输送任务接管后运行；E 传感器确认指定 UID 到达并将其放入 `buffer_e_c`。检查带尾与 AGV dock E 不重叠。
6. D→E 专项先做 D 的 S2 conveyor 取料和 AGV 装载，再做一趟空车到 dock D 和一趟带载 D→E，最后由 E 取到 `buffer_e_d`。记录真实 dock 命中、停稳和载荷滑移，不用 route endpoint 几何接近代替到站确认。
7. 让 E 单独处理“只到 C 件”“只到 D 件”“两件都到”的当前逻辑状态：缺件时留在 buffer 等待，两件类型和 UID 匹配后只产生一个 FINAL，并保留两条父 UID。这里沿用已通过的 material/tuple 逻辑，不扩成物理拼装。
8. 每条路线按现有运行报告记录 UID、起止 alias、传感器确认和状态结果；无需另写逐路线日志。只在布局/载荷/控制参数变化影响的路径上重跑，不重复全部阶段四五场景。

产物：能按新坐标构建和校验的 stage4 新工件。受影响路线的检查结果保留在标准运行证据中，由阶段报告概括。

### 4.1-5：将 AGV 单直线替换为最小可用分段路网

1. 在候选布局配置中给 AGV 路网定义有向节点：初始/等待点、B/D 装载 dock、A/E 卸载 dock、必须经过的转向点和路线交汇点。节点只设在需要装卸、改变方向或避障处，不按固定距离机械加点；自动生成的布局预览据此显示路线。
2. 从实际场景读取 AGV yaw 和 footprint，确定 pioneer 前进方向、倒车能力、dock 传感器朝向及载台/载荷外伸尺寸。每个 dock 选择不会扫过工作台、conveyor 或 UR5 base 的进出朝向。
3. 先将 B→A 和 D→E 各拆为可理解的少量路段；配置每段起点、终点、航向、载荷状态、速度上限和到站传感器。路线方向不能只由 XY 起终点猜测，尤其要区分倒车和原地转向。
4. 将线段/窄道/ dock 纳入资源表，资源按固定顺序获取；AGV 进入某窄道前确认其令牌，dock 由当前运输/装卸任务占用。两任务同时等待时，只在 AGV 停于安全等待点时比较优先级。
5. 路线执行仍调用现有轮速控制器；一个 route segment 完成后先执行停稳判定，再切换下一段。禁止在 `sim.step()` 循环里写 AGV 位置或姿态以“补正”路线。
6. 若需要转弯，使用现有差速运动控制在 waypoint 间完成转向；按实际 footprint 做低速试跑，检查带载时内轮/外轮扫掠及载荷滑移。若路线控制器暂不支持稳定转弯，采用“直线段 + 停车转向 + 直线段”的简单动作，或将 dock 调整到不需要转弯的位置。
7. 先做无货路线和站点传感器检查，再做每条带载路线。发生 BLOCKED 时遵循既有行为：停车、保留 task/UID 和现场，人工清障后的续行仅沿已定义路线，不自动重新规划。
8. 两类任务同时排队时运行一次现有 priority 场景，确认 B→A/D→E 的选择规则、等待记录和不可抢占语义仍生效。路线完全未改的部分引用 PHASE4_REPORT 对应实测数据。

产物：布局配置中的 AGV waypoint/route，以及被修改路线的标准运行证据；路段和 dock 显示在同一张自动生成的布局预览中。无需创建独立路线图、通用地图导航、动态避障或多车交通系统。

### 4.1-6：运行一个交错批次，让联动可见

1. 复用 `full_flow` 的任务链和三种原料类型，增加少量有限批次输入，使 A/C 固定流、B→A 返工流、D→E 装配供料流有机会在不同区域同时处于等待/加工/运输状态。批次数量只需足以形成交错，不以吞吐量优化为目标。
2. 开始前检查各线、交接台、AGV 载台和 E buffers 的容量。每条容量为 1 的区域只允许一个 UID；满载时上游停供/等待并在日志显示原因，不通过增大容量隐藏阻塞。
3. 按阶段四已有 coordinator 顺序启动任务，保持一个 AGV 单任务。允许传送带输送或非冲突的岛内等待与 AGV 运输在时间线上重叠；需要共享机械臂、交接台、dock 或 AGV lane 时，仍遵守资源互斥。
4. 先运行无故障批次，检查任务事件按 UID 排序能解释物料从来源到 E 的去向；再选一个既有故障注入场景运行一次，验证停机后队列/物料没有被错误清除或标成 DONE。
5. 从现有运行报告确认 UID 流向、关键任务状态、AGV 路线、E 两个 buffer 和 FINAL 父件关系；直接引用运行 JSON 与摘要，不另生成一份时间线文件。若现有报告缺少判断验收所需的信息，只补充该字段。
6. 若时间线上所有设备仍串行，先判断是否由真实空间冲突和资源锁导致；若无真实冲突，再缩小对应资源 envelope/释放时机，并重跑受影响的路径碰撞检查。不要为了画面热闹而放开双臂或AGV穿越共享区域。

产物：一个有限交错批次的标准运行证据，在阶段报告中用简短摘要说明三路物料进入 E 缓冲并形成 FINAL 的结果。

### 4.1-7：整理新工件和实施记录

1. 将选中的布局、waypoint、datum 和必要的任务/资源参数写入配置与工件契约；避免把临时探针 target、shadow object 或运行状态保存进场景工件。
2. 对最终新工件执行保存、重载和既有只读场景校验，确认父工件、layout digest、别名和稳定配置摘要相符。
3. 在 PHASE4_REPORT 增加阶段 4.1 小节，记录新布局 ID、自动生成预览的位置、必要的高度例外、受影响路线结论、交错批次结果和引用的阶段四基线证据；只保留能解释决策和验收结论的信息。
4. 保留旧 `L4_COLUMN/v008` 和它的报告数据；新布局未达到原三组验收边界时，默认指针仍指向原通过工件，并将新候选标记为未通过/实验状态。

## 6. 精简验收边界

阶段 4.1 只保留以下三组检查，以上详细步骤不额外增加验收矩阵：

1. **布局与可达**：布局配置及其自动生成预览体现新物流方案和明确高度 datum；代表性机械臂路径及 AGV 两路线通过既有 IK、碰撞和轮速检查。预览用于审查关系，不独立增加验收条件。
2. **流程联动**：一个有限交错批次（`staggered_batch`）完成 A/C/E 与 D/E 输入配对，以及 B→A 返工链；UID、类型、缓冲和 FINAL 父 UID 一致。
3. **基本停机回归**：运行一个已有 AGV 阻塞或 conveyor 停带场景，证明受影响任务停止/保留且不误报 DONE。统一故障恢复继续留在最终阶段。

不要求：穷举所有岛组合/每个初始姿态、性能最优布局证明、完整节拍优化、连续碰撞认证、真实 E 岛装配、双臂同时动作、Bezier 作为默认路径，或重复阶段四全部五个场景。布局、载荷和路线未发生变化的既有验收证据可以引用阶段四报告。

## 7. 交付物与决策

1. 新 `Stage4Layout` 配置和独立 stage4 工件；`L4_COLUMN/v008` 及其既有报告作为基线引用，不复制为新对照材料。
2. 从候选布局配置生成的一张俯视预览，随阶段报告或既有文档资源保存；不另交基线图、差异图、AGV 路线图或重复坐标表。
3. 更新后的 `PHASE4_REPORT` 4.1 小节，简要记录布局选择、必要 datum 例外、受影响路径与交错批次/停机回归结论，并引用标准 probe/run 证据。

若候选外围路网需要较大范围移动 A/B、重写 conveyor 输送模型，或无法在当前一辆 pioneer 上完成安全进出 dock，则先保留 L4_COLUMN 作为通过验收基线，并把未解决的布局约束列明；不扩大到更换 AGV、增加多车或重新设计全部物料生命周期。

- 外围路网是**南侧开口的 U 形**，不是闭合环线。C/E 占住北侧且

- 四个 dock 是所在直道上的内联停靠点，没有独立支线；单 AGV、单向
  分段路网下无超车需求，dock 占用由资源表在装卸期间独占。

  直线段失败并回退到 06-15 的同高度 `detour +0.30 m`；从 AGV→交接台
  的转运为直接路径。这是 06-15 已验证行为，不是 4.1 新增路径缺陷。
- E 缓冲的横向折叠位置在本轮实测中导致连续 IK 偏差 23.8 mm，已改为
