# 柔性工业车间重构方案

> 本文是供审核的详细设计方案，不代表当前仓库已经完成实现。目标是建立一套以 CoppeliaSim 内置模型为基础的柔性搬运单元，并逐步扩展为多工位车间。

> 工程实施时必须同时遵守项目全局强制规范：[CLAUDE.md](../../../CLAUDE.md) 的“柔性车间重构工程规范”。本方案中的模型、物理、传感器、IK、吸附和 AGV 约束不得被旧版控制层的历史行为覆盖。

## 1. 设计目标与范围

本方案固定采用以下内置组件：

| 组件 | 内置模型或 API | 设计用途 |
|---|---|---|
| 传送带 | `generic conveyor (belt).ttm` | 动态皮带输送 |
| 机械臂 | `UR5.ttm` | 六轴关节控制与 IK 搬运 |
| 末端执行器 | `suction pad.ttm` | 指定物料吸附与释放 |
| AGV | `pioneer p3dx.ttm` | 保留原始动力学的差速移动 |
| 位置检测 | `sim.createProximitySensor` | 检测物料到达、吸盘对准和卸料完成 |
| 物料 | 动态可响应形状 | 传送带、吸盘和 AGV 载台之间转移 |

第一阶段先实现一个可验收的单元：

```text
原料区 → 内置动态皮带 → 取料检测位 → UR5 + suction pad
                                      ├→ 工位放置区
                                      └→ pioneer p3dx 载台
```

阶段一之后先进入物理与运行基础能力阶段，解决 TCP 外表面接触、碰撞约束、
场景构建与仿真启动解耦、故障状态语义和传送带停机等基础问题；完成后再复制
工位、传送带和任务调度，形成双工位柔性搬运，最后扩展到多岛车间。

## 2. 总体物料流与任务边界

### 2.1 单元物料流

```text
Warehouse_Raw
      │
      ▼
Conveyor_In
      │
      ▼
Sensor_PickStation
      │
      ▼
指定物料 Part_N ──► UR5 吸附 ──► 工位 A / AGV 载台
                                      │
                                      ▼
                               pioneer p3dx 运输
```

控制器不把“检测到任意物料”当作抓取任务。每个任务携带明确的物料句柄或 UID、取料目标和放置目标：

```python
PickTask(
    object_alias="Part_0001",
    pick_target="PickTarget_0001",
    place_target="PlaceTarget_AGV",
)
```

传感器用于确认物理条件满足，任务对象用于确认“抓取的是谁”。

### 2.2 后续车间扩展

阶段二基础能力验证通过后，阶段三、阶段四再逐步扩展为：

```text
S1 ── Conveyor_S1_to_A ──► A 岛 ──► C 岛 ── Conveyor_C_to_E ──► E 岛
  └─ Conveyor_S1_to_B ──► B 岛 ── AGV ──► A 岛
S2 ── Conveyor_S2_to_D ──► D 岛 ── AGV ──► E 岛
```

AGV 任务仍采用单车队列，B→A 为高优先级，D→E 为低优先级并支持等待升级；不依赖在途抢占。

## 3. 场景层级、别名与句柄

CoppeliaSim 4.10 中，实际别名使用扁平下划线命名，不能把斜杠路径直接传给 `setObjectAlias` 或依赖斜杠形式调用 `getObject`。推荐别名如下：

```text
Warehouse
Conveyor
Island
Mobile
Part

Warehouse_Raw
Conveyor_In
Conveyor_Out
Sensor_PickStation
Sensor_ConveyorExit
Island_A
Robot_UR5_01
SuctionPad_01
SuctionPad_01_TCP
Sensor_SuctionPad_01
Mobile_AGV_P3DX
AGV_LoadTray
Part_0001
```

构建顺序：

1. 地面和静态平台；
2. `Warehouse`、`Conveyor`、`Island`、`Mobile`、`Part` 层级根 dummy；
3. 内置传送带和传感器；
4. 工作台、UR5 和 suction pad；
5. pioneer p3dx 和载台/挡边；
6. 运行时生成物料。

模型加载后必须执行脚本检查和必要的脚本剥离，避免多个内置模型的 Lua 脚本在 CoppeliaSim 4.10 中造成启动冻结。模型句柄缓存后，运行时通过别名叶匹配获取对象，不使用每步 `getObject` 查询。

## 4. 传感器设计

### 4.1 传感器配置

| 传感器 | 类型 | 安装位置 | 作用 |
|---|---|---|---|
| `Sensor_PickStation` | proximity sensor | 传送带取料区 | 判断物料是否到达可抓取区域 |
| `Sensor_SuctionPad_01` | proximity sensor | 吸盘接触面附近 | 判断 TCP 与指定物料是否满足吸附距离 |
| `Sensor_ConveyorExit` | proximity sensor | 传送带末端 | 判断物料是否离开皮带或进入工位 |
| `Sensor_AGV_Dock` | proximity sensor | AGV 装卸位 | 判断小车是否到达装卸姿态 |

固定位置、已知物料类型的搬运任务只需要 proximity sensor，不默认增加视觉传感器。若以后需要颜色、型号或未知位置识别，再增加 Vision Sensor；视觉识别不替代任务 UID 校验。

### 4.2 检测与任务绑定

传感器检测流程如下：

```text
Sensor_PickStation 命中
    ↓
读取命中对象句柄
    ↓
与当前 PickTask.object_alias / UID 比对
    ↓
不匹配：保持输送或报警
匹配：进入 UR5_APPROACH
```

传感器只提供“物理条件已满足”的证据，不直接调用吸附动作。这样可以避免内置 suction 脚本枚举全场景后吸附错误的 pad、平台或其他物料。

## 5. 传送带设计：HYBRID_DYNAMIC

### 5.1 模型和原始尺寸

使用：

```text
models/equipment/conveyors/generic conveyor (belt).ttm
```

当前 CoppeliaSim 4.10 模型测量值约为：

| 尺寸 | 约值 | 用途 |
|---|---:|---|
| 外包围盒 X 长度 | `1.216 m` | 模型整体长度 |
| 上层 pad 有效运行区 | `0.997 m` | 物料可稳定承载的主要范围 |

两端滚筒不应作为物料生成点或停止点。取料位应位于有效 pad 运行区内，并至少向滚筒边缘内缩一个物料半长加安全裕量。

### 5.2 尺寸缩放策略

传送带尺寸只在构建阶段确定：

```text
loadModel → 读取 native 包围盒 → 计算构建缩放 → 放置与旋转 → 仿真启动
```

仿真开始运行后不再改变模型长度。`sim.scaleObjects` 在当前版本按标量进行等比缩放；例如把 `1.216 m` 单段放大到 `4 m`，缩放因子约为 `3.29`，宽度和高度也会同步放大，因此不建议用单个模型承担过长距离。

推荐：

- 小于约 1 m：使用一个原始模型；
- 中等距离：串联多个内置皮带段；
- 必须使用长段时：构建阶段统一等比缩放，并重新测量有效承载区。

### 5.3 动态属性

正式运行模式只保留：

```text
HYBRID_DYNAMIC
```

其物理关系为：

```text
传送带 pad：可响应承载面，由内置模型驱动
物料：dynamic + respondable
物料与 pad：优先依靠动态接触和摩擦
输送控制：只在物理速度不足时提供受限的路径补偿
```

补偿不是任意瞬移，必须满足：

1. 传感器确认物料仍在该传送带有效区域；
2. 修正方向沿传送带中心线切向；
3. 修正速度不超过配置的最大输送速度；
4. 物料仍保留动态属性和碰撞属性；
5. 超过最大偏差时进入 `CONVEYOR_FAULT`，不继续强行推进。

4.10 下不能假设所有物理引擎都能稳定把移动 pad 的切向速度传递给 dynamic 物料。因此，HYBRID_DYNAMIC 是工程运行模式；纯摩擦效果可以作为验收对照，但不再作为正式配置选项。

## 6. UR5、IK 与工具中心点

### 6.1 UR5 控制原则

机械臂统一使用内置 UR5 六轴模型：

```text
目标位姿 → simIK 求解六个关节角 → setJointTargetPosition
```

禁止用关键帧姿态代替取料和放料 IK。每台机械臂独立创建 `simIK` environment 和 group：

- 主组：伪逆求解；
- 备用组：阻尼最小二乘；
- 关节限位：同步到 IK 环境；
- 约束：优先使用位置约束，必要时增加受限姿态；
- 到位判定：TCP 世界位置误差、姿态误差、关节误差和碰撞状态联合判断。

IK 失败时不能使用预设关节角冒充成功，应进入退避、重试或任务失败状态。

### 6.2 TCP 定义

TCP 不是 suction pad 外壳的任意模型原点，也不默认等于 UR5 `connection` 力传感器中心。应在吸盘接触面中心建立专用 dummy：

```text
Robot_UR5_01
  └── SuctionPad_01
        └── SuctionPad_01_TCP
```

`SuctionPad_01_TCP` 作为：

- simIK 的 tip；
- 抓取目标的参考点；
- 吸附距离计算点；
- 释放位置计算点。

抓取目标位姿应位于物料目标接触面上方一个小的接近距离，而不是简单使用物料几何中心：

```text
approach pose = contact pose + surface normal × approach_clearance
pick pose     = contact pose + surface normal × pick_clearance
```

吸盘法向与物料表面法向的夹角超过配置阈值时，任务失败或重新规划。

## 7. 吸附与释放

### 7.1 吸附范围

当前阶段不模拟真实真空压力、真空流量或吸力大小，也不使用力传感器作为吸附判据。吸附条件为：

```text
目标物料 UID 匹配
Sensor_SuctionPad 命中目标
TCP 与接触点距离小于容差
吸盘法向满足倾角限制
UR5 速度低于吸附速度阈值
无碰撞和 IK 错误
```

### 7.2 状态保存

吸附前保存物料的：

- 原始父对象；
- 世界位姿；
- dynamic/static 状态；
- respondable 状态；
- 质量和摩擦参数；
- 碰撞掩码。

吸附时将物料逻辑绑定到 `SuctionPad_01_TCP` 或吸盘 link，关闭物料的动态响应，避免重力把物料从工具上拉脱。释放时恢复上述状态，并调用动态对象重置，使物料重新参与重力、接触和摩擦计算。

## 8. pioneer p3dx AGV 与载荷物理

### 8.1 AGV 本体

AGV 使用内置 `pioneer p3dx.ttm`，保留其：

- 车体质量和惯量；
- 左右轮结构；
- 轮半径和轮距；
- 差速驱动关节；
- 车轮与地面碰撞；
- 原始动力学属性。

AGV 不采用每帧 `setObjectPosition` 瞬移。控制器输出车体线速度 `v` 和角速度 `w`，再转换为左右轮目标速度：

```text
v_left  = (2v - wL) / (2R)
v_right = (2v + wL) / (2R)
```

其中 `R` 为轮半径，`L` 为左右轮中心距。pioneer p3dx 由物理引擎完成加速、转向、接触和减速。

### 8.2 载台与载荷

AGV 增加一个与车体刚性连接的低矮载台和必要挡边。物料放上载台后：

```text
物料保持 dynamic + respondable
不直接 parent 到 AGV
依靠载台接触、摩擦和挡边保持
AGV 加速度受限，避免载荷不必要滑移
```

因此，AGV 载荷默认不使用“无摩擦的刚性跟随”。如果验收发现物料在合理加速度下仍会滑落，优先增加机械限位或调整摩擦和载台几何；只有为了特定确定性实验，才允许配置一个明确标记为“非物理保持”的约束模式。

### 8.3 装卸流程

```text
AGV_DOCK_SENSOR 确认到站
    ↓
UR5 将物料放到载台有效区域
    ↓
释放吸附并恢复物料动态属性
    ↓
等待物料稳定
    ↓
AGV 按轮速驶向目标站
    ↓
目标站传感器确认到位
    ↓
UR5 或卸料机构取走物料
```

## 9. 碰撞与物理关系

| 对象 | 动力学属性 | Respondable | 主要碰撞对象 |
|---|---|---:|---|
| 地面 | static | 是 | 物料、AGV、设备平台 |
| 工作台 | static | 是 | 物料、UR5 基座 |
| conveyor 承载面 | 内置承载面 | 是 | 物料 |
| conveyor 框架 | static | 否或受限 | 不与 AGV 路径相交 |
| 物料 | dynamic | 是 | 地面、载台、传送带 |
| UR5 连杆 | 动态位置控制 | 按碰撞配置 | 工件和工作台，避免自碰撞 |
| suction pad | 随 UR5 工具 | 主要用于检测 | 指定物料 |
| pioneer p3dx | dynamic | 是 | 地面、障碍物、载台 |
| AGV 载台/挡边 | 与车体刚性连接 | 是 | 物料 |

必须配置碰撞掩码，避免：

- AGV 撞击传送带 pad；
- suction pad 吸附传送带 pad；
- UR5 连杆与工作台互相穿透；
- 物料释放后与载台重复重叠；
- 载荷挡边与载荷使用错误的自碰撞组合。

## 10. 控制状态机

### 10.1 UR5 搬运状态

```text
IDLE
  → WAIT_PART_SENSOR
  → IK_APPROACH
  → IK_PICK
  → SUCTION_ATTACH
  → IK_LIFT
  → IK_PLACE
  → RELEASE
  → VERIFY_RELEASE
  → IDLE
```

异常状态：

```text
IK_FAILED       → RETRY / ABORT
SENSOR_TIMEOUT  → WAIT / SUPPLY_PAUSE
PICK_MISMATCH   → 不吸附并报警
COLLISION       → 安全退避 / 急停
RELEASE_FAILED  → 保持物料状态并进入人工处理队列
```

### 10.2 AGV 状态

```text
IDLE
  → DOCKING
  → LOADING
  → MOVING
  → ARRIVED
  → UNLOADING
  → IDLE
```

路径堵塞进入 `BLOCKED`，清障后恢复；不在 AGV 行驶过程中抢占当前任务。

### 10.3 单步执行顺序

Python 端作为时钟主控，使用 stepping 模式。推荐单步顺序：

1. 检查通信、碰撞、传感器和异常状态；
2. 更新传送带运行状态；
3. 更新物料输送和传感器检测；
4. 创建或更新 UR5 搬运任务；
5. 计算 IK 并下发关节目标；
6. 执行吸附、抬升、放置或释放状态转换；
7. 计算 pioneer p3dx 左右轮速度；
8. 更新 AGV 路径、装卸和任务队列；
9. 更新日志、节拍和故障状态；
10. 调用 `sim.step()` 推进物理引擎。

## 11. 建议模块边界

正式实现时建议恢复删除前的控制层，并按以下边界重构。阶段一实际实现把
下列模块集中在 `src/stage1/` 包内（入口 `src/run_stage1.py` 为兼容包装）：

```text
build_scene.py          场景、内置模型、层级和脚本处理
factory_config.py       模型路径、布局、容差和物理参数
factory_physics.py      dynamic/respondable/mass/friction 工具
conveyor_controller.py  HYBRID_DYNAMIC 输送和传感器
ur5_ik_controller.py    simIK、关节目标和 TCP 到位
suction_controller.py   指定物料吸附、释放和状态恢复
pioneer_controller.py   差速轮控制、路径跟踪和到站
material_manager.py     物料 UID、生命周期和状态
flexible_scheduler.py   UR5、传送带、AGV 任务调度
factory_controller.py   stepping 总循环和异常处理
```

所有可调参数集中放在配置模块，不在控制循环内散落硬编码。

## 12. 分阶段实施

详细的逐步执行、联调、故障注入和阶段退出门槛见：
[[wiki/06-工业案例/06-05-柔性工业车间分阶段执行步骤]]。

### 阶段一：单元闭环

组件：一条 conveyor、一个 UR5、一个 suction pad、一个 pioneer p3dx、一个物料和两个目标位。

验收：

- 传送带使用内置模型并在构建阶段完成尺寸处理；
- `Sensor_PickStation` 能检测目标物料；
- UR5 IK 能到达 `SuctionPad_TCP` 取料位；
- 只吸附指定 UID 的物料；
- AGV 通过左右轮速度运动；
- 物料释放后能在载台上保持动态接触。

### 阶段二：物理与运行基础能力

不增加工位数量，完成以下基础能力：

- TCP 只能在物料外表面有效接触，吸附判据包含法向、间隙、传感器、UID 和碰撞状态；
- UR5、suction pad、工件、工作台、conveyor 和载台建立碰撞集合与局部路径检查；
- 场景构建、保存、加载、校验和仿真启动在 CLI 和模块层解耦；
- 故障统一进入 `FAULT`、`BLOCKED`、`RETRYABLE_FAILURE` 或人工处置状态，禁止
  把阻塞任务统计为 `DONE`；
- 验证传感器停带、最大越程和 `Conveyor_In_PickupStopper` 的安全挡停职责；
- 固化内置模型脚本的保留/剥离策略和场景 manifest。

阶段二通过后，才允许进入双工位扩展。

### 阶段三：双工位柔性搬运

增加第二工位、AGV 路径、装卸传感器和任务队列，验证重复取放、排队、堵塞和恢复。

### 阶段四：多岛车间

恢复 A–E 岛、仓库供料、节拍追踪、异常检测和共享 AGV 调度，逐步接入现有岛式车间拓扑。双工位资源互斥、单步协调和轮速驱动等既有能力从阶段三复用；五岛生产流、共享 AGV 新路线及多物料配对需要单独实现和验收。详细实施边界与步骤见 [[wiki/06-工业案例/06-16-柔性工业车间阶段四多岛实施步骤]]。

### 四阶段后的补充优化：Bezier 水平带载转运

四个建设阶段完成后，可评估将阶段二/三共享的 `TRANSFERRING` 水平带载路径扩展为固定高度 Bezier 曲线。此项是可选的后续运动质量优化，不属于阶段四交付，也不作为四阶段验收或最终故障治理的前置条件。

优化目标是在保持 TCP 高度、工具姿态、IK 连续性及带载碰撞/净空约束的前提下，评估曲线对绕行能力、底座方位变化和关节运动质量的影响。TCP 绕底座的几何路径不等于由 UR5 底座关节 `q[0]` 单独或主导运动；`q[0]` 只作为候选比较指标，不设硬锁或单调变化要求。

先保留已验证的固定高度直线路径作为对照，使用相同起点、终点、载荷、场景和安全检查比较 Bezier 候选。只有曲线稳定通过现有 IK、分支、关节限制、带载碰撞与执行复核，且对关节总变差/运动质量有可重复收益、没有不可接受的净空或执行时间退化时，才考虑设为默认。路径参数化、采样、连续 IK、对照实验和采纳门槛见 [[wiki/06-工业案例/06-15-柔性工业车间水平带载转运与放置下探修改方案]] §7。

## 13. 审核验收指标

### 场景与模型

- [ ] 传送带为内置 `generic conveyor (belt)`；
- [ ] 机械臂为内置 UR5，且每台为六轴；
- [ ] 末端为内置 suction pad，并有明确 `SuctionPad_TCP`；
- [ ] AGV 为内置 pioneer p3dx，未被几何体替代；
- [ ] 所有别名为下划线形式，句柄通过别名叶匹配；
- [ ] 场景启动后无残留脚本导致 `state=8` 冻结。

### 传送带与传感器

- [ ] 模型原始长度和有效 pad 区域已测量；
- [ ] 缩放只发生在构建阶段；
- [ ] 取料点位于有效承载区而不是滚筒区；
- [ ] 运行配置只有 `HYBRID_DYNAMIC`；
- [ ] 传感器能区分“到位”与“目标 UID 匹配”。

### UR5 与吸附

- [ ] 取料和放料均由 simIK 求解；
- [ ] IK 失败不会被预设角度伪装成成功；
- [ ] TCP 位置误差达到配置容差；
- [ ] 目标物料之外的对象不会被吸附；
- [ ] 吸附和释放前后物料物理属性正确恢复。

### AGV 与载荷

- [ ] pioneer p3dx 通过轮速驱动，而不是位置瞬移；
- [ ] AGV 车体质量、惯量和轮子物理属性保持；
- [ ] 载荷默认保持 dynamic + respondable；
- [ ] 载荷依靠载台接触、摩擦和挡边运输；
- [ ] 加速、转弯和停车时没有明显穿透或无故漂移。

## 14. 当前待审核决策

实现前只需要确认以下默认决策：

1. 正式运行模式只保留 `HYBRID_DYNAMIC`；
2. 固定位置物料检测使用 proximity sensor，不默认加入视觉识别；
3. TCP 使用吸盘接触面中心的专用 dummy；
4. 不模拟真实真空力；
5. UR5 搬运阶段采用逻辑吸附，AGV 搬运阶段采用动态接触和摩擦；
6. 先完成单元闭环，再扩展到五岛车间。
