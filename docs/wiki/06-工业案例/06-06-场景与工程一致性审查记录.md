# 场景与工程一致性审查记录

## 结论

同步前，skill、全局规范、README 和旧案例文档存在明显冲突，不能直接视为
同一套当前实现说明。主要冲突是：UR5 被写成关键帧纯视觉动画、AGV 被写成
位置插值、物料被写成非响应体、传送带被写成脚本位置输送，以及生产模型缺失时
静默回退 primitive。

本轮已将新方案约束同步到 skill、scene-building/control-framework reference、
`CLAUDE.md`、README、分层命名教程和模块参考。06-01、06-02、06-03 保留原始
经验，但均已标记为历史案例或迁移参考，不能覆盖 06-04/06-05 和 `CLAUDE.md`。

## 当前权威约束

| 主题 | 当前要求 | 审查结果 |
|---|---|---|
| 传送带 | `generic conveyor (belt).ttm`，正式模式仅 `HYBRID_DYNAMIC` | 已同步；旧 `KINEMATIC_BELT_TRANSPORT` 仅保留为历史实验事实 |
| 机械臂 | 内置六轴 UR5，取放必须 `simIK` 求解六关节 | 已同步；关键帧仅可用于诊断演示 |
| 末端 | 内置 `suction pad.ttm`，TCP 为吸盘接触面中心 | 已同步；要求 `SuctionPad_*_TCP` |
| 检测 | 固定位置使用 proximity sensor，并校验物料 UID/句柄 | 已同步；Vision Sensor 不再是隐含依赖 |
| 吸附 | TCP 到位 + 传感器命中 + UID/类型/姿态/速度/碰撞确认 | 已同步；不启用全场景自动吸附 |
| AGV | 内置 `pioneer p3dx.ttm`，左右轮目标速度驱动 | 已同步；禁止车体位置瞬移 |
| 载荷 | 默认 dynamic + respondable，依靠载台接触、摩擦和挡边 | 已同步；禁止仅 parent 到 AGV 冒充物理运输 |
| 缺失模型 | 生产构建失败并报警；primitive 只允许诊断场景 | 已同步 |
| 命名 | 实际 alias 扁平下划线，启动时缓存 alias-leaf 句柄 | 已同步 |

## 代码阶段仍需验证

文档同步不等于实现已验收。重构代码时仍需完成：

1. 在 CoppeliaSim 4.10 中核对四个内置模型路径、脚本剥离和句柄清单。
2. 标定 conveyor 有效 pad 区、TCP、proximity sensor、轮半径、轮距和载台高度。
3. 用 `simIK` 验证取料/抬升/放料可达性及 TCP 世界坐标误差。
4. 验证吸附、释放后 dynamic/respondable、质量、摩擦和碰撞掩码完整恢复。
5. 验证 pioneer p3dx 直行、转向、停车、载荷滑移和 dock sensor 到站条件。
6. 完成阶段一、阶段二、阶段三的日志、故障注入和 `state=8` 冻结回归。

在上述证据完成前，文档中的“必须”表示工程约束，“已验证”只应写在有日志或
可复现测试的位置。
