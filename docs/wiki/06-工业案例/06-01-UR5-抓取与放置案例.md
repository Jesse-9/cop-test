# UR5 机械臂抓取与放置案例

> **历史案例 / API 参考**：本文保留早期 UR5 + simIK 的通用教程和验证经验，
> 不定义当前柔性车间的完整实现。当前工程必须额外遵循
> [[wiki/06-工业案例/06-04-柔性工业车间重构方案]]：内置 `suction pad.ttm`、
> 专用 `SuctionPad_*_TCP`、proximity sensor、指定物料 UID 双重确认，以及
> 释放时恢复动态属性。本文中的 primitive/示例回退不能替代生产模型。

## 场景描述

使用 UR5 六轴工业机械臂在 CoppeliaSim 4.10 中实现**抓取与放置**（Pick and Place）任务。UR5 安装在工作台上方，从拾取点抓取工件，经过空中转运，放置到目标区后回退待机。

场景要素：

| 组件 | 说明 | 来源 |
|------|------|------|
| UR5 机械臂 | 6 轴回转关节，运动学模式（非动态） | `models/robots/non-mobile/UR5.ttm` |
| 末端 tip / target | IK 链的 tip dummy 与 target dummy | 手册 IK 教程 |
| 夹爪 | 装在 UR5 末端 base，两指开合 | 内置夹爪模型 |
| 工件 | 小立方体（拾取点处） | 基本几何体 |
| 放置区 | Dummy 标记的目标位置 | 自建 |

本案例采用**外部控制器 + ZMQ Remote API + stepping 模式**：Python 是时钟主导者，每次 `sim.step()` 推进一个仿真步，控制逻辑与物理引擎严格同步（见 [[wiki/01-API参考/01-02-Remote-API-ZMQ]]）。

## 系统架构

```
┌─────────────────────────────────────────────┐
│           CoppeliaSim 4.10 场景             │
│   UR5(6关节) + tip/target + 夹爪 + 工件     │
│   (运动学模式, 无需模型自带脚本)             │
└───────────────┬─────────────────────────────┘
                │ ZMQ Remote API (localhost:23000)
                │ stepping: sim.setStepping(True) → sim.step()
┌───────────────▼─────────────────────────────┐
│  Python 外部控制器 (cop-test 仓库模式)       │
│  - getObject 取关节句柄                      │
│  - simIK.addElementFromScene 建 IK 任务      │
│  - setObjectPosition(target) + handleGroup  │
│  - setJointTargetPosition / 夹爪信号控制     │
│  - sim.step() 推进物理引擎                  │
└─────────────────────────────────────────────┘
```

要点（依据 `externalControllerTutorial.htm`）：外部控制器是控制 CoppeliaSim 的六种方式之一，通过 ZeroMQ 远程 API 调用 `sim.*` 与 `simIK.*` 等全部 Regular/Plugin API，可在 stepping 模式下与仿真步严格同步。

## 关键步骤

### 1. 场景搭建与 UR5 加载

通过 `sim.loadModel` 加载 UR5 模型后设置别名。本仓库踩过的坑（见 [[wiki/02-仿真建模/02-01-分层命名场景构建]] 与 CLAUDE.md「已知问题与坑」）：内置 UR5 携带 IK/定制脚本，多臂场景下脚本在 4.10 ZMQ addOn 层争用导致约 3 帧处整场冻结。**缓解办法**是剥离模型自带脚本子对象，仅保留几何体 + 关节，动画/控制完全由 Python 端驱动。

```python
from coppeliasim_zmqremoteapi_client import RemoteAPIClient

client = RemoteAPIClient()
sim = client.require('sim')

# 加载 UR5 并设置别名 (别名不含斜杠, 见 02-01)
ur5 = sim.loadModel('models/robots/non-mobile/UR5.ttm')
sim.setObjectAlias(ur5, 'UR5')  # 别名一律下划线, 不用斜杠

# 可选: 剥离模型自带脚本, 避免多臂场景冻结
def strip_scripts(handle):
    tree = sim.getObjectsInTree(handle, sim.handle_all, 0)
    for obj in tree:
        try:
            if sim.getObjectType(obj) == sim.object_script_type:
                sim.removeObjects([obj])
        except Exception:
            pass
strip_scripts(ur5)
```

### 2. 取关节句柄与 tip/target

手册 `accessingSceneObjects.htm` 规定：`sim.getObject(path)` 用**斜杠路径**查询；别名本身不含斜杠。UR5 自带的 tip/target dummy 可通过路径定位：

```python
joints = [sim.getObject(f'/UR5/joint{i}') for i in range(1, 7)]
tip    = sim.getObject('/UR5/tip')       # IK 链末端
target = sim.getObject('/UR5/target')   # IK 目标 dummy
base   = sim.getObject('/UR5')           # IK 基座
```

### 3. 构建 IK 任务（simIK 插件）

依据 `simIK.htm` 与 `inverseKinematicsTutorial.htm`：IK 任务通过 `simIK.addElementFromScene` 从场景运动链自动构造，约束选 `constraint_pose`（位置+姿态）。手册推荐配置**无阻尼 + 有阻尼两组**：无阻尼组失败时回退有阻尼组，避免末端不可达时机械臂抖动。

```python
simIK = client.require('simIK')

ik_env = simIK.createEnvironment()
ik_group_undamped = simIK.createGroup(ik_env)
simIK.setGroupCalculation(ik_env, ik_group_undamped,
                          simIK.method_pseudo_inverse, 0, 6)
simIK.addElementFromScene(ik_env, ik_group_undamped,
                          base, tip, target, simIK.constraint_pose)

ik_group_damped = simIK.createGroup(ik_env)
simIK.setGroupCalculation(ik_env, ik_group_damped,
                          simIK.method_damped_least_squares, 1, 99)
simIK.addElementFromScene(ik_env, ik_group_damped,
                          base, tip, target, simIK.constraint_pose)
```

### 4. 设定目标位姿并求解 IK

每次移动只需设置 target dummy 的位置/姿态，再调 `simIK.handleGroup`（`syncWorlds=True` 把求解结果同步回场景关节）。无阻尼组失败时回退有阻尼组（与手册教程一致）：

```python
def move_to(pos, orient=None):
    sim.setObjectPosition(target, pos, sim.handle_world)
    if orient is not None:
        sim.setObjectOrientation(target, orient, sim.handle_world)
    res, *_ = simIK.handleGroup(ik_env, ik_group_undamped,
                                {'syncWorlds': True})
    if res != simIK.result_success:
        simIK.handleGroup(ik_env, ik_group_damped, {'syncWorlds': True})
    return res == simIK.result_success
```

### 5. 关节目标位置与夹爪控制

`sim.setJointTargetPosition` 适用于运动学模式或动态位置控制模式（见 `regularApi/simSetJointTargetPosition.htm`）：在运动学模式下，关节按最大速度/加速度/加加速度的运动剖面平滑移动到目标。若不用 IK 直接驱动关节，可逐关节下发目标值（见 [[wiki/01-API参考/api/api-simSetJointTargetPosition]]）。夹爪常用信号控制开合：

```python
def set_gripper(open_):
    # 0=闭合, 1=打开 (具体语义取决于夹爪模型)
    sim.setIntegerSignal('gripper_open', 1 if open_ else 0)

def step_motion():
    # 在 stepping 模式下逐帧推进, 让运动学剖面平滑执行
    sim.step()
```

### 6. 抓取循环（stepping 模式完整骨架）

下面是可运行的完整骨架：approach（上方接近）→ grasp（下降闭合）→ lift（提起）→ transfer（运至放置区上方）→ place（下降放置）→ release（松开）→ retreat（回安全位）。

```python
import math
import time

# --- 步进仿真主循环 ---
sim.setStepping(True)
sim.startSimulation()
time.sleep(0.2)

GRASP  = [0.30,  0.00, 0.085]   # 拾取点
PLACE  = [-0.25, 0.35, 0.085]   # 放置点
ORIENT = [math.pi, 0, 0]       # 末端朝下
SAFE_Z = 0.30

def goto(pos, orient=ORIENT, n_steps=40):
    """移动到 pos, 在 stepping 模式下推进 n_steps 让运动剖面完成."""
    move_to(pos, orient)
    for _ in range(n_steps):
        sim.step()

# 1. 接近 (上方)
goto([GRASP[0], GRASP[1], SAFE_Z])
# 2. 张开夹爪
set_gripper(True); sim.step()
# 3. 下降到抓取位
goto(GRASP)
# 4. 闭合夹爪
set_gripper(False)
for _ in range(10): sim.step()
# 5. 提起
goto([GRASP[0], GRASP[1], SAFE_Z])
# 6. 运至放置区上方
goto([PLACE[0], PLACE[1], SAFE_Z])
# 7. 下降放置
goto(PLACE)
# 8. 松开
set_gripper(True)
for _ in range(10): sim.step()
# 9. 回退
goto([PLACE[0], PLACE[1], SAFE_Z])
# 10. 回安全位
goto([0.0, -0.30, SAFE_Z])

sim.stopSimulation()
```

> 注：若场景中保留 UR5 自带 IK 脚本，则无需在 Python 端重复建 IK 任务——移动 target dummy 即可由脚本驱动关节。本仓库为避免多臂 ZMQ addOn 冻结而剥离脚本，故 IK 在 Python 端显式求解。两种方式择一即可。

## 结果分析与注意事项

### 1. IK 求解策略
- `method_pseudo_inverse`（无阻尼）精度高但末端不可达时会抖动；`method_damped_least_squares`（有阻尼）稳定但牺牲精度。手册教程的标准做法是无阻尼为主、有阻尼兜底（见 `inverseKinematicsTutorial.htm`）。
- 关节限位由 `sim.getJointInterval` / `simIK.setJointInterval` 同步，避免超限。

### 2. stepping 模式是精确节拍的基础
依据 `zmqRemoteApiOverview.htm`，ZMQ 远程 API 支持 stepping（与每步同步）与 non-stepping 两种。本案例与 cop-test 仓库均用 stepping：Python 是时钟主导者，`sim.setStepping(True)` 后每次 `sim.step()` 推进固定一步（cop-test 默认 0.05s）。抓取时序（夹爪闭合等待、运动剖面完成）因此可精确复现。

### 3. 别名与路径的陷阱（本仓库实测）
- `setObjectAlias` 会把含 `/` 的别名转换成下划线（如 `/Mobile/AGV` → `_Mobile_AGV`），导致后续 `getObject('/斜杠路径')` 查询失败（见 [[wiki/02-仿真建模/02-01-分层命名场景构建]] 与 CLAUDE.md §1）。
- 规则：**别名一律不含斜杠**，`getObject` 查询时才用斜杠路径。UR5 子对象用 `/UR5/joint1` 这类路径访问。

### 4. 模型脚本剥离（多臂场景冻结缓解）
- 4.10 下 UR5/iiwa/Franka、AGV、夹爪等内置模型各自携带 Lua 定制/子脚本，多个模型组合时脚本在 ZMQ addOn 层争用，导致启动约 3 帧处整场冻结并报 `abort execution Connectivity >> ZMQ remote API server@addOnScript`。
- cop-test 的缓解（见 `src/build_scene.py` 的 `_strip_model_scripts`）：加载每个模型后按 `object_script_type` + 别名含 "script" 匹配并 `removeObjects` 剥离脚本子对象；同时统一全臂为 UR5（6 轴）避免关节数不匹配。本案例单臂不会触发此问题，但多臂部署时务必剥离。

### 5. 关节句柄采集容错
- `sim.getObjectsInTree` 在仿真未启动或子树含不可查询对象时会抛 "Operation cannot be accomplished in current state"。cop-test 的 `RobotArmAnimator._collect_arm_joints()`（`src/factory_robot.py`）加了全场景关节扫描回退 + HOME 姿态预置：0 关节时输出 WARNING 而非静默失败。本案例单臂通常不会触发，但批量化时参考此容错。

### 6. 关节位置 vs 目标位置
- `sim.setJointPosition` 直接设关节当前位置（无运动剖面，瞬移）。
- `sim.setJointTargetPosition` 设目标位置，运动学/动态位置控制模式下按速度/加速度/加加速度平滑运动（见 [[wiki/01-API参考/api/api-simSetJointTargetPosition]]）。本案例用 IK 求解后关节由 `handleGroup` 同步，若需关节级平滑运动可改用 `setJointTargetPosition`。

## 扩展方向

1. **视觉引导** — 添加视觉传感器，用颜色识别确定工件位置，`getObjectPosition` 反馈给 IK target。
2. **传送带跟踪** — 动态抓取移动工件，target 跟随传送带速度前馈。
3. **多目标调度** — 多工件 + 多放置区，参见 [[wiki/06-工业案例/06-02-岛式车间柔性生产案例]] 的岛式车间调度。
4. **避障路径规划** — 复杂环境下用 OMPL 规划关节空间避障路径（见 [[wiki/03-运动规划与控制/03-02-OMPL运动规划]]），`simIK.generatePath` 可在 IK 环境内生成路径。
5. **力控装配** — 加力传感器实现精密轴孔装配，接触力反馈闭环。
