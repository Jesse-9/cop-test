# src 模块参考手册

> **迁移中参考手册**：本文的旧 `factory_*` 模块说明保留历史接口、诊断经验
> 和 MCP 用法；其中关键帧机械臂、位置插值 AGV、非响应物料和静默几何体回退
> 均不属于当前生产架构。新实现以 06-04/06-05 和 `CLAUDE.md` 的工程规范为准。

> `cop-test` 项目源码全部平铺在 [src/](../../../src/) 下（非包，顶层模块），按职责分四层。
> 本文逐文件总结作用、核心导出、用法与设计要点，配合 [[wiki/06-工业案例/06-02-岛式车间柔性生产案例]] 阅读。

## 基础层

### factory_config.py — 集中配置
**作用**：所有位置/尺寸/颜色/路径/节拍/异常阈值集中定义，改它即可调参，不动控制逻辑。命名遵循 `/Warehouse`、`/Island`、`/Conveyor`、`/Mobile`。

**关键配置组**：
| 组 | 内容 | 改后是否需重建场景 |
|----|------|------------------|
| `WORK_ISLANDS` / `WAREHOUSES` / `CONVEYORS` | 岛/仓库/传送带坐标与尺寸 | ✅ 需 `build_scene` |
| `TAKT_TIME` / `PROCESS_TIME` | 各岛节拍/加工时长 | ❌ 重跑仿真即可 |
| `ZMQ_*` / `CONGESTION_TIMEOUT` / `D_E_STARVATION_THRESHOLD` / `MAX_QUEUE_LENGTH` | 通信与异常阈值 | ❌ 重跑仿真即可 |
| `SIM_STEP` / `CONVEYOR_SPEED` / `AGV_SPEED` / `MATERIAL_INTERVAL` | 步长/速度/产出间隔 | ❌ 重跑仿真即可 |
| `MODEL_BASE` / `BUILTIN_MODELS` / `TCP_OFFSETS` / `SENSOR_TOLERANCES` | 内置模型、TCP、传感器和物理标定 | ⚠️ 改动需重建并执行受影响阶段回归 |

**用法**：被所有模块 `import factory_config as cfg` 后引用常量。

---

### factory_core.py — 仿真基础设施层
**作用**：封装与 CoppeliaSim 的底层通信、通信健康监控与结构化日志。是三层架构的"通信与基础设施层"。

**核心导出**：
| 名称 | 类型 | 说明 |
|------|------|------|
| `setup_logger(name, log_file, ...)` | 函数 | 双输出日志器（文件 DEBUG / 控制台 INFO） |
| `CoppeliaConnector` | 类 | ZMQ 连接 + 重连 + 健康检查；核心方法 `connect()`、`check_alive()`、`reconnect_if_needed()`、`_read_version()` |
| `ZMQMonitor` | 类 | 通信层健康检查，`check(sim_time)` 返回状态字符串 |

**要点**：
- Python 是 clock master：`sim.setStepping(True)` 后每次 `sim.step()` 推进一个 `SIM_STEP`，控制与物理严格同步。步进循环由上层 `FactoryController.run()` 直接内联（不另设封装类）。
- `_read_version()` 容错处理 4.10 `coppeliaSimVersion` 信号可能为 `None` 的坑；`check_alive()` 在版本信号空时回退 `getSimulationState()` 探针。
- 场景对象句柄在启动时由 `FactoryController`/`RobotArmAnimator` 经别名扫描匹配采集（因 4.10 别名路径陷阱，不用斜杠路径 `getObject`，见 [[wiki/02-仿真建模/02-01-分层命名场景构建]]）。

---

### factory_types.py — 类型定义与物料工具
**作用**：定义所有枚举、数据类、共享常量与物料创建/删除工具函数。

**核心导出**：
| 名称 | 类型 | 说明 |
|------|------|------|
| `ItemType` | Enum | 物料生命周期阶段：`RAW_A/RAW_B/SEMI_AB/SEMI_AC/RAW_D/SEMI_CE/PART_DE/FINAL` |
| `AGVState` | Enum | AGV 状态：`IDLE/MOVING_B_TO_A/MOVING_D_TO_E/BLOCKED` |
| `AGVTask` | Enum | 运输任务：`B_TO_A`(高优先 p0) / `D_TO_E`(低优先 p1，可饥饿升级) |
| `IslandState` | Enum | 岛状态：`IDLE/PROCESSING/COMPLETE/WAITING_FOR_AGV/TIMEOUT/OFFLINE` |
| `Material` | dataclass | 物料实体（uid/type/位置/所在岛/历史） |
| `AGVJob` | dataclass | AGV 运输任务（task/material_uid/priority/wait_start） |
| `IslandBeatState` | dataclass | 单岛节拍追踪状态 |
| `ITEM_COLOR_MAP` | 常量 | 物料类型→颜色 |
| `lerp_2d(p1,p2,t)` | 函数 | 二维线性插值 |
| `spawn_material(sim,type,pos,...)` | 函数 | 在场景创建物料并返回 `Material` |
| `remove_material(sim,mat)` | 函数 | 从场景删除物料 |

## 控制层

### factory_controller.py — 主控制器（Orchestrator）
**作用**：整合通信、步进、传送带/物料、工作岛、simIK、吸盘、pioneer AGV、
节拍、供料门控和异常处理为完整仿真循环。顶层编排器。

**核心导出**：`FactoryController`

**Public API**：
- `FactoryController(sim, total_time=60.0, log_file="factory_sim.log")` 构造
- `run()` — 启动主循环，按重构后的物理工作流执行每个 `SIM_STEP`

**重构循环顺序**（见 [CLAUDE.md](../../../CLAUDE.md)）：
1. 异常/碰撞/传感器轮询 → 2. UID 物料确认 → 3. `HYBRID_DYNAMIC` 传送带与物料 →
4. 节拍/队列/资源锁 → 5. simIK + UR5 关节目标 → 6. 吸附/抬升/放置/释放 →
7. pioneer p3dx 轮速 → 8. 交接与装配 → 9. UID 日志 → 10. `sim.step()`

**主要私有方法**（按循环顺序）：`_spawn_from_warehouses` / `_move_conveyors` /
`_process_islands` / `_schedule_agv_tasks` / `_update_agv` /
`_handle_ac_transfer` / `_handle_ce_transfer` / `_check_assembly_at_E` /
`_update_scene_positions` / `_update_robot_animations` / `_setup_agv_visual`。

**用法**：
```python
from factory_core import CoppeliaConnector
from factory_controller import FactoryController
conn = CoppeliaConnector(); conn.connect()
ctrl = FactoryController(conn.sim, total_time=60.0)
ctrl.run()
```

### factory_island.py — 工作岛 + 节拍 + 供料门控
**作用**：封装三个紧密耦合组件，协同实现"超时→降级→暂停上游→恢复"闭环。

**核心导出**：
| 类 | 职责 | 关键方法 |
|----|------|---------|
| `IslandController` | 单岛状态机 + 物料队列 | `can_accept()`/`enqueue()`/`update(dt)`/`release_material()`/`confirm_pickup()`/`enter_timeout()`/`exit_timeout()` |
| `BeatTracker` | 节拍偏差监控 + 自动降级/恢复 | `start_cycle()`/`update()`/`check()` |
| `SupplyController` | 上下游供料门控 | `pause()`/`resume()`/`is_paused()`/`is_target_paused()`/`pause_all_upstream()`/`resume_all_upstream()` |

**协同流程**：
```
岛超时 → BeatTracker.check() → IslandController.enter_timeout()
       → SupplyController.pause_all_upstream(目标岛)
连续 3 正常周期 → BeatTracker 自动恢复 → exit_timeout()
               → resume_all_upstream()
```

> `IslandState` 从 `factory_types` 重导出，避免循环导入。

---

### factory_agv.py — 共享 AGV 柔性调度器
**作用**：共享 pioneer p3dx 的任务调度和物理行驶状态机；通过左右轮目标速度
驱动车体，不能用位置插值或车体瞬移替代运动。

**核心导出**：`AGVScheduler`

**设计决策**：
- 单一共享 AGV 消除多 AGV 死锁
- B→A 高优先级（priority=0）
- D→E 低优先级（priority=1），等待 > `D_E_STARVATION_THRESHOLD` 后升级到 0

**Public API**：
| 方法 | 说明 |
|------|------|
| `request_task(task, material_uid, sim_time)` | 提交运输请求入队 |
| `update(dt, sim_time, path_blocked)` | 推进状态机一步（IDLE 时取队首任务） |
| `current_position()` | 读取 AGV 当前物理位姿（只读诊断） |
| `is_available()` | 是否处于 IDLE 可接新任务 |

**状态机**：`IDLE → MOVING_B_TO_A / MOVING_D_TO_E → (完成) → IDLE`；
路径阻塞 > `CONGESTION_TIMEOUT` → `BLOCKED` → 清除后恢复 `IDLE`。

> ⚠ 已知缺陷（见 review）：`_fair_sort_priority_zero` 实际是按 `wait_start` 归并两个已排序子表，
> 结果与普通排序一致，并未真正交替 B→A/D→E；且 preemption 已移除，
> `AGVTask` 注释仍写"可抢占"属 stale contract。详见 [[wiki/06-工业案例/06-02-岛式车间柔性生产案例]] 末尾。

### factory_exceptions.py — 统一异常处理器
**作用**：每步轮询所有异常源，协调恢复，记录异常日志。`poll()` 返回 False 时主循环应紧急停止。

**核心导出**：`ExceptionHandler`

**Public API**：`poll(sim_time, island_controllers, agv_scheduler) → bool`

**异常分类（按优先级）**：
| 优先级 | 异常 | 检测 | 恢复 |
|--------|------|------|------|
| 1 | ZMQ 通信异常 | ZMQMonitor | 判定 dead → 紧急停止 |
| 2 | 工位超时 | BeatTracker | IslandController→TIMEOUT → SupplyController 暂停上游 |
| 3 | 物料溢出 | 队列 ≥ `MAX_QUEUE_LENGTH` | 暂停上游，降到 ≤ 一半后恢复 |
| 4 | AGV 拥堵 | BLOCKED > `CONGESTION_TIMEOUT` | 记录事件 |

内部检查方法：`_check_workstation_timeouts` / `_check_overflow` / `_check_congestion` / `_record`。

## 视觉层

### factory_robot.py — 历史机械臂动画兼容层
**作用**：保留旧演示接口，不得用于当前方案的取放控制；生产取放由
`stage1/ur5_ik_controller.py`、`stage1/suction_controller.py` 和专用 TCP/传感器完成。

**核心导出**：`RobotArmAnimator`

**Public API**：
| 方法 | 说明 |
|------|------|
| `__init__(sim, logger)` | 采集各岛机械臂关节句柄 |
| `trigger(island_key, anim_name)` | 触发某岛机械臂播放指定动画 |
| `update(dt, islands, agv_scheduler)` | 每步推进：PROCESSING→自动 idle_wiggle，并推进所有播放中的动画 |
| `on_assembly()` | E 岛装配完成时双臂协同（E_C + E_D） |

**动画类型**（对应 `cfg.ARM_ANIMATIONS`）：
- `pick_and_place` — 完整抓取-放置循环
- `assemble` — E 岛双臂协同装配
- `idle_wiggle` — PROCESSING 期间轻微活动

**迁移限制**：关键帧线性插值不是 IK，也不能形成物料 UID 生命周期证据；新代码不得调用
`trigger()` 作为生产任务完成条件。

> ⚠ 已知缺陷：docstring 承诺"岛 COMPLETE→触发 pick_and_place"，但 `update()` 只在 PROCESSING 触发 idle_wiggle，COMPLETE 的 pick_and_place 未自动触发（仅 E 的 assemble 由控制器显式调用）。

## 接入层

### factory_mcp_server.py — MCP 服务器
**作用**：通过 MCP (Model Context Protocol) 向 Claude Code 暴露仿真完整生命周期工具，让 AI 像调函数一样编排 CoppeliaSim。

**架构**：
- stdio 传输，Claude Code 启动本进程，长驻管理 ZMQ 连接
- 双连接：主连接 (写/控制类工具 + 主仿真循环) 与 `ro_connector` (只读诊断工具 +
  `run_lua`) 经 `ro_lock` 隔离，避免运行中诊断工具与主循环互挤（解决假断连）
- 仿真在守护线程：`start_simulation` 不阻塞；`status`/`stop`/`step` 可运行中查询
- **默认后端为 `stage1`**（当前阶段一实现）；`build_scene`/`start_simulation`/
  `get_config`/`set_config` 接受 `backend="legacy"` 才回到旧五岛参考层。
  `start_simulation` 对 stage1 额外接受 `target`/`fault`；步骤 1.2 起
  **不再自动重建场景**，只启动当前已加载且已校验的场景/工件。

**24 个工具**：
| 档 | 工具 | 说明 |
|------|------|------|
| 连接/场景 | `connect` / `build_scene(clear, backend)` / `save_scene(phase, parent, note, force, protected)` / `load_scene(artifact, phase)` / `validate_scene(artifact)` / `lifecycle_status` / `disconnect` | 连接 / 构建 / 保存工件 / 加载工件 / 只读校验 / 生命周期状态 / 断开 |
| 生命周期 | `start_simulation(total_time, log_file, backend, target, fault)` / `stop_simulation` / `step_simulation(n=1)` | 启动（守护线程；stage1 需已校验场景）/ 停止 / 单步或多步（上限 1000；stage1 需先 pause） |
| 状态/配置 | `status` / `get_config(backend)` / `set_config(key, value, backend)` / `tail_log` / `tail_coppelia_console` | 实时状态 / 读配置 / 改配置 / 读 Python 日志 / 读 ConPTY 控制台日志 |
| A 读取 | `get_object_pose` / `list_objects` / `read_signal` / `get_object_tree` | 读位姿 / 列物体 / 读信号 / 列子树（只读，走 ro_connector） |
| B 诊断 | `inspect_scene_state` / `get_simulation_state` / `run_lua` | 场景快照 / 轻量状态探针 / 远程 Lua 探针（带护栏） |
| C 控制 | `pause_simulation` / `resume_simulation` | 暂停控制逻辑（stage1 同时停 runner 以便手动 step；legacy 物理仍推进）/ 恢复 |

**注册**：经 [.mcp.json](../../../.mcp.json) 注册，Claude Code 在本项目会话自动加载。


## CLI 入口

### build_scene.py — 场景构建器
**作用**：在 CoppeliaSim 中构建新方案场景，遵循扁平下划线别名并强制加载
`generic conveyor (belt).ttm`、`UR5.ttm`、`suction pad.ttm` 和 `pioneer p3dx.ttm`。
生产模型缺失必须失败；primitive 仅用于诊断场景。

**关键函数**：
- `build_scene(sim)` — 主构建入口
- `clear_scene(sim)` — 幂等清场（构建前调用，避免别名冲突）
- `connect(host, port)` — 连接 ZMQ 并返回 `(client, sim)`
- `create_hierarchy_roots(sim)` — 建立 `/Warehouse`/`/Island`/`/Conveyor`/`/Mobile` 层级根
- `create_conveyor` / `create_robot_arm` / `create_floor` 等子构建器

**用法**：
```bash
uv run python src/reference/build_scene.py [--host HOST] [--port PORT]
# 或入口脚本
uv run build-scene [--host HOST] [--port PORT]
```

> ⚠ 注意 `clear_scene` 类型清单含 `object_camera_type`/`object_light_type`，会删默认相机/灯光。

---

### run_simulation.py — 仿真 CLI 入口
**作用**：解析 CLI 参数 → 初始化日志 → 建立 ZMQ 连接 → 创建 `FactoryController` 并启动主循环。

**用法**：
```bash
uv run python src/reference/run_simulation.py [--host HOST] [--port PORT] [--time TIME] [--log LOG]
# 或入口脚本
uv run run-simulation [--time 60]
```
参数：`--time` 仿真总时长秒（0=无限直到 stop，默认 60）；`--log` 日志路径（默认 `factory_sim.log`）。

---

### main.py — 交互菜单入口
**作用**：交互式菜单，选择 (1) 构建场景 或 (2) 运行仿真。延迟导入对应入口模块。

**用法**：`uv run python src/reference/main.py`
