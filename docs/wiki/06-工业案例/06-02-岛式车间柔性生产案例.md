# 岛式车间柔性生产仿真案例

> 本案例对应仓库 v1 产品 `flexible-factory` 1.0.0：五岛 `L5_UFLOW`、共享
> AGV、四条物流线和 E 岛配对，唯一用户运行模式 `full_flow`。拓扑、节拍和
> 4.10 实测经验保留；实现细节以
> [工程参考](../../../PROJECT_ENGINEERING_REFERENCE.md) 和
> [V1 实施报告](../../implementation/reports/v1-product-implementation.md) 为准。

> 真实项目 `cop-test`：5 个工作岛 + 2 仓库 + 共享 AGV + 4 传送带的柔性生产线仿真。

## 场景描述

岛式车间（island workshop）是一种柔性制造布局：把加工单元按“岛”组织，
每个岛独立完成一道工序，岛间通过传送带和 AGV 柔性转运。本案例拓扑：

```
S1 仓库 ──S1_to_A──► A 岛 ──A→C刚性──► C 岛 ──C_to_E──► E 岛 (装配)
        └──S1_to_B──► B 岛 ◄── AGV B→A (高优先) ──┘
S2 仓库 ──S2_to_D──► D 岛 ── AGV D→E (低优先,饥饿升级) ─────────────┘
```

E 岛收到 C 线半成品（SEMI_CE）与 D 线零件（PART_DE），**配对装配**出金色成品 FINAL。

## 系统架构（v1 分层）

```
flexible-factory CLI                  ← 唯一用户入口
        │
application (lifecycle/run/coordinator)  ← 生命周期、运行用例、多岛编排
        │
domain / simulation / artifacts       ← 规则与物料 / 仿真适配 / 工件与迁移
        │ ZMQ Remote API (stepping)
CoppeliaSim 4.10 (物理引擎 + 内置模型)
```

**时钟主导**：Python 端 `sim.setStepping(True)` 后，每次 `sim.step()` 推进一个 `SIM_STEP`（默认 0.05s），
控制逻辑与物理严格同步——这是精确工业节拍时序的基础。

## 关键步骤

### 1. 加载已校验的工件

v1 启动不构建、不清场，只加载 `docs/scene_artifacts/v1/current.json` 指向的
受保护工件；`run` 在取得运行锁后执行完整只读校验，校验失败拒绝启动。
分层命名与句柄规则见 [[wiki/02-仿真建模/02-01-分层命名场景构建]]。

### 2. 步进式仿真循环

`application/run.py` 每个 `SIM_STEP` 按固定顺序推进：异常轮询 → 通信暂停
判定 → 仓库产出 → 传送带移动 → 岛处理 → AGV 调度 → AGV 状态机 →
A→C 刚性传输 → C→E 传送带 → E 岛装配 → 场景位置同步 → 机械臂动画 →
`sim.step()`。

### 3. 共享 AGV 柔性调度

单 AGV 双航线：

- **B→A**：基础优先级 0（最高），不可抢占
- **D→E**：基础优先级 1，等待 > 15s 饥饿升级到 0
- **拥堵**：路径占用 > 5s → BLOCKED → 重规划/恢复

v1 使用 `simulation/agv.py` 与 `simulation/agv_route.py`；航线要求全部 dock
空闲，并持有实际经过的直道资源。

### 4. 工业节拍追踪

`BeatTracker` 对照 `TAKT_TIME={A:5,B:3,C:4,D:6,E:8}s`：偏差 > 1s 警告，
实际 > 节拍×1.5 → 超时降级，连续 3 正常周期 → 自动恢复。

### 5. 异常与安全

ZMQ 断连重试、AGV 拥堵、工位超时、物料溢出构成四类基础异常处理。v1 另有
运动层安全锁存和停带联锁：故障后冻结现场，任务不得改写成 DONE，锁存不自动
恢复。

## 关键代码片段

步进同步核心：

```python
sim.setStepping(True)
sim.startSimulation()
for _ in range(n_steps):
    # 固定顺序控制逻辑…
    sim.step()                 # 推进物理引擎一个 SIM_STEP
```

E 岛装配门控：

```python
def _check_assembly_at_E(self):
    # E 队列同时持有 SEMI_CE 与 PART_DE → 配对消耗 → 生成 FINAL
    if has_pair:
        final = spawn_material(ItemType.FINAL, e_pos, ...)
        self.assembled_count += 1
```

## 运行入口

```bash
flexible-factory load
flexible-factory validate        # 可选诊断
flexible-factory run --scenario full_flow --time 700
```

详细命令、工件与日志位置见 [[wiki/98-ProjectUsage/USAGE]]。MCP 不在 v1 范围。

## 结果与已知限制

- v1 `full_flow` 实机验收通过：FINAL 由 UID 1 和 3 配对生成，无失败/阻塞
  任务，无安全锁存，资源全部释放；证据见
  [v1 报告](../../implementation/reports/v1-product-implementation.md)。
- `conveyor_fault` 代表性故障回归通过：停带后冻结、无 FINAL、资源释放。
- `agv_blocked` 尚未执行，不得报告为通过。
- 阶段三安全锁存不自动恢复；统一故障恢复未实现。

## 小结

本案例展示了 CoppeliaSim 外部控制的完整工程化范式：已校验工件 → 分层架构 →
步进同步控制 → 柔性调度 + 节拍 + 异常 → 可追溯验收报告。可作为工业柔性生产
线数字孪生的起点。
