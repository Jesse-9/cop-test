# 岛式车间柔性生产仿真案例

> **历史案例 / 迁移参考**：本文描述的是旧五岛、共享 AGV 和脚本编排架构，
> 用于保留拓扑、节拍和 4.10 冻结排查经验。它不是当前生产实现的权威规范。
> 当前实现以 [[wiki/06-工业案例/06-04-柔性工业车间重构方案]]、
> [[wiki/06-工业案例/06-05-柔性工业车间分阶段执行步骤]] 和 `CLAUDE.md`
> 的工程不变量为准：`HYBRID_DYNAMIC`、simIK + suction pad、proximity sensor、
> pioneer p3dx 轮速控制和动态响应物料。

> 真实项目 `cop-test`：5 个工作岛 + 2 仓库 + 共享 AGV + 4 传送带的柔性生产线仿真。

## 场景描述

岛式车间（island workshop）是一种柔性制造布局：把加工单元按"岛"组织，
每个岛独立完成一道工序，岛间通过传送带和 AGV 柔性转运。本案例拓扑：

```
S1 仓库 ──S1_to_A──► A 岛 ──A→C刚性──► C 岛 ──C_to_E──► E 岛 (装配)
        └──S1_to_B──► B 岛 ◄── AGV B→A (高优先) ──┘
S2 仓库 ──S2_to_D──► D 岛 ── AGV D→E (低优先,饥饿升级) ─────────────┘
```

E 岛收到 C 线半成品（SEMI_CE）与 D 线零件（PART_DE），**配对装配**出金色成品 FINAL。

## 系统架构（三层）

```
MCP 工具层 (factory_mcp_server.py)      ← Claude Code 接入
        │ 调用
Python 控制层 (controller/island/agv/…)   ← 编排 + 调度 + 节拍 + 异常
        │ ZMQ Remote API (stepping)
ZMQ 基础设施层 (factory_core.py)         ← 连接/重连/步进/句柄
        │ TCP 23000
CoppeliaSim 4.10 (物理引擎 + 内置模型)
```

**时钟主导**：Python 端 `sim.setStepping(True)` 后，每次 `sim.step()` 推进一个 `SIM_STEP`（默认 0.05s），
控制逻辑与物理严格同步——这是精确工业节拍时序的基础。

## 关键步骤

### 1. 分层构建场景
见 [[wiki/02-仿真建模/02-01-分层命名场景构建]]：`/Warehouse`、`/Island`、`/Conveyor`、`/Mobile` 四个根，
旧案例曾允许内置模型缺失时回退几何体；该策略仅保留作诊断经验，当前生产构建
必须对指定内置模型缺失直接失败。

### 2. 步进式仿真循环（13 步固定顺序）
[factory_controller.py](../../../src/factory_controller.py) 每个 `SIM_STEP` 按固定顺序：
异常轮询 → 通信暂停判定 → 仓库产出 → 传送带移动 → 岛处理 →
AGV 调度 → AGV 状态机 → A→C 刚性传输 → C→E 传送带 → E 岛装配 →
场景位置同步 → 机械臂动画 → `sim.step()`。

### 3. 共享 AGV 柔性调度
单 AGV 双路径：
- **B→A**：基础优先级 0（最高），不可抢占
- **D→E**：基础优先级 1，等待 > 15s 饥饿升级到 0
- **拥堵**：路径占用 > 5s → BLOCKED → 重规划/恢复

### 4. 工业节拍追踪
`BeatTracker` 对照 `TAKT_TIME={A:5,B:3,C:4,D:6,E:8}s`：偏差 > 1s 警告，
实际 > 节拍×1.5 → 超时降级，连续 3 正常周期 → 自动恢复。

### 5. 四类异常处理
ZMQ 断连重试、AGV 拥堵、工位超时、物料溢出——见 `factory_exceptions.py`。

## 关键代码片段

步进同步核心：

```python
sim.setStepping(True)
sim.startSimulation()
for _ in range(n_steps):
    # 13 步控制逻辑…
    sim.step()                 # 推进物理引擎一个 SIM_STEP
```

E 岛装配门控：

```python
def _check_assembly_at_E(self):
    # E 队列同时持有 SEMI_CE 与 PART_DE → 配对消耗 → 生成 FINAL
    if has_pair:
        final = spawn_material(ItemType.FINAL, e_pos, ...)
        self.assembled_count += 1
```

## MCP 集成
[factory_mcp_server.py](../../../src/factory_mcp_server.py) 经 [.mcp.json](../../../.mcp.json) 注册，
向 Claude Code 暴露 20 个工具，分三档：

- **连接/场景/生命周期/配置** (11)：`connect`/`build_scene`/`disconnect`/
  `start_simulation`/`stop_simulation`/`step_simulation`/`status`/`get_config`/`set_config`/`tail_log`/`tail_coppelia_console`
- **A 读取** (4，走只读 `ro_connector`)：`get_object_pose`/`list_objects`/`read_signal`/`get_object_tree`
- **B 诊断** (3)：`inspect_scene_state`/`get_simulation_state`/`run_lua`
- **C 控制** (2)：`pause_simulation`/`resume_simulation`

`step_simulation` 已扩展为 `step_simulation(n=1)`（上限 1000，支持多步逐帧排查冻结）。
详见 [wiki/98-ProjectUsage/MCP_USAGE.md](../../98-ProjectUsage/MCP_USAGE.md)。

## 结果与已知限制

- ✅ 步进同步、节拍追踪、AGV 优先级调度、四类异常处理均按设计运行
- ⚠ 完整场景（6 机械臂 + 传送带 + AGV）启动后约 3 帧处可能冻结（`state=8`），
  推断为某机械臂模型脚本组合阻塞；MCP `status` 已内置启动探活告警
- ⚠ 单 ZMQ 连接共享：运行中 `status` 可能瞬时返回 `connected:false`（连接被主循环占用），属正常

## 小结

本案例展示了 CoppeliaSim 外部控制的完整工程化范式：分层场景 → 步进同步控制 →
柔性调度 + 节拍 + 异常 → MCP 化供 LLM 编排。可作为工业柔性生产线数字孪生的起点。
