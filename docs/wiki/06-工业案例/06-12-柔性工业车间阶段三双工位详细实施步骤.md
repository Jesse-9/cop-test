# 柔性工业车间阶段三：双工位详细实施步骤

> 本文把阶段三拆成布局收敛、共享区域安全、第二单元接入、AGV 两站转运、最小任务调度和精简验收。阶段一/二已有能力优先复用；本阶段不重做场景生命周期、碰撞探针或单工位控制器，也不提前实现五岛生产线和通用故障恢复。阶段一/二遗留动作质量门槛见 [[wiki/06-工业案例/06-11-柔性工业车间阶段一二遗留动作质量与后续优化规划]]。

## 1. 阶段目标与边界

建立两个可独立启停的 UR5 工位，共用一条输入传送带和一台轮速驱动 AGV。Station A 取料并装载 AGV；AGV 将指定 UID 物料送至 Station B；Station B 卸载、处理并完成放置。需要证明物料身份连续、站点互不串线、AGV 到站稳定后才能装卸、共享运动区域不会造成两臂/AGV/物料冲突。

本阶段包含双工位场景与控制器接入、两站 dock、A→B→A 路线、UID 任务流、共享资源互斥、必要背压及堵塞暂停。排除多 AGV、五岛、视觉识别、真空力学和故障锁存后的自动恢复。阶段三遇到阶段二安全锁存时，保持停止并记录失败；复位/续作由项目最终故障恢复阶段处理。

## 2. 设计依据与复用基线

### 2.1 项目内已有证据

- **布局起点**：阶段 1.1 的 `L1_S1` 已将 UR5 放在传送带 `+Y` 侧，基座 `(-0.20, 0.55, z)`，取料区域、station 与 AGV dock 均通过当时的离散可达性筛选。该证据支持“从传送带侧方取料”作为首选，不支持把机器人放在输送方向末端延长线上；但其坐标只对单工位有效，不能直接复制两份作为最终双工位布局。详见 [[wiki/06-工业案例/06-07-柔性工业车间步骤1.1-布局与无挡板取料验证]] 与 [[implementation/PHASE0_BASELINE]]。
- **场景与对象复用**：继续使用 CoppeliaSim 内置 conveyor、UR5、suction pad、pioneer p3dx，保持 `HYBRID_DYNAMIC`、别名叶匹配、UID 绑定和阶段一对象生命周期规则。
- **物理与安全复用**：复制阶段二 contact、collision runtime、shadow probe、ConfigurationChecker、LocalPlanner、Trajectory executor、SafetyLatch 和 conveyor stop monitor 的既有契约。每台机器人使用独立 IK context 和自己的碰撞几何；未知查询仍拒绝运动。
- **工件与运行入口复用**：从只读 stage2 父工件派生阶段三工件；沿用 manifest/契约校验、build/load/validate/start/stop 和运行锁，不复制第二套生命周期。
- **动作质量约束**：AGV 的 q[0]/q[3] 行程与 jerk 尚有未关闭问题（06-11 MQ-01～MQ-05）。新布局、新路线必须记录分段实测，不把原先单工位通过结果外推为双工位通过。

### 2.2 外部工程参考原则

布局方法参考 ISO 10218-2 的机器人应用集成思路：按完整工作空间、设备交互、人员/设备通道和可预见运行状态组织单元，再验证集成后的应用；此规划不是符合性评估或安全认证。标准入口：[ISO 10218-2:2025 页面](https://www.iso.org/standard/73933.html)。仿真阶段使用项目已有 CoppeliaSim 4.10 场景、simIK、碰撞查询和对象 pose 测量；正式建图前以实际模型包围盒和当前工件测量为准，不能用示意坐标代替验证。

## 3. 双工位布局方案

### 3.1 推荐拓扑：传送带侧置、两站外展、AGV 连接两站

继续沿用“机械臂靠传送带侧方”的布局逻辑，保留传送带轴向、有效行程和阶段一取料传感区域。两个工位分别布置在可达的侧向工作区，工作台放在各自机械臂外侧，AGV dock 位于机械臂能安全装卸、AGV 又能沿外围通道离开的区域。优先让两臂的常用工作包络朝各自工位与取料区，不让机械臂基座、工作台或 AGV 通道占用传送带末端延长线。

概念图仅表示相对关系，不表示坐标比例：

```text
                   工作台 A
                      ↑
                UR5_A 基座 ── dock A
                      ↘
入口 →═══════ 输入传送带/共享取料区 ═══════→ 末端
                      ↙
                UR5_B 基座 ── dock B
                      ↓
                   工作台 B

           AGV 路线连接 dock A 与 dock B
```

传送带两侧镜像布置可作为首选候选，但不是未经验证的结论：双臂可能在共享取料区或跨带姿态下互相干涉。与“同侧沿 X 错位布置”作为备选一起做有限几何/IK/碰撞筛选；不开展大规模布局参数扫描。若两臂工作空间仍重叠，阶段三先通过共享区域资源锁串行化进入，不为追求并行而放宽碰撞过滤。

### 3.2 候选比较与选型步骤

1. **冻结不动项**：输入传送带中心、轴向、尺寸、有效 pad/传感器/停带区和高度沿用 L1_S1；模型尺寸、TCP/吸盘安装、UR5/AGV 物理参数沿用已验收工件。任何确需修改的项目单独记录并派生新工件。
2. **建立两个候选而非网格扫描**：A 方案为传送带两侧各一台 UR5、工位向外布置；B 方案为同侧沿输送轴向错位、工位向外或后侧布置。候选均从 L1_S1 的基座/工作台相对关系出发，使用物理尺寸和通道包络定位，不先指定未经测量的新坐标。
3. **确定必需空间包络**：在 XY 平面画出 conveyor、每台 UR5 基座/支撑台、station、AGV 车体与转弯扫掠、两站 dock、人员/维护通道的占用矩形或多边形。使用 CAD/实际模型包围盒与 AGV footprint；为机器人扫掠另用阶段二碰撞几何，不把矩形间不重叠当作无碰撞证明。
4. **只筛关键目标**：每个布局检查 pick、pre-pick/lift/pre_place（含横向绕行）、station 放置与接近、dock 装卸目标的完整 simIK 位姿与关节限位。中心目标和对边界有影响的关键点即可，不复制步骤 1.1 的前沿/中部/后沿大矩阵。
5. **做跨设备通路检查**：检查每臂完整空载/带载取放链、AGV 满载 A→B→A 路线和两臂静态/动态互扰。若阶段二探针暂不支持双机器人对象对查询，阶段三先在控制层以共享资源锁防止任意两臂同时进入相交 envelope，并在规划阶段补足真实 inter-arm collision query；不能把互斥锁冒充碰撞检查已实现。
6. **选取最简单可行方案**：优先选改动 L1_S1 最少、取料/放置均有 IK 余量、AGV 路线清晰、共享危险区最小且碰撞规则容易复用的方案。若两候选都不满足，不增加机器人/传送带复杂度，先调整 station/dock 相对位置并重测。将选中与淘汰候选的坐标、可达性、主要碰撞/通道原因写入阶段三记录。

选型门槛：每台 UR5 到其 pick、station 和 dock 装卸目标都可达；AGV 不需穿过另一机械臂的基座或工作台；AGV 转弯扫掠不穿越 station 占地；任意共享空间有明确的互斥所有者；任何活动机构之间没有未检查的轨迹交叉。

## 4. 阶段实施步骤

### 步骤 3.0：派生场景与冻结接口

1. 从已验收 stage2 工件只读派生 `stage3` 副本，记录 parent artifact、scene/config digest、阶段二控制器和测试版本。
2. 固定输入 conveyor、AGV、现有 A 单元和阶段二契约；仅在 stage3 副本构建第二单元。
3. 复用现有 `LayoutSpec` 思路扩展为 station list/robot list/dock list 数据结构；不要复制 `stage1.config` 全局常量并产生两个互相覆盖的配置源。
4. 对象 alias 使用稳定编号（如 `Island_A/Robot_UR5_01/...`、`Island_B/Robot_UR5_02/...`）；句柄从 alias 表解析，不依赖构建顺序。
5. build → save → load → start/stop 继续经步骤 1.2 生命周期入口；start 在
   启动点自动校验，validate 只在需要查看差异报告时显式调用；阶段三 runner
   只做组合路由。

**本步交付**：一份阶段三布局规格、候选筛选记录和通过校验的派生工件。只有新增对象、布局/碰撞几何与契约需测，不重复运行完整阶段一生命周期测试集。

### 步骤 3.1：第二工位与第二控制器

1. 从阶段一的场景构建函数复用工位、sensor、UR5、吸盘和目标位创建逻辑，以参数化工位 ID 构建 B；不要复制一份有独立 bug 修复周期的整套构建代码。
2. 为 `Robot_UR5_02` 建独立 IK environment/group、shadow arm、planner、executor、collision runtime 和 safety latch；共享的只应是纯配置/算法，不共享 simulator handle、IK context 或可变任务状态。
3. 第二工位传感器绑定自己的 dock/目标 UID；任务中的 source/destination 明确到 station ID。
4. 单独运行 A 一次、B 一次，验证互不改写对方关节、target、物料父子关系、状态机或安全锁存。

**通过条件**：任一工位可单独启用；控制器、IK context、资源和 alias 唯一；A/B 的任务结果与报告可区分。

### 步骤 3.2：共享区域、碰撞和资源互斥

1. 定义少量实际资源：`pick_zone`（共享传送带取料区）、`dock_A`、`dock_B`、`agv_lane`、每个 UR5 的局部 motion envelope 和目标工位。
2. 取料区单一令牌：同一时刻只允许一个 UR5 执行跨入/离开 conveyor envelope 的运动；锁从计划开始持有，到手臂退出共享区且 TCP/载荷安全后释放。
3. AGV lane 与 dock 锁由一条 AGV 调度器持有；AGV 在 dock 对接或沿共享路线行驶时，禁止机器人进入对应冲突 envelope。
4. 将第二台 UR5 及对方载荷纳入对臂碰撞策略。若未能可靠查询双臂碰撞，所有可能相交的动作通过 envelope 互斥串行执行，不能同时运动。
5. 所有获取锁按固定资源顺序申请；失败/停止时释放未执行任务持有的普通调度锁，但阶段二安全锁存不能通过释放资源或任务重排清除。
6. 日志记录资源名、所有者、申请/释放时刻和等待任务，便于复现死锁/饥饿问题。

不建设通用资源图框架：两个工位、一台 AGV 用小型明确定义的锁表即可。

### 步骤 3.3：AGV A↔B 路径与动作质量基线

1. 用选定布局为 A/B dock 建立低复杂度二维路线，路径点只在转向、障碍或停靠姿态确实需要处设置。沿现有轮速控制和到站判断扩展，不用位置瞬移。
2. 测量空载和带载的 A→B、B→A 停车误差、航向误差、速度稳定窗口及载荷相对滑移。每个方向各做一次基线运行；失败或重复性不明时只针对失败方向补测。
3. 复用阶段二运动计划、执行器和安全锁存，记录本规划要求的分段 `q[0:6]` TV、jerk、载荷净空和执行误差；并将实测值与基线阶段二比较。具体阈值沿用 06-11 冻结值，若未冻结，先声明待测而不虚构阈值。
4. 不先引入 OMPL。仅当既定路线被局部/几何检查拒绝，且确认存在绕障通路时，再提出独立的全局路线规划需求。

**通过条件**：AGV 满载可双向到站并停稳，停靠误差满足两工位装卸窗口；载荷未越出载台/安全边界；堵塞时进入 `BLOCKED` 并停止增加轮速。

### 步骤 3.4：定义 UID 任务流和状态转换

最小工作流为：

```text
物料在输入 conveyor 被识别并停稳
  → station A 锁定 pick_zone，按 UID 抓取并放到 AGV
  → 确认物料仍在载台、释放成功，关闭 A 装载任务
  → AGV 获取 agv_lane/dock_B，带指定 UID 行驶到 B
  → 到站并稳定后，station B 获取 dock_B，按同一 UID 卸载/处理
  → 目标状态确认后结束任务并释放资源
```

1. 每个任务携带 `task_id`、物料 UID、source station、destination station、当前阶段、AGV dock 和尝试计数。
2. 每次交接必须由物料状态/父对象/位置证据确认；sensor 只报告目标，不替代 UID 确认。
3. AGV 出发前确认载台只含目标 UID；到站后确认目标 dock、车体稳定和物料仍在载台，再许可卸载。
4. `FAILED/BLOCKED` 不转成 `DONE`；安全锁存后冻结原任务，不自动重试/续作。阶段三只实现无安全锁存时的正常排队、BLOCKED 检测及人工移除障碍后的受控续行。
5. 先串行跑通完整 A→B 闭环，再启用两个工位的并发请求；队列和资源锁不应改变既有单工位动作行为。

### 步骤 3.5：必要的背压和堵塞处理

仅实现阶段三闭环所需行为：

- AGV 路线占用/跟踪超时：置 `BLOCKED`，保持停止，保留 UID/task 和当前阶段。
- B 工位不可用或载台占满：暂停向 AGV 派发，不继续向满队列生产。
- 共享 pick zone 忙：其他取料任务等待，不重复抓取或改变已锁定 UID。
- 人工清障后，若没有 safety latch 且当前位置/路线/所有权可重新确认，可按低速正常 BLOCKED 流程续行；涉及安全 latch 的故障转入项目最终恢复阶段。

不实现无限重试、自动复位、自动释放不确定载荷或复杂优先级策略。阶段三仅保留一个普通关键任务优先级和等待时间记录；若没有实际饥饿需求，不做优先级提升算法。

## 5. 精简验收

复用阶段一/二已通过的单元和安全证据，只验证阶段三新增/受影响链路。无需逐包 smoke、固定次数的大矩阵、重复进程重启或重复证明已测的模型 API。

| 用例 | 一次运行覆盖的内容 | 通过条件 |
|---|---|---|
| A→B 闭环 | 指定 UID 从 conveyor 经 A 装载、AGV 到 B、B 卸载并完成；同时记录两站控制器和 AGV 运动剖面 | UID 全程一致；每次交接有证据；停靠与载荷稳定；无碰撞/锁存；任务只有在目标确认后 DONE |
| 竞争与重复请求 | A/B 同时提交共享取料区或 AGV 请求，并对同一 UID 重复提交一次 | 资源互斥生效；无双重吸附/重复派车；锁最终释放；任务可追踪 |
| 单次受控阻塞 | 在 AGV 路线上放置一个已知障碍，随后移除 | 先进入 BLOCKED 并停车；仅在无 safety latch、现场与资源所有权重新确认后续行；原任务不得误报完成 |
| 不稳定卸载拒绝 | 只注入一种明确 dock/载荷不稳定条件 | 机器人不释放载荷，任务不 DONE，现场保留且有失败原因 |

若 A→B 运行已同时覆盖两个 UR5、collision query、载荷跟踪、目标 sensor 和报告记录，则不另拆对应单项测试。异常注入只保留上表中能验证阶段三新边界的两个情形。

## 6. 退出条件

- 两个工位可独立运行，使用独立 IK 与运行状态；共享 conveyor/AGV/相交运动区有明确互斥。
- 所选布局在完整 pick/place/dock 目标可达，AGV 双向路线通畅且无未检查的机器人/车辆冲突。
- A→B 指定 UID 闭环成功，资源不泄漏、不重复执行，物料不丢失/串线。
- AGV 停靠、带载稳定与动作质量满足阶段三冻结指标；新路线未把 q[0]/q[3]/jerk 问题藏到其他轴或段。
- 阻塞和不稳定卸载按预期停止/拒绝；阶段三未绕过阶段二 safety latch，也未把失败任务记为 DONE。
- 仅保存本阶段派生工件、精简验收报告和运行记录；通过的阶段一/二证据以链接复用。

- **选定布局**：`L2_MIRROR`（传送带两侧镜像；A 单元沿用 L1_S1，
  B 单元关于 Y=0 镜像）。A/B 基座 `(-0.20, ±0.55, 0.30)`，置物台
  `(-0.20, ±1.20)`，AGV dock `(0.40, ±0.70)`，共享取料区
  `(-0.20, 0.0, 0.50)`。
- **淘汰候选**：`L3_SAME_SIDE`（同侧沿 X 错位）在静态筛选中因 B 臂取料
  不可达、Island/dock 压占、AGV 路线轴/通道检查失败被拒绝；未做大规模
  参数扫描。
- **父/子工件**：父 `stage2/L1_S1/v013_20261024_232558`；阶段三
  `stage3/L2_MIRROR/v004_20261025_131837`，契约
  `stage3_contract_20261025_v1`，109 项构建契约、229 项只读校验通过。
- **资源锁表**：`pick_zone → agv_lane → dock_A → dock_B → arm_A →
  arm_B`；`pick_zone` 在 TCP 退出 conveyor envelope 后释放；AGV 运输
  任务持有 `agv_lane`/`dock_B`，B 工位在运输途中记录 WAIT 但不到提前
  获取；失败/停止释放普通调度锁，安全锁存不由资源释放清除。
- **A→B→A 路线**：x=0.40 直线穿梭，A→B 前进带载、B→A 倒车空载，
  不在 dock 处原地旋转；名义速度 0.12 m/s。
- **四个验收用例结果**：
  - A→B 闭环：3 任务 DONE，停靠误差 0.019733 m，航向 −0.000203 rad，
    滑移 0.0；
  - 竞争/重复请求：3 个重复请求被拒绝，dock_B 等待 1 次，资源最终释放；
  - 受控阻塞：t=44.90 BLOCKED，t=54.95 清障续行，停靠 0.019773 m；
  - 不稳定卸载：`LOAD_DRIFT(0.0400>0.02)` 锁存，unload FAILED，载荷仍
    `HELD_BY_SUCTION`，未释放、未 DONE。
- **分段动作质量**：A 装载总 TV 18.731 rad，`TV(q[3])=8.133`；
  `pre_place` 单段 `TV(q[3])=4.931`；B 卸载总 TV 11.649 rad。实测
  jerk 峰值 113.9–120.7 rad/s³ > 100，MQ-01/02/03 仍未关闭。
- **未解决问题**：阶段 2.1 统一故障恢复未实现（锁存后冻结原任务）；
  OMPL 未启用；多物料/多 AGV/两臂并发未验证；碰撞检查仍为离散采样。
  这些不阻止阶段四的结构性工作，但改变布局、载荷、轮速或动作参数时
  必须重跑本阶段验收。
