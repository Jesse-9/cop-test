# 柔性工业车间步骤 1.1：布局与无挡板取料验证

> 本文是 [[wiki/06-工业案例/柔性车间/历史与待评估规划/06-05-柔性工业车间分阶段执行步骤]] 中步骤 1.1
> 的独立执行计划。计划完成不等于功能已经实现或验收通过；每项结论都必须由
> 可复现的场景参数、仿真日志或测量记录支撑。

> **执行状态（2026-10-20）**: 已按本计划执行，详细结果与证据见
> [STEP1_1_REPORT](../../implementation/STEP1_1_REPORT.md)。选定布局
> `L1_S1`；B 组无挡板主动停带 **30/30** 通过冻结门槛、完整取放 **3/3**
> 成功；A 组 front/middle 的最终位置越过冻结允许区；C 组关闭补偿后仍
> 观察到物理输送。本页保留为计划与判定口径，执行结果不以“计划完成”
> 替代验收结论。
>
> **迁移到阶段一（2026-10-20）**: `L1_S1` 与 B 组流程已成为
> `src/stage1/` 的生产路径；旧 `stage1_baseline` 布局和挡停体只保留为
> A 组历史证据。阶段一入口不再提供布局开关。

## 1. 目标与范围

在阶段一单元闭环与阶段二物理/运行基础能力之间，完成两项输入收敛：

1. 复核 UR5 是否应从传送带末端延长线移至取料区侧方，并同步调整置物台位置；
2. 评估能否在不使用 `Conveyor_In_PickupStopper` 的前提下，检测到目标物料后
   主动停带、读取物料停稳后的实际位姿，再由 UR5 对该位置执行抓取。

本步骤只做布局选择、可达性检查、受控可行性试验和决策记录。它不实施完整碰撞
检测/避障、运行期碰撞停止或生产级安全停机；这些仍属于 06-05 的阶段二，特别是
§3.2–§3.7 与 §3.9。通用故障分类、重试和恢复归项目最终阶段（06-05 §6）。本步骤
也不实现移动物料跟踪抓取。步骤 1.1 的推荐
方案是“物料到位后停带并稳定，再按实测位姿抓取”，不是机械臂追踪运行中的物料。

## 2. 阶段一基线与已知限制

执行前先从当前场景及 [PHASE1_REPORT.md](../../implementation/PHASE1_REPORT.md)
重新导出实际值。报告中的数值作为候选布局初始参考，不得直接当作新场景最终坐标。

| 项目 | 阶段一记录 | 用途与限制 |
|---|---:|---|
| 世界坐标约定 | X 为输送方向，Y 为横向，Z 为高度 | 所有候选布局和测量统一使用世界坐标 |
| UR5 基座 | `(0.42, 0.0, 0.30) m` | 现状基线；位于传送带末端延长线附近 |
| 取料 TCP 目标 | `(-0.20, 0.0, 0.45) m` | 阶段一固定目标；新方案应覆盖允许取料区域 |
| 带速 | `0.20 m/s` | 报告中已测运行点，不代表全部速度范围 |
| conveyor 停车设置 | `accel=2.0 m/s^2`；报告记录约 `0.10 s / 0.010 m` | 是当前模型配置下的带面记录，物料越程必须另测 |
| 取料目标距离 | 基座到 TCP 目标约 `0.669 m` | 仅作阶段一可达性参考，不代表碰撞安全或路径可行 |
| 工位目标距离 | 基座到工位 TCP 约 `0.659 m` | 移动置物台和基座后必须重算 |
| 传感器语义 | `Sensor_PickStation` 是固定位置 proximity sensor | 检测/返回命中对象，不直接提供物料六维位姿 |
| 取料端挡停体 | 阶段一当前生产场景不创建 `Conveyor_In_PickupStopper` | A 组仅代表早期历史对照；生产基线采用传感器命中后主动零速并等待稳定 |

阶段一报告 §8 第 1 条说明：当前 `HYBRID_DYNAMIC` 下，物料输送仍主要靠控制器沿
带面切线作位置补偿，不能据此证明带面摩擦在真实驱动物料。报告 §8 第 11 条还
指出，故障 JSON 的时间戳早于停车加速度修复。若本步骤修改基线或相关停车参数，
应重新生成受影响的证据并标记对应配置版本。

## 3. 工作站布局收敛

### 3.1 建立候选布局

1. 从当前场景读取并保存 conveyor、有效 pad 区、取料传感器、UR5 基座、工位、
   AGV dock、地面和固定支架的世界位姿及外包围盒；确认坐标单位均为米、角度单位
   明确为弧度或度。
2. 保持 conveyor 轴向和有效输送区域不变，至少建立两个 UR5 侧置候选布局。候选
   可以位于 conveyor 横向两侧；机械臂基座应靠近取料区域，但不能只凭“到取料点
   距离短”选点。
3. 对每个基座候选布局，至少比较两个置物台位置：一个位于机械臂可达工作区内、
   尽量不占用传送带取料空间的方案；必要时再评估另一侧方案。保留阶段一需要的
   AGV 装卸空间和 dock 检测区，不要把 AGV 通道或传感器位置挤出可用范围。
4. 记录每个候选下 UR5 基座、取料区域、工位 TCP 目标、AGV dock 目标、台面高度、
   支架尺寸和 AGV 进出方向。坐标应由 CAD/场景测量和验证得出，不在计划阶段
   预设未经验证的固定新坐标。

### 3.2 仅做本步骤需要的可达性筛选

对每个候选布局建立并验证下列 TCP 目标：取料区中心及边界采样点、垂直接近点、
抬升点、置物台放置点、阶段一继续保留 AGV 目标时的装卸点。每个目标检查：

- `simIK` 返回成功且 TCP 位置/姿态误差在配置容差内；
- 六个关节均在限位内，目标姿态和吸盘接触方向满足当前抓取定义；
- 如果使用多个接近/抬升 waypoint，各 waypoint 均分别可达；
- 记录边界点余量或最近不可达位置，避免只以中心点成功代表整个取料区可用。

该筛选只说明离散目标的逆运动学可达，不说明 waypoint 之间的路径无碰撞，也不
说明 UR5 连杆、吸盘、conveyor、置物台或物料之间不存在穿模。碰撞集合、路径
检查和运行期碰撞处理按 06-05 阶段二完成。

### 3.3 选定布局

优先选择能让 UR5 从侧方接近取料点、减少机械臂目标落在传送带末端延长线上的
候选；同时要求置物台放置点和必要的 AGV 装卸点可达，且不牺牲 conveyor 有效
行程、传感器视场/检测区和 AGV dock 空间。若多个候选均满足，选择工作点余量较大、
对实际物料位置变化更不敏感、后续碰撞验证更简单的方案。把未通过候选及失败的
IK 目标也记入记录，避免只保留成功结果。

## 4. 无挡板停带与按实测位姿抓取试验

### 4.1 明确传感和定位链路

当前 `Sensor_PickStation` 是固定位置 proximity sensor。它用于报告检测事件/命中
对象；它本身不测量物料中心或姿态。仿真试验可在确认命中对象属于当前目标 UID 后，
通过该物料对象句柄读取世界位姿，再按物料几何和已标定的吸盘接触面偏移生成 TCP
抓取目标。记录中必须把“sensor 检测”和“仿真器读取 ground-truth 位姿”作为两个
不同来源字段。

这条链路验证的是仿真中的状态读取，不代表现实设备已经具备视觉/三维定位能力。
若未来要脱离仿真器直接读取坐标，需要另行定义并标定相机、测距或其他定位传感器，
不属于本步骤默认范围。

### 4.2 设计对照组与隔离条件

至少比较以下三组；用于物理诊断的隔离试验不得改变阶段一正常验收配置：

| 组别 | 挡板 | 输送方式 | 目的 |
|---|---|---|---|
| A：当前基线 | 保留阶段一场景中的挡停体 | 阶段一 `HYBRID_DYNAMIC` 和当前控制流程 | 记录真实现状；先确认当前流程是否发零速，不能预设其行为 |
| B：主动停带候选 | 从隔离副本移除 | `HYBRID_DYNAMIC`，sensor 确认后主动发零速 | 验证无挡停体时的控制链路、越程和补偿场景下抓取可行性 |
| C：物理输送诊断 | 移除 | 隔离场景中关闭位置补偿，仅观察动态物料与带面的实际相互作用 | 单独判断当前模型/物理配置下摩擦输送是否成立 |

若 C 组中物料不能到达检测区，应如实记录为物理输送限制；不得通过重新打开补偿
后把结果记为摩擦输送成功。只有在隔离副本中能可靠地区分并关闭位置补偿时才执行
C 组；否则记录为“当前无法单独验证”，不从 B 组推导真实摩擦结论。C 组是诊断，
不是步骤 1.1 的生产实现方案。

### 4.3 传感器触发点与停带顺序

1. 先用 A 组测量从 sensor 检测到 pad 实际停止的时间，以及物料在该期间的位移。
   若现有 sensor 位于目标抓取中心附近，物料在停稳前可能越过允许区域，应根据
   实测停止距离把触发区前移，不能只依靠触发后机械臂立即开始运动。
2. B 组按以下事件顺序执行：sensor 命中 → 校验目标 UID → 向 conveyor 发零速 →
   等待 pad 实际停止 → 等待物料稳定 → 读取目标物料实际世界位姿 → 生成 TCP
   接近/抓取目标 → 检查 IK 可达性。停带及稳定等待期间不下发机械臂抓取运动。
3. 以 pad 速度反馈为优先停止依据；若模型无法提供可信速度反馈，使用连续仿真步
   的 pad 位姿差/位移确认带面已停止。记录采用的判据和采样周期。物料稳定性还要
   单独检查，pad 停止不等于物料立即停止。
4. 在读取位姿后固定当前物料 UID，整个抓取目标生成与任务日志继续沿用同一 UID；
   不能因为 sensor 随后命中其他对象而切换抓取目标。
5. 本步骤不尝试移动中追踪抓取。如停带与等待稳定导致节拍不可接受，将其记为
   方案限制，另立后续需求，不以“机械臂追赶”作为未验证的临时绕过。

### 4.4 试验变量与重复次数

试验速度使用阶段一已验证的名义速度，以及项目允许的最低/最高运行速度；如果最低
或最高速度尚无冻结值，先记录为待冻结参数，不自行扩大到设备范围外。对每个速度，
至少测试物料在传感器检测区的前沿、中部和后沿三个初始位置。每个“速度 × 初始位置
× 组别”组合建议重复 10 次，作为可行性筛选；10 次结果不能宣称达到生产可靠性或
统计安全认证。若仿真随机性、物料姿态或碰撞时序对结果影响明显，应增加重复次数并
覆盖不同初始姿态。

每次试验至少记录：

| 记录项 | 说明 |
|---|---|
| 运行标识、组别、配置版本、随机种子 | 用于复现和区分 A/B/C 组 |
| 初始物料 UID、世界位姿、线速度/角速度 | 确认输入条件一致并追踪单件物料 |
| sensor 命中时刻、命中对象、零速命令时刻 | 测检测与命令延迟 |
| pad 零速确认时刻和停止距离 | 测带面停车过程 |
| 物料停带前后位姿、残余速度、稳定等待时间 | 测物料是否继续滑动、滚动或漂移 |
| 最终抓取目标、TCP 姿态、simIK 结果和误差 | 证明实测位姿能否形成可执行目标 |
| 最终吸附判据、是否越出允许区域、失败原因 | 区分定位、可达性和稳定性失败 |
| HYBRID_DYNAMIC 补偿量/是否关闭补偿 | 防止将补偿输送误记成摩擦输送 |

同时保存物料位姿轨迹或逐步采样摘要，不能只保存最终成功/失败标志或平均值。

### 4.5 运行与复算命令

前置：CoppeliaSim 4.10+ 已启动，ZMQ Remote API server 监听 `23000`；
场景无需手动清空，构建前会自动 `clear_scene`。

```bash
# 完整流程：基线测量 → 候选布局扫描 → A/B/C 矩阵
.venv/Scripts/python src/run_step1_1.py --phase all --repeats 10

# 分阶段执行
.venv/Scripts/python src/run_step1_1.py --phase measure
.venv/Scripts/python src/run_step1_1.py --phase layout
.venv/Scripts/python src/run_step1_1.py --phase experiment --selected-layout L1_S1

# 冒烟：只跑 B 组、每个初始位置 1 次
.venv/Scripts/python src/run_step1_1.py --phase experiment \
  --selected-layout L1_S1 --groups B --repeats 1

# 复用已有布局证据
.venv/Scripts/python src/run_step1_1.py --phase experiment \
  --layout-report docs/implementation/step1_1_layout_<stamp>.json

# 从证据重新生成统计
.venv/Scripts/python docs/measurement/analyze_step1_1.py \
  --stamp <stamp> --out docs/implementation/step1_1_analysis_<stamp>.json
```

- `--phase experiment` 如果既没有 `--selected-layout` 也没有 `--layout-report`，
  会自动执行 `all`（先扫描再试验）。
- 证据写入 `docs/implementation/step1_1_*_<stamp>.json` / `.jsonl`；
  运行日志为 `step1_1.log`（已忽略，不入库）。
- 完整结果与限制见 [STEP1_1_REPORT](../../implementation/STEP1_1_REPORT.md)。
- 同一 CoppeliaSim 实例不要同时运行阶段一、MCP 控制或另一份步骤 1.1 试验。

## 5. 挡板移除决策

在运行试验前先冻结“允许抓取区域”和稳定标准，避免试验后按观察结果放宽标准：

1. 允许抓取区域由 conveyor 有效 pad 区、物料外形、吸盘/TCP 接触几何、已配置的
   suction 距离/法向/速度容差，以及第 3 节可达性检查共同确定；不能简单使用
   proximity sensor 的检测体积代替抓取容差。
2. 物料稳定标准使用阶段一 suction controller 已有速度门槛；需要不同阈值时，先
   记录变更理由和复测要求。建议至少要求连续多个采样步满足阈值，并报告最大值，
   不只报告均值。pad 速度和物料速度分别判定。
3. 移除挡板的可行性门槛：B 组每个计划测试条件下，物料都能被 UID 正确绑定；pad
   停止后物料稳定且未滚落/越界；最终位姿落入预先冻结的允许抓取区域；该位姿生成
   的 TCP 目标均通过 simIK 和现有吸附前置检查；无未解释的失败或数据缺失。
4. 任一条件失败，或出现越程超出抓取范围、物料持续漂移、位置散布压缩了 IK 余量，
   则结论为“暂不移除挡板”。保留现有挡板作为失效保护，或调整 sensor 触发位置、
   带速和停止配置后重新试验。物理挡板不能取代主动停带和安全策略。
5. 增大物料/带面摩擦只能作为单变量试验。摩擦可能改变物料跟随带面和减速时的相对
   滑动，但本身不等于主动制动，也不能保证物料停在指定坐标；必须分别报告带面停止
   与物料停止结果。

通过本门槛只表示“在本仿真配置和已测范围内，无挡板方案可行”，不表示真实设备
已经满足安全认证或量产可靠性要求。进入阶段二后，仍须按 06-05 §3.9 回归停止
延迟、越程、停止确认可信度和停止失败边界；当前生产流程不含挡板，阶段二不把挡板
实现或挡停行为列为验收项。碰撞后的即时停止与现场锁存见 §3.7；通用故障恢复见
项目最终阶段（06-05 §6）。

## 6. 交付物与验收

### 6.1 交付物

- 候选布局图/场景截图及坐标表；包括 UR5、置物台、conveyor、Sensor_PickStation
  和 AGV dock 的基准与选定坐标；
- 每个候选布局的 TCP 目标清单、simIK 结果、误差、关节限位结果和失败记录；
- A/B/C 试验配置及逐次记录，含物料位姿、pad/物料速度、停止距离、位置散布、
  抓取目标和失败原因；
- 挡板“保留/移除/暂缓决策”及适用的速度、物料范围和已知限制；
- 更新的阶段一报告/证据索引，明确哪些证据在停车参数或场景基线更新后重跑；
- 提供给阶段二的固定输入：选定场景坐标、允许取料区域、传感器触发策略、物料
  位姿到 TCP 目标的变换定义，以及尚待碰撞/安全验证的事项。

### 6.2 通过条件

- 选定布局覆盖阶段一保留的所有目标（工位；若继续保留 AGV 目标，也包括 AGV
  装卸位），并有取料区域边界点的 simIK 证据；
- 传感器负责目标对象检测，目标位姿来源被准确标注；仿真器 ground-truth 读取没有
   被描述成传感器测量；
- 已按重复试验作出明确的挡板决策，所有门槛和失败样本均可追溯；
- 报告清楚区分 `HYBRID_DYNAMIC` 位置补偿与关闭补偿后的物理输送诊断结果；
- 文档和报告没有把离散 IK 可达性写成路径无碰撞，也没有把仿真可行性写成现实安全
  认证。

未满足上述条件时，步骤状态保持“未通过/待补证”，不得以主观判断宣布移除挡板或
完成布局收敛。
