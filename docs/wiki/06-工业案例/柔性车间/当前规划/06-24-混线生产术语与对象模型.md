# 混线生产术语与对象模型

> 本文按截至 2026-11-12 的代码与产品文档解释当前柔性车间实现，并用阶段号标注
> 各能力的演进来源。重点是区分
> **静态工艺与资源定义**、**运行时工序状态**、**兼容任务视图**、**设备/资源** 和
> **场景验收** 五个层次。代码标识以 `src/flexible_factory/` 为准；业务名称只是对现有
> 仿真物料流的解释，不代表真实切削或物理装配。

本文将可复用、按稳定 ID 查询的工艺和资源定义称为**静态工艺与资源定义**，下文简称
**目录**；代码/API 沿用 `ProcessCatalog`、`catalog` 等名称。这里的“目录”指
结构化定义集合，不是文件系统目录，也不包含运行中的物料、占用或设备状态。

**速查：** §2.1–2.2 生产/工艺对象 · §2.3 调度/运行时 · §2.4–2.8 场景包/
物料/事件/失败/执行层 · §3 字段级对象 · §4 易混概念 · §5 旧→新映射 ·
§6 默认工艺 · §7 未来名词 · §8 命名/版本。

## 1. 一句话理解当前实现

```text
RecipeSpec / OperationTemplate / RouteVariant     （目录中的静态工艺定义，
        │                                            纯数据、可校验）
        │ 按入口固定路线实例化工序 DAG（阶段 3）
        ▼
OperationGraph / OperationInstance                （依赖、ready 与状态）
        │
        ├─ 阶段 4：ready 快照 → 确定性候选筛选/派工
        └─ 物理工序入队为 Stage4Task                （兼容执行视图）
        │
        ▼
DeviceExecutor → 既有臂/AGV 控制器                 （阶段 2）
        │
        ▼
MaterialRegistry / ResourceTable                  （物料谱系/区域 + 资源互斥）
```

阶段 0-1 固化 `full_flow` 基线并抽取可校验的默认工艺定义；阶段 2 增加设备绑定和
执行适配器；阶段 3 增加工序 DAG 与依赖解锁；阶段 4 增加 ready 工序的确定性候选
筛选和派工。另有订单 DAG/API/持久化/planner 路径（阶段 1-6），可创建和运行
订单版本。它与 `full_flow` 的有限场景批次是不同入口：`full_flow` 仍按来料入口
固定选择路线，不是订单驱动的运行时动态选路。各阶段验收细节以实施报告为准。

## 2. 业务与生产对象

### 2.1 混线生产语义

| 术语 | 英文/代码 | 解释 |
|---|---|---|
| **混线生产** | mixed-model / mixed-line | 同一仿真场景中同时存在多条来料路线和多个产品/物料变体，共享 A–E 工位、传送带、AGV 和缓冲。当前通过“壳体直达”“壳体绕行”“支架供料”三条路线表达。 |
| **阶段 0-1** | stage 0-1 | 不是新的生产阶段：0 固化 `full_flow` 基线，1 把 coordinator 固定工艺映射抽成可校验默认目录；执行层不变。 |
| **壳体** | housing | 业务名称，对应 `RAW_A`/`RAW_B → SEMI_AC → SEMI_CE` 的物料流。A/B/C 的“加工”在当前仿真中只是抓取、转运和物料类型转换。 |
| **支架** | bracket | 业务名称，对应 `RAW_D → PART_DE`。D 的“加工”同样是抓取/转运抽象。 |
| **成套配对** | kit join / E join | E 岛在 `buffer_e_c` 和 `buffer_e_d` 同时具备正确输入时，逻辑消费两件物料并生成一个 `FINAL`。不是机械臂真实装配。 |
| **成品** | `FINAL` | E 配对产物，记录两条父 UID；当前放在 `output_e`，由逻辑配对生成，不由机械臂搬运。 |
| **产品类型** | `RecipeSpec.product_type` | 当前产品工艺定义的产品类型为 `assembled_module`；是模型元数据，不是完整产品主数据。 |
| **订单** | order | 订单子系统中的持久化业务对象，有不可变版本、预览、planner 草稿和运行记录；订单 JSON 由校验器/编译器转为运行图。`full_flow` 用户入口仍直接使用有限场景批次，不等于订单。 |

### 2.2 工艺定义对象

| 术语 | 英文/代码 | 解释 |
|---|---|---|
| **产品工艺定义** | 代码对象 `RecipeSpec`（字段/模块仍称 recipe） | 某个产品可复用的静态工艺结构：稳定 ID、版本、产品类型、工序模板、路线变体、入口和逻辑合流。它不是原料配比，也不意味着支持用户运行时编辑。当前 ID 为 `mixed_line_v1`。 |
| **默认产品工艺定义/默认目录** | `default_process` / `default_catalog()` | `default_process.py` 保存代码内默认产品工艺定义及静态资源定义；`default_catalog()` 构造并校验 `ProcessCatalog`，进程内缓存，是 coordinator 的默认输入。 |
| **静态定义版本** | 代码字段 `PROCESS_MODEL_VERSION` | 当前版本以 `default_process.PROCESS_MODEL_VERSION` 为准；修改产品工艺定义/工序/路线/设备能力时应递增。 |
| **工序** | Operation / `OperationTemplate` | 可调度、可验收的工作模块，例如“把 UID 从 AGV 卸到 A 的交接台”。工序模板是静态定义，不是一次执行。 |
| **工步** | Work Step / `WorkStepTemplateRef` | 工序内部可执行、可观察的步骤引用。一个工步可由多个底层动作和控制器阶段组成；例如一次机械臂 `arm_pick_place` 工步内部包含接近、吸附、抬升、移动、放置和验证。多个工步按顺序/条件完成后，才构成工序完成。当前引用 `conveyor_pickup`、`arm_pick_place`、`agv_route`、`logical_join` 等已有执行路径，不把任意 Python 代码写进配置。 |
| **动作** | Action | 设备级控制原语或持续过程，例如吸盘启停、关节目标更新、轮速跟随、传送带启停。动作通常是工步的内部实现细节，不单独成为生产调度单元；当前没有独立 `Action` 数据类，具体行为由既有控制器实现。 |
| **工序模板** | OperationTemplate | 工序的静态字段集合：id、旧 task kind、语义、执行器类型、能力、候选设备、输入/输出、资源请求、工步引用、完成验证器、优先级、前置/后继。 |
| **工序实例** | `OperationInstance` | 针对具体物料 UID/订单节点实例化的一道工序，保存唯一运行状态、前驱、输入/输出和派工信息；由 `OperationGraph` 管理依赖与 ready 状态。 |
| **路线变体** | `RouteVariant` | 命名路线的一组有序工序选择，带进入/离开区域。`housing_direct` 和 `housing_alt` 是同组互斥选项，不是同时执行的两条并行分支。 |
| **路线组** | `RouteVariant.group` | 同一组内的变体互斥。当前有 `housing_supply`（直达/绕行）和 `bracket_supply`（支架独立路线）。 |
| **订单入口** | `OrderEntry` | 来源线、来料类型与初始工序的绑定，例如 `s1a → line_s1a/RAW_A → housing_direct_A`。 |
| **候选设备** | `candidate_devices` | 工序模板显式允许的设备 ID 列表。阶段 4 派工只在该名单内筛选；默认物理工序仍各只有一个候选设备，因此默认生产路线没有跨设备替代。 |
| **能力** | Capability / `CapabilitySpec` | 设备提供的静态能力，如 `robotic_pick_place`、`agv_transport`、`logical_join`。阶段 4 策略会检查候选设备是否具备工序声明的能力；它不动态推断能力，也不单独证明几何/运动可行。 |
| **设备** | Device / `DeviceSpec` | 提供能力的实体或逻辑处理器。当前有 `arm_A`…`arm_E`、`agv_1` 和逻辑处理器 `logic_E`；`logic_E.physical=false`，不是物理设备。 |
| **资源** | Resource | 需要独占/限量/互斥的对象或区域锁，例如 `line_ce`、`dock_A`、`agv_lane_west`、`arm_A`、`zone_ac`。资源由 `ResourceTable` 管理；不等于物料容量区域。 |
| **区域** | Zone / `ZoneSpec` | 稳定区域 ID 与容量，例如 `handoff_ac`、`buffer_e_c`、`agv`、`output_e`。物料所在区域/容量由 `MaterialRegistry` 管理。资源锁与区域占用是两类约束。 |
| **物料端口** | `MaterialPort` | 工序输入/输出的“区域 + 物料类型”，例如 `line_s1a:RAW_A`、`handoff_ac:SEMI_AC`。 |
| **完成验证器** | `completion_verifier` | 完成工序后由哪个既有验证路径检查，例如 `unit_handoff_verified`、`agv_route_verified`、`join_pair_committed`。当前是稳定 ID，不携带代码。 |
| **执行器类型** | `executor_kind` | `arm`、`agv` 或 `logic`。用于区分机械臂工序、AGV 路线工序和无物理运动的逻辑合流。 |
| **资源策略** | `resource_policy` | `fixed`（模板写死资源集）、`agv_route`（按实际路线动态申请 lanes/docks）、`logical_join`（逻辑配对，不进资源派工）。 |
| **前置策略** | `predecessor_policy` | `all` 表示 AND（所有前置都完成），`any` 表示 OR（任一路线终端完成即可）。当前 `housing_finish` 为 `any`，`kit_join` 为 `all`。 |
| **后继** | `successors` | 工序语义上的后继边。只有实际前驱成功提交后才解锁后继；`kit_join` 的输入齐备后由合流逻辑提交，不创建物理执行任务。 |

### 2.3 调度与运行时对象

| 术语 | 英文/代码 | 解释 |
|---|---|---|
| **ready 工序** | ready operation | `OperationGraph` 中状态为 `PENDING`、尚未派发且所有实际前驱均为 `DONE` 并已提交的工序实例；无前驱的入口工序可直接 ready。ready 只表示依赖图已解锁、可进入派工评估，不代表物料位置、目标区容量、设备可行性均已通过，也不代表可以立即执行。 |
| **任务** | Task / `Stage4Task` | `TaskQueue` 使用的执行任务兼容视图。基于产品工艺定义创建的任务对应一个已派工 `OperationInstance`，状态通过受控属性映射回实例；AGV 空载移位任务是运行时物流任务，不属于工序 DAG。 |
| **工序运行时** | `operation_runtime.py` / `OperationGraph` | 管理 `OperationInstance`、依赖索引、ready 判定和受控状态迁移；不负责仿真步进或物理执行。 |
| **旧任务类型** | legacy task kind | 旧 `TASK_KIND_*` 标识，如 `a_conveyor`、`transport_ba`、`e_conveyor`。只用于报告/证据兼容和任务 id；工艺语义以 `OperationTemplate` 为准。 |
| **任务状态** | `TaskStatus` | 当前成员：`PENDING`、`WAITING`、`RUNNING`、`BLOCKED`、`DONE`、`FAILED`、`REJECTED`、`CANCELLED`。终态为 `DONE/FAILED/REJECTED/CANCELLED`；`FAILED/BLOCKED` 不得改写成 `DONE`。 |
| **任务队列** | `TaskQueue` | 去重、状态转换、优先级/老化、拒绝记录；不直接调度设备。 |
| **AGV 空载移位** | `reposition` | AGV 无载荷前往后续任务所需 dock 的动态任务，不属于产品工艺定义中的工序；优先级来自 `config.TASK_PRIORITY[TASK_KIND_REPOSITION]`。 |
| **优先级** | priority | 数值越小越优先；`transport_ba`/`a_agv`/`e_agv` 为 0，`transport_de` 为 1 并等待老化，普通单元任务为 1，AGV 空载移位任务为 2。当前只在 AGV 派车和任务排序中使用。 |
| **任务老化** | aging / starvation upgrade | D→E 等待超过 `D_E_STARVATION_UPGRADE_S` 后在下一次派车时提升一级；不抢占运行中任务。 |
| **背压** | backpressure | 下游区域/缓冲/线占用时上游任务进入 WAITING 并记录原因；不丢弃 UID。等待超过 `BACKPRESSURE_MAX_WAIT_S` 会触发失败/冻结。 |
| **阻塞** | `BLOCKED` | AGV 路线受阻或传送带停带等现场条件导致的非终态；与正常 `WAITING` 不同。清障/重新确认所有权后特定场景可续行。 |
| **冻结** | freeze | 协调器停止 AGV/所有线、保持控制器现场、把活动任务置为 FAILED/BLOCKED、释放普通调度锁；**不自动恢复**。 |
| **安全锁存** | safety latch | `Stage2Safety` 每臂独立锁存；与任务失败/冻结相关但独立。资源释放不会清除安全锁存。 |

### 2.4 场景包、场景与验收

| 术语 | 英文/代码 | 解释 |
|---|---|---|
| **场景** | Scene / `.ttt` | CoppeliaSim 场景文件。 |
| **场景包** | Scene package；代码字段为 `artifact` | `docs/scene_artifacts/` 下可版本化、可校验、可追溯的软件交付包，包含 `scene.ttt`、`manifest.json`、`validation.json`、`lifecycle.jsonl`。当前 v1 场景包为 `v1/L5_UFLOW/v001_20261103_004317`，由 `stage4/L5_UFLOW/v004_20261029_133249` 迁移；v1 场景包受保护，不修改。它不是生产流程中的在制品或零部件。 |
| **来源场景包** | source artifact | v1 场景包由已验收 stage4 场景包迁移而来；迁移来源与 stage3 父场景包摘要记录在 v1 manifest provenance 中。 |
| **契约版本** | contract version | 当前 `v1_contract_20261103`；与 v1 场景包 manifest 的 `extra.v1` 关联。 |
| **config digest** | 配置摘要 | 对 v1 各层配置的大写稳定值计算；以 v1 场景包 manifest 中的摘要为准。配置变化会使旧场景包启动校验失败。 |
| **layout digest** | 布局摘要 | 对 `Stage4Layout.digest_payload()` 计算；当前 `ed7759fd…def`。 |
| **manifest digest** | manifest 摘要 | 保存/加载校验使用；当前版本的 manifest 摘要见生命周期状态。 |
| **基线** | baseline | 阶段 0 冻结的 `full_flow` 行为：13/13 DONE、1 个 FINAL（父 UID 1+3）、1 个未配对 SEMI_CE、两条载货路线。 |
| **归一化签名** | normalized signature | `phase0_1_baseline_full_flow_20261030_093231.json`：只保留批次、验收、任务终态、物料终态/可读位置、路线和 per-UID 事件序列，不比较时间/句柄/停靠误差。 |
| **`full_flow`** | scenario | 唯一正式用户运行模式；默认批次为 `RAW_A=1, RAW_B=1, RAW_D=1`，也可用受支持的 batch profile 改变本次投料数量。 |
| **内部回归场景** | `no_pair`、`agv_priority`、`agv_blocked`、`conveyor_fault`、`staggered_batch` | CLI 暴露的内部回归/诊断场景，不是正式用户运行模式；各自验收范围见对应报告，不能由 `full_flow` 结果推断。 |

### 2.5 现场对象、物料与 UID

| 术语 | 英文/代码 | 解释 |
|---|---|---|
| **工位/岛** | Unit / island | 当前 A–E 五个 UR5 工位；每台臂有自己的岛体、吸盘、TCP、IK target 和影子臂。 |
| **来源** | Source | `S1`/`S2` 仓库及出口。S1 有 `s1a`、`s1b` 两个出口，S2 有 `s2d`。 |
| **物流线** | Line | `line_s1a`、`line_s1b`、`line_s2d`、`line_ce` 四条内置传送带及其取料区。 |
| **dock** | AGV dock | A/B/D/E 四个 AGV 停靠位；不是工作台或物料区域。 |
| **直道/节点** | lane / node | AGV 路网的西/南/东三条直道；`J_SW`、`J_SE` 是两个原地转向节点。 |
| **交接台** | `handoff_ac` | A→C 的固定交接区，复用 A 置物台；C 从这里取料。 |
| **E 缓冲** | `buffer_e_c` / `buffer_e_d` | E 岛两个输入缓冲，分别接受 `SEMI_CE` 和 `PART_DE`，容量各 1。 |
| **成品输出** | `output_e` / `E_Output` | E 岛外独立输出台；逻辑配对生成的 `FINAL` 放在这里，不进入机械臂包络。 |
| **AGV 托盘** | AGV tray | AGV 上承载物料的托盘；取放位姿按实测托盘中心生成，不按固定标称。 |
| **UID** | unique id | 物料唯一整数标识（如 `uid=1`）。任务、证据和谱系都以 UID 关联，不依赖 alias 或屏幕位置。 |
| **别名** | alias | 场景对象的稳定字符串名，如 `Robot_UR5_01`、`Conveyor_C_to_E`、`Part_0001`；`arm_A` 是设备目录 ID，不是场景 alias。alias 不含 `/`。 |
| **句柄** | handle | CoppeliaSim 返回的整数对象引用，只在运行时绑定/controller 中使用，不写入配方或持久证据。 |
| **物料类型** | `ItemType` | 稳定枚举：`RAW_A`、`RAW_B`、`SEMI_AB`、`SEMI_AC`、`SEMI_CE`、`RAW_D`、`PART_DE`、`FINAL`。 |
| **物料谱系** | genealogy / parents | 一个 UID 的来源、处理历史和配对父 UID。E 合流生成的 FINAL 记录两个父 UID。 |
| **流程记录状态** | `RecordState` | `MaterialRegistry` 的逻辑状态：`CREATED`、`IN_TRANSIT`、`READY`、`HELD`、`DELIVERED`、`CONSUMED`。 |
| **物理物料状态** | `MaterialState` | 阶段一物理生命周期：`SPAWNED`、`ON_CONVEYOR`、`HELD_BY_SUCTION`、`RELEASED` 等；与 `RecordState` 不是同一套状态。 |

物料类型主链：

```text
RAW_A ─A→ SEMI_AC ─C→ SEMI_CE ─E→ buffer_e_c ┐
RAW_B ─B→ SEMI_AB ─AGV B→A→ A ─→ SEMI_AC ─C→ … ┤
RAW_D ─D→ PART_DE ─AGV D→E→ E → buffer_e_d ────┴→ FINAL @output_e
```

### 2.6 证据事件名词

运行报告中的 `events`/`kind` 字段使用以下事件名：

| 事件 | 含义 |
|---|---|
| `COORDINATOR_START` | 协调器开始，记录 scenario/fault/batch。 |
| `SOURCE_BACKPRESSURE` | 来源线未空，暂不生成物料。 |
| `MATERIAL_SPAWN` | 场景中生成新物料（含 UID/类型/位置）。 |
| `MATERIAL_CREATED` | `MaterialRegistry` 登记物料/谱系记录。 |
| `MATERIAL_MOVE` | 物料区域变更（`detail.from` 为原区域）。 |
| `MATERIAL_PROCESS` | 工序类型转换（如 `RAW_A → SEMI_AC`）。 |
| `MATERIAL_PLACE` | 放置完成后的区域/类型提交事件。 |
| `MATERIAL_CONSUMED` | 合流消费某条父物料。 |
| `TASK_CREATED` | 任务进入队列。 |
| `TASK_START` | 任务开始执行（记录设备/资源/线路）。 |
| `TASK_WAIT` | 任务等待前置条件/资源/背压。 |
| `TASK_BLOCK` | 任务因 AGV 阻塞或传送带故障进入 BLOCKED。 |
| `TASK_DONE` | 任务完成且验证通过。 |
| `TASK_FAILED` | 任务失败；不得改写成 DONE。 |
| `ROUTE_START` / `ROUTE_DONE` | AGV 航线开始/完成，含 `route_id`、lanes、停靠/滑移指标。 |
| `JOIN_COMMIT` | E 合流原子提交（`pair_key`、父 UID、FINAL UID）。 |
| `JOIN_REJECTED` | 合流被拒绝（缺件/重复/错型）。 |
| `FINAL_CREATED` | E 合流生成 FINAL 的协调器事件。 |
| `FREEZE` | 协调器冻结现场（含 abort 标志）。 |
| `FAULT_INJECT` / `FAULT_INJECT_FAILED` | 故障注入/注入失败。 |

`task_id` 关联任务，`uid` 关联物料，`evidence_id` 关联航线/配对等证据；
`detail` 是事件补充字段。指标重算只依赖 `TASK_*`/`ROUTE_*`/物料事件，
不依赖屏幕位置。

### 2.7 验收字段与常见失败术语

| 术语 | 解释 |
|---|---|

| `MISSING_INPUT` / `DUPLICATE_PAIR` / `JOIN_REJECTED` | E 合流缺输入/重复父配对/整体拒绝。 |
| `STAGE4_FROZEN` | 协调器冻结后对相关任务/控制器的统一失败/阻塞原因。 |

### 2.8 执行层与几何名词

| 术语 | 解释 |
|---|---|
| **UR5** | 项目使用的六轴协作机械臂；A–E 各一台，模型脚本在阶段四被剥离，由 Python 控制。 |
| **TCP** | Tool Center Point，工具中心点；本项目指吸盘接触面中心的专用 dummy，是 IK tip、距离检测和放置参考点。 |
| **吸盘/吸附/释放** | `SuctionPad_*` 工具；吸附是“TCP 到位 + suction sensor 命中指定 UID + 姿态/速度/碰撞检查”的逻辑流程，不是真实真空压力模型。 |
| **影子臂** | `Shadow_*` 会话资源：每台臂的隐藏副本，用于规划/碰撞查询；仿真结束销毁，不写入场景包。 |
| **simIK environment** | 每台 UR5 独立的 IK 求解环境；主求解失败才使用阻尼备用组。 |
| **ConfigurationChecker** | 阶段二逐段检查 IK、碰撞、关节限位、腕部分支和水平姿态的组件；阶段四每台臂独立拥有。 |
| **LocalPlanner** | 阶段二局部路径规划器；带规划墙钟预算，执行阶段仍逐步复核碰撞/偏差/超时。 |
| **Stage2Safety** | 每臂独立的安全锁存；触发后停止并保持现场，不自动清除。 |
| **Stage4UnitController** | 单岛工位控制器：取料源 `conveyor/agv/station`，放置汇 `station/agv/conveyor`；内部状态包括 `WAITING_FOR_ITEM`、`STOPPING`、`MATERIAL_SETTLING`、`APPROACHING`、`ATTACHING`、`LIFTING`、`TRANSFERRING`、`PLACING`、`RELEASING`、`SETTLING`、`DONE/FAILED`（按取料源分支）。 |
| **AGVRouteController4** | 阶段四 AGV 路线控制器：西/南/东直道 + `J_SW/J_SE` 原地转向；路线状态为 `IDLE/DRIVING/SETTLING/DONE/BLOCKED/FAILED`。 |
| **HYBRID_DYNAMIC** | 传送带生产模式：内置 conveyor 物理驱动 + 受控切向补偿；必须记录驱动来源和补偿原因。 |
| **H_transfer** | 水平带载转运 TCP 高度，当前 `0.65 m`；与 `Z_base=0.30 m`、`Z_work`、`Z_belt=0.45 m` 一起构成高度 datum。 |
| **停止区/取料区** | 传送带上的传感器停止区和允许抓取的矩形窗口；物料只能在取料区内被吸附。 |
| **dock sensor** | AGV 停靠位的接近传感器；命中只表示车辆到位，不能单独作为物料交接/任务完成证据。 |
| **AGV tray** | AGV 托盘；放置点/释放目标按实测托盘位姿生成，避免停靠偏差导致固定标称点碰撞。 |
| **MaterialRegistry** | 物料 UID、类型、区域容量、谱系和 E 合流的逻辑登记表。 |
| **ResourceTable** | 调度资源互斥表；固定顺序、全有或全无申请，不代替碰撞检查。 |
| **UnitSceneView / runtime** | 单岛控制器可见的场景/影子臂接口；控制器不直接持有任意全局句柄。 |

### 3.4 `ProcessCatalog`

| 方法/属性 | 解释 |
|---|---|
| `recipe(id)` / `operation(id, recipe_id=None)` | 唯一索引查询；重复 ID 会报错。 |
| `operation_for_kind(kind)` | 旧 task kind → 工序模板，用于兼容任务/报告。 |
| `operations_for_device(device_id)` | 某设备的候选工序，替代旧 `UNIT_TASKS`。 |
| `device(id)` / `capability(id)` / `zone(id)` | 设备/能力/区域索引。 |
| `route_lines()` | 报告用路线摘要，不参与调度。 |
| `validate()` | 启动前完整校验；失败抛 `ProcessModelError`，错误带 `recipe=`/`operation=` 定位。 |
| `validate_report()` | 返回结构化 checks/errors，供测试/证据使用。 |
| `as_dict()` | 目录的稳定序列化，写入运行摘要。 |

`validate_default_against_config()` 另外核对默认目录与 `config.py` 冻结值：
优先级、`PROCESS_TRANSITIONS`、`JOIN_INPUTS/JOIN_OUTPUT/JOIN_BUFFER_OF`、
`SOURCE_ITEMS`。它不是场景契约校验，而是防止“目录改了一套、冻结场景包仍是另一套”。

### 3.5 `OperationInstance`

| 字段 | 解释 |
|---|---|
| `instance_id` / `template_id` | 实例 ID（当前等于 task id）与工序模板 ID。 |
| `kind` / `uid` | 旧 task kind 兼容标识与物料 UID。 |
| `source` / `destination` / `dock` / `device` | 任务派工用的稳定字段投影。 |
| `transport` | 是否 AGV 运输任务；替代按 kind 判断。 |
| `state` | `OperationInstance` 使用 `TaskStatus`；执行器另有 `ExecutionState`。不要把执行状态枚举误认为工序实例状态。 |
| `phase` / `priority` / `attempts` | 当前阶段文本、优先级、尝试次数。 |
| 时间字段 | `created/started/finished/waiting_since/blocked_since`，均为仿真时间。 |
| `failure_reason` / `evidence` | 失败原因与验证证据。 |
| `resources` / `upgraded` | 已申请资源列表与优先级老化标记。 |

当前 `Stage4Task` 的 `kind/uid/source/destination/dock/device` 是只读属性；
`status/phase/时间/证据/资源/upgraded` 是受控属性，实际都写入同一个
`OperationInstance`。这样不在任务对象上维护第二份可独立修改的状态。

## 4. 容易混淆的概念

| 对比 | 关键区别 |
|---|---|
| **产品工艺定义 vs 工序 vs 工步 vs 动作** | `RecipeSpec` 表达产品级可复用工艺结构；工序是可调度/可验收模块；工步是工序内部可执行步骤；一个工步可以包含多个动作/控制器阶段。动作是设备级控制原语。当前只有产品工艺定义/工序/工步引用是显式数据对象，动作仍由控制器实现。 |
| **模板 vs 实例 vs 任务** | `OperationTemplate` 是静态定义；`OperationInstance` 是本次运行的工序记录；物理工序派工后投影为 `Stage4Task` 供旧队列/执行接口使用。实例图管理依赖和生命周期；逻辑合流没有物理执行任务，`reposition`（AGV 空载移位）则是 DAG 外的运行时物流任务。 |
| **目录 vs 运行时状态** | `ProcessCatalog` 保存可复用的工艺/设备/能力/区域等定义，不持有 UID、仿真句柄、运行时间或资源占用；运行状态分别由 `OperationInstance`、物料账本 `MaterialRegistry`、资源占用表 `ResourceTable` 和控制器管理。 |
| **能力 vs 设备 vs 资源 vs 区域** | 能力是抽象功能；设备提供能力；资源是互斥锁（线/臂/dock/lane/zone 锁）；区域是物料容量/位置。四者不能互相替代。 |
| **路线变体 vs 并行分支** | 同组变体是互斥选择（direct 或 alternate），不是同时执行。当前 `housing_finish` 用 `predecessor_policy=any` 表示任一路线终端完成即可。 |
| **AND 合流 vs OR 路线选择** | `kit_join` 的 `all` 要求两个输入都完成；`housing_finish` 的 `any` 表示直达或绕行任一路线完成。 |
| **逻辑合流 vs 物理装配** | `kit_join` 消费两条父 UID 并生成 FINAL；没有机械臂装配动作，也不是几何切削/检测。 |
| **`source_kind/sink_kind` vs `source_zone/destination_zone`** | 前者是介质类型（conveyor/agv/station）；后者是稳定区域 ID。`inputs[].zone`/`output.zone` 是实际的物料区域。 |
| **`operation id` vs `template id` vs `task kind` vs `task id`** | `housing_direct_A` 是工序模板 ID；`a_conveyor` 是旧 task kind；`a_conveyor_uid1` 是兼容执行任务 ID；订单节点另有订单节点 ID，并通过模板引用定义要实例化的工序。 |
| **物料类型 vs 业务名称** | `RAW_A/SEMI_AC/SEMI_CE` 等是 `ItemType` 稳定枚举；壳体/支架是报告解释用语，不参与类型判断。 |
| **场景包 vs 场景 vs 模型 vs 生产工件** | 场景包是可追溯的软件交付物（含场景文件、manifest、校验和生命周期）；场景是 `.ttt`；模型是可复用 `.ttm`；生产工件是仿真中被加工或搬运的实体，属于物料/产品语境。 |
| **冻结 vs 安全锁存 vs 资源释放** | 冻结是协调器停止现场并冻结任务；安全锁存是每臂独立安全状态；资源释放只释放调度锁，不清除安全锁存。 |
| **冻结配置 vs 当前静态定义** | `config.py` 的 `TASK_FLOW/TASK_PRIORITY/...` 保留为场景包摘要/旧报告兼容值；当前工艺定义以 `default_process.py` 为准，启动时核对冻结值与当前定义约束。 |
| **基线 vs 当前运行** | 基线是阶段 0 的冻结行为/归一化签名；当前运行是本次 `full_flow` 样本。时间、句柄、停靠误差允许波动，任务/FINAL/物料/事件序列必须一致。 |
| **config digest vs layout digest vs manifest digest** | config digest 约束配置值；layout digest 约束布局对象；manifest digest 约束整个场景包 manifest。三者任一不匹配都可能拒绝启动。 |

| `housing_alt_B` | `b_conveyor` | `line_s1b:RAW_B → agv:SEMI_AB` | `arm_B` |
| `transport_BA` | `transport_ba` | `agv:SEMI_AB → agv:SEMI_AB`（B→A） | `agv_1` |
| `housing_alt_A` | `a_agv` | `agv:SEMI_AB → handoff_ac:SEMI_AC` | `arm_A` |
| `housing_finish` | `c_handoff` | `handoff_ac:SEMI_AC → line_ce:SEMI_CE` | `arm_C` |
| `housing_to_E_buffer` | `e_conveyor` | `line_ce:SEMI_CE → buffer_e_c:SEMI_CE` | `arm_E` |
| `bracket_process` | `d_conveyor` | `line_s2d:RAW_D → agv:PART_DE` | `arm_D` |
| `transport_DE` | `transport_de` | `agv:PART_DE → agv:PART_DE`（D→E） | `agv_1` |
| `bracket_to_E` | `e_agv` | `agv:PART_DE → buffer_e_d:PART_DE` | `arm_E` |
| `kit_join` | `logical_join` | `buffer_e_c:SEMI_CE + buffer_e_d:PART_DE → output_e:FINAL` | `logic_E`（逻辑） |

路线变体：

```text
housing_supply/housing_direct: housing_direct_A → housing_finish → housing_to_E_buffer
housing_supply/housing_alt:    housing_alt_B → transport_BA → housing_alt_A
                               → housing_finish → housing_to_E_buffer
bracket_supply/bracket_route:  bracket_process → transport_DE → bracket_to_E
mixed_line_v1/join:            buffer_e_c:SEMI_CE + buffer_e_d:PART_DE
                               → output_e:FINAL
```

`full_flow` 按来料入口固定选择路线并实例化工序图，不做订单级动态选路。阶段四
派工策略针对 ready 工序生成只读快照，在 recipe 声明的候选设备中按执行器类型、
静态能力、场景绑定、物料/区域条件、占用状态和已验证的设备-工序组合筛选并记录
决策。默认物理工序仍各只有一个候选设备，因此当前不等于已验收通用跨设备替代。

## 7. 运行时边界与未来名词

### 7.1 当前已实现

- 默认产品工艺定义和目录：`RecipeSpec`、`OperationTemplate`、`RouteVariant`、`OrderEntry`、`ProcessCatalog` 及启动校验；
- 运行时工序图：按固定入口路线创建 `OperationInstance`，维护前驱、ready 集合和状态迁移；
- 阶段四派工：对 ready 工序执行确定性候选评估，记录接受/拒绝原因、选择设备和等待原因；
- 设备执行适配器：将机械臂/AGV 执行生命周期包装给协调器，唯一 `sim.step()` 仍由协调器推进；
- 订单子系统：订单版本持久化、校验/预览/编译、HTTP 服务、planner 草稿及同步运行入口；
- `full_flow` 和订单路径分别有对应阶段报告与验收证据，具体范围见实施资料索引。

### 7.2 当前边界与未支持能力

| 名词 | 所属阶段 | 说明 |
|---|---|---|
| **`SUCCEEDED` / `WAITING_INPUT` / `READY` / `RESERVED`** | 状态设计 | 这些词可用于执行端/订单节点语义；`OperationInstance.state` 当前仍使用 `TaskStatus`，不要把它们当作该字段的实际枚举值。 |
| **订单运行中的动态路线改选** | 当前未支持 | planner 可在生成订单草稿时按请求和目录生成候选方案；候选经确认并保存为订单版本后，再校验/编译运行。运行图创建后不会因设备或物料状态改变同一物料的既定路线。`full_flow` 则按入口映射固定选路，不使用订单 planner。产品工艺定义是可复用的工艺结构，不是“固定版运行方案”；动态候选选择发生在订单草稿阶段。 |
| **动态发现设备能力** | 当前未支持 | 调度只检查目录中的静态能力声明和已登记候选，不从仿真现场推断新能力。 |
| **通用跨设备替代** | 当前未支持 | 替代候选必须先列入 recipe，并具备有效场景绑定及已验证的设备-工序组合；当前默认物理工序为单候选。 |
| **设备健康、工具载荷、姿态包络** | 未建模 | 当前没有权威数据源，不纳入候选筛选；调度记录中标为未建模维度。 |
| **YAML/JSON 用户工艺定义** | 后续 | 默认产品工艺定义保存在代码模块；CLI 不支持用户运行时编辑或直接导入任意工艺定义。 |
| **调度优化 / 有限恢复** | 阶段 5（暂缓） | 当前不提供全局优化求解或通用故障后自动恢复；错误处置按已验收边界执行。 |
| **物理装配 / 真实加工检测** | 未规划 | E 合流是逻辑配对；没有切削、检测或机械装配动作。 |

## 8. 命名与版本约定

- 稳定 ID 使用 `snake_case`（`housing_direct_A`、`buffer_e_c`、`arm_A`）；
  业务中文名只用于文档/报告，不参与运行时判断。
- 产品工艺定义/工序/设备/区域 ID 是稳定字符串，不能写入 CoppeliaSim handle；
  handle 只在启动绑定/runtime 中使用，不进入静态定义或持久证据。
- 对象 alias 不含 `/`；`getObject` 路径查询才使用 `/` 前缀（项目既有约定）。
- `PROCESS_MODEL_VERSION` 随产品工艺定义/工序/路线/设备能力变化递增；
  当前 `v1_process_20261106a`。
- `STAGE4_TASK_FLOW_VERSION`、`TASK_FLOW`、`TASK_PRIORITY` 仍保留为
  场景包 config digest 和旧报告兼容值；不要为了“更新版本”改这些值，否则
  当前 `v004` 场景包会拒绝启动。工艺语义变化应改 `default_process.py`。
- `kit_join` 是逻辑合流：可以被声明为 successor/依赖，但**不能**创建
  `Stage4Task`；它由 `_check_join` 在输入就绪时提交。
