# 混线生产术语与对象模型

> 本文解释当前柔性车间混线生产方案和阶段 0-1 实现中使用的名词。重点是区分
> **静态工艺定义**、**运行时工序状态**、**兼容任务视图**、**设备/资源** 和
> **场景验收** 五个层次。代码标识以 `src/flexible_factory/` 为准；业务名称只是对现有
> 仿真物料流的解释，不代表真实切削或物理装配。

**速查：** §2.1–2.2 生产/工艺对象 · §2.3 调度/运行时 · §2.4–2.8 场景/
物料/事件/失败/执行层 · §3 字段级对象 · §4 易混概念 · §5 旧→新映射 ·
§6 默认工艺 · §7 未来名词 · §8 命名/版本。

## 1. 一句话理解当前实现

```text
RecipeSpec / OperationTemplate / RouteVariant     （静态工艺目录，
        │                                            纯数据、可校验）
        │ 阶段 0-1：每个任务创建一个 OperationInstance
        ▼
OperationInstance                                 （运行时状态唯一存储）
        │
        ▼
Stage4Task                                        （旧任务字段的只读兼容视图）
        │
        ▼
Stage4UnitController / AGVRouteController4        （已验收执行层，未改造）
        │
        ▼
MaterialRegistry / ResourceTable                  （物料谱系/区域 + 资源互斥）
```

阶段 0-1 没有实现订单、工序 DAG 推进或设备执行适配器；它只把原先散落在
`coordinator.py` 的固定工艺映射抽成一份可校验的默认目录。执行仍由原控制器
完成，运行结果与阶段 0 基线对照通过。

## 2. 业务与生产对象

### 2.1 混线生产语义

| 术语 | 英文/代码 | 解释 |
|---|---|---|
| **混线生产** | mixed-model / mixed-line | 同一仿真场景中同时存在多条来料路线和多个产品/物料变体，共享 A–E 工位、传送带、AGV 和缓冲。当前通过“壳体直达”“壳体绕行”“支架供料”三条路线表达。 |
| **阶段 0-1** | stage 0-1 | 不是新的生产阶段：0 固化 `full_flow` 基线，1 把 coordinator 固定工艺映射抽成可校验默认目录；执行层不变。 |
| **壳体** | housing | 业务名称，对应 `RAW_A`/`RAW_B → SEMI_AC → SEMI_CE` 的物料流。A/B/C 的“加工”在当前仿真中只是抓取、转运和物料类型转换。 |
| **支架** | bracket | 业务名称，对应 `RAW_D → PART_DE`。D 的“加工”同样是抓取/转运抽象。 |
| **成套配对** | kit join / E join | E 岛在 `buffer_e_c` 和 `buffer_e_d` 同时具备正确输入时，逻辑消费两件物料并生成一个 `FINAL`。不是机械臂真实装配。 |
| **成品** | `FINAL` | E 配对产物，记录两条父 UID；当前放在 `output_e`，由逻辑配对生成，不由机械臂搬运。 |
| **产品类型** | `RecipeSpec.product_type` | 当前默认配方为 `assembled_module`；是配方元数据，不是完整产品主数据。 |
| **订单** | order | 阶段 3 才计划引入的运行时概念。当前只有有限场景批次，**没有订单对象/订单释放器**。 |

### 2.2 工艺定义对象

| 术语 | 英文/代码 | 解释 |
|---|---|---|
| **配方** | Recipe / `RecipeSpec` | 某个产品可复用的工艺定义：配方 id、版本、产品类型、工序模板集合、路线变体、订单入口和合流工序。当前唯一默认配方为 `mixed_line_v1`。 |
| **默认配方/默认目录** | `default_process` / `default_catalog()` | `default_process.py` 保存代码内唯一默认配方；`default_catalog()` 构造并校验目录，进程内缓存，是 coordinator 的默认输入。 |
| **配方版本** | recipe version | 当前为 `v1_process_20261103`，由 `default_process.PROCESS_MODEL_VERSION` 提供；修改 recipe/operation/route/设备能力时应递增。 |
| **工序** | Operation / `OperationTemplate` | 可调度、可验收的工作模块，例如“把 UID 从 AGV 卸到 A 的交接台”。工序模板是静态定义，不是一次执行。 |
| **工步** | Work Step / `WorkStepTemplateRef` | 工序内部的执行步骤引用。当前只引用已存在的执行路径标识：`conveyor_pickup`、`arm_pick_place`、`agv_route`、`logical_join`；不把任意 Python 代码写进配置。 |
| **动作** | Action | 设备级控制原语/持续过程（如吸附、轮速跟随、传送带启停）。当前没有独立的 `Action` 数据类；实际动作由 `Stage4UnitController`、`AGVRouteController4` 等既有控制器实现。 |
| **工序模板** | OperationTemplate | 工序的静态字段集合：id、旧 task kind、语义、执行器类型、能力、候选设备、输入/输出、资源请求、工步引用、完成验证器、优先级、前置/后继。 |
| **工序实例** | `OperationInstance` | 阶段 0-1 中附加在 `Stage4Task` 上的运行时记录，保存状态、时间、证据和资源。当前是**单个任务的生命周期记录**，还不是阶段 3 的依赖 DAG 实例。 |
| **路线变体** | `RouteVariant` | 命名路线的一组有序工序选择，带进入/离开区域。`housing_direct` 和 `housing_alt` 是同组互斥选项，不是同时执行的两条并行分支。 |
| **路线组** | `RouteVariant.group` | 同一组内的变体互斥。当前有 `housing_supply`（直达/绕行）和 `bracket_supply`（支架独立路线）。 |
| **订单入口** | `OrderEntry` | 来源线、来料类型与初始工序的绑定，例如 `s1a → line_s1a/RAW_A → housing_direct_A`。 |
| **候选设备** | `candidate_devices` | 工序可以使用的设备 ID 列表。当前每个工序只有一个候选设备；阶段 4 才计划做替代设备/能力匹配。 |
| **能力** | Capability / `CapabilitySpec` | 设备提供的抽象能力，当前有 `robotic_pick_place`、`agv_transport`、`logical_join`。能力是静态目录字段，当前不用于动态派工。 |
| **设备** | Device / `DeviceSpec` | 提供能力的实体或逻辑处理器。当前有 `arm_A`…`arm_E`、`agv_1` 和逻辑处理器 `logic_E`；`logic_E.physical=false`，不是物理设备。 |
| **资源** | Resource | 需要独占/限量/互斥的对象或区域锁，例如 `line_ce`、`dock_A`、`agv_lane_west`、`arm_A`、`zone_ac`。资源由 `ResourceTable` 管理；不等于物料容量区域。 |
| **区域** | Zone / `ZoneSpec` | 稳定区域 ID 与容量，例如 `handoff_ac`、`buffer_e_c`、`agv`、`output_e`。物料所在区域/容量由 `MaterialRegistry` 管理。资源锁与区域占用是两类约束。 |
| **物料端口** | `MaterialPort` | 工序输入/输出的“区域 + 物料类型”，例如 `line_s1a:RAW_A`、`handoff_ac:SEMI_AC`。 |
| **完成验证器** | `completion_verifier` | 完成工序后由哪个既有验证路径检查，例如 `unit_handoff_verified`、`agv_route_verified`、`join_pair_committed`。当前是稳定 ID，不携带代码。 |
| **执行器类型** | `executor_kind` | `arm`、`agv` 或 `logic`。用于区分机械臂工序、AGV 路线工序和无物理运动的逻辑合流。 |
| **资源策略** | `resource_policy` | `fixed`（模板写死资源集）、`agv_route`（按实际路线动态申请 lanes/docks）、`logical_join`（逻辑配对，不进资源派工）。 |
| **前置策略** | `predecessor_policy` | `all` 表示 AND（所有前置都完成），`any` 表示 OR（任一路线终端完成即可）。当前 `housing_finish` 为 `any`，`kit_join` 为 `all`。 |
| **后继** | `successors` | 工序语义上的后继边。后继不一定是可派工任务：`kit_join` 是 `housing_to_E_buffer`/`bracket_to_E` 的 successor，但由 `_check_join` 触发，不创建 `Stage4Task`。 |

### 2.3 调度与运行时对象

| 术语 | 英文/代码 | 解释 |
|---|---|---|
| **任务** | Task / `Stage4Task` | 阶段四调度/证据层的工作单元。任务 id 形如 `a_conveyor_uid1`；它持有 `OperationInstance`，旧字段是只读/受控投影。 |
| **operation runtime** | `operation_runtime.py` / `OperationInstance` | 阶段 0-1 指持有工序实例状态的运行时模块；它不实现 DAG、ready set 或依赖推进，这些是阶段 3 的扩展。 |
| **旧任务类型** | legacy task kind | 旧 `TASK_KIND_*` 标识，如 `a_conveyor`、`transport_ba`、`e_conveyor`。只用于报告/证据兼容和任务 id；工艺语义以 `OperationTemplate` 为准。 |
| **任务状态** | `TaskStatus` | 当前成员：`PENDING`、`WAITING`、`RUNNING`、`BLOCKED`、`DONE`、`FAILED`、`REJECTED`。终态为 `DONE/FAILED/REJECTED`；`FAILED/BLOCKED` 不得改写成 `DONE`。 |
| **任务队列** | `TaskQueue` | 去重、状态转换、优先级/老化、拒绝记录；不直接调度设备。 |
| **空载调机** | reposition | AGV 无载荷前往某个 dock 的动态任务，不属于配方工序；优先级来自 `config.TASK_PRIORITY[TASK_KIND_REPOSITION]`。 |
| **优先级** | priority | 数值越小越优先；`transport_ba`/`a_agv`/`e_agv` 为 0，`transport_de` 为 1 并等待老化，普通单元任务为 1，调机为 2。当前只在 AGV 派车和任务排序中使用。 |
| **任务老化** | aging / starvation upgrade | D→E 等待超过 `D_E_STARVATION_UPGRADE_S` 后在下一次派车时提升一级；不抢占运行中任务。 |
| **背压** | backpressure | 下游区域/缓冲/线占用时上游任务进入 WAITING 并记录原因；不丢弃 UID。等待超过 `BACKPRESSURE_MAX_WAIT_S` 会触发失败/冻结。 |
| **阻塞** | `BLOCKED` | AGV 路线受阻或传送带停带等现场条件导致的非终态；与正常 `WAITING` 不同。清障/重新确认所有权后特定场景可续行。 |
| **冻结** | freeze | 协调器停止 AGV/所有线、保持控制器现场、把活动任务置为 FAILED/BLOCKED、释放普通调度锁；**不自动恢复**。 |
| **安全锁存** | safety latch | `Stage2Safety` 每臂独立锁存；与任务失败/冻结相关但独立。资源释放不会清除安全锁存。 |

### 2.4 场景、工件与验收

| 术语 | 英文/代码 | 解释 |
|---|---|---|
| **场景** | Scene / `.ttt` | CoppeliaSim 场景文件。 |
| **工件** | Artifact | `docs/scene_artifacts/` 下的版本化场景包：`scene.ttt`、`manifest.json`、`validation.json`、`lifecycle.jsonl`。当前 v1 工件为 `v1/L5_UFLOW/v001_20261103_004317`，由 `stage4/L5_UFLOW/v004_20261029_133249` 迁移；v1 工件受保护，不修改。 |
| **父工件** | parent artifact | v1 工件由已验收 stage4 工件迁移而来；迁移来源与 stage3 父件摘要记录在 v1 manifest provenance 中。 |
| **契约版本** | contract version | 当前 `v1_contract_20261103`；与 v1 场景工件 manifest 的 `extra.v1` 关联。 |
| **config digest** | 配置摘要 | 对 v1 各层配置的大写稳定值计算；以 v1 工件 manifest 中的摘要为准。配置变化会使旧工件启动校验失败。 |
| **layout digest** | 布局摘要 | 对 `Stage4Layout.digest_payload()` 计算；当前 `ed7759fd…def`。 |
| **manifest digest** | 工件摘要 | 保存/加载校验使用；当前 v004 的 manifest 摘要见生命周期状态。 |
| **基线** | baseline | 阶段 0 冻结的 `full_flow` 行为：13/13 DONE、1 个 FINAL（父 UID 1+3）、1 个未配对 SEMI_CE、两条载货路线。 |
| **归一化签名** | normalized signature | `phase0_1_baseline_full_flow_20261030_093231.json`：只保留批次、验收、任务终态、物料终态/可读位置、路线和 per-UID 事件序列，不比较时间/句柄/停靠误差。 |
| **`full_flow`** | scenario | 当前阶段 0-1 唯一端到端验收场景，批次 `RAW_A=1, RAW_B=1, RAW_D=1`。其它场景只引用历史结果，不在本阶段重跑。 |
| **`staggered_batch` / `no_pair` / `agv_priority` / `agv_blocked` / `conveyor_fault`** | 其它 v1 内部回归场景 | 历史验收场景；阶段 0-1 未重跑，不能由 `full_flow` 推断其等价性。 |

### 2.5 现场对象、物料与 UID

| 术语 | 英文/代码 | 解释 |
|---|---|---|
| **工位/岛** | Unit / island | 当前 A–E 五个 UR5 工位；每台臂有自己的岛体、吸盘、TCP、IK target 和影子臂。 |
| **来源** | Source | `S1`/`S2` 仓库及出口。S1 有 `s1a`、`s1b` 两个出口，S2 有 `s2d`。 |
| **物流线** | Line | `line_s1a`、`line_s1b`、`line_s2d`、`line_ce` 四条内置传送带及其取料区。 |
| **dock** | AGV dock | A/B/D/E 四个 AGV 停靠位；不是工作台或物料区域。 |
| **直道/节点** | lane / node | AGV 路网的西/南/东三条直道；`J_SW`、`J_SE` 是两个原地转向节点。 |
| **交接台** | `handoff_ac` | A→C 的固定交接区，复用 A 置物台；C 从这里取料。 |
| **E 缓冲** | `buffer_e_c` / `buffer_e_d` | E 岛两个输入缓冲，分别接受 `SEMI_CE` 和 `PART_DE`，容量各 1。 |
| **成品输出** | `output_e` / `E_Output` | E 岛外独立输出台；逻辑配对生成的 `FINAL` 放在这里，不进入机械臂包络。 |
| **AGV 托盘** | AGV tray | AGV 上承载物料的托盘；取放位姿按实测托盘中心生成，不按固定标称。 |
| **UID** | unique id | 物料唯一整数标识（如 `uid=1`）。任务、证据和谱系都以 UID 关联，不依赖 alias 或屏幕位置。 |
| **别名** | alias | 场景对象的稳定字符串名，如 `Robot_UR5_01`、`Conveyor_C_to_E`、`Part_0001`；`arm_A` 是设备目录 ID，不是场景 alias。alias 不含 `/`。 |
| **句柄** | handle | CoppeliaSim 返回的整数对象引用，只在运行时绑定/controller 中使用，不写入配方或持久证据。 |
| **物料类型** | `ItemType` | 稳定枚举：`RAW_A`、`RAW_B`、`SEMI_AB`、`SEMI_AC`、`SEMI_CE`、`RAW_D`、`PART_DE`、`FINAL`。 |
| **物料谱系** | genealogy / parents | 一个 UID 的来源、处理历史和配对父 UID。E 合流生成的 FINAL 记录两个父 UID。 |
| **流程记录状态** | `RecordState` | `MaterialRegistry` 的逻辑状态：`CREATED`、`IN_TRANSIT`、`READY`、`HELD`、`DELIVERED`、`CONSUMED`。 |
| **物理物料状态** | `MaterialState` | 阶段一物理生命周期：`SPAWNED`、`ON_CONVEYOR`、`HELD_BY_SUCTION`、`RELEASED` 等；与 `RecordState` 不是同一套状态。 |

物料类型主链：

```text
RAW_A ─A→ SEMI_AC ─C→ SEMI_CE ─E→ buffer_e_c ┐
RAW_B ─B→ SEMI_AB ─AGV B→A→ A ─→ SEMI_AC ─C→ … ┤
RAW_D ─D→ PART_DE ─AGV D→E→ E → buffer_e_d ────┴→ FINAL @output_e
```

### 2.6 证据事件名词

运行报告中的 `events`/`kind` 字段使用以下事件名：

| 事件 | 含义 |
|---|---|
| `COORDINATOR_START` | 协调器开始，记录 scenario/fault/batch。 |
| `SOURCE_BACKPRESSURE` | 来源线未空，暂不生成物料。 |
| `MATERIAL_SPAWN` | 场景中生成新物料（含 UID/类型/位置）。 |
| `MATERIAL_CREATED` | `MaterialRegistry` 登记物料/谱系记录。 |
| `MATERIAL_MOVE` | 物料区域变更（`detail.from` 为原区域）。 |
| `MATERIAL_PROCESS` | 工序类型转换（如 `RAW_A → SEMI_AC`）。 |
| `MATERIAL_PLACE` | 放置完成后的区域/类型提交事件。 |
| `MATERIAL_CONSUMED` | 合流消费某条父物料。 |
| `TASK_CREATED` | 任务进入队列。 |
| `TASK_START` | 任务开始执行（记录设备/资源/线路）。 |
| `TASK_WAIT` | 任务等待前置条件/资源/背压。 |
| `TASK_BLOCK` | 任务因 AGV 阻塞或传送带故障进入 BLOCKED。 |
| `TASK_DONE` | 任务完成且验证通过。 |
| `TASK_FAILED` | 任务失败；不得改写成 DONE。 |
| `ROUTE_START` / `ROUTE_DONE` | AGV 航线开始/完成，含 `route_id`、lanes、停靠/滑移指标。 |
| `JOIN_COMMIT` | E 合流原子提交（`pair_key`、父 UID、FINAL UID）。 |
| `JOIN_REJECTED` | 合流被拒绝（缺件/重复/错型）。 |
| `FINAL_CREATED` | E 合流生成 FINAL 的协调器事件。 |
| `FREEZE` | 协调器冻结现场（含 abort 标志）。 |
| `FAULT_INJECT` / `FAULT_INJECT_FAILED` | 故障注入/注入失败。 |

`task_id` 关联任务，`uid` 关联物料，`evidence_id` 关联航线/配对等证据；
`detail` 是事件补充字段。指标重算只依赖 `TASK_*`/`ROUTE_*`/物料事件，
不依赖屏幕位置。

### 2.7 验收字段与常见失败术语

| 术语 | 解释 |
|---|---|
| `acceptance.ok` | 场景验收总结果；由任务全部 DONE、FINAL 数/父 UID、无锁存、资源释放、路线指标等组合判定。 |
| `final_count` / `final_parents` | FINAL 数量与父 UID 列表；`full_flow` 期望 1 个、父件 `1+3`。 |

| `any_safety_latch` / `resources_released` | 是否有安全锁存、调度资源是否全部归还。 |

| `RELEASE_FAILED` / `RELEASE_CORRECTION_EXCEEDED` | 吸盘释放前实际物料位姿与目标修正量超过 stage2 阈值（`pos=0.010 m`、`ang=0.05 rad`）。 |

| `TASK_TIMEOUT` / `BACKPRESSURE_TIMEOUT` | 任务执行/背压等待超过仿真时间上限。 |
| `CONTROLLER_BUILD_FAILED` / `ROUTE_BUILD_FAILED` | 单元控制器/AGV 航线构造失败。 |
| `AGV_ROUTE_FAILED` / `AGV_BLOCKED_TIMEOUT` | AGV 路线失败或清障后仍无法续行。 |
| `ITEM_TYPE_MISMATCH` / `ZONE_MISMATCH` | 任务期望的物料类型/区域与 `MaterialRegistry` 当前记录不一致。 |
| `FLOW_RECORD_MISSING` / `UID_NOT_REGISTERED` | 物料谱系记录或物料登记缺失。 |
| `MISSING_INPUT` / `DUPLICATE_PAIR` / `JOIN_REJECTED` | E 合流缺输入/重复父配对/整体拒绝。 |
| `STAGE4_FROZEN` | 协调器冻结后对相关任务/控制器的统一失败/阻塞原因。 |

### 2.8 执行层与几何名词

| 术语 | 解释 |
|---|---|
| **UR5** | 项目使用的六轴协作机械臂；A–E 各一台，模型脚本在阶段四被剥离，由 Python 控制。 |

| **Stage4UnitController** | 单岛工位控制器：取料源 `conveyor/agv/station`，放置汇 `station/agv/conveyor`；内部状态包括 `WAITING_FOR_ITEM`、`STOPPING`、`MATERIAL_SETTLING`、`APPROACHING`、`ATTACHING`、`LIFTING`、`TRANSFERRING`、`PLACING`、`RELEASING`、`SETTLING`、`DONE/FAILED`（按取料源分支）。 |

| **HYBRID_DYNAMIC** | 传送带生产模式：内置 conveyor 物理驱动 + 受控切向补偿；必须记录驱动来源和补偿原因。 |

| **dock sensor** | AGV 停靠位的接近传感器；命中只表示车辆到位，不能单独作为物料交接/任务完成证据。 |
| **AGV tray** | AGV 托盘；放置点/释放目标按实测托盘位姿生成，避免停靠偏差导致固定标称点碰撞。 |
| **MaterialRegistry** | 物料 UID、类型、区域容量、谱系和 E 合流的逻辑登记表。 |
| **ResourceTable** | 调度资源互斥表；固定顺序、全有或全无申请，不代替碰撞检查。 |
| **UnitSceneView / runtime** | 单岛控制器可见的场景/影子臂接口；控制器不直接持有任意全局句柄。 |

### 3.5 `OperationInstance`

| 字段 | 解释 |
|---|---|
| `instance_id` / `template_id` | 实例 ID（当前等于 task id）与工序模板 ID。 |
| `kind` / `uid` | 旧 task kind 兼容标识与物料 UID。 |
| `source` / `destination` / `dock` / `device` | 任务派工用的稳定字段投影。 |
| `transport` | 是否 AGV 运输任务；替代按 kind 判断。 |

| `phase` / `priority` / `attempts` | 当前阶段文本、优先级、尝试次数。 |

`OperationInstance`。这样不在任务对象上维护第二份可独立修改的状态。

## 4. 容易混淆的概念

| 对比 | 关键区别 |
|---|---|
| **配方 vs 工序 vs 工步 vs 动作** | 配方是产品级工艺定义；工序是可调度/可验收模块；工步是工序内部步骤；动作是设备级控制原语。当前只有配方/工序/工步引用是显式数据对象，动作仍由控制器实现。 |
| **模板 vs 实例 vs 任务** | `OperationTemplate` 是静态意图；`OperationInstance` 是本次运行的工序记录；`Stage4Task` 是兼容旧任务队列/证据的视图。阶段 0-1 中除逻辑合流 `kit_join`（只有模板，由 `_check_join` 执行）外，带任务的工序三者一一对应；阶段 3 会扩展成一单多实例 DAG。 |
| **静态目录 vs 运行时状态** | `ProcessCatalog` 不持有 UID、句柄、时间或资源；运行时状态在 `OperationInstance`、`MaterialRegistry`、`ResourceTable`、控制器中。 |
| **能力 vs 设备 vs 资源 vs 区域** | 能力是抽象功能；设备提供能力；资源是互斥锁（线/臂/dock/lane/zone 锁）；区域是物料容量/位置。四者不能互相替代。 |
| **路线变体 vs 并行分支** | 同组变体是互斥选择（direct 或 alternate），不是同时执行。当前 `housing_finish` 用 `predecessor_policy=any` 表示任一路线终端完成即可。 |
| **AND 合流 vs OR 路线选择** | `kit_join` 的 `all` 要求两个输入都完成；`housing_finish` 的 `any` 表示直达或绕行任一路线完成。 |
| **逻辑合流 vs 物理装配** | `kit_join` 消费两条父 UID 并生成 FINAL；没有机械臂装配动作，也不是几何切削/检测。 |
| **`source_kind/sink_kind` vs `source_zone/destination_zone`** | 前者是介质类型（conveyor/agv/station）；后者是稳定区域 ID。`inputs[].zone`/`output.zone` 是实际的物料区域。 |
| **`operation id` vs `template id` vs `task kind` vs `task id`** | `housing_direct_A` 是工序模板 ID；`a_conveyor` 是旧 task kind；`a_conveyor_uid1` 是任务 ID；阶段 3 的计划字段 `operation_template_id` 指向工序模板。 |
| **物料类型 vs 业务名称** | `RAW_A/SEMI_AC/SEMI_CE` 等是 `ItemType` 稳定枚举；壳体/支架是报告解释用语，不参与类型判断。 |
| **工件 vs 场景 vs 模型** | 工件是版本化场景包（含 manifest/校验/生命周期）；场景是 `.ttt`；模型是可复用 `.ttm`。 |
| **冻结 vs 安全锁存 vs 资源释放** | 冻结是协调器停止现场并冻结任务；安全锁存是每臂独立安全状态；资源释放只释放调度锁，不清除安全锁存。 |
| **配置冻结值 vs 运行时目录** | `config.py` 的 `TASK_FLOW/TASK_PRIORITY/...` 冻结为工件 digest/旧报告兼容值；运行时流程以 `default_process.py` 为准，启动时核对两者一致。 |
| **基线 vs 当前运行** | 基线是阶段 0 的冻结行为/归一化签名；当前运行是本次 `full_flow` 样本。时间、句柄、停靠误差允许波动，任务/FINAL/物料/事件序列必须一致。 |
| **config digest vs layout digest vs manifest digest** | config digest 约束配置值；layout digest 约束布局对象；manifest digest 约束整个工件 manifest。三者任一不匹配都可能拒绝启动。 |

## 6. 当前默认工艺速查

默认配方 `mixed_line_v1` 的工序：

| 工序 ID | 旧 kind | 输入 → 输出 | 执行器 |
|---|---|---|---|
| `housing_direct_A` | `a_conveyor` | `line_s1a:RAW_A → handoff_ac:SEMI_AC` | `arm_A` |
| `housing_alt_B` | `b_conveyor` | `line_s1b:RAW_B → agv:SEMI_AB` | `arm_B` |
| `transport_BA` | `transport_ba` | `agv:SEMI_AB → agv:SEMI_AB`（B→A） | `agv_1` |
| `housing_alt_A` | `a_agv` | `agv:SEMI_AB → handoff_ac:SEMI_AC` | `arm_A` |
| `housing_finish` | `c_handoff` | `handoff_ac:SEMI_AC → line_ce:SEMI_CE` | `arm_C` |
| `housing_to_E_buffer` | `e_conveyor` | `line_ce:SEMI_CE → buffer_e_c:SEMI_CE` | `arm_E` |
| `bracket_process` | `d_conveyor` | `line_s2d:RAW_D → agv:PART_DE` | `arm_D` |
| `transport_DE` | `transport_de` | `agv:PART_DE → agv:PART_DE`（D→E） | `agv_1` |
| `bracket_to_E` | `e_agv` | `agv:PART_DE → buffer_e_d:PART_DE` | `arm_E` |
| `kit_join` | `logical_join` | `buffer_e_c:SEMI_CE + buffer_e_d:PART_DE → output_e:FINAL` | `logic_E`（逻辑） |

路线变体：

```text
housing_supply/housing_direct: housing_direct_A → housing_finish → housing_to_E_buffer
housing_supply/housing_alt:    housing_alt_B → transport_BA → housing_alt_A
                               → housing_finish → housing_to_E_buffer
bracket_supply/bracket_route:  bracket_process → transport_DE → bracket_to_E
mixed_line_v1/join:            buffer_e_c:SEMI_CE + buffer_e_d:PART_DE
                               → output_e:FINAL
```

当前 `full_flow` 仍然按来源和固定后继链执行；目录中的互斥路线/候选设备/
能力字段是**静态声明**，尚未实现订单级路线选择或动态设备匹配。

## 7. 运行时边界与未来名词

### 7.1 阶段 0-1 已实现

- 静态 `RecipeSpec`/`OperationTemplate`/`RouteVariant`/`OrderEntry`；
- `ProcessCatalog` 索引与启动校验；
- `OperationInstance` 单一任务状态存储；
- coordinator 按目录读取任务字段，执行层沿用原控制器；
- `full_flow` 端到端对照通过。

### 7.2 规划中、尚未实现的名词

| 名词 | 所属阶段 | 说明 |
|---|---|---|
| **DeviceExecutor / `start()` / `poll()`** | 阶段 2 | 设备执行适配器；当前 coordinator 直接构造控制器。 |
| **`SUCCEEDED` / `WAITING_INPUT` / `READY` / `RESERVED`** | 阶段 3 | 计划中的工序实例生命周期；当前 `OperationInstance.state` 仍使用 `TaskStatus`。 |
| **工序 DAG / ready set / 依赖解锁** | 阶段 3 | 当前只有单任务生命周期和语义 `depends_on/successors`，没有运行实例图。 |
| **订单 / 订单释放 / `order_id`** | 阶段 3 | 当前只有场景批次，不是订单模型。 |
| **路线选择 `selected_route`** | 阶段 3 | 当前路线变体只是静态数据；运行时仍由来源和固定后继决定。 |
| **能力匹配 / 替代设备** | 阶段 4 | 当前每个工序只有一个候选设备。 |
| **YAML/JSON 用户配方** | 后续 | 当前只有代码内默认配方，不支持用户运行时编辑。 |
| **调度优化 / 有限恢复** | 阶段 5（暂缓） | 当前不自动重试、不恢复、不优化求解。 |
| **物理装配 / 真实工艺** | 未规划 | E 合流仍是逻辑配对；没有切削、检测或机械装配。 |

## 8. 命名与版本约定

- 稳定 ID 使用 `snake_case`（`housing_direct_A`、`buffer_e_c`、`arm_A`）；
  业务中文名只用于文档/报告，不参与运行时判断。
- 配方/工序/设备/区域 ID 是稳定字符串，不能写入 CoppeliaSim handle；
  handle 只在启动绑定/runtime 中使用，不进入配方或持久证据。
- 对象 alias 不含 `/`；`getObject` 路径查询才使用 `/` 前缀（项目既有约定）。
- `PROCESS_MODEL_VERSION` 随 recipe/operation/route/设备能力变化递增；
  当前 `v1_process_20261103`。
- `STAGE4_TASK_FLOW_VERSION`、`TASK_FLOW`、`TASK_PRIORITY` 仍保留为
  工件 config digest 和旧报告兼容值；不要为了“更新版本”改这些值，否则
  当前 `v004` 工件会拒绝启动。工艺语义变化应改 `default_process.py`。
- `kit_join` 是逻辑合流：可以被声明为 successor/依赖，但**不能**创建
  `Stage4Task`；它由 `_check_join` 在输入就绪时提交。
