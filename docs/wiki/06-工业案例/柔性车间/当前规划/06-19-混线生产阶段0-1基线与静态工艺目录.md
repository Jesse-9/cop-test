# 混线生产阶段 0-1：基线与静态工艺目录

## 目标

在不改变生产行为的前提下，把阶段四当前固定在 coordinator/config 中的任务语义集中成一份可校验的默认工艺定义。阶段完成后仍是代码内默认流程，不支持用户运行时自定义配方；先建立可比较的基线和清楚的数据边界。

概念边界：工序是可调度、可验收的业务模块；工步是工序内部的执行步骤；设备是提供能力的资源。此阶段只抽取**工序模板和默认流程**，不拆控制器的每个状态，也不做设备动态选型。

## 工作包

### 0A. 固化行为基线

- 核对 `stage4/L5_UFLOW/v004_20261029_133249` 当前工件、契约、布局和场景校验结果，不修改已保护工件。
- 只把 `full_flow` 的输入批次、预期工序/路线、FINAL 数、物料终态和代表性事件作为本计划验收基线。其它既有场景仅引用历史报告，不重跑。
- 从既有证据整理代表性 UID 事件轨迹：直达壳体、B→AGV→A 绕行壳体、D→AGV→E 支架、E 两输入合流。
- 把业务示例标为仿真语义：壳体/支架的加工是当前抓取、转运和物料类型转换的抽象；E 当前是逻辑配对，不是真实装配。

### 1A. 建立静态工艺模型

新增 `src/stage4/process_model.py`，定义最小不可变数据模型：

- `RecipeSpec`: recipe id、版本、产品类型、订单入口和工序模板集合。
- `OperationTemplate`: id、工序语义、输入/输出物料类型、前置依赖、候选设备 ID、能力要求、资源请求、工步模板 ID、完成验证器 ID。
- `WorkStepTemplateRef`: 当前只引用已存在的执行路径标识，如 `arm_pick_place`、`agv_route`、`conveyor_pickup`、`logical_join`，不把任意 Python 代码塞进配置。
- `RouteVariant`: 命名路线的工序选择及进入/离开连接点。直达 A 和 B→AGV→A 是互斥路线选项，不是同时执行的两个并行分支。
- `ProcessCatalog`: recipe / capability / device / zone 引用的唯一索引和完整性校验入口。

新增 `src/stage4/default_process.py` 或等价配置文件保存当前默认计划。将 `coordinator.py` 中的 `UNIT_TASKS`、`TASK_RESOURCES`、`TASK_TYPES`、source/sink/zone/dock 映射、`FOLLOWUP` 逐项迁入模型。`config.py` 保留仿真参数、场景常量和旧 task kind 的兼容标识，不再重复声明流程语义。

### 1B. 渐进接入

- 让 coordinator 从默认工艺目录读取当前任务字段；执行仍调用原 `Stage4UnitController`、`AGVRouteController4`、物料注册表和资源表。
- 以单一 operation runtime 状态作为运行时真相；`Stage4Task` legacy 字段只在序列化/报告边界提供只读兼容映射，不维护双向、可独立修改的状态。
- 将 E join 的输入类型、缓冲区和输出类型声明到默认工艺模型；此阶段可继续调用原 `_check_join` 实现，避免同时改事务语义。
- 启动前验证未知设备/zone/resource、重复 operation id、缺失输入输出、无效后继和循环依赖，并提供指向 recipe/operation 的错误信息。

## 不在此阶段做

不引入 YAML/JSON 用户配方、不改变调度策略、不改状态枚举、不拆设备执行端、不加新设备/场景、不实现物理装配、不做自动恢复或优化求解。

## 验收

- 默认工艺模型表达的路线与现有 `TASK_FLOW` 一致，A/B 壳体路线在 C 前正确汇合，D 支架到 E 的独立分支及 E AND 合流完整。
- catalog 校验对循环依赖、重复 ID、未知资源/能力和不匹配的物料类型均有负向测试。
- 原阶段四单元、AGV、场景契约、材料生命周期和指标测试通过。
- 仅 `full_flow` 按原输入批次运行，完成结果、FINAL 数、父 UID、物料位置和关键事件与阶段 0 基线一致；保存对照证据并注明输入工件。
- 静态模型与配方 validator 可运行纯数据正/负单元测试；不执行故障注入或异常恢复场景。
- 若无法重跑完整仿真，至少区分“模型/单元测试通过”和“端到端等价未验证”，不把前者写成阶段完成。

## 完成标志

coordinator 不再维护重复的工艺映射表；运行行为由一个默认 `RecipeSpec` 驱动，执行层仍沿用已验收控制器。阶段 2 以此 catalog 作为设备/能力注册的输入。
