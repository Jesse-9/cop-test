# 混线生产阶段 0-1：基线与静态工艺目录

## 原定目标与当前结论

本阶段已完成：在不改变 `full_flow` 生产行为的前提下，将默认工艺语义收敛为可校验的静态目录，并接入 v1 分层。阶段完成后仍是代码内默认流程，不支持用户运行时自定义配方；本阶段没有实现工序 DAG 调度或独立设备执行器。

概念边界：工序是可调度、可验收的业务模块；工步是工序内部的执行步骤；设备是提供能力的资源。此阶段只抽取**工序模板和默认流程**，不拆控制器的每个状态，也不做设备动态选型。

## 工作包

### 已交付内容

- 核对 `v1/L5_UFLOW/v001_20261103_004317` 当前工件、契约、布局和场景校验结果，不修改已保护工件。
- 只把 `full_flow` 的输入批次、预期工序/路线、FINAL 数、物料终态和代表性事件作为本计划验收基线。其它既有场景仅引用历史报告，不重跑。
- 从既有证据整理代表性 UID 事件轨迹：直达壳体、B→AGV→A 绕行壳体、D→AGV→E 支架、E 两输入合流。
- 把业务示例标为仿真语义：壳体/支架的加工是当前抓取、转运和物料类型转换的抽象；E 当前是逻辑配对，不是真实装配。

静态模型包含 `RecipeSpec`、`OperationTemplate`、`WorkStepTemplateRef`、`RouteVariant`、`OrderEntry`、设备/能力/区域模型和 `ProcessCatalog` 完整性校验，定义位于 `src/flexible_factory/domain/process_model.py`。默认数据位于 `domain/default_process.py`。

- `Stage4Coordinator` 通过 `default_catalog()` 读取目录，现有执行仍使用 simulation 控制器、物料注册表和资源表。
- `OperationInstance` 是单个工序运行记录；`Stage4Task` 的状态字段通过受控属性代理到该实例。该兼容队列仍是当前运行生命周期入口，不能描述为只读序列化投影。
- 默认目录声明了 E join 的输入/输出语义；物料谱系的实际配对提交仍由 coordinator/material registry 负责。
- `ProcessCatalog.validate()` 在启动时验证静态模型引用与结构。

## 未包含的能力

不引入 YAML/JSON 用户配方、不改变调度策略、不拆设备执行端、不加新设备/场景、不实现物理装配、不做自动恢复或优化求解；未实现依赖图实例化、ready set 和工序解锁。

## 验收

- 默认工艺模型表达的路线与现有 `TASK_FLOW` 一致，A/B 壳体路线在 C 前正确汇合，D 支架到 E 的独立分支及 E AND 合流完整。
- catalog 校验对循环依赖、重复 ID、未知资源/能力和不匹配的物料类型均有负向测试。
- 原阶段四单元、AGV、场景契约、材料生命周期和指标测试通过。
- 仅 `full_flow` 按原输入批次运行，完成结果、FINAL 数、父 UID、物料位置和关键事件与阶段 0 基线一致；保存对照证据并注明输入工件。
- 静态模型与配方 validator 可运行纯数据正/负单元测试；不执行故障注入或异常恢复场景。
- 若无法重跑完整仿真，至少区分“模型/单元测试通过”和“端到端等价未验证”，不把前者写成阶段完成。

## 本阶段完成标志

默认 `RecipeSpec` 驱动当前目录查询，`full_flow` 通过 v1 入口运行，执行层仍沿用已验收控制器。后续阶段使用该 catalog 中已有的设备/能力静态声明，不再重新建设同一目录。

## 后续复核项

阶段 0–1 报告将 `Stage4Task` legacy 字段描述为“只读投影”，但当前
`src/flexible_factory/domain/tasks.py` 仍为 `status`、`phase`、`priority`、
时间戳、`failure_reason`、`evidence`、`resources`、`upgraded` 等字段提供
setter。它们代理到同一个 `OperationInstance`，因此目前证据不能说明存在两份
状态或 `full_flow` 错误；但调用方仍可绕过 `OperationRuntime` 的状态迁移和
提交校验，接口约束没有落实。

后续修复纳入阶段 4 开始运行时能力派工前的前置工作：将 legacy 任务字段收敛
为只读兼容投影，把队列/coordinator 的生命周期写入改走 runtime 的受控方法；
对 `runtime_backed` 任务验证直接赋值被拒绝，且正常队列生命周期仍能正确更新
运行时实例。若非 DAG 的 reposition/兼容任务确需可变字段，应显式限定其写入
边界，不得让 recipe-backed 实例重新获得任意 setter。具体执行与验收见
[[wiki/06-工业案例/柔性车间/当前规划/06-22-混线生产阶段4产品变体与能力匹配调度]]。
