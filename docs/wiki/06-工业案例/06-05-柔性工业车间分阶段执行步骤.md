## 0. 执行原则

### 0.1 当前仓库与参考资料

当前 `main` 分支最近历史提交已经删除旧版 `src` 控制层文件。执行阶段不需要恢复旧版控制层，
可以直接按审核方案重新建立源码、模块边界和测试。删除前提交只作为参考资料，用于核对内置模型
路径、CoppeliaSim 4.10 已知问题、历史参数测量和可复用测试经验；旧版架构、关键帧机械臂和
位置驱动 AGV 不构成新实现约束。

建议流程：

```text
确认工作树状态
    ↓
创建 codex/* 实施分支
    ↓
查阅删除前提交中的模型路径、物理坑点和测试经验
    ↓
按新方案直接创建模块、场景构建器和测试
    ↓
运行新实现的静态检查和最小测试
```

### 0.2 每阶段交付规则

每个阶段必须同时交付：

1. 场景文件或场景构建代码；
2. 配置参数和对象别名清单；
3. 控制模块及其单元测试；
4. 一份运行日志或测试报告；
5. 该阶段的已知限制和未解决问题。

阶段未通过时不进入下一阶段。下一阶段只能依赖上一阶段已经通过的接口，不通过复制临时脚本绕过前置验收。

### 0.3 全局不变量

以下约束在三个阶段都必须保持：

- 传送带使用内置 `generic conveyor (belt).ttm`；
- 机械臂使用内置六轴 UR5；
- 末端工具使用内置 `suction pad.ttm`；
- AGV 使用内置 `pioneer p3dx.ttm`；
- 运行模式只有 `HYBRID_DYNAMIC`；
- 固定位置检测使用 proximity sensor；
- 任务按物料 UID/句柄绑定，传感器命中不等于自动抓取；
- UR5 取放由 `simIK` 求解，不能用关键帧伪装成功；
- AGV 通过左右轮速度驱动，不能逐帧瞬移车体；
- AGV 载荷默认保持 dynamic + respondable，通过载台接触、摩擦和挡边运输；
- 别名使用扁平下划线形式，句柄采用别名叶匹配；
- 内置模型加载后检查并剥离会造成 4.10 启动冻结的脚本。

## 1. 阶段零：实施准备与参数冻结

阶段零是四个实施阶段的共同前置，不计入“单元闭环、物理与运行基础能力、双工位、多岛车间”四阶段本身。这里冻结的是新方案的坐标、模型测量和验收参数，不是旧源码基线。

### 1.1 建立实施分支和变更记录

步骤：

1. 记录 `git status --short`、当前分支、当前提交和场景文件时间戳；
2. 确认现有删除状态属于历史提交，不将其误认为本次修改；
3. 创建形如 `codex/flexible-workshop-phase1` 的实施分支；
4. 建立 `docs/implementation/` 或在本文件中记录恢复来源、提交号和恢复文件列表；
5. 将 `.ttt` 场景和运行日志列入不覆盖清单。

产物：

```text
实施分支
参考提交记录
新建文件清单
不覆盖文件清单
```

通过条件：参考资料、目标分支、新建模块清单和当前工作树状态可由另一位开发者复现；
不要求旧版控制层恢复成功。

### 1.2 检查 CoppeliaSim 和 Remote API

步骤：

1. 确认 CoppeliaSim 版本不低于 4.10；
2. 确认内置模型目录可访问；
3. 确认 `robots/non-mobile/UR5.ttm`、`components/grippers/suction pad.ttm`、`robots/mobile/pioneer p3dx.ttm` 和 `equipment/conveyors/generic conveyor (belt).ttm` 存在；
4. 启动 ZMQ Remote API 服务；
5. 通过 Python 客户端连接，并用 `getSimulationState()` 作为探活回退；
6. 验证 stepping 模式可推进至少 20 个仿真步。

通过条件：连接、启动、暂停、单步和停止均成功；`coppeliaSimVersion` 即使为 `None` 也不会误判为断线。

### 1.3 固化参数和坐标系

步骤：

1. 确定世界坐标：X 为主要输送方向，Y 为横向，Z 为高度；
2. 确定地面高度、传送带工作面高度和 UR5 基座高度；
3. 测量 conveyor 原始外包围盒与有效 pad 区域；
4. 测量 UR5 工作半径和 suction pad TCP 偏移；
5. 测量 pioneer p3dx 轮半径、轮距、车体高度和载台高度；
6. 将测量结果写入配置文件或 `docs/measurement/`，禁止只写在控制代码注释中；
7. 为位置、姿态、速度、加速度和传感器距离定义统一单位：m、rad、s。

通过条件：所有后续场景和测试引用同一套坐标、单位和测量值。

## 2. 阶段一：单元闭环

### 2.1 阶段目标和边界

目标是完成一条传送带、一个 UR5、一个 suction pad、一个 pioneer p3dx、一个指定物料的完整闭环：

```text
生成物料 → 传送带输送 → 取料传感器确认
→ UR5 IK 接近 → 指定物料吸附 → 抬升
→ 放到工位或 AGV 载台 → 释放
→ 物料恢复动态属性 → 结果验证
```

本阶段不实现：多物料队列、多机械臂竞争、五岛节拍、AGV 多任务调度和真实真空力。

### 2.2 建立单元目录和模块骨架

步骤：

1. 在源码目录建立方案中的模块边界：

   ```text
   build_scene.py
   factory_config.py
   factory_physics.py
   conveyor_controller.py
   ur5_ik_controller.py
   suction_controller.py
   pioneer_controller.py
   material_manager.py
   factory_controller.py
   ```

2. 创建测试目录，至少包含 `test_scene_contract.py`、`test_material_lifecycle.py` 和 `test_differential_drive.py`；
3. 为每个模块定义输入输出和异常类型；
4. 建立 `DeviceHandleMap` 或等价的集中句柄表；
5. 将所有可调参数放到配置模块：模型路径、坐标、速度、容差、摩擦、轮速限制和超时。

通过条件：模块可以被导入，配置可以被读取，测试可在没有 CoppeliaSim 连接时运行纯逻辑部分。

### 2.3 构建地面、层级根和静态平台

步骤：

1. 清理本次测试场景中由构建器管理的对象；
2. 创建地面，设置 static + respondable；
3. 创建 `Warehouse`、`Conveyor`、`Island`、`Mobile`、`Part` 五个层级根 dummy；
4. 创建 UR5 固定平台和 AGV 载台；
5. 为载台增加低矮挡边，挡边不应阻碍 UR5 放料；
6. 检查平台和地面没有重复面或相互穿透；
7. 输出对象别名、类型、父对象和世界位姿清单。

通过条件：场景在不加载任何设备时能启动，地面能承载动态方块，所有根对象别名符合下划线规则。

### 2.4 加载和标定内置 conveyor

步骤：

1. 使用 `sim.loadModel` 加载 `generic conveyor (belt).ttm`；
2. 在重命名和挂父之前记录根对象和 pad 子对象；
3. 检查是否存在内置脚本，按项目规则剥离会产生冲突的脚本；
4. 获取模型 native 长度和 pad 有效运行区；
5. 计算构建阶段等比缩放因子；
6. 先完成缩放，再设置世界位置和绕 Z 轴旋转；
7. 在有效 pad 区域内创建 `Sensor_PickStation`；
8. 创建 `Sensor_ConveyorExit`，避开两端滚筒；
9. 将传送带 pad 设置为可响应承载面，将运行模式写为 `HYBRID_DYNAMIC`；
10. 保存构建后的实际长度、宽度、有效区间和传感器位姿。

通过条件：传送带只在构建阶段缩放；物料生成在有效 pad 区域；单步运行时模型尺寸不变化；传感器不命中滚筒或框架。

### 2.5 创建动态物料和生命周期管理

步骤：

1. 创建一个具有固定 alias 的测试物料 `Part_0001`；
2. 设置 dynamic + respondable、质量、摩擦和碰撞掩码；
3. 将物料生成在传送带入口有效区，不生成在模型外包围盒端点；
4. 为物料记录 UID、句柄、当前父对象、生命周期状态和历史事件；
5. 定义状态：`SPAWNED`、`ON_CONVEYOR`、`READY_FOR_PICK`、`HELD_BY_SUCTION`、`ON_TRAY`、`RELEASED`、`FAULT`；
6. 每次状态变化记录仿真时间和原因；
7. 禁止控制器通过 alias 猜测目标物料，必须引用当前任务的 UID。

通过条件：物料能够被创建、查询、删除；状态转换没有跳过吸附或释放；测试可还原物料完整历史。

### 2.6 加载 UR5 并建立工具链

步骤：

1. 加载内置 `UR5.ttm`；
2. 检查并剥离会与外部控制冲突的模型脚本；
3. 挂载到静态工作台时保存并恢复根 shape 的 static 属性；
4. 枚举并确认恰好六个 UR5 本体关节；
5. 加载 `suction pad.ttm` 并挂到 UR5 末端 connection/flange；
6. 创建 `SuctionPad_01_TCP` dummy，位置设为吸盘接触面中心；
7. 创建 `Sensor_SuctionPad_01`，检测方向朝向物料接触面；
8. 配置 UR5 与工具的碰撞掩码，避免工具与工作台自碰撞；
9. 将 UR5 当前关节值、TCP 位姿和工具偏移写入诊断日志。

通过条件：UR5 不下坠、不塌陷；六个关节顺序稳定；TCP 位置与吸盘接触面中心测量一致。

### 2.7 建立 simIK 上下文

步骤：

1. 为该 UR5 创建一个独立 `simIK` environment；
2. 创建主求解 group，配置伪逆和最大迭代次数；
3. 创建备用 group，配置阻尼最小二乘；
4. 使用 UR5 base、`SuctionPad_01_TCP` 和 target dummy 建立 IK element；
5. 初始使用 `constraint_position`，再根据工具姿态需求增加受限姿态约束；
6. 同步六个关节的限位、权重和最大步长；
7. 编写 `solve_target(target_pose)`，返回关节角、结果码、原因和误差；
8. 失败时尝试备用 group；
9. 两组均失败时返回明确失败状态，不写回伪造角度；
10. 为接近、抓取、抬升和放置分别定义 target pose。

通过条件：目标在工作半径内时稳定求解；目标不可达时可解释地失败；TCP 世界坐标误差在配置容差内。

### 2.8 实现 proximity sensor 检测

步骤：

1. 配置 `Sensor_PickStation` 的检测形状、距离和方向；
2. 读取 sensor 命中的对象句柄；
3. 将命中对象映射到物料 UID；
4. 检查命中对象是否为当前任务目标；
5. 目标不匹配时不触发吸附，记录 `PICK_MISMATCH`；
6. `Sensor_SuctionPad_01` 只用于确认 TCP 与目标物料的距离和接触方向；
7. 添加 sensor 无命中、命中多个对象、命中非物料对象的测试；
8. 将传感器读数和最终任务判断分开记录。

通过条件：传感器检测不会直接吸附任意对象；错误物料可被拒绝；传感器超时能进入等待或故障状态。

### 2.9 实现逻辑吸附与释放

步骤：

1. 定义 `attach(target_uid)` 前置检查：UID、sensor、TCP 距离、法向、速度和碰撞状态；
2. 保存物料原始父对象、位姿、dynamic/respondable、质量、摩擦和碰撞掩码；
3. 将物料绑定到吸盘 link 或 TCP 参考对象；
4. 关闭物料动态响应，避免重力使其从吸盘脱落；
5. 将状态改为 `HELD_BY_SUCTION`；
6. UR5 完成抬升和转运；
7. 到达 AGV 载台或工位放置位后调用 `release(target_uid)`；
8. 先设置目标位姿，再恢复 dynamic/respondable 等物理属性；
9. 调用 `resetDynamicObject`，等待若干仿真步使物料稳定；
10. 检查物料未穿透载台且速度在稳定阈值内；
11. 失败时保留故障现场和原始属性快照。

通过条件：不模拟真实真空力也能稳定完成指定物料搬运；释放后物料重新参与重力、接触和摩擦；属性没有丢失。

### 2.10 加载 pioneer p3dx 并实现轮速控制

步骤：

1. 加载内置 `pioneer p3dx.ttm`；
2. 检查模型脚本并按规则剥离外部控制冲突脚本；
3. 记录车体、左右驱动轮和传感器句柄；
4. 保存车体质量、惯量、轮半径和轮距，作为基线快照；
5. 实现 `cmd_vel(v, w)` 到左右轮速度的差速换算；
6. 为轮速、线速度、角速度设置限幅和加速度斜坡；
7. 通过 `setJointTargetVelocity` 驱动左右轮；
8. 禁止控制器在运行循环中直接设置 AGV 世界位置；
9. 建立简单直线和原地转向测试；
10. 创建 `Sensor_AGV_Dock`，确认装卸位姿。

通过条件：AGV 能通过轮速前进、转向、停车；车体不会被位置控制器瞬移；质量和惯量快照与加载后保持一致。

### 2.11 阶段一总控制循环

当前生产布局为步骤 1.1 选定的 `L1_S1`，场景不构建挡停体；取料采用
B 组流程（传感器命中即停带、物料稳定后按实测位姿抓取）。按以下顺序
实现单步循环：

1. 读取通信和仿真状态；
2. 更新 conveyor 驱动和 HYBRID_DYNAMIC 物料输送；
3. 读取 `Sensor_PickStation`；命中目标 UID 后立即下发 conveyor 零速；
4. 等待带面停止（速度回读 + pad 位姿差确认）和物料稳定；
5. 读取物料实测世界位姿，校验允许抓取区和倾角，固定一次 TCP 目标；
6. 求解 IK 并下发关节目标；
7. 检查 TCP 和 `Sensor_SuctionPad_01`，执行吸附；
8. 执行抬升、转运和放置；
9. 释放物料并等待稳定；
10. 若目标是 AGV，更新 pioneer p3dx 轮速；
11. 写入事件日志；
12. 调用 `sim.step()`。

### 2.12 阶段一故障注入

逐项执行并保存日志：

| 故障 | 注入方式 | 期望行为 |
|---|---|---|
| 目标未到位 | 暂停 conveyor 或移走物料 | UR5 保持等待，不执行吸附 |
| 目标 UID 不匹配 | 将另一物料放入 sensor 区 | 记录 `PICK_MISMATCH`，不吸附 |
| IK 不可达 | 将 target 移出工作半径 | 主组、备用组失败后进入重试/终止 |
| 传感器无读数 | 禁用 sensor | 任务超时或在停止区保护边界停带失败，不误抓取 |
| AGV 路径受阻 | 放置静态障碍物 | AGV 降速或进入 `BLOCKED` |
| 释放不稳定 | 提高载台倾角或降低摩擦 | 记录载荷不稳定，不宣称通过 |

### 2.13 阶段一退出门槛

## 3. 阶段二：物理与运行基础能力

### 3.1 阶段目标和边界

阶段二不扩展工位数量，专门消化阶段一暴露的工程缺口，形成可复用的
“物理约束 + 场景生命周期 + 故障处置”基础层。原阶段二“双工位柔性搬运”
顺延到阶段三，原阶段三“多岛车间”顺延到阶段四。

阶段二必须完成：

```text
TCP 外表面接触约束
    → UR5/工具/工件碰撞检测与局部避障
    → 构建、保存、加载、校验、启动解耦
    → 统一故障状态、物料 FAULT 和恢复/人工处置
    → 传送带停机、越程和安全挡停验证
    → 脚本所有权清单与可复现验收
```

本阶段不增加第二个工位、不引入任务队列竞争，也不恢复五岛生产拓扑。

### 3.2 建立物理接触约束

1. 明确定义 TCP 接触面、物料外表面法向和允许接触间隙；TCP 目标不得使用
   物料几何中心替代接触面。
2. 将吸附判据拆为：外表面有符号距离、法向夹角、proximity sensor 命中、
   UID/类型匹配、物料速度、TCP 速度和碰撞状态。
3. 为 UR5 连杆、suction pad、工件、工作台、conveyor 和载台建立碰撞集合与
   respondable/collision mask，明确自碰撞和允许接触对。
4. 在 IK 目标之间执行离散路径碰撞检查；发生碰撞时立即停止关节目标，进入
   `COLLISION`，不得继续下探或宣称到位。
5. 为取料、抬升、转运、放料分别建立安全退避点；局部 IK 失败时不得用 seed
   角度冒充路径可行。
6. 记录最小外表面间隙、碰撞对象句柄、碰撞时刻和当前任务 UID。

通过条件：TCP 不进入物料体积；UR5 与工作台、conveyor、载台之间的测试障碍
不能被穿过；碰撞或接触异常均有可重放日志。

阶段二的路径策略明确分为三种，按以下优先级执行：

| 方法 | 作用 | 阶段二定位 |
|---|---|---|
| 离散构型碰撞检查 | 验证当前 IK 目标之间的插值构型是否安全 | 必须实现的基线 |
| 局部关节空间避障 | 通过有限 waypoint、接近高度和 wrist 姿态变化绕开局部障碍 | 推荐的主方法 |
| OMPL 全局规划 | 在局部候选全部失败或障碍拓扑复杂时搜索全局关节路径 | 可选增强/兜底 |

`sim.checkDistance` 的安全裕量检查和运行期碰撞轮询属于所有方法共用的支撑机制，
不替代最终的 `sim.checkCollision`，也不单独构成一条“无碰撞路径”。

### 3.3 建立碰撞集合、距离集合和允许碰撞对

步骤：

1. 使用 `sim.createCollection` 创建并保存以下集合句柄：
   `COLL_UR5_01`（六个连杆和 suction pad）、`COLL_WORKCELL`（工作台、
   conveyor 框架、载台和测试障碍物）、`COLL_PARTS`（动态物料）以及
   `COLL_AGV`（车体、轮子、载台和挡边）。集合内容写入场景 manifest，不能
   依赖本次对象创建顺序。
2. 通过 `sim.checkCollision(entity1, entity2)` 检查集合或对象；需要诊断相交
   线段时才使用 `sim.checkCollisionEx`。不把已弃用的注册式
   `sim.handleCollision` 作为新控制器主接口。
3. 明确碰撞对和例外白名单：

   | 碰撞对 | 策略 |
   |---|---|
   | `COLL_UR5_01` vs `COLL_WORKCELL` | 禁止，路径检查和运行期检查均必须为无碰撞 |
   | `COLL_UR5_01` vs `COLL_PARTS` | 接近段禁止；仅目标物料的最终外表面接触允许 |
   | suction pad vs 非目标物料 | 禁止 |
   | 物料 vs conveyor pad / AGV 载台 | 允许物理接触，但不得穿透 |
   | `COLL_AGV` vs 地面/静态障碍物 | 禁止 |
   | UR5 相邻连杆 | 按运动链过滤连续杆件，保留可能自碰撞的非相邻对 |

4. 为每个集合记录 `collidable`、`respondable` 和碰撞掩码；“允许接触”只表示
   该对不应触发路径失败，不表示可以关闭物理响应或允许几何重叠。
5. 为工作台边缘、传送带框架、AGV 挡边和物料外包围盒设置安全距离
   `collision_margin`。用 `sim.checkDistance` 做预警，最终通过条件仍以
   `sim.checkCollision` 为准。

通过条件：每个集合可由 manifest 复建；禁止碰撞对能触发失败；允许接触对不会
   因碰撞掩码错误而被误报或被无限穿透。

### 3.4 实现离散构型碰撞检查

这是阶段二的最低成本基线，适用于障碍物少、路径较短的单元场景：

1. 读取当前六关节构型 `q_start`，用 simIK 为预接近、接触、抬升和放置目标
   求解 `q_goal`；目标构型先单独检查，目标本身碰撞则立即返回
   `COLLISION_AT_GOAL`。
2. 在关节空间按最大关节步长 `delta_q_max` 插值。步数至少覆盖最大关节位移，
   并额外满足 TCP 直线接近段的最大笛卡尔步长；禁止只检查起点和终点。
3. 对每个候选构型在影子 UR5/碰撞检查副本上更新关节姿态，然后依次执行：
   `sim.checkCollision(COLL_UR5_01, COLL_WORKCELL)`、目标/非目标物料检查，
   以及 `sim.checkDistance` 安全裕量检查。影子副本不参与动力学，不改变真实
   机械臂当前状态。
4. 记录首个失败构型的索引、关节角、TCP 位姿、最小距离、碰撞对象句柄和任务
   UID；若只违反安全裕量而未碰撞，标记为 `NEAR_COLLISION`，不得直接当作通过。
5. 仅当所有离散点均通过时，才把构型序列交给 `sim.moveToConfig`/Ruckig 或
   关节目标执行；执行阶段仍需按仿真步重复检查。

局限：采样间隔过大会漏掉两个采样点之间的穿模，因此 `delta_q_max`、TCP 步长
和 `collision_margin` 必须是配置项并写入日志，不能用“终点无碰撞”代替路径证明。

### 3.5 实现局部关节空间避障（阶段二主方法）

局部避障不是忽略碰撞，而是在离散检查失败后有限地改变路径：

1. 先按 3.4 检查 `q_start → q_goal`。无碰撞时直接执行，不额外引入随机规划。
2. 检测到碰撞或 `NEAR_COLLISION` 时，按固定顺序尝试局部候选：
   减小插值步长、增加预接近高度、沿工作台法向/传送带法向偏移一个
   `waypoint_clearance`、改变 wrist 姿态（保持 TCP 接触法向约束），再重新运行
   simIK 和 3.4 的完整检查。
3. 每个候选最多生成有限数量 waypoint，例如
   `approach_high → lateral_clear → approach_low → q_goal`；候选排序使用
   路径长度、最小距离和关节变化量，禁止只按“能到达”选择最危险路径。
4. 候选全部通过后，用 `sim.moveToConfig`/Ruckig 分段执行；每段的开始和结束
   均复核碰撞集合，运行中由 3.7 的监控器兜底。
5. 局部候选耗尽后，不得继续下探或使用 IK seed 角度冒充成功；返回
   `LOCAL_AVOIDANCE_FAILED`，转入 OMPL（3.6）或故障恢复（3.9）。

适用边界：本方法适合阶段二的单 UR5、少量固定障碍物和已知抓取姿态；它不是
全局最优规划，也不能保证绕过狭窄或拓扑复杂的障碍物。

### 3.6 选择性接入 OMPL 全局规划

当局部 waypoint 失败、障碍物增多或需要跨越不同工作区时，使用
[[wiki/03-运动规划与控制/03-02-OMPL运动规划]] 的关节空间规划：

1. 建立 UR5 六关节 state space，设置关节上下限、规划时间和状态验证分辨率。
2. 通过 `simOMPL.setCollisionPairs` 配置 UR5 集合与工作区集合的禁止碰撞对，
   并用同一份碰撞白名单过滤自碰撞和允许的目标接触。
3. 以当前构型为 start、经 simIK 验证的目标构型为 goal，优先使用
   `RRTConnect`；规划结果必须再经过 3.4 的逐点碰撞和距离复核。
4. 对 OMPL 输出的离散路径做简化和 Ruckig 时间参数化；最终取料段仍保留
   物料表面法向约束，必要时用 simIK 直线接近段与全局路径拼接。
5. 规划超时、无解或复核失败时返回 `GLOBAL_PLAN_FAILED`，进入故障恢复，不得
   降级为无碰撞检查的直线运动。

OMPL 是阶段二的可选增强，不应阻塞先完成“离散检查 + 局部 waypoint + 运行期急停”
的主路径；只有在主路径的验收障碍案例中确实需要全局绕行时才启用。

### 3.7 运行期碰撞监控、急停和恢复

1. 在每个 stepping 周期检查 UR5/工具与工作区、物料与承载面、AGV 与障碍物的
   当前碰撞状态，并检查 `sim.checkDistance` 是否跌破安全裕量。
2. 发生碰撞时立即把六个关节目标置为当前安全目标，传送带和 AGV 下发零速，
   记录仿真时间、碰撞对象、关节构型、TCP 位姿、物料 UID 和最近事件；不能等
   到任务超时后才处理。
3. 未吸附物料：保持现场并退回最近安全构型；已吸附物料：先沿已验证的退避
   段抬升，再释放到隔离区或转入 `MANUAL_INTERVENTION`，禁止在碰撞状态下继续
   横移。
4. 急停恢复前重新检查碰撞对、最小距离、物料动态属性、工具姿态和传感器读数；
   只有连续若干正常周期后才能进入 `RECOVERED`，否则保持 `COLLISION`。
5. 对动态障碍物增加“检测→停机→重新规划”回路；重规划失败时保持执行机构
   停止并转人工，不把急停事件统计为完成任务。

通过条件：静态障碍、动态障碍和 TCP 过低三类测试均能在碰撞前或碰撞瞬间停机；
恢复后不会重复吸附错误 UID，也不会丢失物料属性和故障现场。

### 3.8 解耦场景构建与仿真启动

1. 将场景操作拆成 `build_stage1_scene`、`save_scene`、`load_scene`、
   `validate_scene` 和 `start_simulation` 五个动作。
2. CLI 提供显式模式：首次构建、加载已有 `.ttt`、仅校验已有场景、启动已有
   场景；默认启动不得隐式 `clear=True` 或重建对象。
3. 构建完成后保存场景 manifest，至少包含模型路径、模型版本、配置摘要、
   alias/句柄清单、几何测量和场景契约结果。
4. 启动前重新校验 manifest 与当前场景；模型、别名、TCP 偏移或物理参数不一致
   时拒绝启动并给出差异。
5. 构建期才允许缩放、挂父、剥离脚本和创建固定几何；仿真运行期不得改变
   设备尺寸或拓扑。
6. 为构建、加载、启动、停止和恢复分别写入结构化生命周期事件。

通过条件：不重建场景即可重复启动和停止仿真；重启 CoppeliaSim 后可从保存的
`.ttt` 恢复；过期或不匹配场景会在启动前失败，而不是静默运行。

### 3.9 统一故障状态与恢复策略

1. 定义任务状态 `RUNNING`、`RETRYABLE_FAILURE`、`FAULT`、`BLOCKED`、
   `MANUAL_INTERVENTION`、`RECOVERED` 和 `DONE`，禁止 `DONE + BLOCKED` 这类
   含义冲突的组合。
2. 所有故障都必须绑定任务 UID、物料状态、执行机构状态、故障原因、时间戳和
   快照；不能只写字符串日志。
3. IK/碰撞失败时：停带、停 AGV、停止关节目标；若物料已吸附，先退避到安全
   位，随后释放到隔离区或进入人工处理队列。
4. 传感器超时、UID 不匹配、输送掉落和释放不稳定时，将相关物料显式置为
   `MaterialState.FAULT`，保留属性快照，不得遗留为可再次领取的正常状态。
5. AGV 堵塞进入 `BLOCKED`，任务保持未完成；清障后低速试运行并重新确认位置、
   航向、载荷和路径占用，连续正常周期后才能进入 `RECOVERED`。
6. 重试必须有次数、退避策略和幂等边界；超过上限进入 `MANUAL_INTERVENTION`。
7. 提供显式复位操作，只有操作者确认现场和物理属性后才能将物料从 `FAULT`
   复位为 `SPAWNED` 或将任务重新入队。

通过条件：每类故障都能安全停机、明确归类、保留现场并按策略恢复或转人工；
故障任务不会被统计为完成任务。

### 3.10 传送带停机与安全挡停

1. 传感器连续确认目标 UID 后向 conveyor 下发零速，并测量命令到 pad 停止的
   延迟和物料最大越程。
2. 区分“控制停机”和“被动挡停”：`Conveyor_In_PickupStopper` 可作为最后一道
   安全保护，但不得替代传感器和零速控制。
3. 记录停止前后带速、物料位置、越程和是否发生碰撞；停止失败进入
   `CONVEYOR_FAULT`。
4. 明确单物料阶段可以全带停机；多物料阶段必须设计分区、缓存或背压，不能
   用全局停带掩盖队列问题。

通过条件：正常停机不依赖挡板，最大越程在配置容差内；去除挡板的诊断测试能
明确暴露停止失败，而不是让物料静默通过。

### 3.11 内置脚本所有权和场景契约

1. 为每个内置模型记录脚本清单、保留/剥离决策、唯一控制者和回归证据。
2. conveyor customization script 由模型负责 pad 驱动，Python 只写明确定义的
   控制接口；UR5、suction、pioneer 不得出现重复控制源。
3. 吸盘脚本若保留，必须证明不会全场景自动吸附；否则继续剥离并由阶段二的
   显式控制器负责 UID 绑定。
4. 场景契约增加 collision collection、TCP 外表面偏移、脚本所有权、保存版本和
   启动模式检查。

### 3.12 阶段二回归测试矩阵

| 测试 | 场景 | 通过条件 |
|---|---|---|
| 外表面接触 | TCP 过高、过低、横向偏移、倾斜 | 只允许有效外表面接触 |
| 集合与碰撞对 | UR5、工具、工件、工作台、conveyor、载台 | 禁止/允许碰撞对与 manifest 一致 |
| 离散路径检查 | 起点、终点和不同 `delta_q_max` | 所有采样构型无碰撞，安全裕量可量化 |
| 局部 waypoint 避障 | 增加工作台边缘或侧向障碍 | 生成无碰撞局部路径，失败有明确状态 |
| OMPL 兜底 | 局部 waypoint 全部失败的狭窄障碍 | 全局路径可复核；无解不降级直线运动 |
| 运行期碰撞 | 工作台、conveyor、载台、动态障碍物 | 碰撞前/瞬间停止并进入 `COLLISION` |
| 场景复用 | 保存后重启 CoppeliaSim 再加载 | 无需重建即可校验并运行 |
| 场景不匹配 | 修改模型/alias/参数版本 | 启动前拒绝并报告差异 |
| 故障处置 | IK、传感器、释放、AGV 堵塞 | 物料/任务状态明确，不能误报 DONE |
| 停带越程 | 不同速度和停止延迟 | 零速、越程和挡停行为可量化 |
| 脚本冲突 | 启用/剥离模型脚本 | 单一控制源，无冻结和重复吸附 |

### 3.13 阶段二退出门槛

- [ ] TCP 外表面接触和碰撞状态可观测、可拒绝、可追溯；
- [ ] UR5 取放路径通过离散碰撞检查；局部 waypoint 避障失败时有明确状态，
      需要时可由 OMPL 规划并完成二次复核；
- [ ] 运行期碰撞或安全距离不足时，传送带、AGV 和 UR5 能安全停止并按状态恢复；
- [ ] 场景构建、保存、加载、校验和仿真启动已解耦；
- [ ] 已保存场景可重复启动，不要求每次重新 `build_scene`；
- [ ] 故障任务、物料 `FAULT`、AGV `BLOCKED` 和人工处置状态语义一致；
- [ ] 故障后执行机构停止，物料属性和现场快照可恢复；
- [ ] conveyor 停机延迟、最大越程和挡停策略有实测数据；
- [ ] 脚本所有权清单和阶段二回归报告已保存。

## 4. 阶段三：双工位柔性搬运

### 4.1 阶段目标和边界

在阶段一单元上增加第二工位、第二组目标位、AGV 装卸站、任务队列和简单堵塞恢复：

```text
Conveyor_In → Station_A / UR5_A
                    ↓
              AGV 载台运输
                    ↓
              Station_B / UR5_B
```

本阶段不恢复五岛完整生产节拍，不增加多 AGV，不引入真实真空力和视觉识别。

### 4.2 复制单元但隔离句柄和状态

步骤：

1. 复制工位几何和传感器配置；
2. 第二工位使用唯一别名，例如 `Island_B`、`Robot_UR5_02`、`SuctionPad_02_TCP`；
3. 每台 UR5 建立独立 IK context；
4. 每个传感器绑定所属工位和允许的物料类型；
5. 句柄表不得依赖对象创建顺序；
6. 运行时验证每个 alias 唯一；
7. 为每个工位建立独立状态机，但共享物料和任务调度接口。

通过条件：单独启用任意一个工位不影响另一个工位；两个 UR5 的 TCP、传感器和物料状态不会串线。

### 4.3 定义任务队列和资源锁

步骤：

1. 定义任务类型：`PICK_FROM_CONVEYOR`、`PLACE_AT_STATION`、`LOAD_AGV`、`UNLOAD_AGV`；
2. 为任务记录优先级、创建时间、目标 UID、源工位、目标工位和重试次数；
3. 为 UR5、传送带取料位、AGV 装卸位建立资源锁；
4. 任务只有在资源可用时才进入执行状态；
5. 禁止两个 UR5 同时抢同一个物料；
6. 任务失败时释放锁并按重试策略回队列；
7. 超过最大重试次数进入人工处理队列；
8. 记录任务排队、开始、暂停、完成和失败时间。

通过条件：两个工位并发请求时没有重复抓取、死锁或资源锁泄漏。

### 4.4 实现 AGV 路径与装卸站

步骤：

1. 为 A→B 建立带中间路点的二维路径；
2. 路径避开 conveyor、工作台和传感器实体；
3. 创建 `Sensor_AGV_Dock_A` 和 `Sensor_AGV_Dock_B`；
4. AGV 到站时使用位置、航向和传感器三重判定；
5. 到站后将轮速目标降为零，并等待车体速度稳定；
6. 只有稳定后才允许 UR5 进入装卸状态；
7. 装卸完成且物料状态确认后才释放 AGV 任务；
8. AGV 离站前检查载台区域没有残留物料。

通过条件：AGV 能重复完成 A→B→A 路线，停车位置和朝向满足 UR5 放料工作空间。

### 4.5 实现柔性调度

步骤：

1. 建立单一共享 AGV 队列；
2. 默认优先处理生产关键路径任务；
3. 为低优先级任务设置最大等待时间；
4. 低优先级任务等待超限时提升优先级，但不抢占正在执行的任务；
5. UR5 任务与 AGV 任务通过物料 UID 关联；
6. AGV 离站前禁止下一个工位误判物料已到达；
7. 任务完成后由目标传感器和物料状态共同确认；
8. 记录调度决策、等待时间、路径和任务结果。

### 4.6 实现堵塞、超时和恢复

步骤：

1. 定义 AGV 位置误差、速度误差和路径占用超时阈值；
2. 发现路径被占用时进入 `BLOCKED`，不继续增加轮速；
3. 记录阻塞起始时间和障碍物句柄（若可获得）；
4. 路径清除后以低速恢复，再逐步恢复正常速度；
5. 工位超过处理时间时暂停对应上游物料生成；
6. 队列超过上限时触发背压；
7. 三个连续正常周期后恢复暂停的上游供料；
8. 所有恢复动作写入事件日志，不静默改变任务状态。

### 4.7 双工位回归测试矩阵

| 测试 | 场景 | 通过条件 |
|---|---|---|
| 单任务 | A→B 一件物料 | 物料 UID 全程一致 |
| 连续任务 | 连续生成 5 件物料 | 无重复抓取和丢失 |
| 双工位竞争 | A、B 同时请求 UR5/AGV | 资源锁和队列正确 |
| 阻塞恢复 | AGV 路径放置障碍 | 进入 BLOCKED 后恢复 |
| 上游背压 | B 工位停止处理 | conveyor/供料暂停 |
| 低优先级等待 | 连续高优先级任务 | 等待超限后升级 |
| 释放失败 | 人为改变载台高度 | 进入故障，不误报完成 |

### 4.8 阶段三退出门槛

- [ ] 两个工位可独立运行并共享一个 AGV；
- [ ] 任务队列、资源锁和物料 UID 关联完整；
- [ ] AGV 装卸前后都有传感器和稳定性确认；
- [ ] AGV 阻塞、工位超时和队列溢出可恢复；
- [ ] 连续任务运行无重复抓取、错误卸载和句柄串线；
- [ ] 低优先级任务不会无限期饥饿；
- [ ] 阶段三报告包含吞吐量、平均等待时间、失败率和载荷滑移记录。

## 5. 阶段四：多岛车间

### 5.1 阶段目标和范围

将已通过双工位验收的组件扩展到现有五岛拓扑：

```text
S1 → A → C → E
S1 → B → AGV → A
S2 → D → AGV → E
```

阶段四重新接入：

- A–E 五个工作岛；
- S1、S2 两个仓库；
- 多条内置 generic conveyor (belt)；
- 每岛 UR5；
- 共享 pioneer p3dx；
- 仓库供料、物料生命周期、节拍追踪、异常处理和共享 AGV 调度。

### 5.2 迁移旧拓扑配置

步骤：

1. 从旧版配置中提取岛位置、传送带起终点、AGV 路线和节拍目标；
2. 逐项检查旧配置是否依赖已删除模块或关键帧动画；
3. 将每条传送带转换为新的 conveyor 配置：模型路径、有效 pad 区域、传感器和 `HYBRID_DYNAMIC`；
4. 将每个机械臂转换为 UR5 + 独立 IK context + suction TCP；
5. 将旧 AGV 位置插值逻辑替换为 pioneer p3dx 轮速控制；
6. 将旧物料阶段映射到新的物料生命周期；
7. 为每个岛建立输入、处理、输出传感器；
8. 保存迁移前后配置对照表；
9. 先只启用 A、B 两岛完成局部验证，再逐步打开 C、D、E。

通过条件：旧拓扑信息被完整迁移，但没有把旧的“位置瞬移 AGV”或“关键帧机械臂”逻辑带回新控制器。

### 5.3 分岛构建和验证

按照以下顺序启用，不一次性加载完整场景：

1. S1、A 和 `Conveyor_S1_to_A`；
2. 增加 B 和 `Conveyor_S1_to_B`；
3. 增加共享 pioneer p3dx，验证 B→A；
4. 增加 C 和 A→C 传输；
5. 增加 `Conveyor_C_to_E` 和 E；
6. 增加 S2、D 和 `Conveyor_S2_to_D`；
7. 增加 D→E AGV 路径；
8. 最后启用 E 的配对装配逻辑。

每增加一个岛，执行一次启动冻结、句柄、关节数、传感器和单步推进检查。

### 5.4 恢复仓库供料和物料生命周期

步骤：

1. 为 S1→A、S1→B、S2→D 定义供料节拍；
2. 供料前检查下游岛是否处于可接收状态；
3. 物料进入 conveyor 时记录来源仓库和目标岛；
4. conveyor 末端由传感器确认物料交接，不仅依赖距离阈值；
5. 进入岛后由 UR5 任务接管指定物料；
6. A→C、C→E 和 D→E 分别定义交接事件；
7. E 岛只在 C 线半成品和 D 线零件都到位后配对装配；
8. 成品生成后关闭对应原料链的任务引用；
9. 任一物料丢失、重复或状态回退都触发异常。

### 5.5 恢复工业节拍

步骤：

1. 为 A–E 配置目标节拍；
2. 每个岛在 `PROCESSING` 开始时记录仿真时间；
3. 完成时计算实际耗时和偏差；
4. 超过警告阈值时记录 warning；
5. 超过超时阈值时把岛置为 `TIMEOUT`，暂停上游供料；
6. 下游队列恢复后继续处理滞留物料；
7. 连续三个正常周期后恢复原节拍和供料；
8. 在报告中区分机械臂运动耗时、传送带等待、AGV 等待和工位处理耗时。

通过条件：节拍异常不会导致物料静默丢失；背压和恢复过程可从日志重放。

### 5.6 恢复共享 AGV 调度

步骤：

1. 将 B→A 和 D→E 注册为两类 AGV 任务；
2. B→A 设置高优先级；
3. D→E 设置低优先级和等待升级阈值；
4. 当前任务执行期间不抢占；
5. 任务选择只在 AGV `IDLE` 时发生；
6. 路径占用、碰撞和堵塞状态由 pioneer p3dx 实际位姿与传感器判断；
7. AGV 到站后必须通过目标站传感器确认卸载；
8. 调度器只在物料状态确认后关闭任务；
9. 输出任务队列长度、等待时间、路径耗时和饥饿升级次数。

### 5.7 多岛控制循环

最终循环建议固定为：

1. 通信和仿真状态探测；
2. 急停、碰撞、传感器和异常轮询；
3. 仓库按背压条件生成物料；
4. 更新所有 HYBRID_DYNAMIC conveyor；
5. 处理 conveyor 入口/出口传感器事件；
6. 更新各岛状态、节拍和队列；
7. 为可执行的 UR5 任务求解 IK；
8. 执行吸附、抬升、放置和释放；
9. 提交和更新共享 AGV 任务；
10. 计算 pioneer p3dx 轮速并检查到站；
11. 处理 A→C、C→E 和 E 配对装配；
12. 更新物料生命周期和场景诊断；
13. 写入日志、图表和异常快照；
14. 调用 `sim.step()`。

控制循环中的所有操作都必须能通过 `sim_time` 和物料 UID 追踪，不能只依赖屏幕上的几何位置。

### 5.8 多岛故障注入

| 故障 | 注入位置 | 期望行为 |
|---|---|---|
| 某 conveyor 停止 | 任一主线 | 上游背压，不产生无限堆积 |
| A 岛超时 | A 处理阶段 | 暂停 S1→A，恢复后自动续作 |
| B→A 路径阻塞 | AGV 路线上 | AGV BLOCKED，关键任务状态保留 |
| D→E 长时间等待 | AGV 队列 | 低优先级任务升级但不抢占当前任务 |
| UR5 IK 不可达 | 任一岛取料位 | 重试/退避/报警，不伪造成功 |
| 物料 UID 丢失 | 传感器交接处 | 进入异常队列并输出轨迹 |
| E 配对缺件 | E 入口 | 不生成 FINAL，等待另一条物料 |
| ZMQ 短暂断线 | 主控制连接 | 进入通信暂停并尝试恢复 |

### 5.9 阶段四退出门槛

- [ ] A–E 岛可以按顺序单独启用并通过局部验收；
- [ ] 全部机械臂均为 UR5 六轴，且每台 IK context 独立；
- [ ] 所有传送带使用内置模型和 HYBRID_DYNAMIC；
- [ ] 共享 pioneer p3dx 通过轮速服务 B→A 和 D→E；
- [ ] 五岛物料生命周期可通过 UID 和日志完整追踪；
- [ ] 节拍、背压、超时和恢复逻辑可验证；
- [ ] E 岛配对装配不会因缺件误生成成品；
- [ ] 运行至少一个完整生产周期无启动冻结、0 关节、错误吸附和任务死锁；
- [ ] 已保存吞吐量、节拍偏差、AGV 等待、IK 失败、传感器误报和物料丢失统计。

## 8. 变更与回退规则

1. 场景结构、模型路径和物理属性变更必须先更新配置和本执行手册，再运行验收；
2. 传送带长度、TCP 偏移、轮距、轮半径或传感器距离改变后，必须重新执行阶段一标定测试；
3. UR5 IK 约束改变后，必须重新执行所有取料位和放料位可达性测试；
4. AGV 质量、摩擦、加速度和载台几何改变后，必须重新执行载荷稳定性测试；
5. 任一阶段失败时，回退到该阶段最后一个通过的场景快照和配置提交；
6. 不使用 `git reset --hard` 或覆盖用户场景文件作为回退手段；
7. 失败日志、异常快照和回退原因保留在阶段报告中。
