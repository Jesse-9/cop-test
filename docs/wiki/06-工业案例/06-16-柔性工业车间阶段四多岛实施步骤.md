# 柔性工业车间阶段四：多岛车间详细实施步骤

> 本文基于 2026-10-28 工作区代码和阶段三报告审查阶段四范围，并给出阶段四实施与验收步骤。阶段四已按本文实施（见 §7）；旧五岛控制器只用于提取拓扑和业务语义，不作为新实现基线。

阶段四验收后的布局复审、平台高度 datum 与交错联动优化另列为阶段 4.1，见 [[wiki/06-工业案例/06-17-柔性工业车间阶段4.1场景布局与联动优化方案]]。该计划不改变本文记录的阶段四基线验收结论。

## 1. 审查结论

阶段四的目标拓扑合理，建议保留：

```text
S1 ──► A ──固定衔接──► C ──Conveyor──► E
 └──► B ──AGV 高优先级 B→A──► A
S2 ──► D ──AGV 低优先级 D→E──► E
```

实施前需要收紧以下边界：

| 项目 | 审查判断 | 阶段四处理 |
|---|---|---|
| 双工位、独立 UR5 IK 上下文、共享仿真步进、UID 任务、资源互斥、AGV 轮速驱动、BLOCKED 与卸载稳定性检查 | 阶段三已有实现和实测，不应作为新能力重复建设 | 复用 `src/stage3/` 与阶段三工件/契约；按扩展影响补充回归 |
| 五岛、两仓库、多传送带、多物料生产流 | 阶段三只覆盖两工位、单 UID 闭环；阶段四真实新增范围 | 扩展场景配置、物料流协调和验收场景 |
| AGV B→A / D→E 调度 | 阶段三是 A↔B 直线穿梭，和五岛的取货/送货路网及优先级语义不同 | 复用车辆物理驱动和状态/指标模式；重新实现并验证阶段四路线、装卸点与调度策略 |
| A→C 固定衔接、C→E 传送带、E 配对装配 | 旧案例有业务定义，阶段三未覆盖 | 迁移业务规则，避免迁移旧控制器的位置瞬移与关键帧行为 |
| 故障检测、安全停机、任务失败状态 | 前序阶段已要求具备局部检测和安全停止 | 阶段四补充多岛传播、背压和诊断；不重做锁存/停止基础能力 |
| 统一复位、跨设备恢复、有限重试和人工处置 | 已单列为最终阶段 | 阶段四只冻结/阻塞并保留证据，不实现自动复位或通用恢复 |

原阶段四退出门槛方向正确，但“恢复逻辑”“至少一个完整周期”等表述尚不够可执行。需要先固定工件身份、物料谱系、E 岛配对规则、AGV 等待升级语义、场景矩阵及指标口径，再开始写多岛控制逻辑。阶段三 AGV 当前为直线 A/B 路线；不能只改任务名称就视为 B→A / D→E 已经支持。验收应集中在代表性物流闭环、配对正确性和基本故障停机，不要求安全认证或穷举每种排列。

## 2. 基线、复用与禁止回退

阶段四实施输入：

- 阶段三通过验收的代码、场景工件、契约和证据；参见 [[implementation/PHASE3_REPORT]]。
- 旧拓扑和业务语义；参见 [[wiki/06-工业案例/06-02-岛式车间柔性生产案例]]。
- 当前运动、安全、物料生命周期及场景生命周期模块；以仓库当前实现和测试为准。

直接复用并扩展：

- 阶段三两工位 `UnitController` 的执行契约和共享 `sim.step()` 编排；每个新机械臂仍使用独立 IK/runtime 上下文。
- `TaskQueue`、UID 去重、资源申请/释放事件、任务证据及“失败/BLOCKED 不得 DONE”约束。
- `MaterialManager` 的物料状态与历史记录，但要扩充多阶段产品类型、来源、父子谱系和装配消耗语义。
- 场景构建、manifest、只读契约校验和 lifecycle 生命周期；新增阶段四契约应继承 stage3 父工件并记录父契约摘要。
- 差速轮速控制、载荷稳定性、传感器交接、急停/安全锁存和碰撞检查。

不复用旧实现行为：逐帧设置 AGV 位姿、关键帧机械臂、凭坐标直接传送物料、以几何靠近代替传感器交接、失败后自动清除安全锁存。新增实现必须通过真实场景控制器或已定义的仿真接口完成。

## 3. 布局建议：沿用阶段三约束，围绕物流重新排布

### 3.1 布局依据与假设

- 阶段一 `L1_S1` 证明 UR5 从输送带侧方抓取的布局可行；阶段三 `L2_MIRROR` 证明 A/B 两臂分置中央输送带两侧可行，但它只覆盖双工位、单条直线 AGV 路线。阶段三报告中的坐标是布局锚点，不是五岛最终坐标。
- 阶段三静态筛选拒绝了同侧沿 X 错位的 `L3_SAME_SIDE`，原因包括 B 臂取料可达性和 AGV 通道/站位压占。因此不把五个工位排成同一侧的简单长队列。
- 旧五岛场景使用约 `18 m × 11 m` 地面，可作为阶段四初始画布量级；当前 stage1/stage3 的地面较小。应先依据内置模型包围盒、工作区和 AGV 扫掠范围确定地面，不把旧尺寸直接当作已验收值。
- AGV 站点、路径和设备位置相互影响。布局阶段同时绘制 From-To 物流边、AGV 路径和取送点，再验证机器人可达与碰撞；不能先定机器人坐标后才寻找 AGV 通路。

### 3.2 推荐相对布局

以下是首轮候选的**相对关系**，非比例图、非最终坐标。按物流方向把固定输送段放在单元内部，把 AGV 主通道放在工位/机器人包络外侧：

```text
北侧固定物流区（机器人从侧方工作，工作台朝单元外侧）

                         +X 主物流方向 →
               A ──短固定交接──► C ──Conveyor_C_to_E──► E(C入口)
              /                                             │
S1 ──分流────<                                               ├─配对/成品区
              \                                             │
               B (dock_B)       S2 ──Conveyor──► D(dock_D)  E(D入口)
                     ╲             ╲               ╲       ╱
                      ╰────── AGV 外围通道 / 支线 dock ────╯

AGV 任务边：B 装载→A 卸载；D 装载→E 卸载；卸载后走外围回流段至下一任务/等待位
（箭头仅表明业务流；实际路网必须按车体扫掠、净空和 dock 朝向确定）
```

可用于首轮场景摆放的轴向分区：A/B 先以阶段三 L2_MIRROR 的两侧工位为锚点，C 放在 A 固定衔接的下游，E 放在 C→E 输送末端；D 与 S2 放在 AGV 通道另一侧，使 D 的取料 conveyor 不穿过 C→E 线。B、A、D、E 的 dock 靠外围 AGV 通道，AGV 车头进出 dock 时不扫过 robot base 或 station。最终是 X/Y 具体坐标由 3.3 的测量与路径检查定，不预设数值。

布局要点：

1. 保留阶段三中央输入带及 A/B 两侧工作单元的相对结构作为候选起点。A、B 的 UR5 基座靠近各自取放区侧方，工位台放在机器人外侧；不要把基座放到传送带末端延长线上。A→C 尽量采用短、明确、可检测的固定交接，C→E 沿固定输送方向布置。
2. S1→A 与 S1→B 在业务上分流，但不默认两条皮带共用一个物理 Y 形岔道；首轮优先从 S1 出料区布置两条独立短支路。只有确需共用单带时，才增加经验证的分流机构和占用互锁。S2→D 是独立支路；各入口预留传感检测与有限缓冲位置，避免两路物料在同一窄区无序堆叠。
3. E 放在 C→E 固定带末端与 D→E AGV 到站侧的交汇附近。C 线入口和 AGV 入口分列 E 的不同侧，并各有一个缓冲/检测位；机械臂取放区和成品输出区留在另侧。这样配对依赖明确的两路输入，不让 AGV 停在 conveyor 出口或机械臂常用路径上。
4. AGV 主通道沿单元外围形成低交叉路线，优先用单向环路或具有明确会车/等待点的双向分段路线。B→A 与 D→E 共享路段；在实际拓扑中标出交叉口、窄道、dock 占用区和等待点。将高优先级用于下一次派车选择，不在窄道或载荷运输中抢占。
5. 每个 dock 采用沿 AGV 行进方向的直线进出，留出车辆和载荷的停车/转向包络；装卸点避开 robot arm 底座、station 外伸区域以及传送带框架。E 的 AGV dock 与 C 带出口应空间分离，避免卸料时相互阻挡。
6. 机器人只覆盖本岛、相邻传送带交接点和本岛 dock 的必要目标。不要为了让一台 UR5 跨越整条主线而把它布置在 AGV 通道上方；邻岛间传递优先交给定义好的 conveyor/AGV 边。

### 3.3 坐标确定与轻量筛选

按以下顺序生成坐标，不在文档里预填未验证的五岛数值：

1. 固定世界坐标：沿用 X 为主输送方向、Y 为横向、Z 为高度；将阶段三 A/B 基座和 conveyor 作为可调整锚点。先确认业务图中阶段四 B 是 S1 的独立工序岛，而阶段三 B 是 A→B 双工位目的站；两者业务角色不同，不能只沿用 `unit_id="B"` 的旧 dock/站位语义。
2. 读取每个内置 conveyor、UR5、suction pad、pioneer p3dx 的真实包围盒和关节/轮组范围。将 conveyor 有效 pad、传感器检测区、物料尺寸和工作台高度加入平面图。
3. 按 3.2 放置岛、工作台与 conveyor 后，绘制 AGV 车体加最大载荷的 footprint、直线制动距离、转弯扫掠和各 dock 进出方向；在平面图中明确禁止区和共享区域。
4. 只保留两种有实际差异的候选：本节推荐的“两条固定物流支路 + 外围 AGV 环线”，以及一个简单的“外围主干道 + 支路 dock”对照。若第一候选通过就停止扩展搜索，不做无目标的坐标网格扫描。
5. 静态检查设备不重叠、AGV 连续可达、dock 可直线进出、工作区不压占输送交接区；再对每岛 pick/place/dock 和 conveyor 交接关键位姿运行 simIK、关节限位与阶段二已有的离散路径/碰撞检查。静态平面筛选不能代替真实碰撞检查。
6. 逐岛短程驱动验证最小代表轨迹：抓取→本岛放置/交接，AGV 空载及代表性带载通过每个 dock/路段。若重排了 A/B 或改变了 payload、摩擦、轮速，重跑阶段三受影响闭环；无需重复不受影响的全部阶段一/二实验。
7. 通过后再确定地面边界、对象坐标、路线 waypoint 和阶段四布局摘要，写入 `stage4` 配置及契约。

首轮应优先试用阶段三实测的 A/B 侧置结构；新岛坐标由真实模型和路线检查导出。若 AGV 环线与 UR5 工作区无法分离，先调整岛/停靠位或将冲突动作串行化，不能用资源锁掩盖几何碰撞。

### 3.4 动线冲突表

| 动线/区域 | 主要设备 | 需要避免的冲突 | 简单处理 |
|---|---|---|---|
| S1→A/B | S1 出料带、分流点、A/B 取料区 | 分流区堆料；两台 UR5 同时占用共享取料口 | 每条支路设传感器和有限缓冲；共享区沿用资源互斥 |
| A→C→E | A/C UR5、固定交接、C→E conveyor | 交接点落入 AGV dock 或机械臂不可达区；E 入口堵塞回推 | 优先短直固定交接；E 入口满时停上游带并保留 UID |
| S2→D→E | S2/D conveyor、D UR5、AGV | AGV 路线横穿 D 取料/机械臂运动区 | D dock 贴外围主通道设置，独立定义装载状态与等待位 |
| B→A / D→E | 共享 AGV、四个站点、外围通道 | 两任务同时占窄道/dock；卸载期间车辆阻塞主线 | 单车单任务；dock/路段令牌；清晰等待点；只在安全空闲时调度 |
| C 线 + D 线→E | 两个入口缓存、E 工作区 | 两个物料争同一抓取位或半成品错配 | 入口分侧、按 UID/配对键缓存；缺件等待，不凭位置配对 |

## 4. 阶段四工作包与顺序

### F4-0：冻结旧拓扑迁移表

输入：06-02 旧案例、旧 `src/reference/` 仅供查阅、当前 stage3 配置及工件。

步骤：

1. 建立对象清单：S1/S2、A–E、每岛 UR5/TCP/传感器、传送带段、AGV、装卸站、目标位和安全区域。
2. 为每条物流边记录来源、目的地、运送介质、物料类型、传感器、目标节拍、队列上限和背压传播方向。
3. 明确 A→C 是固定衔接还是独立传输任务；明确 C→E 传送带的物理交接点及停带/挡停行为。
4. 明确 B→A 和 D→E 的取货/卸货位、载荷状态、路线、最小通道净空、优先级、等待升级条件和不可抢占区间。
5. 从旧代码提取参数时逐项标记“保留业务语义 / 重新测量 / 丢弃旧控制实现”，记录来源与新值的测量计划。
6. 冻结 E 岛输入类型与配对键。缺件时等待且不生成成品；重复事件不得二次消耗。若装配目前只需逻辑合成，阶段四默认按可追溯的逻辑消耗与 FINAL 生成实现，不宣称真实物理装配；若要几何/机器人装配，需先作为独立工序定义治具、路径和验收。

产物：阶段四配置/表格，包含拓扑、相对布局、对象别名、物流边、参数来源、配对语义及待测项。

通过条件：S1→A/B、S2→D、A→C、C→E、B→A、D→E 和 E 配对均可从表中追溯；不存在未定义的物料交接或“到站即完成”假设。

### F4-1：建立阶段四工件和契约

步骤：

1. 从受保护的阶段三工件派生阶段四工件，不改写 stage2/stage3 父工件。
2. 在 lifecycle/manifest 中增加 `stage4` 阶段路由、必需别名、构建器/runner 标识和阶段四额外契约校验；保持旧阶段校验不变。
3. 契约记录父工件 ID、manifest 摘要、stage3 契约/配置摘要，以及阶段四拓扑、布局、流程、物料规则、路线版本和验收场景摘要。
4. 确保启动时对 stage4 工件执行只读校验；句柄、仿真时刻、运行时任务队列等易变数据不得写入稳定摘要。
5. 做缺对象、错别名、错误父摘要、配置漂移、残留影子资源和错误阶段路由的负向校验。

产物：可从 stage3 派生、保存、只读校验和正确分派 runner 的 stage4 工件；对应契约测试。

通过条件：阶段三基线未变；阶段四错误工件在启动前失败关闭；合法空扩展场景可加载且只读校验稳定。

### F4-2：按物料动线分岛构建场景

按 3.2 的物料流顺序构建：先固定内部固定输送段与 S1 两条独立支路，再启用 A/C/C→E；加入 B 支路和 B→A AGV 任务；再加入 S2/D/D→E；最后启用 E 双入口缓存及配对逻辑。这样每一步都对应一条可单独观察的物料路径。

每次增量只做基本检查：场景契约/必需对象、别名与关节数、独立 IK 上下文、传感器触发、一个短 stepping smoke、保存重载和只读校验。出现与该增量相关的失败才扩展诊断；不要求每个增量重跑完整性能或故障矩阵。

通过条件：每个阶段工件可以单独构建和校验；错误只在该增量引入时被定位；未出现 stage3 基线回归或旧脚本启动冻结。

### F4-3：多类型物料与生产谱系

步骤：

1. 定义稳定 UID、物料类型、当前状态、当前持有设备/区域、来源仓库、目标岛、父 UID、工序版本和时间事件。
2. 明确物料类型至少涵盖两类原料、C 线半成品、D 线零件和 FINAL；具体命名与旧案例对齐，避免仅用岛编号推断类型。
3. 每次 conveyor、AGV、机械臂和工位交接都要求 UID、来源状态、目标状态及传感器/稳定性证据一致后提交状态变化。
4. 为 S1/S2 设置有限在制品队列；只在下游可接收且队列未满时生成物料。为数量、生成周期和仿真结束条件配置显式参数。
5. E 岛维护按配对键索引的输入缓存；两件必需输入均到位且身份/状态正确后，原子地消费输入并生成一个 FINAL，记录两条父 UID；重复提交、缺件、错型或状态回退不得产生成品。
6. 定义工件级去重键，确保同一配对事件重放不会重复生成 FINAL 或重复关闭原料任务。

产物：类型/状态转换表、有限队列与背压规则、E 岛 join 契约、事件示例和纯逻辑测试。

通过条件：正常配对恰好生成一个 FINAL；缺一件、错类型、重复输入、重放和 UID 丢失均有明确拒绝/等待结果，原料及半成品谱系可查询。

### F4-4：多岛任务协调、共享资源与 AGV 调度

步骤：

1. 将物流边建模为有向任务链，并为各任务定义前置状态、资源、开始证据、完成证据、超时和终态；不靠控制循环中的岛编号分支隐式编排。
2. 从实际路径包络建立资源表：AGV 车道、各 dock、共享取料区、各机械臂运动包络及传送带交接区。定义全局资源申请顺序，禁止循环等待。
3. 实现 AGV 空间路线图和 B→A/D→E 路段控制；底层保留 pioneer 轮速驱动。路线段记录方向、是否带载、装卸姿态、停靠/航向/速度容差、滑移上限、超时和 BLOCKED 检测。
4. 明确调度语义：B→A 高优先；D→E 低优先并按已冻结阈值等待升级；运行中的运输任务不可抢占，升级只影响下一次派车选择。若产品要求允许在安全站点中断，另行定义安全站与载荷交接，不能直接套用抢占标志。
5. AGV 到站后，经站点传感器、停稳、物料 UID 和载荷状态确认，才提交卸载/运输完成并释放资源。
6. 所有控制器在同一 Python 时钟下按 pre-tick → AGV/协调器命令 → 单次 `sim.step()` → post-tick/证据提交运行；扩展岛数不得增加每周期物理步数。
7. 对未配置、过期或与拓扑不一致的路线/任务请求失败关闭并保留诊断。

产物：阶段四协调器、路线图/调度配置、资源冲突单测、双任务竞争与实际路线报告。

通过条件：两条业务路线分别闭环；并发请求时优先级、等待升级、资源互斥和 FIFO/策略结果确定且可从日志解释；BLOCKED 和失败任务不被标记 DONE。

### F4-5：节拍、背压与可观测性

步骤：

1. 为每岛、每条输送边和 AGV 任务分别记录开始、结束、等待、处理、阻塞和交接确认的仿真时刻。
2. 定义节拍指标为处理时间、周期时间还是出件间隔；同时记录吞吐量、WIP、队列峰值、背压时长、AGV 各路线等待/运行时间和设备利用率，统一预热期与统计窗口。
3. 工位超时触发该支路暂停供料并向上游传播背压；队列未恢复或安全状态未核验前不自动重启故障任务。普通队列水位恢复可解除供料抑制，但不得清除设备安全锁存。
4. 每个事件使用 `sim_time`、任务 ID、UID、物料类型、来源/目标、设备别名和证据 ID 关联；记录异常前后的任务、资源、载荷及仿真状态快照。
5. 固定至少一个有限生产批次或明确的停止条件，避免以无限供料运行计算“完整周期”。

通过条件：报告能从原始事件重算指标；背压启动/解除原因可追踪；重复运行在相同配置下指标定义和任务终态一致。

### F4-6：代表性联调与阶段验收

按小到大运行代表性场景，保留工件 ID 和简明结果摘要：

| 场景 | 核心检查 | 通过条件 |
|---|---|---|
| A→C→E 与 S2→D→E | 两种来源到 E 的物流与配对 | 类型/UID 正确；缺件时等待，合法配对生成一个 FINAL |
| S1→B→AGV→A | B→A 路线、装卸与高优先级 | AGV 按实际轮速到站，UID 和卸载位置确认一致 |
| AGV 任务竞争 | B→A 与 D→E 同时等待 | 空闲时按冻结优先级选择；占用/运行中的任务不被抢占 |
| 有限批次 + 一次受控堵塞 | 代表性全链路和基本停机/背压 | 无静默丢料、重复成品或 BLOCKED 误报 DONE；堵塞支路停止并可诊断 |

最终退出条件：

- [ ] 布局图包含设备、两条固定物流支路、AGV 路线与 dock，代表性 UR5 路径和 AGV 转弯/停车不与其他设备明显冲突。

- [ ] B→A 和 D→E 均有实际轮速路线代表运行；空闲派车遵循已定义优先级，运行任务不抢占。
- [ ] E 缺件时不生成 FINAL，配对时仅生成一个且保留父 UID。
- [ ] 一个有限批次能结束并给出完成数、主要等待/堵塞和异常摘要；不要求完整节拍优化。
- [ ] 一次代表性故障（如 AGV 阻塞或 conveyor 停止）会停住受影响支路并保留任务/物料现场；不要求在阶段四实现统一复位恢复。
- [ ] 阶段四相关测试和阶段三关键闭环回归通过；报告说明工件版本与未覆盖事项。

## 5. 阶段边界

阶段四包含多岛范围内的运行状态检测、供料抑制、背压、诊断、有限批次联调和安全停止验证。它不实现跨设备统一故障分类、自动复位、失败任务自动续作、通用有限重试策略或人工处置工作流；这些属于 [[wiki/06-工业案例/06-05-柔性工业车间分阶段执行步骤]] 的最终故障治理阶段。阶段四验收失败时保留故障态和证据，不通过清锁存或忽略异常达成吞吐量指标。
