# 柔性工业车间阶段二：物理约束与运动规划

> 本文是 [[wiki/06-工业案例/06-05-柔性工业车间分阶段执行步骤]] 中阶段二的独立
> 实施方案。**2026-10-21 已按本方案实施并通过 §12 最小验收**，实施结果、
> 实测偏差与证据见 [[implementation/PHASE2_REPORT]] 和本文 §17。阶段一场景
> 及步骤 1.2 是输入基线，历史 phase2 分支仅作参考。

## 1. 输入基线、目标和明确不做的事项

本阶段以当前主线及步骤 1.2 通过的场景工件为输入，不以历史 phase2 分支为起点。
前置证据见 [[implementation/STEP1_2_REPORT]]：基线工件为
`stage1/L1_S1/v002_20261020_234403`，CoppeliaSim 4.10、Bullet、步长 0.05 s；
保存重载检查 130 项通过，两次仿真器进程重启后均完成 station 任务。
这些是已记录的历史验收结果，不代表阶段二碰撞、规划和停止边界已经通过。

| 能力 | 当前主线实际情况 | 阶段二处理 |
|---|---|---|
| 布局和无挡板取料 | 已使用 L1_S1；目标 UID 命中后停带、等待稳定、按实测位姿抓取 | 保留布局和流程，验证物理改动后的回归 |
| 工具安装与吸附前置判断 | 已有 Rx(pi) 安装、真实 pad/TCP/sensor 轴向、UID、距离、倾角、速度判断 | 复用；补齐物料局部坐标下的表面几何、吸盘覆盖范围和禁止碰撞判据 |
| IK 与机械臂执行 | simIK 求解六关节；已有 waypoint 和目标下发 | 补齐多解连续性、整段碰撞检查、轨迹执行一致性 |
| 碰撞集合、影子检查和避障 | 当前 `src/stage1/` 未实现完整链路 | 阶段二核心新增 |
| 场景生命周期 | build/save/load/validate/start/stop、工件保护及运行锁已完成 | 复用；只增加阶段二契约和控制器路由 |
| 故障状态 | 已有物料 FAULT/事件历史、任务 FAILED 和设备停止逻辑 | 保留；阶段二新增安全锁存，统一恢复放在阶段 2.1 |

本阶段目标是：现有单元中的 TCP 按正确工具几何接触物料外表面，空载与带载取放
路径经过碰撞和距离检查，执行轨迹不绕过检查，异常时停止并锁存。继续使用逻辑吸附，
不声称实现真空力、密封、负载极限或全动力学机械臂控制。

范围不包含：第二工位、多物料队列、AGV 全局导航、多 AGV、视觉位姿估计、通用重试/
故障恢复、自动隔离区释放。阶段二只验证 AGV 既有运动和装卸时的碰撞/停机边界。
sensor 仍负责检测目标，物料精确位姿来自仿真器对象句柄，不能写成真实传感定位能力。

实施顺序：基线盘点 → 表面几何 → 碰撞策略与影子探针 → 离散路径 →
局部规划及执行 → 运行期联锁 → 停带/输送回归 → 工件集成与完整验收。
§7 的最小停止联锁必须在第一次真实机械臂运动前具备；OMPL 为可选增强。

## 2. 物料外表面接触与工具几何

**建议文件**：新增 `src/stage2/contact.py`、`suction.py`，
复用 `stage1/suction_controller.py`；测试为 `tests/test_stage2_contact.py`、
`test_stage2_suction.py`。下文新文件/接口均为实施建议，不表示当前已存在。

1. 从父工件和实景读取法兰→pad→TCP→sensor 变换、物料形状和局部包围盒；
   核对真实杯口中心。当前 TCP +Z 与 pad +Z 同向，探测方向是 -pad Z；不得通过
   单独旋转 TCP dummy 掩盖吸盘反装，也不沿用旧分支未经重标定的工具偏移。
2. 首版限定为当前刚性长方体物料的选定顶面。将 TCP 点变换到物料局部坐标：
   `p_local = inverse(T_world_part) * p_world_tcp`，以该面局部高度计算带符号平面
   间隙；正值为外侧，负值为下探。局部包围盒中心不一定等于对象原点，必须使用
   实测 bbox 的 min/max。该量不是任意网格的通用有符号距离。
3. 计算面内偏移、杯口投影覆盖和法向夹角。物料外法向为 n 时，工具朝向物料的
   探测方向应与 -n 对齐；不能把相向的法向误判为需要同向。杯口投影应完整落在
   有效表面内，不能只检查 TCP 中心在面内。
4. 生成 `ContactEvaluation`：UID、选定面、gap、法向、投影边界、工具几何、
   sensor 命中、物料/TCP 速度、碰撞结果及拒绝原因。已有 UID/速度判据继续有效；
   几何或查询未知时拒绝吸附，不能默认通过。
5. 目标位姿由物料停稳后的实测位姿和表面变换生成，预接近/下降沿物料法向；冻结
   后若物料漂移超限则停止本次执行，不把物料重新移到设计抓取中心。
6. 为负间隙设独立数值误差预算；不直接采用历史分支的 -2 mm 或 30 mm 接触间隙。
   最大间隙应与当前杯口和 sensor 距离一致。超过误差预算必须拒绝，不能以逻辑
   setParent 后“看起来贴上了”证明表面接触正确。

简单验证：小型逻辑测试保留正常接触、下探/反向工具和错误 UID 的拒绝分支；
杯口位置与有效接触在正常取放时一并确认，不另设完整姿态矩阵。逻辑吸附不得表述为物理吸力。

## 3. 碰撞对象、距离查询与允许接触策略

**建议文件**：`src/stage2/collisions.py`、`config.py`；
测试 `test_stage2_collisions.py`。先做只读几何盘点，再配置查询，不先改场景尺寸。

1. 输出真实 UR5 各连杆 shape、可见网格/动力学网格、pad、conveyor pad/框架、
   工位台面、安装平台、AGV 车体/车轮/载台/挡边、地面的 alias/父级/几何/属性。
   集合保存稳定成员规格，句柄仅在当前会话解析。
2. 分离规划机器人本体、工具、目标物料、非目标物料、工作区、地面、AGV 本体及
   载荷的查询角色。物料生成、吸附、释放、移除时更新角色和集合，不把目标物料
   从所有检查中全局排除。
3. 明确几何查询与动力学响应不同：`collidable`、`measurable` 决定查询参与性，
   `respondable` 和 response mask 决定动力学接触。关闭 response mask 不等于
   路径安全；`sim.checkCollision` 也不会自动阻止 kinematic 关节运动。
   查询属性是否生效还取决于对象对/集合调用方式及 collection 覆盖选项，适配层要
   实测；不能仅以某个 shape 的属性值推断其必然被纳入或排除。
4. 使用 `sim.checkCollision` 与 `sim.checkDistance` 直接查询；实现 4.10 返回值
   适配层并用实机样本确认。距离查询在给定阈值内无结果时，不应自动解释为查询
   失败或距离为零；须区分“阈值内无近邻”“有效距离”和“异常/不可计算”。
5. 自碰撞先采用显式非相邻 link 对及有依据的安装接触例外；若使用 collection
   self-collision indicator，必须实测枚举其过滤结果，不凭编号推断。不能因为
   某个连杆误报就从所有自碰撞和工作区检查中删除该连杆。

| 对象关系 | 允许条件 | 仍需禁止/检查 |
|---|---|---|
| UR5 基座—安装台 | 固定安装面正常接触 | 其他连杆与安装台；不能整个平台排除 |
| 车轮—地面 | 正常滚动接触 | 车体穿地、车体/轮子撞障碍 |
| 物料—conveyor pad/工位台面/载台 | 当前阶段对应的承载接触 | 物料穿透、越出承载范围、撞挡边之外的障碍 |
| 杯口—当前目标表面 | 最终接触段、UID 一致、§2 有效 | pad 其他部位/腕部碰物料；非目标物料 |
| 已吸附物料—工具 | 已标定的附着接触关系 | 带载物料与其他连杆、框架、台面及障碍 |
| 非相邻连杆—非相邻连杆 | 无已验证安装例外时禁止 | 全程自碰撞检查 |

简单验证：用一个已知相交对象对确认查询有效，正常取放同时确认分离与承载例外；
记录对象对及必要距离即可，不单独建立批量实验。安全裕量应按关系和动作阶段设置；最终接触及放置不能
机械套用全工作区统一 1 cm 距离阈值，也不能用整物料白名单放开碰撞。

## 4. 影子探针与离散路径检查

**建议文件**：`src/stage2/shadow.py`、`path_planning.py`；
测试 `test_stage2_shadow.py`、`test_stage2_path_planning.py`。

1. 在派生副本或独立查询环境中建立同基座、同关节链、同工具偏移的影子臂；
   优先复制当前通过模型，不重新加载具有不同脚本/尺寸的模型。影子无控制脚本、
   不可响应、不影响质量/动力学；仅参与专用几何查询，不进入生产 sensor 检测。
2. 对 HOME、预接近、接触和放置等构型验证真实/影子 FK：TCP 和每个连杆变换误差
   均在事先定义的数值容差内。检查真实与影子成员集合不会互相查询而产生假碰撞。
3. 搬运时复制载荷几何，保存 attach 时的 TCP→物料相对变换；每个候选构型更新
   影子载荷。空载路径通过不能替代带载路径检查。
4. 实现 `check_configuration(q, context)` 和 `check_segment(q0, q1, context)`；
   context 至少含动作阶段、目标 UID、载荷变换和场景快照标识。起点/终点碰撞应
   单独报错；路径结果保留首个失败构型、对象对、TCP 和最小间隙。
5. 初版可从最大关节增量 2°、接近段 TCP 间隔 2 mm 开始试验，二者均为候选值，
   不是已验收安全参数。增加 link/载荷位移检查和必要的自适应细分，不能只限制 TCP
   位移而漏掉肘部扫掠。达到采样/时间预算而未查完必须返回“验证未完成”，不能
   截断、增大步长或改成仅两点检查后当作通过。
6. 所有测试在影子构型上进行，不能为了检查候选而修改真实机械臂关节再改回来。
   查询异常或非有限构型按失败处理。报告采样间隔与剩余离散漏检局限，不声称已
   实现连续碰撞检测。

简单验证：初始化时检查真实/影子 FK 一致；小型探针测试覆盖中间碰撞和带载碰撞。
可复用 §12 的拒绝案例，检查前后真实关节与物料位姿不得被探针修改。

## 5. 有限局部规划、轨迹生成与执行一致性

**建议文件**：`src/stage2/path_planning.py`、`trajectory.py`、
`unit_controller.py`；在 `stage1/ur5_ik_controller.py` 增加必要的兼容接口，
默认阶段一调用行为不变。

1. 先在原布局冻结取料允许区域和工位/AGV 目标，求解预接近、接触、抬升、转运、
   放置及撤离构型。严格保持真实工具姿态约束，不能改成只约束位置来消除碰撞。
2. 多解 IK 仅在 IK 环境/影子环境尝试。候选以当前 q 和已验证安全构型为 seed，
   按限位、碰撞、安全距离、关节连续性筛选；不强制腕部趋近零，不凭 q6 符号
   判断分支。此处是阶段二原始规划要求，不代表实现已禁止腕部分支翻转；阶段二
   实施没有腕部分支硬约束。阶段 2.01 增加同一腕部分支连续执行的硬约束，细节见
   [[wiki/06-工业案例/06-10-柔性工业车间阶段2.01-动作轨迹优化]]。周期关节仅在
   实际允许周期时 wrap，有限位关节不得跨限位走“短路”。
3. 第一候选为直接关节路径；失败后尝试有上限的预接近高度、横向绕行 waypoint、
   允许的工具绕法向 yaw 与 IK 分支组合。该阶段二策略可能选到视觉上不必要的腕部
   翻转；阶段 2.01 将限制候选必须保持同一腕部分支，分支内无解则失败。减小采样
   步长用于提高检查分辨率，本身不会把同一条碰撞路径变成绕障路径。
4. 最终接近/离开承载面按笛卡尔法向分段生成位姿，并以上一解为 seed 连续求解；
   对每段重新执行 §4。普通关节插值不保证 TCP 走直线，必须用 FK 验证偏差。
   当前带载转运的 `transit → pre_place` 仍是一个高位中转到低位预接近的合并目标段；
   阶段 2.01 计划增加同高 `high-above-place` waypoint，先完成水平 XY 对位，再单独
   沿 Z 轴下降到 `pre_place`，详见 [[wiki/06-工业案例/06-10-柔性工业车间阶段2.01-动作轨迹优化]]。
5. 输出 `MotionPlan`：有序 q、段落语义、速度/加速度/jerk 限制、载荷和接触策略、
   场景快照、检查结果、耗时。只把完整通过检查的计划交给执行器，不在下发前再用
   单次 IK 结果覆盖原计划。
6. 采用可逐步推进的轨迹执行器；若使用 Ruckig/moveToConfig，必须确认不会阻塞
   外部 stepping 和安全轮询。平滑/时间参数化可能改变路径，实际输出的每步 q 和
   相邻 q 扫掠段要按同一策略复核，不能只复核原始 waypoint。
7. kinematic UR5 的关节位置/目标接口在 4.10 实机验证后选择；当前六关节 mode=0，
   不在本阶段默默切换到动态伺服模式。真实观测 q/TCP 偏离计划超限即停止；已检
   起始构型不匹配或障碍/目标移动时计划失效。
8. 放置时先根据真实 TCP 与 attach 相对变换计算载荷位置，确认目标承载面和姿态
   达标后再释放。阶段一 release 会写入目标物料位姿，阶段二必须约束该修正量在
   已冻结的小误差内或采用保持世界位姿的解绑；不得通过 release 瞬移修正错误放置
   路径。复用原始属性快照恢复 dynamic/respondable/质量/摩擦/mask，并在后续
   stepping 稳定窗口验证穿透、滑移和速度，而非刚 resetDynamicObject 就判成功。
9. 局部搜索设候选数、单次求解、总采样数和墙钟预算，先记录基线耗时再冻结预算。
   规划过程不推进生产运动；长计算拆为可取消批次并报告进度。预算用尽返回
   `LOCAL_AVOIDANCE_FAILED`/`PLAN_BUDGET_EXCEEDED`，保持停止，不回退到旧直线动作。

简单验证：复用 §12 的正常取放和路径拒绝案例，确认完整路径经过空载/带载检查、
关节连续、下降与放置正确。局部绕行仅在实际用到时补一个成功案例。
尚未找到路径只能说明当前搜索无解，不能直接宣布场景几何必须修改。

## 6. 可选 OMPL 兜底

在 §3–§5 的探针、载荷和执行检查稳定后，才决定是否接入
[[wiki/03-运动规划与控制/03-02-OMPL运动规划]]。不是阶段二默认必装依赖。

1. 用当前六关节真实限位建立状态空间，先选择 RRTConnect；显式记录插件版本、
   state validity 分辨率、随机种子（接口支持时）、总规划墙钟预算。
2. 使用与局部规划一致的禁止对象对和自碰撞策略；复杂阶段白名单/载荷需要自定义
   validity 检查时，先核对插件回调在当前 Python/ZMQ 方式下是否可用。若两套
   validity 无法等价，不声称 OMPL 路径已安全。
3. 只规划到预接近点；最终表面接触沿 §5 的法向约束段拼接。全局算法的自由姿态
   路径不能替代受约束的接触动作。
4. OMPL 路径简化、插值及时间参数化后用 §4 和执行检查重新验证全部段及载荷；
   插件返回成功不等于最终验收成功。
5. 插件缺失/超时/无解/复核失败返回明确状态并保持停止，不降低几何精度或关闭
   检查。当未启用 OMPL 时，报告标为“未纳入/未验证”，不填通过。

## 7. 运行期安全停止与现场锁存

**建议文件**：`src/stage2/safety.py`；接口可为
`SafetyObservation`、`SafetyLatch`、`request_stop(reason)`。
这是阶段二必需的最低异常处理，不是阶段 2.1 的恢复框架。

1. 每步先读取真实 q、TCP、载荷/物料状态与必要的障碍位姿，检查当前和下一段
   运动，再下发关节/轮速。所有运动阶段（含撤离和 AGV 载货）都经过联锁；step
   推进后复查真实状态，动态场景变化使原计划失效时立即锁存。
2. 风险出现时取消剩余轨迹和所有后续目标下发。对当前 kinematic UR5 保持最后
   实测构型，不保持尚未到达的旧 goal；conveyor 和 AGV 发零速。分别记录命令
   是否成功和停止是否被真实读数确认，避免把命令成功当作停稳。
3. 保留 UID、原始物理属性和附着关系；不自动退避、抬升、释放或复位。现场保全指
   保存诊断及禁止继续动作，不代表动态物料和重力被自动冻结。
4. 停止反馈、碰撞查询、速度或位姿缺失时记为“未知/停止未确认”，禁止继续抓取。
   若无法确认受控停止，可按运行入口策略暂停/停止仿真；先记录原因和可获得快照，
   注意 stopSimulation 可能重置动态现场，不能把重置后的状态当成故障瞬间快照。
5. 日志至少包含 run/task/UID、仿真/墙钟时间、风险对象对、计划段/样本、真实 q、
   TCP、物料位姿/附着状态、设备命令与停止确认。锁存可用现有 FAILED 承载并附原因，
   不必在阶段二新增完整的跨设备故障枚举。
6. 最小验证保留一次运行期受控障碍触发，确认取消剩余轨迹、停止并保持锁存；
   关键查询失效的拒绝分支用逻辑/适配测试覆盖，不逐类做仿真注入。先规划拒绝的
   案例不能代替运行期停机检查；清障后不得自动继续或误报 DONE。

轮询只能在离散时间检测，不能承诺任意动态障碍下“零碰撞”。按速度、步长、最大
停止位移确定预警距离，报告检测/命令/实际停止时刻和最大侵入；超出冻结误差预算
即不通过，不能用“下一步停住了”掩盖实质穿透。

## 9. 故障恢复边界与实现包顺序

完整故障分类、重试、退避、自动重新规划、隔离区释放、人工复位和任务恢复移到
阶段 2.1（§14）；本阶段只完成 §7 安全停止、锁存和明确失败结果。阶段一已有
故障逻辑应保持或收紧，不能为了延期恢复而删除现有防护。

| 实施包 | 主要文件/接口 | 进入条件 | 结束后应得到的可审查结果 |
|---|---|---|---|
| P2-0 基线盘点 | scene_contract/config；父工件记录 | 步骤 1.2 通过 | 几何/脚本/控制模式清单、基线哈希、复用/新增差距清单 |
| P2-1 接触几何 | contact/suction | P2-0 | 正确工具轴、局部面判据、有效/无效接触证据 |
| P2-2 碰撞探针 | collisions/shadow | P2-1 | 对象对策略、真实/影子一致性、中间穿模与带载碰撞被检出 |
| P2-3 路径执行 | path_planning/trajectory | P2-2，首次运动前已具备最小安全锁存 | station 完整路径和实际轨迹复核；需要时验证局部绕行 |
| P2-4 安全与停带 | safety/conveyor 适配 | P2-3 | 一次运行期锁存；正常任务内确认停带/稳定与补偿边界 |
| P2-5 工件集成 | integration/scene_contract；现有 lifecycle 扩展 | P2-0 起设计，P2-4 后正式验收 | stage2 显式路由、只读校验、保存重载后一次复跑 |
| P2-6 可选全局规划 | ompl_planner | 局部路径/执行已稳定且确有需要 | 一个成功案例及后处理复核；失败分支用逻辑测试覆盖 |
| P2-7 简单验收 | run/report，必要 tests | 必做包通过 | §12 最小检查结果、简短报告及剩余限制 |

按包实现，验证统一复用 §12：同一次正常取放可同时确认接触、停带、路径和释放，
不要求每包额外跑一套 smoke。只补能揭示关键风险的逻辑/适配测试；真实几何查询仍
需仿真样本确认，不用 fake/mock 证明其可用。实现按功能边界拆分，不整体导入旧分支。

控制器接入点应落在当前 `Stage1UnitController.step()` 的运动前后和
`_run_motion()` 的关节下发之前，并覆盖 `attach()`/`release()`；不能只在任务开始
时检查一次。建议阶段二组合/扩展控制器注入 probe、planner、executor、safety，
阶段一默认依赖保持原行为。最小接口合同为：

- contact 返回可复算的有效/拒绝原因；
- probe 返回安全/碰撞/距离不足/查询未知及具体对象对；
- planner 返回完整 MotionPlan 或明确失败，不返回“部分路径也可执行”；
- executor 每步仅提交已验证的下一构型，并暴露实际状态与取消入口；
- safety 锁存后禁止 planner/attach/release 自动重新启动原任务；
- integration 负责选择控制器、重建运行时资源和统一生命周期，不能自行创建第二个 step 循环。

## 10. 主动停带、摩擦输送与物料稳定回归

**建议文件**：`stage2/conveyor_safety.py`；复用并修正必要的阶段一读数适配。
当前场景没有 `Conveyor_In_PickupStopper`，不重建挡板，不做“移除挡板”故障注入。

1. 默认只支持当前冻结的 0.20 m/s、现有物料和取料区域。在正常取放时记录目标
   命中、零速命令、带面停止、物料稳定及抓取目标冻结的关键时刻与位置/速度，
   不另设前沿/中部/后沿重复矩阵。
2. 当前 `_pad_velocity()` 异常时可能返回 0.0，`_advance_stopping()` 缺失位姿时
   初始 `pos_ok=True`；先消除这些把未知读数当安全的路径。保留“模型速度字段可能
   陈旧、可使用独立位移判据”的能力，但必须验证所跟踪对象确实反映带面运动。
   不能用固定框架的位置不变作为 conveyor 停止证据。
3. 停止读数须记录来源、有效性、时间和可信度；选择事先冻结的速度主判据/有效
   位移回退策略。回退仅在独立信号可验证、连续窗口有效时使用；两者未知或无法
   解释的矛盾必须锁存，不通过等待若干步就把非零速度判为不可信。
4. 沿实际带面切线测量有符号前进越程、反滑和侧向/高度漂移；最大越程和允许
   抓取区分别判定。pad 停止后继续观察物料稳定窗口，不能把 pad 零速当作物料停稳。
5. 步骤 1.1 C 组在当前配置关闭补偿后已观察到物理输送，不能沿用旧 phase2 的
   “4.10 pad 不传速度”结论。比较“仅物理输送”与“当前 HYBRID_DYNAMIC”逐步轨迹，
   排查物理输送叠加固定位置补偿导致超带速；只在物料确实落后于冻结目标且允许
   的条件下使用受限补偿，并逐步记录补偿量/原因。
6. 吸附前不居中瞬移物料，停带后不继续补偿来修正终点。任何补偿策略改变都要
   复查到位范围、稳定和一次完整取放，可复用 §12；不以提高摩擦/加速度代替停止证据。
7. 本阶段不强制扩展带速或物料范围；以后确有需求再补对应检查。延迟、最大越程
   和稳定阈值根据当前工况与可抓取区域预先定义，不照搬旧分支 0.15 s/0.03 m；
   越界立即拒绝抓取，恢复措施留待 2.1。

简单验证：复用正常任务确认停止/稳定后才抓取、未知读数不放行。补偿仍启用时，
追加一次短距离“关闭补偿”对照，排查双倍输送；已关闭补偿时不重复该对照。

| 检查 | 最小做法 | 通过条件 |
|---|---|---|
| 关键逻辑/适配测试 | 仅覆盖接触有效/拒绝、错误 UID、中间/带载碰撞、查询未知触发锁存、控制器/契约不匹配 | 错误分支不吸附、不提交运动；取消后不再下发旧轨迹；不匹配不能启动 |

| 运行期停止 | 正常运动中在实验副本受控加入一个风险障碍，触发一次联锁 | 取消剩余轨迹、发出停止并核对真实状态；保持锁存，不自动恢复、不误报 DONE |

配置集中保存当前采用的接触容差、碰撞裕量、采样间隔、轨迹限制、规划预算和

## 14. 阶段 2.1：统一故障状态与恢复

阶段二退出后执行；复用现有 MaterialManager 的 FAULT、事件历史和复位接口，
以及阶段二停止锁存，不另造不相连的状态机。

1. 梳理任务/物料/设备状态转换，关联 task/UID、原因码、设备和场景版本，定义
   可重试失败、终止失败、BLOCKED、人工处置、RECOVERED 与 DONE 的互斥关系。
2. 将 IK/规划失败、碰撞、停止未确认、sensor 超时/UID 错误、释放不稳、掉料、
   AGV 堵塞、通信异常映射到安全动作、物料 FAULT 策略和完整快照。
3. 定义重试上限、退避、重新确认 UID/附着关系/物理属性/真实构型/路径的前置条件，
   防止重复吸附、重复释放和重复完成；未知现场不自动入队。
4. 清障后仍需显式复位。已吸附物料只能沿重新验证的路径退避/释放；没有安全路径
   就保持锁存转人工，不预建隔离区作为所有故障的默认处理。
5. 逐类故障注入，验证停止、快照、恢复检查、幂等、超限转人工；记录发生过故障、
   后续是否恢复以及原任务结果，三者不能合并成一个成功标志。

完整报告与证据见 [[implementation/PHASE2_REPORT]]。阶段二工件

关键实现与计划偏差：

1. **规划器**：使用 12 seeds / 6 candidates 的多解 simIK，加上有界
   DFS 回溯（直接 → HOME 中转 → 抬高中转 → yaw 变体）与最终 2° 复核。
   工位/AGV 放置需要“抬升 → 高位中转（z≥0.80 m）→ 预放置 → 法向放置”
   的带载序列，直接从 lift 插值会让载荷扫过传送带；该序列已固化为
   `TRANSFER_RISE_*` / `TRANSFER_TRANSIT_*`。
2. **接触**：实测杯口半径 0.023579 m；吸附前检查局部顶面带符号间隙、
   横向偏移、杯口覆盖和工具法向。接近段允许绕法向 yaw（圆形杯口），
   最终放置点仍严格检查完整姿态。该 yaw 自由度没有腕部分支约束，故阶段二
   通过不等于“不会翻腕”；阶段 2.01 将新增跨支候选拒绝要求。
3. **碰撞**：4.10 的 collection self-collision indicator 实测不生效，
   改用显式非相邻连杆对 + 吸盘 Body 对 link1–5；conveyor 粗代理
   `shape` 从查询角色排除并记录原因。载荷在抬升起点和放置终点允许与
   承载面接触，中间构型严格检查。
4. **停带**：速度回读与独立 pad 位移双判据；速度不可用时不回退到 0，
   连续窗口无法确认即锁存。补偿只补物理输送相对带速的差额。
5. **安全**：风险/未知读数立即锁存，取消剩余轨迹、停带/停车、保持
   最后实测构型并确认真实停止；不自动恢复、不重试。
6. **工件**：`extra.stage2` 记录契约、配置、碰撞角色、允许接触、规划/
   执行/停带/安全参数；manifest 不写会话句柄；影子臂/集合为会话资源，
   保存/校验拒绝持久化残留。
7. **OMPL**：未启用，记为 N/A；局部规划失败返回明确状态并停止。
